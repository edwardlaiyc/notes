# school — personal university notes

NTU lecture notes, authored in LaTeX and published as a static site. One folder
per semester (`y1s2/`, `y2s1/`, …); inside a semester, one folder per course,
named `scXXXX-topic`.

## Repository layout
```
school/
├── web-pipeline/     shared, semester-independent LaTeX → HTML/Markdown build
├── y1s2/             a semester: six courses + the semester landing page
│   ├── scXXXX-topic/ one course
│   ├── index.md      semester hub content
│   └── hub.yml       semester hub pandoc metadata
└── .claude/skills/   authoring skills (cheatsheet, latex-notes)
```

`web-pipeline/` sits at the repo root rather than inside a semester because it is
topic- and semester-independent — one source of truth for every course in every
semester, never copied.

## Notes structure (per course)
Most courses' notes are a LaTeX `subfiles` project:
- Master docs at the course root: `<course>-partN.tex` (preamble + `\subfile` list).
- Chapters in `chapters-partN/` — each `\documentclass[../<course>-partN.tex]{subfiles}`.
- Figures in `images/`.

**Edit the chapter files, not the masters.** The master only sets the preamble and
includes chapters; chapter content lives in `chapters-partN/*.tex`.

**Exception — a single monolithic article.** Some courses are instead one
standalone `article` (e.g. `y1s2/sc1302-ethics/ethics-test.tex`): all content in
one `.tex`, split by `\section`. There the single `.tex` *is* the source of truth;
any `chapters/` files are generated by the web pipeline, not hand-edited.

## Web-conversion pipeline (shared, any course)
Courses convert their notes to a fast/readable web version (HTML + portable
Markdown) via pandoc + MiKTeX + Pillow. Each course supplies only three files in
its own root: `course.yml` (branding + navigation), `site.psd1` (build manifest —
ordered topics + any preprocessing), and `index.md` (overview page). The site is
**one page per topic** for fast reading; there is no single combined page.

- Build one topic: `..\..\web-pipeline\build.ps1 -Source .\chapters-part1\1-introduction.tex`
- Publish a course: `..\..\web-pipeline\publish.ps1` (reads `site.psd1`)
- Publish a semester hub: `..\web-pipeline\publish-hub.ps1` (run from the semester folder)

`publish.ps1` and `publish-hub.ps1` both default to the current directory — run
them from the course root and the semester root respectively.

The page shell (`web-pipeline/template.html` + `style.css`) is shared, so chrome
changes there apply to every course after a rebuild. Each page has a fixed topbar
(`#reading-bar`, revealed on scroll past the header) showing a reading-progress
fill and the page title; the title is a `#reading-bar-title` button that scrolls
back to the top (smooth, or instant under `prefers-reduced-motion`).

Six y1s2 courses are wired up: `sc1006-comorgarchi/` (a `subfiles` project with
pre-rendered bytefields and a spliced Part 2), `sc1302-ethics/` (a single
monolithic article auto-split by `\section`), `sc1305-linearalgebra/` (a
per-chapter `subfiles` project with pre-rendered inline TikZ/pgfplots figures),
`sc2500-probability/` (a per-chapter `subfiles` project with TikZ/pgfplots in one
chapter), `sc1315-ai/` (two monolithic articles split by `\section`; its
search/game algorithms ship twice, algorithm2e for the PDF and a `Verbatim` code
block for the web), and `sc1008-c++/` (a **link-out course**: the real notes are a
Google Colab notebook, so the site is just an overview page pointing at
Drive/GitHub plus the one `final-summary.tex` cheat sheet built as a single page).
Each has its own `CLAUDE.md`.

**Semester landing page.** `y1s2/index.html` is the hub linking all six courses —
one `.subject-card` per course pointing at that course's `index.html`. It is not a
course (no `site.psd1`, no topics), so `publish.ps1` can't build it; its builder is
`..\web-pipeline\publish-hub.ps1`, which stages the shared assets at the semester
root and runs pandoc once over `y1s2/index.md` with `y1s2/hub.yml`, through the
same shared `template.html`. Cards carry just the course code and title — no
descriptions — hand-written in `index.md`, and are the page's only navigation (the
template's nav pane is deliberately off there; it duplicated the cards).

The pipeline pre-renders LaTeX constructs pandoc can't handle to SVG: `bytefield`
diagrams (`render-bytefields.py`) and `tikzpicture`/`pgfplots` diagrams
(`render-tikz.py`, added for `sc1305`), as opt-in `Preprocess` steps in a course's
`site.psd1`. Algorithms need no pre-render: sc1315 keeps the `algorithm2e` block
for the PDF and puts a `\begin{Verbatim}` plain-text block next to it that pandoc
renders as a copyable web code block — `\excludecomment{Verbatim}` hides the
Verbatim from pdflatex; pandoc drops the algorithm2e to an empty (CSS-hidden) div.
`render-algorithm.py` can alternatively pre-render `algorithm2e` to SVG, but it is
an unused optional fallback.

→ **Read `web-pipeline/README.md` before running or changing the conversion** — it
has the exact commands, the `site.psd1` schema, the procedure for a new subject,
and the gotchas (several LaTeX constructs make pandoc silently drop entire tables
or the whole TOC; `\small`/nested `$…$` inside `\text{}` and `\\` in `\[…\]` break
MathML conversion). `y1s2/sc1006-comorgarchi/CLAUDE.md` and
`y1s2/sc1305-linearalgebra/CLAUDE.md` document those courses' source quirks.

## What is committed
`.tex` source, figures, the generated `.html`/`.md` pages, and the pipeline.
**Compiled PDFs are deliberately not committed** — they live in Google Drive. See
`.gitignore`.

## Adding a semester
Create `yNsM/`, copy a course folder as a template, and point the new course's
`site.psd1`/`course.yml` at its own topics. Nothing under `web-pipeline/` changes.
