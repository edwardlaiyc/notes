# Shared notes web pipeline

Converts a course's LaTeX lecture notes into a fast, readable, responsive static
website — **HTML** (primary; numbered sections, TOC, theme toggle, MathML) plus a
portable **Markdown** export. No framework, package manager, CDN, or runtime
math/JS. The one web font (DM Sans) is **self-hosted and bundled**, so pages
render identically offline — nothing is fetched at page load. Requires only
**Pandoc**, **Python** (+ **Pillow**), and **MiKTeX** + **pdftocairo** (only for
`bytefield` diagrams).

This package is **topic-independent and shared** across every course under
`uni-notes-y1s2/`. Each course keeps only its own content and a little config; the
scripts, template, and stylesheet live here.

## Layout

```
uni-notes-y1s2/
  index.md, hub.yml        ← the semester landing page (links every course)
  index.html, assets/      generated by publish-hub.ps1
  web-pipeline/            ← this package (shared, no course content)
    build.ps1              generic one-topic builder
    publish.ps1            generic whole-site builder (reads a course manifest)
    publish-hub.ps1        semester landing page builder (no manifest)
    split-sections.py      slice a monolithic article into per-section pages
    assemble-page.py       concatenate subfiles chapters under one preamble
    render-bytefields.py   pre-render bytefield diagrams to SVG
    render-tikz.py         pre-render tikzpicture / pgfplots diagrams to SVG
    render-algorithm.py    pre-render algorithm2e pseudocode to SVG
    optimize-images.py     raster → WebP, stamp dimensions
    template.html          metadata-driven pandoc shell
    style.css              all presentation
    assets/fonts/*.woff2   self-hosted DM Sans (latin subset, staged per course)
    lazy.lua, unwrap-multicols.lua, qa-details.lua, toc-hide-unnumbered.lua   pandoc filters
  scXXXX-topic/            ← a course
    course.yml             branding + navigation (pandoc metadata)
    site.psd1              build manifest (topic order + preprocessing)
    index.md              overview page content
    assets/style.css       staged copy of the shared stylesheet (generated)
    assets/fonts/          staged copy of the shared web fonts (generated)
    <sources>.tex, images/, media/, *.html, *.md
```

`course.yml`, `site.psd1`, and `index.md` are the **only** files you author per
course. `assets/style.css` and `assets/fonts/` are staged automatically by the
build so each course's output is self-contained and servable from its own root.

## Build one topic

From the course root:

```powershell
..\web-pipeline\build.ps1 -Source .\chapters-part1\1-introduction.tex
```

Writes `1-introduction.html` and `1-introduction.md` beside the source. Multiple
`-Source` values (and wildcards) are each built independently. Useful options:
`-CourseRoot`, `-Config`, `-Preamble`, `-Title`, `-NumberSections`,
`-SectionOffset`, `-HtmlOnly`, `-MarkdownOnly`, `-NoBytefields`. `-CourseRoot`
defaults to the current directory; `-Config` defaults to `<course>\course.yml`.

## Publish the whole site

```powershell
..\web-pipeline\publish.ps1
```

Reads `<course>\site.psd1`, runs any preprocessing, builds every topic page
(deriving Previous/Next links and section-number offsets from the topic order),
then builds the `index.html` overview. `-SkipPreprocess` rebuilds presentation
only.

## Plain-text navigation entries

A `navigation-groups` link with a `label` but **no `href`** renders as plain text
(`<li class="navigation-text">`) instead of an anchor — for a bullet that explains
something rather than going somewhere. Used by `sc1008-c++` ("Full notes in the
notebook below"). Existing entries all have an `href`, so the branch is inert
everywhere else. A group can also carry a `note:` paragraph above its list;
nothing uses it now.

## Publish the semester landing page

```powershell
.\web-pipeline\publish-hub.ps1        # from uni-notes-y1s2/ (or anywhere — it defaults there)
```

The hub is `uni-notes-y1s2/index.html`: one card per course, each linking to that
course's `index.html`. It is **not** a course — it has no `site.psd1` and no
topics, so `publish.ps1` cannot build it (that script requires `Topics`).
`publish-hub.ps1` is the whole build: stage `assets/style.css` + `assets/fonts/`
at the notes root, then run pandoc once over `index.md` with `hub.yml` as
metadata, through the **same** `template.html` as every course overview (so it
inherits the theme toggle, reading bar, and footer for free).

Authored files: `index.md` (the subject cards + an Ecosystem section; no About) and
`hub.yml` (just `course-code` / `course-title` / `lang` for the header). `-Title`
sets the `<h1>` and reading-bar label (default `Lecture Notes`).

**Neither navigation is rendered here** — the hub passes `hide-page-nav` and omits
`show-site-nav`, so the cards are the only routing. The template's site navigation
is built for a course's long chapter list; with six links it was a half-empty box
duplicating the cards. Hence `hub.yml` has no `navigation-groups`; adding one back
would re-enable the pane.

Each card is one `<a class="subject-card">` written on a **single line** in
`index.md` — pandoc wraps a lone raw-HTML inline in a `<p>`, so the grid items are
those paragraphs (`.subject-grid > p { margin: 0 }` in `style.css` accounts for
it). Keep a card on one line; splitting it across lines lets pandoc parse the
inner markup as markdown. A card carries only the course code and title (both at
the same size, the code muted and letter-spaced) — no description line. When a
course is added, edit `index.md` + `hub.yml` and re-run `publish-hub.ps1`.

Course pages do **not** link back to the hub; navigation within a course is
internal-only (the template prefixes nav hrefs with `$site-root$`). Adding a
`../index.html` link to each course's `course.yml` would work but means
republishing every course.

## The `site.psd1` manifest

A PowerShell data file (`Import-PowerShellDataFile`). Schema:

```powershell
@{
    # Optional, in order. Omit the whole key if the source is already
    # per-topic .tex files with no bytefields.
    Preprocess = @(
        @{ Kind = 'bytefields'; Sources = @('chapters/8-encoding.tex') }
        @{ Kind = 'tikz'; Preamble = 'linear-algebra.tex'
           Sources = @('chapters/0-vectormatrix.tex') }   # pre-render TikZ/pgfplots
        @{ Kind = 'algorithm'; Preamble = 'test1.tex'
           Sources = @('test1.tex') }                      # pre-render algorithm2e
        @{ Kind = 'assemble'; Out = 'part2.tex'; Preamble = 'cheatsheet2.tex'
           Title = '...'; Sources = @('cheatsheet2.tex') }
        @{ Kind = 'split'; Source = 'part2.tex'; OutDir = 'chapters-part2'
           Sections = 'star'                 # any | plain | star (default any)
           Modules = @(@{ Slug='...'; Title='...' }, ...)   # optional; omit for auto
           TableRouting = @(@{ Caption='...'; Slug='...' }, ...) }  # optional
    )

    # Ordered reading sequence. Prev/Next + section offsets derive from order.
    Topics = @(
        @{ Source = 'chapters/1-intro.tex'; Title = 'Introduction'; NumberSections = $true }
        @{ Source = 'chapters/ref.tex';     Title = 'Reference' }   # unnumbered
    )

    Index    = @{ Source = 'index.md'; Title = 'Overview' }
    Obsolete = @('old.html', ...)   # deleted from the course root after publish
}
```

`NumberSections` defaults to `$false` per topic; set `$true` on the ones that
should carry running section numbers. The offset for each numbered topic is the
cumulative count of top-level `\section{...}` in the numbered topics before it.

## Start another subject

1. Author `course.yml` (course code, title, navigation groups/links).
2. Author `index.md` (overview / About / any ecosystem section).
3. Author `site.psd1` (ordered `Topics`, plus `Preprocess` if the source is a
   single monolithic article or uses bytefields).
   - A **monolithic `article`** (one file, many `\section`s): add a `split` step
     with `Sections = 'plain'` and **no** `Modules` — auto mode makes one page per
     section, slug derived from the heading. List the produced
     `<outdir>/<slug>.tex` files as `Topics`.
   - **Per-chapter `subfiles`**: list each chapter `.tex` directly as a topic; no
     preprocessing needed.
4. Run `..\web-pipeline\publish.ps1` from the course root and inspect the output.

Nothing about a course is hard-coded in this package — branding and navigation
come from `course.yml`, structure from `site.psd1`.

## Local preview

`file://` is blocked by the browser extension. Serve over localhost **from the
course root** (so `assets/style.css` and page links resolve):

```powershell
python -m http.server 8765   # → http://127.0.0.1:8765/index.html
```

## Click-to-reveal answers (optional, any course)

A review/question page can make each answer a click-to-reveal dropdown. Author
the answer as an `answer` environment tucked inside the list item, right after
the question (and its options, if any):

```latex
\NewDocumentEnvironment{answer}{}{\par\smallskip\noindent\ignorespaces}{\par\smallskip}
...
\item Some claim. TRUE or FALSE?
\begin{answer}\textbf{FALSE.} Because ...\end{answer}
```

`\NewDocumentEnvironment` is honoured by LaTeX (so the PDF typesets the answer
inline) but **ignored by pandoc**, which leaves the environment as a `Div` of
class `answer`. `qa-details.lua` (run on every HTML build) rewrites any list item
carrying such a Div into a native HTML `<details>`: the question plus any options
become the clickable `<summary>`, the answer becomes the collapsible body, and a
CSS caret after the stem flips down→up on open. No JavaScript. The filter is
inert on items without an `answer` Div, so it is safe for every course; it is
applied to the HTML build only (the Markdown export keeps the plain `answer`
Div). Nested option lists inside a question render as `a, b, c…` via CSS so
letter-referencing answers line up. See `sc1302-ethics` for a worked example.

### Contents box: mirror the PDF's ToC

In LaTeX, *starred* sectioning commands (`\section*`, `\subsection*`,
`\subsubsection*`) are deliberately **not** written to the `.toc`, so the PDF's
Contents lists only numbered headings. Pandoc instead lists **every** heading in
the web Contents — and because a starred sub-step (e.g. `\subsubsection*{Numerical
Calculation}`) is usually authored at the *same* heading level as the numbered
heading it belongs under (`\subsubsection{The posterior parameters}` → 3.5.3), it
lands in the ToC at the same indentation, giving a flat, confusing list.

`toc-hide-unnumbered.lua` (run on every HTML build) marks each `unnumbered`
heading as `unlisted`, which drops it from the table of contents while leaving it
in the page body — so the web Contents mirrors the PDF's. It is inert on numbered
headings and cannot empty a page's ToC in these courses (every chapter's own
`\section`/`\subfile` heading is numbered and stays listed). HTML build only; the
Markdown export is unaffected.

## Typography & reading chrome

**Self-hosted font.** The site uses **DM Sans** (a geometric-humanist sans, the
closest free stand-in for Google Sans / the Google-blog look). The woff2 files
live in `web-pipeline/assets/fonts/` (latin subset, variable weight — one file
covers the whole weight range, plus an italic). They are declared via `@font-face`
in `style.css` with **relative** `url("fonts/…woff2")` paths, so they resolve
wherever the staged `style.css` sits. Both `build.ps1` (`Copy-StagedFonts`) and
`publish.ps1` mirror the `fonts/` folder next to the staged stylesheet, so every
published site is fully offline — no CDN, no dependency on the visitor having the
font installed. woff2 is supported by ~all current browsers.

Family selection goes through two CSS variables in `:root`: `--font-body` and
`--font-heading` (both DM Sans, with a system-sans fallback). Headings and the
site title use weight 500 with slight negative letter-spacing.

**To swap the font:** drop the new `*.woff2` into `web-pipeline/assets/fonts/`,
update the two `@font-face` blocks (family name + filenames) and the two font-
stack variables in `style.css`, delete the old woff2 (from the pipeline *and*
from any already-staged `<course>/assets/fonts/`), then republish. To subset a
Google font to latin only, pull the `latin` `@font-face` block's woff2 URL from
`https://fonts.googleapis.com/css2?family=…` (send a browser User-Agent to get
woff2, not ttf).

**Reading chrome** (defined in `template.html` + `style.css`, driven by a small
inline script): a fixed title bar slides in once you scroll past the page header,
with a slim scroll-**progress bar** riding its bottom edge. Pure progressive
enhancement — with JS off, neither appears. The theme toggle is centred in this
bar; heading `scroll-margin-top` is set so in-page anchor jumps clear the fixed
bar. Both are hidden in print and honour `prefers-reduced-motion`.

**Copy buttons on code blocks.** A small script in `template.html` wraps every
`<pre>` in `main#content` with a `.code-wrapper` and adds a copy button — an inline
SVG copy-icon (two overlapping pages) that swaps to a check-mark for ~1.6s on a
successful copy (top-right, revealed on hover/focus, always shown on touch). Pure
progressive enhancement — it early-returns when the Clipboard API is absent, so
JS-off / old browsers just see plain code. Styled in `style.css` (`.code-wrapper`
/ `.code-copy`), theme-aware, hidden in print. Applies to every course's code
blocks (`lstlisting`, verbatim, fenced) after a rebuild.

## LaTeX → pandoc gotchas (why the helpers exist)

- **Math** uses `--mathml` — native browser rendering, no JS/CDN.
- **Images** are external WebP (not embedded) so HTML stays small; re-running
  pandoc's `--extract-media` re-emits originals, so `optimize-images.py` runs
  after every build (build.ps1/publish.ps1 handle this).
- **`multicols` silently destroys the TOC** — pandoc only collects top-level
  headings, so everything inside the Div vanishes and the contents card drops.
  `unwrap-multicols.lua` fixes it; single-column reflow is what the web wants.
- **Tables pandoc silently drops** (render as raw `&`-text): `\multirow`,
  `\cline`, and `\\` inside `\shortstack` within a cell. Grep built HTML for
  `class="tabular"` — any hit means a table was dropped; flatten the source.
- **bytefield** renders as garbage; `render-bytefields.py` pre-renders each to
  SVG. Commented-out bytefields fail to compile — keep them commented out.
- **tikzpicture / pgfplots** are dropped or garbled by pandoc; `render-tikz.py`
  compiles each as a `standalone` crop (using the course master preamble so
  fonts/colours/macros match) to SVG and splices in an `\includegraphics`. A
  `\tdplotsetmaincoords{..}{..}` line right before a picture is captured with it
  (tikz-3dplot needs it). Add a `tikz` preprocess step (with `Preamble`) for
  courses that carry inline diagrams; `build.ps1` also auto-renders any chapter
  containing `\begin{tikzpicture}`. Both figure kinds share the one `<name>.gen.tex`
  slot and compose (bytefields first, then TikZ chains onto it).
- **algorithm2e** (`\begin{algorithm}…\end{algorithm}`) is dropped by pandoc to an
  empty `<div class="algorithm">` (hidden globally by `.algorithm{display:none}`).
  Ways to handle it, cheapest first:
  1. **Preferred (keeps a copyable code block AND the original PDF): pair each
     algorithm2e with a `Verbatim` block.** Right after the `algorithm2e` block,
     add `\begin{Verbatim}…\end{Verbatim}` holding the same pseudocode as plain
     text; pandoc renders `Verbatim` (fancyvrb) as a real `<pre>` code block (so it
     gets the copy button), while the PDF keeps the algorithm2e. Put
     `\usepackage{comment}` + `\excludecomment{Verbatim}` in the preamble so
     **pdflatex skips the Verbatim** (no duplicate in the PDF) — and do **not** load
     fancyvrb. Because pdflatex never sees the Verbatim you can use Unicode maths
     glyphs (`⟨⟩ ← τ ∈ ∞ …`) freely in it with no inputenc/literate setup. Indent
     with plain spaces (4 per level). This is what `sc1315-ai` does — no pre-render
     step. (`build.ps1` does **not** auto-render `\begin{algorithm}`, precisely so
     this raw algorithm2e is left for pandoc to drop rather than turned into an SVG.)
  2. **Alt (real typeset math, but not a code box): a display-math `array` block.**
     `\[ \begin{array}{ll} … \end{array} \]` converts through `--mathml` to typeset
     pseudocode (true subscripts, `\underset{s'\in C}{\mathrm{arg\,max}}`, `\mathbf`
     keywords, `\mathrm` identifiers). Selectable and theme-aware, but it's math
     typography — no grey code box, no copy button. Keep it MathML-convertible
     (avoid `\small` / nested `$…$` in `\text{}`); grep built HTML for
     `class="math display"` (a hit = raw-TeX fallback).
  3. **Alt (image): pre-render to SVG with `render-algorithm.py`** (mirrors
     `render-tikz.py`) — a `standalone` crop spliced in as
     `\includegraphics[width=0.8\textwidth]`. Opt in via an `algorithm` preprocess
     step (with `Preamble`); shares the `<name>.gen.tex` slot. Not selectable, and a
     white box in dark mode. Currently unused.
- **lstlisting** code blocks convert fine (pandoc's LaTeX reader emits a code
  block) — no pre-render needed.
- The pre-render scripts (`render-tikz.py`, `render-algorithm.py`) drop
  `geometry`/`hyperref`/`caption` **and** their config commands (`\geometry{}`,
  `\hypersetup{}`, `\captionsetup{}`) from the standalone preamble — a master that
  sets page layout / link colours with those bare commands would otherwise fail
  every crop with "Undefined control sequence". `publish.ps1` also clears any
  stale `<name>.gen.tex` before preprocessing, so figures regenerate from source
  each publish (renderers chain onto an in-run `.gen.tex`, so bytefields → tikz →
  algorithm still compose) rather than freezing old output.
- **`--resource-path`** must include the course root and image dirs because some
  chapters reference images by bare name via the master's `\graphicspath`.
- **Theme** defaults to the reader's system preference, toggle persists in
  `localStorage`.
- **CSS cache when previewing:** the `<link>` is unversioned — hard-reload
  (Ctrl+Shift+R) after editing `style.css`, or the old layout sticks.
