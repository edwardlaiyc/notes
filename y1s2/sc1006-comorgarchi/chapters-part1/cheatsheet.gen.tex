\subsection{Size of instructions and its components/operands}
\begin{enumerate}
    \item One instruction: 32 bits / 4 bytes
    \item Condition flags: 4 bits (Bits 28-31)
    \item Opcode: 8 bits (Bits 20-27)
    \item Register: 4 bits (Since there are 16 possible registers in the processor)
    \item Immediate value: 12 bits (4 rotate right bits + 8 bit immediate value.)
\end{enumerate}

\subsection{Execution Cycle}
Fetch-Decode-Execute $\implies$ PC value is 8 bytes ahead of current instruction being executed.
For PC-related addressing, must have offset of 8bytes.
The max offset is $\pm 4096$ bytes or (\#0xFC) , $\because$ offset field only has 12 bits.

\subsection{Flow control}
\texttt{IF} statement: reverse the condition to reduce jump instructions.\newline
Condtional execution: add the condtion codes to the instruction (e.g. MOVEQ). If using multiple of these, ensure the CSPR unchanged.\newline

\smallskip
\noindent Compound AND: If first condition fail, branch out immediately.\newline
Compound OR: If first cond pass, branch immediately.\newline

\smallskip
\noindent SWITCH with narrow consecutive values, use jump table.\newline
SWTICH with wide range of values, use forked cascade.\newline

\smallskip
\noindent PRE-test loops (WHILE): Test condition at the start, branch out if fail.\newline
POST-test loops (DO-WHILE): Test at the end.\newline

\smallskip
\noindent FOR loops are pre-test loops.

\subsection{Modular Programming}
Branch to subroutine (both change LR and PC).
\begin{enumerate}
    \item \texttt{BL}.
    \item \texttt{MOV LR PC; B SUBROUTINE}.
\end{enumerate}
Return to calling program (both only change PC).
\begin{enumerate}
    \item \texttt{BX LR}.
    \item \texttt{MOV PC LR}.
\end{enumerate}
\texttt{STMFD SP! \{R6-R7, LR\}}: R6 at lowest memory, LR at highest memory, i.e. SP pointing at R6.\newline
\texttt{LDMFD SP! \{R6-R7, PC\}}: PC takes over saved LR content.\newline
Immediately after executing \texttt{BL Sub1} located at 0x300, LR = 0x304.\newline
Registers:
\begin{itemize}
    \item R0 – R3: Arguments (Inputs) \& Return Values. Volatile / Caller-saved. (Can be safely overwritten).
    \item R4 – R11: Local Variables. Non-volatile / Callee-saved. (MUST be preserved for transparent subroutines).
    \item R11: Frame pointer (use negative offset)
    \item R12 (IP): Intra-procedure scratch register. Volatile. (Can be safely overwritten).
    \item R13 (SP): Stack Pointer. Points to the top of the system stack. (use positive offset)
    \item R14 (LR): Link Register. Holds the return address (PC + 4).
    \item R15 (PC): Program Counter. Holds the address of the currently executing instruction.
\end{itemize}
When pushing LR or extra registers at the start of a nested subroutine, the SP shifts. To recalculate LDR offsets:\newline
Formula: New Offset = Old Offset + (Number of Extra Registers Pushed × 4 bytes)\newline
Example: If a parameter was at [SP, \#24] and you add LR to your push list (STMFD SP!, {R4-R7, LR}), you pushed 1 extra register. New offset = 24 + (1 × 4) = 28.

\vspace{1em}
\begin{verbatim}
LDR R1, [R0], #4
MOV R2, R0
STMFD SP!, {R1, R2}
BL Sub1
\end{verbatim}
Assuming R0=0x100, V1 stored at 0x100, V2 stored at 0x104.\newline
R1 passed in by value, R2 passed in by reference.\newline

\vspace{1em}

\noindent Each recursive call saves the address of the next instruction using LR.
To find number of recursive calls, find the number of repeated addresses saved, that are close to address in PC.
