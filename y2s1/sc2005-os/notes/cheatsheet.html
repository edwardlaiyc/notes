Part I: Concept Quiz Playbook (MCQs)

1. Operating System Overview & Protection

Key Contrasts & Invariants

Concept Mode / Mechanism A Mode / Mechanism B Core Distinction
CPU Execution Modes User Mode (mode bit = 1) Kernel Mode (mode bit = 0) Hardware prevents user applications from executing privileged instructions (I/O, halt, base/limit registers).
Control Transitions Trap (Software Interrupt) Interrupt (Hardware) Traps are synchronous (system calls, exceptions like divide-by-zero, page faults). Interrupts are asynchronous (timer, disk, network).
Context Switching Mode Switch Context Switch Mode switch switches execution privilege (User ↔\leftrightarrow Kernel) for the same process. Context switch saves state of Process A and loads Process B (high CPU overhead).
Kernel Structure Monolithic Kernel Microkernel Monolithic runs all OS services (VFS, IPC, drivers) in kernel space (fast, but fault-intolerant). Microkernel keeps only minimal primitives in kernel space; OS services run as user processes (robust, but IPC message-passing overhead).

High-Yield MCQ “Watch Out” Checks

  • Privileged Instructions: Direct I/O instructions, loading base/limit registers, modifying the mode bit, disabling hardware interrupts, and HALT are strictly privileged.
  • Non-Privileged Instructions: Reading the time-of-day clock, generating a trap (INT 0x80, syscall), and arithmetic calculations can execute safely in User Mode.
  • Timer Interrupt: The timer is a hardware mechanism that periodically forces control back to the OS scheduler, preventing a runaway user process from monopolizing the CPU.

Process States & Transitions

  • New →\to Ready: Long-term scheduler admits process to ready queue in RAM.
  • Ready →\to Running: Short-term CPU scheduler dispatches process.
  • Running →\to Ready: Time-slice expires (timer interrupt) or preemption by higher-priority job.
  • Running →\to Waiting (Blocked): Process requests synchronous I/O or waits for child/event (wait()).
  • Waiting →\to Ready: I/O transfer completes (hardware interrupt asserted). A blocked process NEVER transitions directly to Running.

High-Yield MCQ “Watch Out” Checks

  • User-Level Threads (ULT) vs. Kernel-Level Threads (KLT):
    • ULT: Thread management handled by user-space runtime library without kernel awareness. Extremely fast context switching (no mode switch), but if one ULT performs a blocking system call, the entire process and all sibling ULTs are blocked.
    • KLT: Managed directly by OS kernel. Individual threads can block without stalling sibling threads, and true multi-core parallel execution is supported.
  • Process Creation (fork()):
    • Child receives an exact duplicate copy of parent address space (separate address space!).
    • In parent, fork() returns the child’s PID (>0> 0). In child, fork() returns 0. On failure, returns -1.

3. CPU Scheduling

Scheduling Criteria & Trade-offs

  • CPU Utilization: Percentage of time CPU is actively executing instructions (40%–90%40\%\text{–}90\%).
  • Throughput: Number of processes completed per unit time.
  • Turnaround Time (TturnT_{\text{turn}}): Tcompletion−TarrivalT_{\text{completion}} - T_{\text{arrival}} (entire lifetime).
  • Waiting Time (TwaitT_{\text{wait}}): Tturn−TburstT_{\text{turn}} - T_{\text{burst}} (total time spent in Ready queue).
  • Response Time: Time from process arrival to first CPU scheduling dispatch.

4. Process Synchronization

The Critical Section Problem

To prevent race conditions, any valid synchronization solution must satisfy all 3 criteria:

  1. Mutual Exclusion: If process PiP_i is executing in its critical section, no other processes can be executing in their critical sections.
  2. Progress: If no process is executing in its critical section and some processes wish to enter, only those processes not in their remainder sections can participate in deciding who enters next, and selection cannot be postponed indefinitely.
  3. Bounded Waiting: There exists a bound on the number of times other processes are allowed to enter their critical sections after a process has made a request to enter and before that request is granted (prevents starvation).

Semaphore Primitives (Atomic)

  • wait(S) / P(S): Decrements SS. If S<0S < 0, the calling process blocks: wait(S):S←S−1;if S<0⟹block();\text{wait}(S): \quad S \leftarrow S - 1; \quad \text{if } S < 0 \implies \text{block();}
  • signal(S) / V(S): Increments SS. If S≤0S \le 0, wakes up one blocked process: signal(S):S←S+1;if S≤0⟹wakeup();\text{signal}(S): \quad S \leftarrow S + 1; \quad \text{if } S \le 0 \implies \text{wakeup();}
  • Invariant Meaning of SS:
    • S>0S > 0: Represents the number of available resources.
    • S≤0S \le 0: Absolute value |S||S| represents the exact number of processes currently blocked in the semaphore queue.

5. Deadlocks

The Four Necessary Conditions (Coffman)

Deadlock can occur if and only if all four conditions hold simultaneously:

  1. Mutual Exclusion: At least one resource is held in a non-shareable mode.
  2. Hold and Wait: A process holding at least one resource is actively waiting to acquire additional resources held by other processes.
  3. No Preemption: Resources cannot be forcibly preempted; they can only be released voluntarily by the holding process.
  4. Circular Wait: A closed chain of processes {P0,P1,…,Pn}\{P_0, P_1, \dots, P_n\} exists such that P0P_0 waits for a resource held by P1P_1, and PnP_n waits for a resource held by P0P_0.

Cardinal Rule: An Unsafe State is NOT inherently a deadlock; it is merely a vulnerable state that has the potential to deteriorate into a deadlock if all processes demand their maximum claims simultaneously.

6. Real-Time OS & Virtualization

RTOS Scheduling

  • Hard Real-Time: Missing a deadline results in total system failure (flight control, pacemakers).
  • Soft Real-Time: Missing a deadline degrades quality of service but does not cause catastrophic system failure (multimedia streaming).
  • Rate Monotonic (RM): Static-priority assignment based on task period. Shorter period Ti⟹T_i \implies Higher priority.
    • Schedulability bound (Liu & Layland): ∑CiTi≤n(21/n−1)\sum \frac{C_i}{T_i} \le n(2^{1/n} - 1) (n=2⟹82.8%n=2 \implies 82.8\%, n→∞⟹69.3%n \to \infty \implies 69.3\%).
  • Earliest Deadline First (EDF): Dynamic-priority assignment based on absolute deadline. Closer deadline ⟹\implies Higher priority.
    • Provably optimal: Guaranteed schedulable if and only if ∑CiTi≤1.0\sum \frac{C_i}{T_i} \le 1.0 (100%100\%).

Virtualization Models

  • Type 1 Hypervisor (Bare-Metal): Runs directly on host hardware without an underlying OS (VMware ESXi, Xen).
  • Type 2 Hypervisor (Hosted): Runs as an application inside a host operating system (VirtualBox, VMware Workstation).
  • Trap-and-Emulate: Sensitive guest kernel instructions trap to hypervisor, which emulates behavior.
  • Binary Translation: Rewrites sensitive unprivileged instructions on-the-fly when hardware lacks virtualization extensions.

7. Physical Memory Organization

Contiguous Allocation & Fragmentation

Allocation Scheme Placement Search Rule Advantages / Disadvantages
First Fit Allocates the first hole large enough from memory start. Fastest search; creates external fragmentation near front of memory.
Best Fit Allocates the smallest hole that is large enough. Preserves large free blocks; produces tiny leftover unusable holes.
Worst Fit Allocates the largest available hole. Produces largest leftover holes; worst overall utilization.
  • Internal Fragmentation: Unused allocated space residing inside a partition/page.
  • External Fragmentation: Total free memory is sufficient to satisfy a request, but storage is fractured into non-contiguous fragments. Resolved via Paging or Compaction.

8. Virtual Memory & Demand Paging

Valid-Invalid Bit & Page Fault Handling Sequence

  • Valid (v): Page resides in physical RAM.
  • Invalid (i): Page resides on backing store (disk). Triggers a Page Fault Trap.
  • Dirty (Modify) Bit: Set on memory writes. Clean victim ⟹\implies discard without I/O; Dirty victim ⟹\implies write back to disk (page-out before page-in).
  • Reference Bit: Set on read/write. Used by Clock to approximate LRU.
  • Belady’s Anomaly: Increasing physical frames causes an increase in page faults.
    • Stack Algorithms (OPT, LRU): Satisfy inclusion property (St(n)⊆St(n+1)S_t(n) \subseteq S_t(n+1)). Immune to Belady’s anomaly.
    • FIFO and Clock: Violate inclusion property. Can suffer Belady’s anomaly.
  • Frame Allocation Rules: Fixed allocation requires local replacement. Variable allocation can use either local or global replacement.
  • Thrashing: Processes spend virtually all time paging rather than computing.
    • Symptom: Low CPU utilization combined with high multiprogramming and saturated paging disks.
    • Remedy: Reduce degree of multiprogramming (swap out processes) or add physical RAM. (Faster CPU does NOT help).

9. File Systems

Inode Structure & Addressing Hierarchy

  • An Inode stores file metadata and direct/indirect block pointers:
    • Direct Pointers: Point directly to data blocks.
    • Single Indirect: Points to an index block filled with direct data block pointers.
    • Double Indirect: Points to an index block containing single indirect pointers.
    • Triple Indirect: Points to an index block containing double indirect pointers.
Allocation Method Access Support External Fragmentation? Storage Reliability / Metadata Overhead
Contiguous Sequential + Direct Yes Fast sequential reads; requires compaction; file size cannot grow easily.
Linked Sequential only No Pointers consume block bytes; random access requires traversing chain; pointer corruption loses file.
FAT Sequential + Direct No Pointers stored in central memory table; faster seeks than linked list; FAT table must reside in RAM.
Indexed Sequential + Direct No Index blocks store pointer arrays; supports fast random access; small files waste entire index blocks.

10. I/O Systems & Storage

Buffering vs. Caching vs. Spooling

Mechanism Purpose Data in Memory Example
Buffering Bridges speed disparities and transfer size mismatches. Data in transit (may be sole copy) Assembling network packets into full disk blocks.
Caching Accelerates repeated access to slow devices. High-speed duplicate copy Retaining disk directory blocks in RAM.
Spooling Manages concurrent access to dedicated, non-sharable devices. Complete sequential output streams Print daemon queue (lpd).

RAID Architecture Levels

  • RAID 0 (Striping): High throughput, zero fault tolerance (1/MTTF1/MTTF multiplies).
  • RAID 1 (Mirroring): 100% capacity redundancy overhead, high fault tolerance.
  • RAID 0+1 (Mirror of Stripes): Striped sets mirrored. Single failure invalidates an entire striped half.
  • RAID 1+0 (Stripe of Mirrors): Mirrored pairs striped together. Survives multiple disk crashes across separate pairs. RAID 1+0 is vastly more reliable than RAID 0+1.

Recipe 1: CPU Scheduling Traces & Metrics

Mathematical Toolkit

Turnaround Time (Tturn)=Tcompletion−Tarrival\text{Turnaround Time } (T_{\text{turn}}) = T_{\text{completion}} - T_{\text{arrival}} Waiting Time (Twait)=Tturn−Tburst\text{Waiting Time } (T_{\text{wait}}) = T_{\text{turn}} - T_{\text{burst}} Average Waiting Time=∑Twaitn\text{Average Waiting Time} = \frac{\sum T_{\text{wait}}}{n}

Execution Protocol

  1. Initialize Timeline (t=0t=0): Track arrived jobs in Ready Queue.
  2. Dispatching Rules:
    • FCFS: Serve strictly by arrival time.
    • SJF (Non-preemptive): Run selected job to completion; on completion, pick arrived job with smallest burst.
    • SRTF (Preemptive): On every arrival, compare remaining burst of running job against new arrival burst. Preempt if new burst is strictly smaller.
    • Round Robin (qq): Run job up to qq. If preempted, enqueue newly arrived jobs first, then re-enqueue preempted job at tail.

Mathematical Toolkit

  • Rate Monotonic (RM) Utilization Bound: U=∑i=1nCiTi≤n(21/n−1)U = \sum_{i=1}^n \frac{C_i}{T_i} \le n(2^{1/n} - 1) (If U≤bound⟹U \le \text{bound} \implies Guaranteed schedulable. If U>bound⟹U > \text{bound} \implies Inconclusive, requires timeline trace).

Recipe 3: Semaphore Bounds & Interleaving Traces

Mathematical Toolkit

Sfinal=Sinitial+Nsignals−NwaitsS_{\text{final}} = S_{\text{initial}} + N_{\text{signals}} - N_{\text{waits}} Blocked Threads=max⁡(0,−S)(when S≤0)\text{Blocked Threads} = \max(0, -S) \quad (\text{when } S \le 0)

Worked Benchmark

Problem: A counting semaphore SS is initialized to 3. Five concurrent processes each execute a loop running 2 wait(S) and 1 signal(S). What is the minimum possible intermediate value of SS?

  • Total wait() operations =5×2=10= 5 \times 2 = 10.
  • Minimum value occurs when all 10 wait() calls execute before any signal(): Smin=3−10=−𝟕S_{\min} = 3 - 10 = \mathbf{-7} (Meaning: 7 processes/threads are queued in the blocked state).
  • Final value when all operations finish: Sfinal=3−10+(5×1)=−𝟐S_{\text{final}} = 3 - 10 + (5 \times 1) = \mathbf{-2}

Recipe 4: Deadlock RAG Cycle Detection & Knot Analysis

Reduction Protocol

  1. In a Resource Allocation Graph (RAG):
    • Request Edge: Pi→RjP_i \to R_j.
    • Assignment Edge: Rj→PiR_j \to P_i.
  2. Single-Instance Resources: A cycle in the RAG is necessary and sufficient for deadlock.
  3. Multiple-Instance Resources: A cycle is necessary but NOT sufficient.
    • Reduction Algorithm: Find a process PiP_i whose requests can be completely satisfied by available free resource units. If found, deallocate all resources held by PiP_i (PiP_i completes), erase its edges, and add its units to available pool. Repeat until no further process can be reduced.
    • If edges remain ⟹\implies the remaining processes are in Deadlock.

Recipe 5: Banker’s Algorithm (Safety & Resource-Request)

Mathematical Toolkit

𝑵𝒆𝒆𝒅[i,j]=𝑴𝒂𝒙[i,j]−𝑨𝒍𝒍𝒐𝒄𝒂𝒕𝒊𝒐𝒏[i,j]\mathbf{Need}[i, j] = \mathbf{Max}[i, j] - \mathbf{Allocation}[i, j]

  1. Let 𝑾𝒐𝒓𝒌=𝑨𝒗𝒂𝒊𝒍𝒂𝒃𝒍𝒆\mathbf{Work} = \mathbf{Available}; 𝑭𝒊𝒏𝒊𝒔𝒉[i]=false\mathbf{Finish}[i] = \text{false} for all ii.
  2. Find ii where 𝑭𝒊𝒏𝒊𝒔𝒉[i]==false\mathbf{Finish}[i] == \text{false} and 𝑵𝒆𝒆𝒅i≤𝑾𝒐𝒓𝒌\mathbf{Need}_i \le \mathbf{Work}. If none, go to Step 4.

Recipe 6: Contiguous Partition Fit Algorithms

Allocation Rules

  • First Fit: Allocates the first free hole large enough (searching from memory start).
  • Best Fit: Allocates the smallest free hole large enough (minimizes wasted leftover space).
  • Worst Fit: Allocates the largest free hole (leaves the largest leftover free block).

Worked Benchmark

Given free holes in order: 100 KB, 500 KB, 200 KB, 300 KB, 600 KB. Place request of 212 KB:

  • First Fit: Scans list →\to rejects 100 KB →\to allocates in 500 KB hole (leaves 288 KB hole).
  • Best Fit: Compares all holes ≥212 KB\ge 212\text{ KB} ({500, 300, 600}) →\to smallest is 300 KB →\to allocates in 300 KB hole (leaves 88 KB hole).
  • Worst Fit: Compares all holes →\to largest is 600 KB →\to allocates in 600 KB hole (leaves 388 KB hole).

Recipe 10: Page Replacement Traces (FIFO, OPT, LRU, Clock)

Replacement Rules

  • FIFO: Evict earliest loaded page. Hits do not change order. (Suffers Belady’s Anomaly).
  • OPT: Evict page unused for longest future time (theoretical benchmark).
  • LRU: Evict page unused for longest past time (stack algorithm, immune to Belady’s).
  • Clock: Circular buffer with hand. If R=1→R=1 \to set R=0R=0, advance hand. If R=0→R=0 \to replace, advance hand. New page starts with R=0R=0 (NTU convention).

Worked Benchmark

Reference string: 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 (4 frames).

  • FIFO: 10 faults.
  • LRU: 8 faults.
  • OPT: 6 faults.
  • Clock (4 frames): 8 faults.

Recipe 15: Disk Arm Scheduling & Seek Movement

Mathematical Toolkit

Total Movement=∑i=1n−1|Cylinderi+1−Cylinderi|\text{Total Movement} = \sum_{i=1}^{n-1} |\text{Cylinder}_{i+1} - \text{Cylinder}_i| Total Service Time=(Total Movement×Tseek_per_cyl)+(N×Tservice)\text{Total Service Time} = (\text{Total Movement} \times T_{\text{seek\_per\_cyl}}) + (N \times T_{\text{service}})

Boundary Rules

  • FCFS: Strict arrival order.
  • SSTF: Greedily select pending cylinder with smallest absolute distance from current head.
  • SCAN: Sweep toward boundary (e.g. 199), service on the way, visit physical boundary (199), reverse and sweep back.
  • C-SCAN: Sweep toward boundary (199), visit 199, jump directly to boundary 0 without servicing, sweep forward. (Return jump 199→0199 \to 0 counts in total movement).
  • LOOK / C-LOOK: Same as SCAN / C-SCAN, but reverse/jump immediately at final pending request (do not visit 0 or 199).
