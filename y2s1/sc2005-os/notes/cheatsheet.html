1. Overview and Protection

Contrast A B Trap
Mode bit 0 = monitor (kernel, supervisor, system) 1 = user An interrupt or trap switches to monitor mode in hardware; the OS sets user mode before returning.
Kernel mode vs. root Hardware operating mode A user account in the OS Root’s programs still run in user mode; root reaches kernel mode only indirectly (e.g. loading a kernel module).
Interrupt vs. trap Hardware interrupt: from a device, asynchronous Trap: generated by the CPU, from a software error or a system call “Trap = software exceptions only” is false.
Interrupt-driven I/O vs. DMA CPU copies each unit; one interrupt per byte/word Controller copies a block to memory; one interrupt per block DMA still interrupts (at the end of the block). Both put the requesting process in Waiting. Mouse → interrupt-driven.
Multiprogramming vs. multiprocessing vs. multi-threading Several processes in memory (works on one core) Several cores in parallel (hardware) Several threads in one process. Multiprogramming does not give parallelism; a multiprocessor without multiprogramming wastes cores.
Time-sharing vs. real-time Fast average response Guaranteed deadlines Windows/Linux are time-sharing, not real-time.

Sequences the sample quiz tests word for word:

  • Interrupt: disable interrupts → save program context → locate the ISR in the interrupt vector table → execute the ISR → restore context → enable interrupts.
  • System call: CPU generates a trap → switches to kernel mode and transfers control to the OS → OS identifies and runs the system-call function → OS switches back to user mode and returns to the user program.

Watch out:

  • Privileged: all I/O instructions; loading base/limit registers. An I/O instruction run directly by a user program makes the CPU trap to the OS.
  • Base/limit: legal iff base≤addr≤base+limit−1\text{base} \le \text{addr} \le \text{base} + \text{limit} - 1. Only one pair in the hardware; each process’s values live in its PCB.
  • System call vs. API: every system call traps to kernel mode; an API (fopen) is a library function that may call one (open).
  • OS goals (convenience vs. efficient use) can conflict: smart allocation needs much information about user programs.
  • System types: batch = one job in memory, CPU idles on I/O. Multiprogramming needs memory management, CPU scheduling, I/O device scheduling. Embedded/CPS = low power, small memory, low bandwidth. Handheld = limited memory, slow processor, small screen. Multiprocessor = throughput, economy (shared memory and I/O), reliability.
  • Storage hierarchy slides are not examinable.

2. Processes and Threads

States: New → Ready → Running → Waiting/Terminated. Waiting → Running never happens: a woken process goes to Ready first. A ready process is not in the waiting state.

Watch out:

  • PCB is in kernel memory (quiz key: “accessed by the OS as well as the process”, i.e. through the OS). Context switch: CPU → PCB₀, then PCB₁ → CPU. Context saved in the PCB, not the stack. Context switch time is pure overhead.
  • fork(): child gets a copy of the parent’s address space; returns child PID in the parent, 0 in the child. Two execution orders: concurrent, or parent waits (wait()/join()).
  • wait() is used by the parent. exit(): a process ends itself. abort(): a parent kills a child (exceeded resources, task not needed, parent exiting).
  • Data region fixed size, globals; stack grows and shrinks, locals.
  • Several processes Running at once is possible only with several cores.

3. CPU Scheduling

  • Scheduling must run only when a core goes idle: Running → Waiting or Running → Terminated (and on admission only if a core is idle).
  • Nonpreemptive: schedules only at those points. Preemptive: also at Running → Ready, Waiting → Ready, New → Ready, or any time.
  • Running → Waiting happens in both kinds; it does not make a policy preemptive.
  • Utilization =∑busy time per core/(total time×cores)= \sum \text{busy time per core} / (\text{total time} \times \text{cores}). Throughput = exits per unit time. Response = admitted → first run.

4. Process Synchronization

Requirements: mutual exclusion; progress (selection of who enters next is not postponed indefinitely); bounded waiting (others enter only a bounded number of times after a request). Progress does not imply bounded waiting.

Mechanism ME Progress BW Note
Alg. 1: turn only Yes No Yes A process in its remainder section blocks the other
Alg. 2: flag only Yes No Yes Both set flags → both spin
Alg. 3: Peterson Yes Yes Yes Flag first, then turn = other. Swap the order, or set turn = self: ME fails
Disable interrupts Yes Yes — Kernel only; not across cores
TestAndSet spinlock Yes Yes No A process can win the lock repeatedly (BW-safe version not examinable)
Plain Boolean lock No Test and set are separate instructions
Blocking semaphore Yes Yes Depends on queue LIFO or priority queue → starvation

Semaphores:

  • Wait(S): S--; if (S < 0) block(); Signal(S): S++; if (S <= 0) wakeup(P); Both must be atomic (update and test).
  • S>0S > 0: SS more processes can pass Wait. S<0S < 0: |S||S| processes blocked. S=I−#Wait+#SignalS = I - \#\text{Wait} + \#\text{Signal}.
  • Counting (any integer) vs. binary (≤ 1). Busy waiting (while (S <= 0); S--;): no context switch, wastes CPU, better for short critical sections.
  • block(): ready queue → S.L, state waiting. wakeup(P): S.L → ready queue, state ready.
  • Making each single read/write atomic does not prevent races (counter++ = load, add, store).
  • Best practice: binary semaphore per critical section; one counting semaphore per resource kind, initial value = number of instances.
  • Ordering: flag = 0; PiP_i: A; Signal(flag); PkP_k: Wait(flag); B.
Problem Semaphores Trap
Bounded buffer mutex = 1, empty = n, full = 0 Wait on empty/full before mutex, else deadlock. Signal order irrelevant. counter not needed. Min mutex with kk processes =−(k−1)= -(k-1).
Readers–writers mutex = 1 (protects readcount), wrt = 1 First reader Wait(wrt), last reader Signal(wrt). Reader preference: writers can starve.
Dining philosophers chopstick[5] = 1 Naive left-then-right deadlocks. Fixes: ≤ 4 hungry; both-or-none; odd/even order.
  • Never hold two semaphores while waiting for a third (Tutorial 5 Q1, apples and oranges).
  • Monitors: not examinable.

5. Deadlocks

Four conditions (mutual exclusion, hold and wait, no preemption, circular wait): necessary but not sufficient.

RAG Verdict
No cycle No deadlock
Cycle, one instance per type Deadlock
Cycle, several instances Possible, not certain
Handling method Note
Prevention Break one condition
Avoidance Banker’s: grant only if the state stays safe; needs declared maximums
Detection + recovery Not examinable
Ignore Most OSes, including UNIX and Windows
Condition Prevention (dining philosophers)
Mutual exclusion Cannot be removed (chopsticks are not shareable)
Hold and wait Pick up chopsticks only if both are free
No preemption Release the first chopstick if the second is unavailable
Circular wait ≤ 4 hungry; odd/even; acquire in a fixed order
  • Safe → no deadlock. Unsafe → deadlock possible. Deadlock → unsafe.
  • Safe = at least one safe sequence exists (other unsafe orders do not matter).
  • A deadlock needs ≥ 2 processes.
  • Avoidance lets processes request at will (within their maximum); it decides when to grant.

6. Real-Time OS and Virtualization

  • Real-time ≠ fast. Real-time = predictable in the worst case. Correctness depends on timing as well as logic.
  • ⟨R,C,D⟩\langle R, C, D \rangle: release, execution, relative deadline; run CC within [R,R+D)[R, R + D). Periodic ⟨T,C,D⟩\langle T, C, D \rangle: released at 0,T,2T,…0, T, 2T, \dots
  • FCFS/SJF/RR ignore deadlines.
  • RM: fixed priority, shorter period = higher. Simple (one queue per process); predictable under load; can miss deadlines when D<TD < T.
  • EDF: dynamic, earliest absolute deadline (not parameter DD). More powerful; harder (online sorting); can be unpredictable under load.
Mechanism Mapping Examples
Multiplexing One → many vCPUs, memory
Aggregation Many → one DIMMs into one address space, RAID, link aggregation
Emulation One kind → another RAM disk, JVM, Rosetta, localhost, serial over USB
Type 1 Type 2
VMM Is the host OS Extension of a host OS
Lecture examples Xen, vSphere KVM + Linux
Host apps beside VMs No Yes
  • Full virtualization: guest OS unmodified, unaware (VMware ESXi, MS Virtual Server). Para-virtualization: guest OS modified to use the VM’s API; more efficient (Xen, XtratuM).
  • Hypervisor abstracts the hardware and interfaces with the guest OS; the guest OS manages its applications.
  • System-level limited direct execution: application and guest OS run directly on the CPU; some privileged guest instructions trap to the VMM. Isolation via non-root mode.
  • Overcommitment: more vCPUs than cores, since VMs are rarely all busy.
  • Guest physical memory (the VM’s) vs. host physical memory (real).

  • Logical = physical for compile- and load-time binding.

  • First fit = first big-enough hole. Best fit = smallest (smallest leftover). Worst fit = largest (largest leftover).
  • Frame size: power of 2, 512–8192 B. PTBR/PTLR (paging), STBR/STLR (segmentation).
  • Paging without TLB = 2 memory accesses; kk-level = k+1k + 1. A TLB does not always help (low hit ratio). The TLB reduces access time, not page faults.
  • Shared pages must be reentrant (read-only).
  • Inverted page table: one entry per frame, ⟨\langlepid, page⟩\rangle; saves memory, increases search time.

8. Virtual Memory

  • Valid–invalid bit: v = in memory (entry holds frame); i = not in memory (entry holds disk address). Initially all i.
  • Page fault: trap, save state → find page on disk → find free frame (or replace) → disk read → update entry → restore and restart the instruction.
  • Victim written back only if dirty (modify bit). The reference bit says “used”, not “modified”.
  • A TLB hit implies the page is resident; a TLB miss may or may not fault.
Algorithm Rule Belady?
FIFO Oldest loaded Yes
OPT Not used for longest future time (benchmark only) No
LRU Not used for longest past time (counter or stack) No
Second chance / Clock FIFO, but R=1R = 1 → clear and skip Yes
  • OPT and LRU have the inclusion property (pages in nn frames ⊆ pages in n+1n + 1).
  • Clock: R=0R = 0 on load, set to 1 on reference; hand at oldest page; all R=1R = 1 → degenerates to FIFO.
  • Fixed allocation → local replacement only. Variable → local or global. Global: performance depends on others. Local: may hold less-used frames.
  • Thrashing: too few frames → high fault rate → low CPU → OS adds processes → worse. Fix: reduce multiprogramming, more RAM, faster paging disk. Faster CPU, bigger paging disk, more processes: no help.
  • Working set: D=∑WSSi>mD = \sum WSS_i > m → suspend a process. Δ\Delta too small: high faults, many processes; too large: few faults, few processes.
  • PFF: rate too high → give a frame; too low → take one; no free frame → swap a process out.
  • Locality: temporal (re-use soon) and spatial (nearby). C arrays are row-major: loop rows outside. Arrays beat linked lists.

I/O control Device drivers and interrupt handlers

Contiguous Yes Yes Start + length; file limited by its hole; overestimate → internal frag.

  • Directory entry: name + attributes, or name + pointer to FCB (UNIX: inode number + name). Linear list (slow) vs. hash table (collisions).
  • Hard link = duplicate the file’s information in several directories (same inode). Symbolic link = entry holding a path name; slower; dangles if the file is deleted, and silently follows a new file at the same path.
  • Shared-file deletion fixes: remove dangling links; delete them on next use; keep the file until all references are gone.
  • Open-file tables: per-process (position pointer, permissions) → system-wide (FCB copy, open count). They cache metadata, not data blocks. seek costs 0 reads.
  • Permissions rwx owner/group/public. r-x r-x --x: group can read too. Directory: r list, w create/delete, x required to access anything inside.
  • Block size: big → fast, wastes space; small → little waste, slow. Two block sizes get both.
  • Free space: bitmap (0 = free; extra space; easy if in memory) vs. linked list (no extra space; inefficient).

10. I/O and Disk

Lecture definition Holds
Buffering Data in memory while transferring between devices; speed and transfer-size mismatch Data in transit (may be the only copy)
Caching Fast memory with a copy; for files written and re-read rapidly A duplicate
Spooling Hold output for a device that serves one request at a time (printer) Whole jobs
  • Blocking: process Waiting until done. Asynchronous: call returns once queued; process signaled on completion. Non-blocking (past papers): returns at once with what is ready; process stays Running/Ready.
  • I/O subsystem: scheduling, buffering, caching, spooling, error handling, device reservation, name translation. The driver layer hides controller differences from it.
  • SSTF ~ SJF: can starve far requests. SCAN/C-SCAN/LOOK/C-LOOK: starvation unlikely; better under heavy load. With one request at a time, every algorithm behaves like FCFS. Contiguous files give close requests.
  • RAID 0 non-redundant striping; RAID 1 mirroring; 1+0 (stripe of mirrors) is more reliable than 0+1 (mirror of stripes).

Part II: Algorithm Quiz

Recipe 1: CPU Scheduling (Gantt Chart, Turnaround, Waiting)

Tturn=Tfinish−Tarrive,Twait=Tturn−∑CPU−∑I/O−event waitT_{\text{turn}} = T_{\text{finish}} - T_{\text{arrive}}, \qquad T_{\text{wait}} = T_{\text{turn}} - \textstyle\sum \text{CPU} - \sum \text{I/O} - \text{event wait}

  1. Step through events: arrival, burst end, quantum expiry, I/O end.
  2. Same-instant order: new arrival → preempted process → process returning from I/O.
  3. Rules: FCFS arrival order. SJF shortest next burst at each completion. SRTF preempt if a new burst is strictly shorter than the remaining time. RR run ≤ qq, then to the tail.
  4. Multi-core global SRTF: a new arrival preempts the core whose process has the longest remaining time, if shorter.
  5. One I/O device: a process whose I/O cannot start waits in the device queue; that time is not waiting time.

Lecture example (SRTF): P1P_1 (0, 7), P2P_2 (2, 4), P3P_3 (4, 1), P4P_4 (5, 4). Gantt: P1P_1 0–2, P2P_2 2–4, P3P_3 4–5, P2P_2 5–7, P4P_4 7–11, P1P_1 11–16. Waits 9,1,0,29, 1, 0, 2 → average 3.

RR efficiency (burst TT, switch SS, count the first switch too): TT+S⋅n\dfrac{T}{T + S \cdot n}, with n=1n = 1 if Q≥TQ \ge T, else ⌈T/Q⌉\lceil T/Q \rceil; Q=SQ = S gives about 0.5; Q=0Q = 0 gives 0.

Practice: Tutorial 3 Q2–Q4; AY16/17 S2 Q1b, AY18/19 S1 Q1b, AY19/20 S1 Q1b (chapter 3).

Recipe 2: RM and EDF Schedules

  1. List releases kTkT and absolute deadlines kT+DkT + D up to the LCM of the periods.
  2. At each release and completion, run the highest priority: RM shortest TT; EDF earliest absolute deadline. Preempt on a higher-priority release.
  3. On a tie, branch: each choice is a separate valid schedule.
  4. Check every instance meets its deadline.

Quick test (not in the lecture): U=∑Ci/TiU = \sum C_i/T_i. EDF (D=TD = T): schedulable iff U≤1U \le 1. RM: schedulable if U≤n(21/n−1)U \le n(2^{1/n} - 1) (0.828 for 2, 0.780 for 3).

Practice: Tutorial 7 Q3 (chapter 6a).

Recipe 3: Semaphore Values

S=I−#Wait+#Signal;S<0⇒|S| blockedS = I - \#\text{Wait} + \#\text{Signal}; \qquad S < 0 \Rightarrow |S| \text{ blocked}

  • Minimum intermediate value: all Waits first. Maximum: all Signals first.
  • Largest value ever = the initial value (count holders + blocked processes, each of which will Signal).
  • Minimum of a mutex with kk processes: −(k−1)-(k - 1) (one holder, k−1k - 1 blocked). Maximum: 1.
  • Blocked processes cannot issue more Waits: a value below −(number of processes)-(\text{number of processes}) is impossible.

Practice: AY16/17 S1 Q1c (= Additional Q2), AY17/18 S2 Q2c (chapter 4).

Recipe 4: Checking a Critical-Section Protocol

  1. Mutual exclusion: run one process up to its CS, switch, try to bring the other in. Start from the given initial values. Try a switch between each pair of entry-section lines.
  2. Progress: find a state where the CS is empty, someone wants in, and a shared variable keeps it out forever (e.g. a process in its remainder section holds turn, or nothing ever resets a lock).
  3. Bounded waiting: while one process waits, count how often the other can enter.
  4. For a modified Wait/Signal: check that Signal wakes a process exactly when one is blocked, and that the first Wait from the initial value lets exactly one process in.

Practice: Tutorial 4 Q1–Q3, Tutorial 5 Q2–Q3, AY19/20 S1 Q1a and Q2c, AY18/19 S1 Q1c–d, AY18/19 S2 Q2b and Q2d (chapter 4).

Recipe 5: RAG Analysis

  1. Request edge P→RP \to R; assignment edge R→PR \to P.
  2. No cycle → no deadlock. Cycle with single instances → deadlock.
  3. Several instances: repeatedly pick a process whose requests the free instances satisfy, let it finish, return its resources, erase it. Whatever remains is deadlocked.

Practice: AY19/20 S1 Q2b (chapter 5).

Recipe 6: Banker’s Algorithm

Need=Max−Allocation;Total=Available+∑Allocation\text{Need} = \text{Max} - \text{Allocation}; \qquad \text{Total} = \text{Available} + \textstyle\sum \text{Allocation}

Safety: Work = Available. Repeat: pick an unfinished PiP_i with Need_i ≤ Work (every component); Work += Allocation_i. All finish → safe (the order is a safe sequence).

Request from PiP_i: (1) Request ≤ Need, else error; (2) Request ≤ Available, else wait; (3) pretend: Available −= Req, Alloc += Req, Need −= Req; (4) safe → grant, unsafe → restore and wait.

Minimum unknown in Available:

  1. Split resources into groups used by disjoint sets of processes, if possible.
  2. For each unknown, find the order that needs the least from Available; take the largest deficit along it.
  3. Check the final vector with a full safety run, and try one less to show it fails.

Lecture example: Available (3,3,2); safe sequence ⟨P1,P3,P4,P2,P0⟩\langle P_1, P_3, P_4, P_2, P_0 \rangle. P1P_1 requests (1,0,2) → granted; then P0P_0 (0,2,0) → unsafe; P4P_4 (2,3,0) → unsafe.

Practice: Tutorial 6 Q2–Q3, Additional Q3, AY18/19 S1 Q2b, AY17/18 S2 Q2b (chapter 5).

Recipe 7: Contiguous Allocation and Compaction

  1. List the holes in address order.
  2. Apply the rule to each request: first fit (first big enough), best fit (smallest big enough), worst fit (largest).
  3. No hole fits → compact: move partitions toward address 0 in address order, one at a time, and stop as soon as the merged hole is big enough.
  4. Count relocated partitions and words.

Practice: AY15/16 S2 Q3a, Tutorial 8 Q1 (chapter 7).

Recipe 8: Paging and Segmentation Addresses

  • Page size 2n2^n → offset nn bits; page number m−nm - n bits; page-table entries 2m−n2^{m-n}.
  • Frames =RAM/page size= \text{RAM}/\text{page size} → frame bits; inverted table entries = frames.
  • Physical =f×2n+d= f \times 2^n + d (frame bits followed by offset bits).
  • Multi-level: entries per page =page size/PTE size= \text{page size}/\text{PTE size} → inner index bits; outer index takes the rest; add levels until the outer table fits in one page. Outer entries =2x−y+2= 2^{x - y + 2} for 4-byte PTEs (xx page bits, yy offset bits).
  • Segmentation: offset bits =log⁡2(max segment)= \log_2(\text{max segment}); trap if d≥d \ge limit; physical =base+d= \text{base} + d.

Lecture examples: 32-bit, 4 KB pages, 4-byte PTEs → [10∣10∣12][10 \mid 10 \mid 12], flat table 4 MB. Segment ⟨3,128⟩\langle 3, 128 \rangle, base 3200, limit 1100 → 3328.

Practice: Tutorial 8 Q4, Tutorial 9 Q1–Q2, Additional Q4, AY15/16 S2 Q3b, AY16/17 S1 Q3b (chapter 7); AY17/18 S2 Q3b, AY19/20 S1 Q3d (chapter 8).

Recipe 9: Effective Access Time

TLB: EAT=(τ+ε)α+(2τ+ε)(1−α)=(2−α)τ+ε\text{TLB: } \text{EAT} = (\tau + \varepsilon)\alpha + (2\tau + \varepsilon)(1 - \alpha) = (2 - \alpha)\tau + \varepsilon

  • No TLB: 2τ2\tau. The TLB helps iff α>ε/τ\alpha > \varepsilon / \tau. kk-level table: miss costs (k+1)τ(k + 1)\tau.
  • With TLB time 0: EAT=ατ+(1−α)2τ\text{EAT} = \alpha\tau + (1 - \alpha)2\tau.

Demand paging: EAT=(1−p)τ+p×page-fault time\text{Demand paging: } \text{EAT} = (1 - p)\,\tau + p \times \text{page-fault time}

Example: τ=100\tau = 100 ns, fault 8 ms, EAT ≤ 110 ns → p≤10/7,999,900≈1.25×10−6p \le 10 / 7{,}999{,}900 \approx 1.25 \times 10^{-6}.

Practice: Tutorial 8 Q3, AY19/20 S1 Q3b (chapter 7).

Recipe 10: Page-Replacement Traces

  1. Draw one column per reference, one row per frame; mark F on each fault.
  2. FIFO: evict the earliest loaded; hits change nothing. LRU: evict the least recently referenced. OPT: evict the page used farthest in the future (or never).
  3. Clock: new page R=0R = 0; a hit sets R=1R = 1; on a fault the hand clears R=1R = 1 pages and evicts the first R=0R = 0, then advances one past it.
  4. Bounds: NN distinct pages, length LL: N≤N \le faults ≤L\le L; with ≥ NN frames, exactly NN.
  5. Reverse problems (evictions given): with one page missing at a time, each fault loads the page the previous fault evicted; a page just loaded cannot be the next LRU victim; a “no eviction” step is a hit that makes the next victim the LRU page.

Lecture string 1 2 3 4 1 2 5 1 2 3 4 5: FIFO 9 (3 frames) / 10 (4 frames, Belady); OPT 6; LRU 8; Clock 8.

Practice: Tutorial 9 Q3, Tutorial 10 Q1, Additional Q5–Q6, AY15/16 S2 Q3d, AY17/18 S2 Q3b, AY19/20 S1 Q3d (chapter 8).

Recipe 11: Working Set

  • WS(t)WS(t) = distinct pages in the last Δ\Delta references; D=∑WSSiD = \sum WSS_i; D>mD > m → suspend a process.
