Lab 4 Quiz: Page Tables and Lazy Allocation

Tap an option to lock in your answer. The page marks it and shows the reason. Every wrong option is a real misconception. The sections follow the Lab 4 Guide.

1. Sv39 Address Translation

01Why does each Sv39 page-table level use exactly 9 index bits?

B. 4096/8=512=294096 / 8 = 512 = 2^9, so 9 bits pick one entry. Three levels give 27 bits, plus the 12-bit offset: 39 bits, hence Sv39.

02How big would one flat page table be for a 39-bit space with 4 KB pages and 8-byte entries?

D. A flat table needs an entry for every possible page: 2272^{27} entries × 8 bytes = 2302^{30} bytes. A tree only builds tables for regions that are in use.

03PX(1, va) extracts the level-1 index. What does it do to va?

B. The shift is 12+9×level12 + 9 \times \text{level}. Level 1 skips the 12 offset bits and the 9 level-0 bits. A shift of 30 is level 2.

04Split the virtual address 0x80003FFF into VPN[2], VPN[1], VPN[0] and the offset.

A. Offset = low 12 bits = 0xFFF. VPN = 0x80003FFF >> 12 = 0x80003. VPN[0] = VPN mod 512 = 3; VPN[1] = (VPN >> 9) mod 512 = 0; VPN[2] = VPN >> 18 = 2. Check: 0x80000000 + 0x3000 + 0xFFF.

05A process maps only two pages, at VA 0x0 and 0x200000. How many page-table pages does it need?

A. 0x200000 = 2212^{21}, so VPN[1] = 1 and VPN[0] = 0. Both share the root and the L1 table, but each needs its own L0 table: root + L1 + 2 × L0 = 4. Pages at 0x0 and 0x1000 would share one L0 table (3 total).

06A leaf PTE holds 0x20048C17. What is the physical address of byte offset 0x456 in its page?

C. PPN = PTE >> 10 = 0x80123. Frame base = PPN << 12 = 0x80123000 (this is PTE2PA). Add the offset: 0x80123456. Low byte 0x17 = V, R, W, U set: a user data page, not executable.

07A valid level-1 entry has PTE_V set and R, W and X all clear. What does that mean?

D. V with no R/W/X marks a non-leaf entry. Its PPN is the next table down. Kernel-only data is a leaf with R/W set and U clear.

08Why is xv6’s MAXVA 2382^{38} and not 2392^{39}?

C. In 64-bit RISC-V, bits 63–39 must copy bit 38. Keeping bit 38 at 0 means bits 63–38 are all 0, so no address looks negative.

09With no TLB, one load under Sv39 needs how many memory accesses? With a TLB (1 ns lookup, 100 ns memory, 98% hit rate), what is the effective access time?

D. Three table reads plus the data make 4. Hit: 1+100=1011 + 100 = 101 ns. Miss: 1+3×100+100=4011 + 3 \times 100 + 100 = 401 ns. EAT =0.98×101+0.02×401=107= 0.98 \times 101 + 0.02 \times 401 = 107 ns.

2. walk() and walkaddr()

10A process’s root table has an invalid entry for some region. The kernel calls walk(pt, va, 1) there. What gets allocated?

C. alloc = 1 creates the missing L1 and L0 tables and nothing else. Mapping a data frame is a separate job for kalloc + mappages. Returning 0 is what alloc = 0 does.

11The L1 and L0 tables exist, but the leaf PTE for va is zero. What does walk(pt, va, 0) return?

B. walk returns 0 only when a table is missing. A non-null result does not mean the page is mapped, so callers such as countpp must also test PTE_V.

12A user program passes the address TRAPFRAME as the buffer for read(). What happens?

C. TRAPFRAME is mapped in the user table and valid, but has no PTE_U. walkaddr returns 0 for it, so a user cannot make the kernel touch memory the user may not touch.

3. Memory Layout and Eager Allocation

13On the supplied eager kernel, p->sz is 0x5000 and a process calls sbrk(8192). What does the call return, and what is p->sz afterwards?

B. 8192 = 0x2000. sbrk returns the old break, the start of the new region. On the eager kernel both pages are mapped at once.

14On the eager kernel, p->sz is 0x3800 and the process calls sbrk(0x1000). How many new frames does uvmalloc take?

C. The new range is 0x3800–0x4800. uvmalloc starts at PGROUNDUP(0x3800) = 0x4000, because page 0x3000 is already mapped. The call returns 0x3800.

15Why does uvmalloc memset each frame to zero right after kalloc?

A. A user must never see another owner’s leftovers. kalloc fills frames with junk bytes (5s) as a debugging aid, not zeros. mappages never looks at the contents.

16Which function takes frames from the free list on an eager sbrk(n) with n>0n > 0?

D. The path is morecore → ecall stub → sys_sbrk → growproc → uvmalloc. growproc only chooses uvmalloc (grow) or uvmdealloc (shrink) and sets p->sz.

17How does exec() give the stack guard page its flags?

C. The guard page is valid and has a frame, but user mode cannot touch it. A stack overflow into it faults, and the process dies instead of silently corrupting its own data.

18A program reserves 50 MB of heap but uses only 100 KB. How many frames does each scheme use?

C. Eager maps every reserved page: 50×1024/4=12,80050 \times 1024 / 4 = 12{,}800. Lazy maps only touched pages: 100/4=25100 / 4 = 25.

19Which is a real cost of lazy allocation?

D. Lazy sbrk succeeds with no RAM behind it. A failure arrives later, as a kill inside the fault handler. Also, a program that touches every page pays one trap per page instead of one batch.

4. Counting Pages and Frames

20A process has p->sz = 0x3001. What does countvp() return?

D. PGROUNDUP(0x3001) / PGSIZE = 0x4000 / 0x1000 = 4. The guard page already lies inside 0 to p->sz, so nothing is added.

21Which of these frames is counted by countpp()?

A. countpp counts valid level-0 entries for addresses below p->sz. Page-table frames are reached through non-leaf entries, TRAPFRAME is far above p->sz, and the kernel stack lives in the kernel’s table.

22A student writes countpp with walkaddr() instead of walk(…, 0). On a fresh process, what changes?

A. walkaddr returns 0 for any entry without PTE_U. The guard page is valid and has a frame but no PTE_U, so it drops out, and the manual says it counts.

23Why must countpp call walk with alloc = 0?

B. With alloc = 1, walking an unused region would allocate L1/L0 tables as a side effect. Counting must only look.

24A student adds countvp to syscall.h, syscall.c and sysproc.c, deletes the placeholders in lazytest.c, but forgets user/usys.pl. What happens?

C. user.h only declares countvp. The code that loads the syscall number and runs ecall is generated from usys.pl into usys.S. Without it, the program has nothing to link against.

25Your system calls build, but lazytest prints 0 for every count. What is the most likely cause?

D. The placeholders return 0, and the program calls them instead of your system calls. Delete them so the calls reach the stubs from usys.pl.

26Running lazytest on the eager kernel, what happens to PP between “after sbrk” and “after touching”?

A. Eager uvmalloc maps all 30 inside the sbrk call. The touches find valid entries, so nothing faults. The “PP count changed immediately” error is expected here: it is written for the lazy kernel.

27lazytest prints an error line, then exits with status 0. What should you conclude?

B. lazytest always exits with status 0, even after a failed check. Its final check also accepts any PP increase of at least 30, so compare the numbers yourself.

28On the lazy kernel, a fresh process has countvp() = countpp() = 6. It calls sbrk(10 * 4096), writes a byte in heap pages 3, 8 and 3 again, then reads a byte from heap page 10. What are the counts now?

C. sbrk adds 10 virtual pages and no frames. Pages 3 and 8 fault once each; the second write to page 3 finds it mapped. A read also faults (scause 13) and gets a zeroed frame. So PP = 6 + 3 = 9.

29Continuing: the process now calls sbrk(-2 * 4096), releasing heap pages 9 and 10. What are the counts?

B. Page 10 had a frame, which is freed. Page 9 was never touched; the fixed uvmunmap skips it. VP = 16 − 2 = 14, PP = 9 − 1 = 8. Without the uvmunmap fix, page 9 would panic.

5. Traps, Page Faults and the Trampoline

30The instruction at 0x2a4 loads from heap address 0x6010, which is not mapped. What do the trap registers hold?

D. sepc is where the code is; stval is the exact address it touched. stval is not rounded: the handler rounds it down itself when it maps the page. scause is 13 (load).

31A user program runs __sync_lock_test_and_set (amoswap) on an address in an unmapped page. What is scause?

A. An AMO both reads and writes, and RISC-V reports it as a store/AMO page fault. 12 is only for fetching the instruction itself.

32The program jumps to 0x9000, in a page without PTE_X. What do scause, sepc and stval hold?

C. An instruction-fetch page fault is cause 12. The instruction itself is at the bad address, so sepc and stval match.

33On a fresh lazy page, how many page faults does a[0] = a[0] + 1 cause?

A. The load faults (13). The handler maps the page with PTE_R | PTE_W | PTE_U, so the store that follows finds it mapped.

34What does the supplied kernel do on a load page fault in user mode?

D. The last branch of usertrap prints the registers and calls setkilled(p); if (killed(p)) exit(-1); ends the process. Only that process dies. The manual asks you to add a diagnostic that names 13 and 15 and prints stval.

35Why does user/fault.c target PGROUNDUP(break) rather than the break itself?

D. Mapping is per page. If the break is mid-page, the rest of that page is still mapped. The next boundary is the first byte that is surely unmapped.

36Why does user/fault.c declare the target byte volatile?

A. A read whose result is thrown away looks useless to the compiler, which may delete it. Then no access happens and nothing faults.

37At the moment a user trap occurs, which page table is the CPU using?

B. That is why the trap entry code must sit on a page the user table maps, and why it saves registers in TRAPFRAME, which the user table also maps.

38Why must the trampoline page be at the same virtual address in the user and kernel page tables?

A. The switching code keeps running after satp changes. If its address meant something else in the new table, the next fetch would get garbage or fault with nothing left to handle it.

39Why does uservec save the user’s registers in TRAPFRAME and not on the kernel stack?

C. TRAPFRAME sits just below the trampoline in every user table. The kernel later reaches the same frame through p->trapframe.

40Across all processes, how are the TRAMPOLINE and TRAPFRAME pages backed?

B. The trampoline is the same code for everyone, so one frame is mapped everywhere. Each process saves its own registers, so each needs its own trapframe.

41Neither TRAMPOLINE nor TRAPFRAME has PTE_U. How can the trap code run there?

A. The missing PTE_U stops user code reading or jumping into these pages. The kernel, in supervisor mode, can still use them.

42xv6 maps program text at virtual address 0. What happens for x = *(int*)0; and for *(int*)0 = 1; on the lab kernel?

B. Address 0 is a valid, readable code page, so the read returns the first bytes of the program. The page is not writable, so the store faults (15). The PTE is valid, so the lazy handler kills instead of allocating. (Exact permissions come from exec(): not in the lab guide.)

6. Lazy Allocation

43Why does lazy sys_sbrk need its own newsz >= TRAPFRAME check?

D. Eager sbrk failed naturally when uvmalloc could not allocate or map. Lazy sbrk only raises a number, so a huge request could push p->sz over TRAPFRAME and TRAMPOLINE. newsz < addr catches a sum that wrapped round.

44After mapping the new page, a student’s fault handler adds 4 to p->trapframe->epc, copying the syscall path. What happens?

A. For a syscall, the ecall is done, so it is skipped. A faulting load or store never happened, so skipping it loses the access: silent corruption, no crash. Faulting forever is what happens if you neither advance epc nor map the page.

45What would happen if a system call did not advance epc by 4?

C. sepc points at the ecall. Returning there makes the program repeat the same system call without end.

46A handler maps a frame for any load/store fault with stval < p->sz, with no PTE check. The stack overflows into the guard page. What happens?

D. The guard page already has a valid leaf entry, only without PTE_U. mappages refuses to overwrite a valid entry and panics. Only a page with no valid entry may be allocated.

47p->sz = 0x4050. A fault arrives at 0x4060. The handler rounds down first, then checks a < p->sz. What happens?

B. 0x4060 is past the break and must be killed. Rounding first hides that. Compare the raw stval with p->sz, then round.

48p->sz = 0x4050. A store faults at 0x3000, an already mapped stack page. What does the lab handler do?

C. Below p->sz is not enough. A page that is valid but faulted anyway broke a permission. Only a page with no valid leaf entry is a first touch.

49Why must the handler check va < p->sz before calling walk?

A. A wild pointer can be any value, up to 2642^{64}. Testing the range first keeps every address that reaches walk below MAXVA.

50In the handler, kalloc succeeds but mappages fails. What must happen before the kill?

A. The frame is not in the page table yet, so exit will not find it. uvmalloc uses the same free-on-failure pattern.

51Lazy sbrk and the fault handler are done, but uvmunmap is unchanged. lazytest reserves 30 pages and touches 1. Which call panics?

D. Exit unmaps 0 to p->sz through uvmfree → uvmunmap, which hits the 29 untouched pages and panics “uvmunmap: not mapped”. This is the manual’s one-touch check: PP must rise by exactly 1 and exit must be clean.

52A process calls sbrk(100 * 4096), touches 3 of those pages, then exits. How many kfree calls does the fixed uvmunmap make for that heap?

C. Only touched pages have frames. The other 97 are holes, skipped with continue. The “not a leaf” panic stays, because a PTE_V-only entry points to a page table, not data.

53On your passing lazy kernel, a program calls p = sbrk(4096) and then read(fd, p, 100) without touching p. What happens?

D. The kernel writes the user buffer with copyout, which uses walkaddr and just fails on a missing page. No user-mode fault happens, so usertrap never runs. lazytest does not test this, nor fork (uvmcopy still panics on holes).

54After the lazy changes, fault read is still killed but lazytest survives its faults. What is the difference?

B. lazytest reserves first with sbrk(4096 * 30). fault calls only sbrk(0), which reserves nothing, so va >= p->sz sends it to kill. Reserve first, then touch.

55On the finished lazy kernel, lazytest reports these PP changes. Which run should worry you?

B. The final check accepts any increase of at least 30, so +32 still says Success. 30 distinct pages should give exactly +30: find out where the extra 2 frames came from.
