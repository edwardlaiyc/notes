How the exam works

The paper has 4 questions. Each question gives 25 marks. You answer all of them in 2 hours. The exam is open-book.

Each paper has one project description in Appendix A. It describes a system, for example a smart home app or a restaurant recommendation app. Most questions ask you to apply a method to that system. Few questions ask you to repeat a definition. So you must know each method well enough to use it on a system that you have not seen before.

The 4 questions follow a fixed shape:

Question Usual content Parts in these notes
Q1 Use case diagram (about 18 marks), use case description, sometimes an activity diagram 2, 3, 6
Q2 Conceptual class diagram with stereotypes, state machine or activity diagram, Waterfall vs Agile, Scrum problems 5, 6, 7, 8
Q3 Choose an architecture, draw a detailed class diagram, add design patterns, explain trade-offs 9, 10, 11
Q4 Testing: equivalence classes, boundary values, defensive test cases. Short discussion parts (testing levels, automation, maintenance). 13 (discussion parts: see below)

Topics with no lecture slides

These topics occur in the short discussion parts of Q4 in recent papers, but no lecture slides cover them.

  • Software maintenance. Challenges during maintenance and ways to reduce them. Part 1 covers why maintenance is hard, but not how to reduce the problems.
  • “Shift left”. Moving testing earlier in the life cycle. Part 1 explains why late faults cost more, which is the reason behind it.
  • Test automation with large language models (LLMs). How an LLM can help to generate or run tests.
