2. Examination Structure and Strategy

The final examination is a 2-hour paper consisting of 4 compulsory questions (25 marks each, 100 marks total).

An Appendix (or system scenario) provides an end-to-end case study (e.g. Grain Elevator System, Smart Clinic, Carpark Management System, Video Rental Platform). Questions test the practical application of software engineering methods to that specific domain:

  • Question 1 (25 Marks) — Requirements Engineering & Use Case Modeling:
    • Construct a complete Use Case Diagram for the case study system (10–15 marks).
    • Author a formal Use Case Description table for one specified use case (6–8 marks).
    • Justify <<include>> vs <<extend>> relationships or classify Functional vs Non-Functional requirements (4–6 marks).
  • Question 2 (25 Marks) — Domain Analysis & Process Models:
    • Construct a Conceptual Domain Class Diagram with BCE stereotypes and multiplicities (8–10 marks).
    • Model system dynamics using a State Machine Diagram or Swimlane Activity Diagram (6–8 marks).
    • Evaluate process model trade-offs (Waterfall vs Agile) or calculate Scrum velocity, capacity, and sprint burndown (4–6 marks).
  • Question 3 (25 Marks) — Software Architecture & Design Patterns:
    • Propose an architectural style (Layered, Client-Server, 3-Tier, MVC) and map a detailed class diagram (8–10 marks).
    • Evaluate architectural trade-offs against a specific Non-Functional Requirement (e.g. high availability or throughput) (4–6 marks).
    • Apply a Gang of Four Design Pattern (Strategy, Observer, Factory, Decorator) to resolve a coupling problem, draw its class diagram, and evaluate trade-offs (8–10 marks).
  • Question 4 (25 Marks) — Verification, Validation & Maintenance:
    • Derive valid/invalid Equivalence Classes for specified input parameters (4–6 marks).
    • Perform Boundary Value Analysis (identifying triplets [b−1,b,b+1][b-1, b, b+1]) and explain why discrete inputs have no boundaries (4–6 marks).
    • Construct a complete Defensive Test Cases table with test inputs and expected outputs (oracle), strictly maintaining one invalid input per row (6–8 marks).
    • White-box analysis (CFG construction, Cyclomatic Complexity CC=E−N+2=P+1CC = E - N + 2 = P + 1, Basis Path testing) OR conceptual discussion (Testing levels, Shift-Left, Software maintenance categories, Refactoring & code smells) (5–8 marks).
