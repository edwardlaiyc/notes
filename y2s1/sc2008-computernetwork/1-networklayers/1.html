1. Network Layers and Physical Resilience

This chapter covers Lectures 1 and 2 of Part I. It answers three questions:

  1. What is a computer network, and where did the Internet come from?
  2. Why do we split a network into layers, and what does each layer do?
  3. How do we calculate the chance that a network stays connected when links break?

Question 3 is a calculation, and it is the most tested idea in this chapter. Sections 7 and 8 build the method step by step.

1. What a Computer Network Is

1.1 The basic idea

  • A computer network is a set of devices that exchange data over links.
  • A link is one connection between two devices. It can be a copper cable, an optical fibre or a radio channel.
  • A node is any device on the network, for example a computer, a switch or a router.
  • A host (also called a station or end system) is a node that runs user programs, for example your laptop or a web server.
  • The Internet is a network of networks. Many separate networks join together, and they all exchange information with the same standard rules.

2. Why Networks Use Layers

2.1 The problem

A network must do many different jobs. It must send bits down a wire, find a path, recover lost data and talk to a program. If one big program does all of these jobs, the program is very hard to build and very hard to change.

2.2 The solution: a stack of layers

We divide the work into layers. Each layer does one group of jobs. The layers sit on top of each other like a stack.

  • Each layer uses the service of the layer directly below it.
  • Each layer gives a service to the layer directly above it.
  • A layer does not need to know how the layer below does its work. It only needs to know what that layer gives.

2.3 What layering gives us

Benefit What it means
Simplicity You design and test one small layer at a time.
Flexibility You can replace one layer (for example, change Ethernet to Wi-Fi). The other layers do not change.
Incremental change You can improve one layer without a full redesign.

2.4 Protocols and architecture

  • A protocol is a set of rules that two machines follow when they talk at the same layer. A protocol defines three things:
    1. The format of each message (which bits mean what).
    2. The order of the messages.
    3. The action that each side takes when it receives a message.
  • A network architecture is the full set of layers and the protocols in each layer.

3. How Two Layers Talk: SAP, SDU and PDU

3.1 Peer processes

The same layer on two different machines is called a peer. For example, the transport layer on your laptop and the transport layer on the server are peers.

Peers do not have a direct wire between them. Data goes down the stack on the sender, across the physical link, and up the stack on the receiver. But each layer acts as if it talks directly to its peer. We call this a logical (or peer-to-peer) connection.

3.2 The three terms

  • Service Access Point (SAP): the point where layer n+1n+1 hands data to layer nn. We name it after the lower layer, which gives the service. So the point between layer 4 and layer 3 is the 3-SAP.
  • Service Data Unit (SDU): the data that layer n+1n+1 passes down to layer nn through the SAP. Layer nn must deliver this data. It does not look inside it.
  • Protocol Data Unit (PDU): the unit that layer nn builds and sends to its peer. It is the SDU plus layer nn’s own header (and sometimes a trailer):

PDUn=Headern+SDUn(+Trailern)\text{PDU}_n = \text{Header}_n + \text{SDU}_n \; (+\ \text{Trailer}_n)

The PDU of one layer becomes the SDU of the layer below:

PDUn=SDUn−1\text{PDU}_{n} = \text{SDU}_{n-1}

3.3 Encapsulation and decapsulation

  • Encapsulation (sender): each layer, from top to bottom, adds its own header. The data gets bigger as it goes down.
  • Decapsulation (receiver): each layer, from bottom to top, reads its own header, removes it, and passes the rest up.

4. The OSI Reference Model (7 Layers)

The Open Systems Interconnection (OSI) model is a reference model from ISO. It has seven layers. Learn them from the top down with “All People Seem To Need Data Processing”.

# Layer Main jobs Unit of data
7 Application Gives network services to user programs (web, e-mail, file transfer). Data
6 Presentation Changes the data format so that both sides understand it. Does compression and encryption. Data
5 Session Controls the dialogue between two programs. Does log-in and checkpointing (restart from a saved point). Data
4 Transport Gives reliable, in-order delivery between the two end hosts with no loss and no duplicates. Can be connection-oriented or connectionless. Lets many programs share one network connection (multiplexing). Segment
3 Network Gives logical addresses, finds a route, controls congestion, joins different networks (internetworking), and breaks large packets into fragments. Packet
2 Data Link Puts bits into frames, sends ACKs and retransmits, does flow control across one link. Supports point-to-point and broadcast links, and simplex, half-duplex or full-duplex operation. Frame
1 Physical Sends raw bits over the medium. Defines the mechanical, electrical, functional and procedural details (plug shape, voltage, pin use, order of signals). Bit
  • Layers 7 to 4 are the host layers. Only the end hosts run them.
  • Layers 3 to 1 are the media layers. Every node on the path runs them.

5. The TCP/IP Model (5 Layers)

The Internet does not use OSI. It uses the TCP/IP model, which has five layers.

# TCP/IP layer Unit of data Example protocols
5 Application Message HTTP, DNS, SMTP
4 Transport Segment TCP, UDP
3 Network (Internet) Datagram IP, ICMP
2 Link Frame Ethernet, Wi-Fi
1 Physical Bit Cable, fibre, radio

5.1 OSI versus TCP/IP

Point OSI TCP/IP

Where it came from A model first, protocols later Protocols first (from ARPANET), model later
Use today A reference for teaching and discussion What the real Internet runs

6. What Happens to Headers Along the Path

6.1 At the sending host

The sending host runs every layer. Each layer adds a header. The data link layer also adds a trailer (DT) at the end. The trailer usually holds an error check.

Application              AH | Data
Presentation          PH AH | Data
Session            SH PH AH | Data
Transport       TH SH PH AH | Data
Network      NH TH SH PH AH | Data
Data link DH NH TH SH PH AH | Data | DT
Physical  ---------------- bits ----------------

6.2 At each switching node (router) in the WAN

A switching node only runs layers 1 to 3. It does these steps for each frame:

  1. The physical layer receives the bits and builds the frame.
  2. The data link layer checks the frame, then removes the old header DH and trailer DT.
  3. The network layer reads the network header NH. It uses the destination address to choose the next link.
  4. The data link layer for the next link adds a new header DH’ and trailer DT’.
  5. The physical layer sends the new bits.

The node does not read or change TH, SH, PH, AH or the data. Only the end host reads those.

In one sentence: at each switching node, the data link header and trailer are removed and replaced for the next link, the network header is read to choose the next link, and the higher-layer headers pass through unchanged.

6.3 At the receiving host

The receiving host runs every layer again. Each layer removes its own header, from DH and DT at the bottom up to AH at the top. The program receives only the data.

7. Network Reliability

7.1 Three times you must know

A link works for some time, then it breaks, then someone repairs it, and then it works again.

  • MTTF (Mean Time To Failure): the average time a link works before it breaks.
  • MTTR (Mean Time To Repair): the average time to repair a broken link.
  • MTBF (Mean Time Between Failures): the average time of one full cycle.

MTBF=MTTF+MTTR\text{MTBF} = \text{MTTF} + \text{MTTR}

7.2 Availability and failure probability

For one link ii:

  • rir_i = the availability (also called reliability) = the fraction of time the link works.
  • bib_i = the failure probability (break probability) = the fraction of time the link is broken.

ri=MTTFMTTF+MTTR,bi=MTTRMTTF+MTTR,ri+bi=1r_i = \frac{\text{MTTF}}{\text{MTTF} + \text{MTTR}}, \qquad b_i = \frac{\text{MTTR}}{\text{MTTF} + \text{MTTR}}, \qquad r_i + b_i = 1

For example, a link that works for 999 hours on average and takes 1 hour to repair has b=1/1000=0.001b = 1/1000 = 0.001.

7.3 The “nines” and downtime

“kk nines” means rr has kk nines, so b=10−kb = 10^{-k}. For example, 99.9% is three nines, and b=10−3b = 10^{-3}.

Because bb is a fraction of time, the downtime in a time window is:

downtime=b×(length of the window)\text{downtime} = b \times (\text{length of the window})

One year has 365×24×3600=31536000365 \times 24 \times 3600 = 31\,536\,000 s.

Availability Failure probability bb Downtime per year
90% (one nine) 10−110^{-1} 36.5 days
99% (two nines) 10−210^{-2} 3.65 days
99.9% (three nines) 10−310^{-3} 8.76 hours
99.99% (four nines) 10−410^{-4} 52.6 minutes
99.999% (five nines) 10−510^{-5} 5.26 minutes
99.9999% (six nines) 10−610^{-6} 31.5 seconds

How to get a row. Take five nines. Then b=10−5b = 10^{-5}, and the downtime is 10−5×31536000 s=315.36 s≈5.2610^{-5} \times 31\,536\,000 \text{ s} = 315.36 \text{ s} \approx 5.26 minutes. To go the other way, divide: a network that may be down for at most 1 hour per year needs b≤3600/31536000≈1.14×10−4b \le 3600 / 31\,536\,000 \approx 1.14 \times 10^{-4}.

8. Network Resilience

8.1 What resilience means

Resilience is a measure of how well a network tolerates faults. We give it as the probability that the network stays connected between two points.

We always make one assumption: links break independently of each other. So the probability that link A and link B are both broken is bA×bBb_A \times b_B.

8.2 The two basic rules

Rule 1: links in series. The data must cross every link. The path works only if all links work.

rseries=r1×r2×⋯×rnbseries=1−rseriesr_{\text{series}} = r_1 \times r_2 \times \cdots \times r_n \qquad b_{\text{series}} = 1 - r_{\text{series}}

Rule 2: links in parallel. The data can use any one of the links. The connection breaks only if all links are broken.

bparallel=b1×b2×⋯×bnrparallel=1−bparallelb_{\text{parallel}} = b_1 \times b_2 \times \cdots \times b_n \qquad r_{\text{parallel}} = 1 - b_{\text{parallel}}

Memory hook. For series, multiply the rr. For parallel, multiply the bb. Change between rr and bb with 1−(⋅)1 - (\cdot) every time you change from one rule to the other.

8.3 Method for a mixed network

A real network mixes series and parallel links. You reduce it in steps, from the inside out, until one equivalent link is left.

  1. Find each group of parallel links between the same two nodes. Replace the group with one equivalent link: b=∏bib = \prod b_i.
  2. Find each path from the source to the destination. Each path is a chain of links in series. Calculate rpath=∏rir_{\text{path}} = \prod r_i, then bpath=1−rpathb_{\text{path}} = 1 - r_{\text{path}}.
  3. If the paths share no link, they are parallel. The source and destination are cut off only when every path is broken: btotal=∏bpathb_{\text{total}} = \prod b_{\text{path}}.
  4. The answer is btotalb_{\text{total}} (disconnected) or 1−btotal1 - b_{\text{total}} (connected). Read the question to see which one it asks for.

Lecture example. Every link has b=0.05b = 0.05.

  • Series path SG–HW–AU: r=0.95×0.95=0.9025r = 0.95 \times 0.95 = 0.9025, so b=0.0975b = 0.0975.
  • Direct link SG–AU: b=0.05b = 0.05.
  • Both must break: btotal=0.0975×0.05=𝟎.𝟎𝟎𝟒𝟖𝟕𝟓b_{\text{total}} = 0.0975 \times 0.05 = \mathbf{0.004875}.

Adding a parallel group inside a path. Now suppose the lecture network gets a second SG–HW link, and every link still has b=0.05b = 0.05. Apply step 1 first:

  1. Two parallel links SG–HW: b=0.05×0.05=0.0025b = 0.05 \times 0.05 = 0.0025, so r=0.9975r = 0.9975.
  2. Path SG–HW–AU in series: r=0.9975×0.95=0.947625r = 0.9975 \times 0.95 = 0.947625, so b=0.052375b = 0.052375.
  3. That path is in parallel with the direct link: btotal=0.052375×0.05=0.00261875b_{\text{total}} = 0.052375 \times 0.05 = 0.00261875.

The extra link cut the failure probability from 0.004875 to about 0.0026. It helped less than you might expect, because the single HW–AU link is now the weak point of the path.

8.4 When paths share a link

Step 3 is only correct when the paths share no link. If two paths share link XX, the paths do not break independently: when XX breaks, both paths break together.

Split into two cases instead:

  • Case 1: XX works. Remove XX’s risk and solve the rest as a normal series and parallel problem.
  • Case 2: XX is broken. Delete XX from the network and solve what is left.

Then combine the cases with their probabilities:

P(cut)=rX⋅P(cut∣X works)+bX⋅P(cut∣X broken)P(\text{cut}) = r_X \cdot P(\text{cut} \mid X \text{ works}) + b_X \cdot P(\text{cut} \mid X \text{ broken})

8.5 Design questions: working backwards from a target

Many questions give the target (“three nines”) and ask for a missing value. The method is always the same:

  1. Write btotalb_{\text{total}} as a formula that contains the unknown.
  2. Set btotal≤10−kb_{\text{total}} \le 10^{-k} for a target of kk nines.
  3. Solve the inequality.

How many links in series? Each link has b=10−3b = 10^{-3}. The path needs two nines. With nn links in series:

(1−10−3)n≥0.99⇒n≤ln⁡0.99ln⁡0.999=10.05⇒n=𝟏𝟎(1 - 10^{-3})^n \ge 0.99 \;\Rightarrow\; n \le \frac{\ln 0.99}{\ln 0.999} = 10.05 \;\Rightarrow\; n = \mathbf{10}

For small bb, (1−b)n≈1−nb(1-b)^n \approx 1 - nb. This gives the same quick answer: n×10−3≤10−2n \times 10^{-3} \le 10^{-2}, so n≤10n \le 10. Round down, because 11 links would miss the target.

If the design needs more links than this, the fix is to add parallel paths. Series links always reduce availability. Parallel paths increase it.

How good must a new link be? A network has bold=0.002b_{\text{old}} = 0.002 between two cities. You add one new direct link in parallel, and the target is five nines. The new link with failure probability pp is in parallel with everything else:

p×0.002≤10−5⇒p≤0.005p \times 0.002 \le 10^{-5} \;\Rightarrow\; p \le 0.005

An unknown inside the network. Sometimes a link’s failure probability is a variable xx. Carry xx through the same steps. For two parallel links with b=0.1b = 0.1 and b=xb = x, the group has b=0.1xb = 0.1x. In series with a link of b=0.02b = 0.02, the path has r=(1−0.1x)(0.98)r = (1 - 0.1x)(0.98), so bpath=0.02+0.098xb_{\text{path}} = 0.02 + 0.098x. The result is linear in xx, so the inequality is easy to solve.

9. Common Traps

  • State the assumption “link failures are independent” at the start of every resilience answer.
  • Series: multiply rr. Parallel: multiply bb. Change with 1−(⋅)1-(\cdot) every time you switch rules.
  • Don’t multiply the bb of two paths that share a link. They are not independent. Split into cases on the shared link.
  • Check whether the question asks for “disconnected” (bb) or “connected / availability” (rr).
  • “kk nines” means b=10−kb = 10^{-k}, not r=10−kr = 10^{-k}.
  • Downtime =b×= b \times the time window. Show the seconds-per-year step.
  • When you solve for the largest number of series links, round down.
  • Adding a parallel link next to one link of a path helps less than adding a whole parallel path. The other links in the path still break.
  • A router reads the network header and replaces the data link header and trailer. It does not touch the transport header or anything above it.
  • OSI has 7 layers. TCP/IP has 5. TCP/IP puts session and presentation inside the application layer.
