Data Link Layer (DLL): Flow & Error Control

1. Universal Timing & Channel Parameters

1.1 Fundamental Time Metrics

  • Frame Transmission Delay (TframeT_{\text{frame}} or TfT_f): The time required to inject all bits of a frame onto the physical wire: Tf=LRT_f = \frac{L}{R}
    • LL: Frame length in bits (convert bytes by multiplying by 8).
    • RR: Link transmission rate in bits per second (bps).
  • Signal Propagation Delay (TpropT_{\text{prop}} or TpT_p): The time needed for a single physical bit to travel from sender to receiver across the physical link: Tp=DVorTp=D×delay factorT_p = \frac{D}{V} \quad \text{or} \quad T_p = D \times \text{delay factor}
    • DD: Distance between sender and receiver in meters.
    • VV: Propagation speed in the medium (typically 2×108 m/s2 \times 10^8\text{ m/s} in copper/fiber).
  • Total Cycle Time (TcycleT_{\text{cycle}}): The complete elapsed time from the start of frame transmission until the acknowledgment (ACK) returns: Tcycle=Tframe+Tprop+Tproc+Tack+Tprop+TprocT_{\text{cycle}} = T_{\text{frame}} + T_{\text{prop}} + T_{\text{proc}} + T_{\text{ack}} + T_{\text{prop}} + T_{\text{proc}}
    • Standard course assumption: Processing delay and ACK transmission time are negligible (Tproc≈0,Tack≈0T_{\text{proc}} \approx 0, T_{\text{ack}} \approx 0).
    • Simplified cycle time: Tcycle=Tf+2TpT_{\text{cycle}} = T_f + 2T_p

1.2 Normalized Propagation Delay (aa)

The parameter aa represents the ratio of propagation delay to transmission delay: a=TpTf=D⋅RV⋅La = \frac{T_p}{T_f} = \frac{D \cdot R}{V \cdot L}

  • Physical Regimes:
    • a<1a < 1 (Transmission Dominates): The frame is long or the link is short/slow (Tf>TpT_f > T_p). Most of the cycle time is spent actively transmitting data bits.
    • a>1a > 1 (Propagation Dominates): The link is fast or the distance is long (Tp>TfT_p > T_f). After transmitting the frame, the sender spends most of the cycle waiting idly for the round-trip signal propagation.

1.3 Link Utilization (UU)

Link utilization is the fraction of total cycle time during which the link actively carries useful data bits: U=TusefulTcycleU = \frac{T_{\text{useful}}}{T_{\text{cycle}}}

2. Flow Control (Error-Free Transmission)

Flow control ensures a fast sender does not overwhelm a slow receiver’s internal memory buffers with data.

2.1 Stop-and-Wait Flow Control

  • Operational Rule: The sender transmits 1 frame, halts, and waits for an explicit ACK from the receiver before transmitting the next frame.
  • Sequence Numbering: Uses a 1-bit alternating sequence number (00 and 11).
    • Frame alternate: F0,F1,F0,F1,…F_0, F_1, F_0, F_1, \dots
    • Meaning of ACKn\text{ACK}_n: Cumulative; indicates the receiver has successfully received frame F1−nF_{1-n} and is expecting frame FnF_n next.
  • Link Utilization: USaW=TfTf+2Tp=11+2aU_{\text{SaW}} = \frac{T_f}{T_f + 2T_p} = \frac{1}{1 + 2a}

2.2 Sliding Window Flow Control

Sliding window allows multiple unacknowledged frames to remain in transit simultaneously, keeping the transmission pipe full.

  • Window Size (NN or WW): The maximum number of frames the sender can transmit without receiving an ACK.
  • Sequence Number Space (kk bits): Frames are numbered modulo 2k2^k, ranging from 00 to 2k−12^k - 1.
  • Theoretical Sequence Bound: To prevent sequence number ambiguity between fresh frames and duplicate retransmissions in error-free flow control: N≤2kN \le 2^k
  • Window Edge Movement Invariants:
    • Sender Window (WtxW_{\text{tx}}): Trailing edge (left) moves forward when frames are sent; leading edge (right) moves forward when ACKs are received.
    • Receiver Window (WrxW_{\text{rx}}): Trailing edge (left) moves forward when frames are received; leading edge (right) moves forward when ACKs are sent.
  • Control Signals:
    • Receive Ready (RR(n)\text{RR}(n) or ACKn\text{ACK}_n): Acknowledges all frames up to n−1n - 1 and indicates readiness to receive frame nn.
    • Receive Not Ready (RNR(n)\text{RNR}(n)): Acknowledges frames up to n−1n - 1 but closes the window, temporarily halting sender transmissions until an RR\text{RR} is sent.
    • Piggybacking: Reverse-direction acknowledgments and sequence numbers are carried directly inside outgoing data frame headers.

2.3 Sliding Window Performance (Error-Free)

Normalizing frame transmission time to Tf=1T_f = 1 (making base cycle duration 1+2a1 + 2a):

  • Case I: Full Pipe (N≥1+2aN \ge 1 + 2a)
    • The window is large enough that the sender can transmit continuously until the first ACK arrives at t=1+2at = 1 + 2a.
    • The link experiences zero idle time: U=1.0(100%)U = 1.0 \quad (100\%)
  • Case II: Window Exhaustion (N<1+2aN < 1 + 2a)
    • The sender exhausts its window of NN frames at t=Nt = N and must sit idle until t=1+2at = 1 + 2a for the first ACK.
    • Utilization is bounded by the window size: U=N1+2aU = \frac{N}{1 + 2a}

3. Error Control: Automatic Repeat Request (ARQ)

When frames are lost or corrupted by bit errors (detected via CRC), ARQ protocols trigger retransmissions to ensure reliable delivery.

3.1 Stop-and-Wait ARQ

  • Sender Behavior: Emits one frame and starts a retransmission timer.
    • If ACK\text{ACK} arrives before timeout: Sends next frame.
    • If timer expires (lost frame or lost ACK) or explicit NAK\text{NAK} is received: Retransmits the same frame.
  • Duplicate Handling: If an ACK is lost, the sender retransmits the frame. The receiver inspects the alternating sequence number, recognizes the duplicate, discards the payload, and retransmits the ACK to keep both sides synchronized.
  • Utilization with Independent Frame Error Probability PP: USaWARQ=1−P1+2aU_{\text{SaW}}^{\text{ARQ}} = \frac{1 - P}{1 + 2a}

3.2 Go-Back-N ARQ (GBN)

  • Mechanics:
    • Receiver Window (Wrx=1W_{\text{rx}} = 1): Accepts frames strictly in sequence. It has zero buffer space for out-of-order frames.
    • Sender Window (Wtx=NW_{\text{tx}} = N): Maintains a buffer of up to NN unacknowledged transmitted frames.
    • If frame nn is damaged or missing, the receiver sends a Reject (REJ(n)\text{REJ}(n) or NAKn\text{NAK}_n) and discards all subsequent out-of-order frames.
    • Upon timeout or receipt of NAKn\text{NAK}_n, the sender rewinds its window back to frame nn and retransmits frame nn plus every subsequent frame already transmitted.
  • Maximum Window Derivation (N≤2k−1N \le 2^k - 1):
    • Because Wrx=1W_{\text{rx}} = 1, the fundamental non-overlap condition requires: Wtx+Wrx≤2k⟹N+1≤2k⟹N≤2k−1W_{\text{tx}} + W_{\text{rx}} \le 2^k \implies N + 1 \le 2^k \implies N \le 2^k - 1
    • Why N=2kN = 2^k Fails (e.g., k=3⟹N=8k = 3 \implies N = 8):
      1. Sender transmits frames 0,1,2,3,4,5,6,70, 1, 2, 3, 4, 5, 6, 7.
      2. Receiver accepts all 8 frames, advances its expected sequence number to 00, and sends ACK 0\text{ACK } 0.
      3. The ACK is lost in transit.
      4. Sender times out and retransmits old frame 00.
      5. Receiver is expecting new frame 00; it cannot distinguish the old duplicate frame 00 from a fresh frame 00, causing duplicate data insertion.
    • Why N=2k−1N = 2^k - 1 Resolves This (e.g., k=3⟹N=7k = 3 \implies N = 7):
      • If the ACK for frames 00 through 66 is lost, the receiver is expecting frame 77.
      • When the sender times out and retransmits old frame 00, the receiver sees 0≠70 \ne 7, identifies it as an out-of-window duplicate, discards it, and resends ACK 7\text{ACK } 7.

3.3 Selective Reject ARQ (SR)

  • Mechanics:
    • Receiver Window (Wrx=NW_{\text{rx}} = N): Allocates an out-of-order buffer of size NN.
    • Sender Window (Wtx=NW_{\text{tx}} = N): Allocates a transmission buffer of size NN.
    • If frame nn is corrupted or lost, the receiver issues a Selective Reject (SREJ(n)\text{SREJ}(n)).
    • Valid subsequent out-of-order frames falling inside the receive window are accepted and stored in memory.
    • The sender retransmits only the single requested frame nn.
    • Once frame nn arrives correctly, the receiver places it in proper sequence and delivers the entire contiguous block to the network layer.
  • Maximum Window Derivation (N≤2k−1N \le 2^{k-1}):
    • Because both sender and receiver maintain active sliding windows of size NN: Wtx+Wrx≤2k⟹2N≤2k⟹N≤2k−1W_{\text{tx}} + W_{\text{rx}} \le 2^k \implies 2N \le 2^k \implies N \le 2^{k-1}
    • Why N>2k−1N > 2^{k-1} Fails (e.g., k=3⟹N=5k = 3 \implies N = 5):
      1. Sender transmits frames 0,1,2,3,40, 1, 2, 3, 4.
      2. Receiver accepts all 5 frames, advances its receive window to [5,6,7,0,1][5, 6, 7, 0, 1], and returns ACK 5\text{ACK } 5.
      3. The ACK is lost in transit.
      4. Sender times out and retransmits old frame 00.
      5. Because 00 falls inside the receiver’s new window [5,6,7,0,1][5, 6, 7, 0, 1], the receiver mistakenly accepts old frame 00 as fresh data.
    • Why N=2k−1N = 2^{k-1} Resolves This (e.g., k=3⟹N=4k = 3 \implies N = 4):
      • When frames 0,1,2,30, 1, 2, 3 are accepted, the receive window shifts forward to [4,5,6,7][4, 5, 6, 7].
      • When sender times out and retransmits old frame 00, 00 is outside [4,5,6,7][4, 5, 6, 7]. The receiver discards it and re-issues ACK 4\text{ACK } 4.

4.2 Formula Reference Sheet

  • Stop-and-Wait Flow Control (Error-Free): U=11+2aU = \frac{1}{1 + 2a}

  • Stop-and-Wait ARQ (Frame Error Probability PP): USaWARQ=1−P1+2aU_{\text{SaW}}^{\text{ARQ}} = \frac{1 - P}{1 + 2a}

  • Sliding Window Flow Control (Error-Free): U={1N≥1+2aN1+2aN<1+2aU = \begin{cases} 1 & N \ge 1 + 2a \\ \dfrac{N}{1 + 2a} & N < 1 + 2a \end{cases}

  • Selective Reject ARQ (Frame Error Probability PP): USR={1−PN≥1+2aN(1−P)1+2aN<1+2aU_{\text{SR}} = \begin{cases} 1 - P & N \ge 1 + 2a \\[0.8em] \dfrac{N(1 - P)}{1 + 2a} & N < 1 + 2a \end{cases}

  • Course Examination Convention for Go-Back-N: The true GBN utilization formula is mathematically complex. In this course, use the Selective Reject formula above to calculate Go-Back-N utilization (UGBNU_{\text{GBN}}).

5. Exam Problem Archetypes

Archetype 1: Throughput-to-Window Dimensioning

  • Problem: A 64 kbps leased line connects two offices. The link protocol uses a 3-bit sequence field. Packet size is 80 bytes, one-way propagation delay is 10 ms, and bit errors are negligible. Find the minimum window size required to achieve a throughput of at least 32 kbps.
  • Step 1: Compute transmission delay and parameter aa: L=80 bytes×8=640 bitsL = 80\text{ bytes} \times 8 = 640\text{ bits} Tf=LR=640 bits64×103 bps=0.01 s=10 msT_f = \frac{L}{R} = \frac{640\text{ bits}}{64 \times 10^3\text{ bps}} = 0.01\text{ s} = 10\text{ ms} a=TpTf=10 ms10 ms=1.0a = \frac{T_p}{T_f} = \frac{10\text{ ms}}{10\text{ ms}} = 1.0
  • Step 2: Find the target link utilization: Throughput=U×R⟹Utarget=32 kbps64 kbps=0.5\text{Throughput} = U \times R \implies U_{\text{target}} = \frac{32\text{ kbps}}{64\text{ kbps}} = 0.5
  • Step 3: Solve for window size WW: U=W1+2a≥0.5⟹W1+2(1.0)≥0.5⟹W3≥0.5⟹W≥1.5U = \frac{W}{1 + 2a} \ge 0.5 \implies \frac{W}{1 + 2(1.0)} \ge 0.5 \implies \frac{W}{3} \ge 0.5 \implies W \ge 1.5
  • Step 4: Apply integer bound and sequence constraint: Round up to the next integer: W=𝟐W = \mathbf{2}. Check sequence limit: For k=3k = 3 bits, maximum window size is 23=82^3 = 8. Since 2≤82 \le 8, W=2W = 2 is valid.

Archetype 2: Multi-Hop Buffer Flow Equilibrium

  • Problem: Node A sends frames to Node C via intermediate Node B.
    • Link A–B: Distance 2000 km, rate 100 kbps, sliding window with W=3W = 3, individual ACKs.
    • Link B–C: Distance 500 km, stop-and-wait protocol.
    • Both links: Full duplex, propagation delay 10μs/km10\ \mu\text{s/km}, data frames are 1000 bits, ACK frames are negligible, error-free. Determine the minimum transmission rate between B and C so Node B’s memory buffer does not overflow.
  • Core Principle: To prevent buffer overflow, Node B’s outgoing frame rate to C must be at least as fast as its incoming frame rate from A: ThroughputB-C≥ThroughputA-B⇔Tcycle, B-C≤Tcycle, A-BWA-B\text{Throughput}_{\text{B-C}} \ge \text{Throughput}_{\text{A-B}} \iff T_{\text{cycle, B-C}} \le \frac{T_{\text{cycle, A-B}}}{W_{\text{A-B}}}
  • Step 1: Timing for Link A–B: Tp,AB=2000 km×10μs/km=20,000μs=20 msT_{p,\text{AB}} = 2000\text{ km} \times 10\ \mu\text{s/km} = 20{,}000\ \mu\text{s} = 20\text{ ms} Tf,AB=1000 bits100×103 bps=10 msT_{f,\text{AB}} = \frac{1000\text{ bits}}{100 \times 10^3\text{ bps}} = 10\text{ ms} Cycle time for A to send 1 frame and receive its ACK: Tcycle, AB=Tf,AB+2Tp,AB=10+2(20)=50 msT_{\text{cycle, AB}} = T_{f,\text{AB}} + 2T_{p,\text{AB}} = 10 + 2(20) = 50\text{ ms} Since W=3W = 3 frames are sent within this cycle, the incoming rate at B is: Arrival interval per frame=50 ms3=503 ms\text{Arrival interval per frame} = \frac{50\text{ ms}}{3} = \frac{50}{3}\text{ ms}
  • Step 2: Timing for Link B–C (Stop-and-Wait): Tp,BC=500 km×10μs/km=5,000μs=5 msT_{p,\text{BC}} = 500\text{ km} \times 10\ \mu\text{s/km} = 5{,}000\ \mu\text{s} = 5\text{ ms} Let xx be the frame transmission delay on link B–C (x=1000/RBCx = 1000 / R_{\text{BC}}).   • Step 3: Solve for transmission rate RBCR_{\text{BC}}: Equate the per-frame service time at B to the arrival interval: x+10≤503⟹x≤503−10=203 ms=0.023 sx + 10 \le \frac{50}{3} \implies x \le \frac{50}{3} - 10 = \frac{20}{3}\text{ ms} = \frac{0.02}{3}\text{ s} RBC=Lx≥1000 bits203×10−3 s=𝟏𝟓𝟎 𝐤𝐛𝐩𝐬R_{\text{BC}} = \frac{L}{x} \ge \frac{1000\text{ bits}}{\frac{20}{3} \times 10^{-3}\text{ s}} = \mathbf{150\text{ kbps}}

Archetype 4: Bidirectional HDLC Ladder Diagram Tracing

  • Frame Label Invariant: Information frames are labeled I(NS,NR)I(N_S, N_R):
    • NSN_S: Sequence number of the data frame being sent.
    • NRN_R: Piggybacked acknowledgment; the sequence number of the next frame expected from the other station (implicitly acknowledging all frames through NR−1N_R - 1).
  • Ladder Diagram State Rules:
    1. Forward and backward streams maintain independent send sequence counters.
    2. Every outgoing frame must copy the latest received sequence counter as its NRN_R value.
    3. When an expected frame is missing, an explicit negative acknowledgment (SREJ(n)\text{SREJ}(n)) requests frame nn.
    4. After receiving missing frame nn, the receiver sends a cumulative RR(m)\text{RR}(m) confirming reception of frame nn and all buffered subsequent frames up to m−1m - 1.
  • Worked Trace (3-bit sequence numbering, modulo 8):
    • Station A sends: I(4,3)I(4, 3), I(5,3)I(5, 3).
    • Station B receives I(4,3)I(4, 3) and sends: I(3,5)I(3, 5).
    • In transit, frame I(5,3)I(5, 3) from A is corrupted/lost.
    • Station A sends: I(6,4)I(6, 4).
    • Station B receives I(6,4)I(6, 4) out of order (expecting 5). B buffers frame 6 and immediately issues: SREJ(5)\text{SREJ}(5)
    • Station A sends: I(7,4)I(7, 4).
    • Station A receives SREJ(5)\text{SREJ}(5) and retransmits only the missing frame: I(5,4)I(5, 4)
    • Station B receives I(5,4)I(5, 4). Because B already buffered frames 6 and 7, B delivers frames 5, 6, and 7 to the higher layer and issues a cumulative ACK: RR(0)(since 7+1=8≡0(mod⁡8))\text{RR}(0) \quad (\text{since } 7 + 1 = 8 \equiv 0 \pmod 8)
