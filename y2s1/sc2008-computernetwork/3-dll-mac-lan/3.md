# Data Link Layer (DLL): Medium Access Control & LANs

![TCP/IP stack next to the IEEE 802 split of the Data Link Layer into LLC and MAC sublayers](3-artifacts/dll-llc-mac-split.png)

## 1. MAC Architecture & Random Access Fundamentals

### 1.1 The Multiple Access Problem
* **Shared Broadcast Medium:** Multiple stations connect to a single shared physical channel.
* **Collision:** When two or more stations transmit electromagnetic signals at the same time, the signals overlap and destroy both frames at the receiver.
* **No Out-of-Band Channel:** All arbitration and coordination must happen over the shared data medium itself.
* **The "Genie-Aided" Ideal MAC:**
  * When 1 node transmits, it achieves the full channel rate $R$.
  * When $M$ nodes transmit, each gets an average fair rate of $R/M$.
  * Fully decentralized (no master clock, no central coordinator).
  * Minimal protocol overhead.

![Taxonomy of MAC protocols: random access, controlled access, and channelization](3-artifacts/mac-protocol-taxonomy.png)

---

### 1.2 The Three Design Pillars of Random Access MAC
Every random access MAC protocol makes three basic design choices:
1. **Carrier Sensing:** Does the station listen before sending (e.g., blind sending in ALOHA vs. listen-before-talk in CSMA)?
2. **Transmission Policy:** Once the channel is idle, how does it transmit (e.g., immediate sending vs. random backoff)?
3. **Collision Detection & Recovery:** Does it detect collisions mid-transmission (e.g., CSMA/CD aborts immediately vs. ALOHA which transmits corrupted frames to the end)?

## 2. Random Access Protocols: The ALOHA Family

### 2.1 Slotted ALOHA
* **Operational Assumptions:**
  * Time is sliced into discrete, synchronized slots equal to one frame transmission time ($T_{\text{slot}} = T_{\text{frame}}$).
  * Stations can start transmission only at the exact beginning of a time slot.
  * If two or more stations transmit in the same slot, a collision occurs. Stations detect the collision and retransmit in future slots with probability $p$.

![Slotted ALOHA timeline showing successful transmissions and collisions across slots](3-artifacts/slotted-aloha-timeline.png)

* **Throughput Derivation ($S$):**
  * Let there be $N$ active stations, each transmitting independently in a slot with probability $p$.
  * Probability that station $i$ succeeds:
    $$Pr(S_i) = p(1 - p)^{N-1}$$
  * Total probability that a slot contains a successful transmission:
    $$Pr(S) = \sum_{i=1}^N Pr(S_i) = Np(1 - p)^{N-1}$$
* **Large Network Limit ($N \to \infty$):**
  * Define offered load $G = Np$ (the average total transmission attempts generated by the network per slot).
  * Taking the limit as $N \to \infty$ (where $p = G/N \to 0$):
    $$S = \lim_{N \to \infty} N\left(\frac{G}{N}\right)\left(1 - \frac{G}{N}\right)^{N-1} = G e^{-G}$$
* **Peak Throughput Optimization:**
  $$\frac{dS}{dG} = e^{-G} - G e^{-G} = e^{-G}(1 - G) = 0 \implies G^* = 1.0$$
  $$S_{\max} = 1.0 \cdot e^{-1} = \frac{1}{e} \approx \mathbf{0.368} \quad (36.8\%)$$
* **Slot Outcome Distribution at Peak Operating Point ($G = 1.0$):**
  * $Pr(\text{Successful Slot}) = 1/e \approx 36.8\%$
  * $Pr(\text{Empty / Idle Slot}) = e^{-1} \approx 36.8\%$
  * $Pr(\text{Collision Slot}) = 1 - 2e^{-1} \approx 26.4\%$

---

### 2.2 Pure (Unslotted) ALOHA
* **Operational Rules:**
  * Continuous time; no slotting, no global clock synchronization.
  * Stations transmit immediately whenever a frame arrives.
* **Vulnerable Time Window ($2T$):**
  * Let frame transmission time be $T$.
  * A target frame transmitted from $t_0$ to $t_0 + T$ is destroyed if another frame starts in:
    * $(t_0 - T, t_0)$: collides with the beginning of the target frame.
    * $[t_0, t_0 + T)$: collides with the end of the target frame.
  * Total vulnerable window is **$2T$** (twice the frame duration).

![Pure ALOHA vulnerable window of duration 2T around a node's frame](3-artifacts/pure-aloha-vulnerable-window.png)

* **Throughput Derivation ($S$):**
  * Using Poisson frame arrivals with average load $G$ attempts per frame time $T$:
    $$Pr(\text{No frame arrives in } 2T) = e^{-2G}$$
    $$S = G e^{-2G}$$
* **Peak Throughput Optimization:**
  $$\frac{dS}{dG} = e^{-2G}(1 - 2G) = 0 \implies G^* = 0.5$$
  $$S_{\max} = 0.5 \cdot e^{-1} = \frac{1}{2e} \approx \mathbf{0.184} \quad (18.4\%)$$

![Throughput S versus offered load G for slotted and pure ALOHA](3-artifacts/aloha-throughput-vs-load.png)

## 3. Carrier Sense Multiple Access (CSMA)

### 3.1 Carrier Sense Principle & Vulnerable Window ($\tau$)
* **Core Rule:** "Listen before talk" (LBT). A station senses the physical wire before transmitting:
  * Channel Idle: Transmit frame.
  * Channel Busy: Defer transmission.
* **Why Collisions Still Happen (Vulnerable Window $\tau$):**
  * Carrier sensing cannot prevent all collisions because signals travel at finite speed ($V \approx 2 \times 10^8\text{ m/s}$).
  * Let $\tau$ be the maximum one-way propagation delay between the two farthest stations.
  * If Station A transmits at $t_0$, Station B at the other end cannot detect the signal until $t_0 + \tau$. If Station B senses the wire during this window, it detects an idle line and starts transmitting, causing a collision.
  * Carrier sensing reduces the collision window from $T_{\text{frame}}$ (ALOHA) down to **$\tau$ (propagation delay)**.

---

### 3.2 CSMA Persistence Variants

| Protocol Variant | Channel State: Idle | Channel State: Busy | Tradeoff / Operational Characteristic |
| :--- | :--- | :--- | :--- |
| **1-Persistent** | Transmits immediately ($p = 1$). | Continuously listens until idle, then transmits immediately with probability 1. | Zero idle waiting time under light loads; high probability of collision under heavy loads when multiple stations defer during an ongoing frame. |
| **Non-Persistent** | Transmits immediately. | Abandons continuous listening, waits a random backoff delay, then re-senses the medium. | Prevents simultaneous transmissions after a frame finishes; wastes channel capacity sitting idle during backoffs when the channel is free. |
| **$p$-Persistent** *(Slotted)* | Transmits with probability $p$; defers to the next slot with probability $1 - p$. | Continuously listens until idle, then applies the probability $p$ slot trial. | Tunable performance via parameter $p$. As $p \to 1$, behaves like 1-persistent; as $p \to 0$, collision rate drops, but idle slot latency increases. |

## 4. CSMA with Collision Detection (CSMA/CD)

### 4.1 Collision Detection Principle
* In pure CSMA, colliding stations continue sending their entire frame to completion, wasting channel time.
* **Listen While Talking:** Transceivers monitor signal voltage/power while transmitting. If the detected signal power exceeds the station's own transmitted signal power, a collision is detected.
* Hubs (Layer 1) detect collisions when signals arrive simultaneously on two or more ports and output a collision presence signal to all ports.

---

### 4.2 Worst-Case Collision Detection Window ($2\tau$)
* Let $\tau$ be the maximum one-way propagation delay between the two farthest stations (A and B).
* **Worst-Case Timeline:**
  1. $t = 0$: Station A starts transmitting on an idle channel.
  2. $t = \tau - \epsilon$: Right before A's signal reaches Station B, B senses the medium idle and transmits.
  3. $t = \tau$: Signals collide at Station B; B detects the collision immediately.
  4. $t \approx 2\tau$: The corrupted signal wavefront travels all the way back to Station A; Station A detects the collision.
* **Core Invariant:** In the worst case, detecting a collision takes **twice the maximum propagation delay ($2\tau$ or $2a$)**.

![Stations A and C both sensing an idle medium and transmitting, with propagation delay before each detects the resulting collision](3-artifacts/csma-cd-collision-detection.png)

![Frame propagation across stations A to D showing the vulnerable time equal to the propagation delay](3-artifacts/csma-cd-vulnerable-time.png)

* **Handling Collisions:**
  1. **Abort Immediately:** Stop transmitting the current data frame.
  2. **Send Jam Signal (32–48 bits):** Emit a brief jamming signal so all stations detect the collision and flush their buffers.
  3. **Execute Backoff:** Run Binary Exponential Backoff before re-sensing the line.

## 5. Wired LAN: Ethernet (IEEE 802.3)

### 5.1 Ethernet Frame Structure

![Ethernet frame format with Preamble, SFD, DA, SA, Length/Type, Data+Padding, and FCS fields](3-artifacts/ethernet-frame-format.png)

* **Preamble (7 bytes):** Pattern `10101010...` used to synchronize receiver clock.
* **Start Frame Delimiter (SFD, 1 byte):** Pattern `10101011` indicating the start of the MAC frame.
* **Destination Address (DA, 6 bytes / 48 bits):** MAC address of the receiving interface.
* **Source Address (SA, 6 bytes / 48 bits):** MAC address of the sending interface.
* **Length / Type (2 bytes):** Length of payload or upper-layer protocol ID (e.g., IPv4, ARP).
* **Data + Padding (46 to 1500 bytes):**
  * Maximum Transmission Unit (MTU) = 1500 bytes.
  * Minimum payload = 46 bytes (padded with dummy bytes if user data $< 46\text{ bytes}$).
* **Frame Check Sequence (FCS, 4 bytes):** 32-bit CRC covering DA through Padding.

---

### 5.2 Destination Address Classification Rules
A 48-bit MAC address consists of 6 hexadecimal pairs: `XX:XX:XX:XX:XX:XX`.

![Unicast, multicast, and broadcast frame delivery patterns](3-artifacts/mac-address-delivery-types.png){width=60%}

* **The Inspection Rule:** Look at the least significant bit (LSB) of the first byte (the **2nd hex character from the left**):
  * **Unicast (One-to-One):** LSB is `0` $\implies$ 2nd hex digit is **even** (`0, 2, 4, 6, 8, A, C, E`).
  * **Multicast (One-to-Many):** LSB is `1` $\implies$ 2nd hex digit is **odd** (`1, 3, 5, 7, 9, B, D, F`).
  * **Broadcast (One-to-All):** All 48 bits are `1`s $\implies$ `FF:FF:FF:FF:FF:FF`.

---

### 5.3 Minimum Frame Size Derivation
* **The Constraint:** A transmitting station only checks for collisions while it is actively sending bits. To guarantee that a sender detects a worst-case collision before it finishes transmission:
  $$T_{\text{frame}} \ge 2\tau_{\text{end-to-end}}$$
  $$L_{\min} = 2\tau_{\text{end-to-end}} \cdot R$$
* **Standard 10 Mbps Ethernet Derivation:**
  * Maximum round-trip time across 2500 m span: $2\tau = 51.2\ \mu\text{s}$ (Slot Time).
  * Bit transmission time at $R = 10\text{ Mbps}$: $\frac{1}{10 \times 10^6} = 0.1\ \mu\text{s/bit}$.
  * Minimum frame length:
    $$L_{\min} = \frac{51.2\ \mu\text{s}}{0.1\ \mu\text{s/bit}} = 512\text{ bits} = \mathbf{64\text{ bytes}}$$
  * Mandatory MAC Header & Trailer:
    $$\text{DA (6B)} + \text{SA (6B)} + \text{Length/Type (2B)} + \text{CRC FCS (4B)} = \mathbf{18\text{ bytes}}$$
    *(Preamble and SFD are physical synchronization bytes and do not count toward MAC frame size).*
  * Minimum Data Payload:
    $$\text{Minimum Payload} = 64\text{ bytes} - 18\text{ bytes} = \mathbf{46\text{ bytes}}$$

---

### 5.4 Binary Exponential Backoff (BEB) Algorithm
* **Contention Window Size:** On collision $i$, pick a random integer slot $K$ uniformly from:
  $$K \in \{0, 1, 2, \ldots, 2^k - 1\} \quad \text{where } k = \min(i, 10)$$
* **Backoff Delay:**
  $$\text{Delay} = K \times 51.2\ \mu\text{s}$$
* **Abort Limit:** After 16 failed attempts (`attempts == 16`), abort and report a network error.

## 6. Collision vs. Broadcast Domains

![Network topology of hubs, switches, and routers illustrating collision and broadcast domain boundaries](3-artifacts/collision-broadcast-domain.png)

* **Collision Domain:** A physical network segment where simultaneous transmissions collide.
  * Hubs/Repeaters (Layer 1): Forward bits out of all ports; merge all connected links into **1 single collision domain**.
  * Switches/Bridges (Layer 2) & Routers (Layer 3): Buffer frames in internal memory; create a **separate collision domain on every individual port**.
* **Broadcast Domain:** The network scope reached by a Layer 2 broadcast frame (`FF:FF:FF:FF:FF:FF`).
  * Hubs, Repeaters, Switches, and Bridges all forward broadcast frames across all ports (**1 shared broadcast domain**).
  * Routers block Layer 2 broadcasts; **each router interface defines a separate broadcast domain**.

| Network Device | Operating Layer | Splits Collision Domains? | Splits Broadcast Domains? |
| :--- | :---: | :---: | :---: |
| **Hub / Repeater** | Layer 1 | **No** (all ports share 1 domain) | **No** (all ports share 1 domain) |
| **Bridge / Switch** | Layer 2 | **Yes** (each port is 1 domain) | **No** (all ports share 1 domain) |
| **Router** | Layer 3 | **Yes** (each port is 1 domain) | **Yes** (each interface is 1 domain) |

## 7. Multi-Access Reservation Protocol (MARP)

### 7.1 Protocol Architecture
* **Purpose:** Solves the problem of high collision rates in random access under heavy loads.
* **Two-Phase Transmission Cycle:**
  * **Phase 1 (Reservation Phase):** Stations use short reservation mini-frames of time duration $v$ to contend for access.
  * **Phase 2 (Data Phase):** The winning station transmits its full data frame of time duration $u$ collision-free.

```text
|<------------------------- Transmission Window ------------------------->|
+---------------------------------------------------+---------------------+
| Phase 1: Reservation Phase                        | Phase 2: Data Phase |
| Contention attempts using mini-frames of length v | Data frame length u |
| (Each attempt succeeds with probability S_r)      | (Collision-free)    |
+---------------------------------------------------+---------------------+
```

---

### 7.2 Window Duration & Utilization Formulas
* Let $S_r$ be the channel utilization of the reservation protocol used in Phase 1.
* The number of reservation attempts $X$ required to succeed follows a geometric distribution:
  $$E[X] = \frac{1}{S_r}$$
* Average reservation duration:
  $$T_{\text{res}} = E[X] \times v = \frac{v}{S_r}$$
* Total average transmission window:
  $$T_{\text{window}} = u + \frac{v}{S_r}$$

#### Case 1: Reservation Frame Carries NO User Data (Standard Case)
$$S = \frac{\text{Data Transmission Time}}{\text{Total Window Duration}} = \frac{u}{u + \frac{v}{S_r}}$$

#### Case 2: Reservation Frame Carries User Data (Piggybacked)
If the mini-frame carries $v$ units of data, the remaining payload transmitted in Phase 2 is $\mu = u - v$:
$$S = \frac{u}{(u - v) + \frac{v}{S_r}}$$

#### Maximizing MARP Throughput
$$\max(S) \iff \max(S_r)$$
* If Phase 1 uses **Slotted ALOHA**: $S_{r,\max} = 1/e \approx 0.368$ (when offered load $G^* = 1.0$).
* For $n$ stations: station transmission probability is $p^* = G^*/n = 1/n$.

## 9. Exam Problem Archetypes

### Archetype 1: Multi-Segment Minimum Frame Size Calculation
* **Problem:** A CSMA/CD network operates at 20 Mbps:
  * Maximum cable length per segment: 200 m; propagation delay: $1\ \mu\text{s}$ per 100 m.
  * Maximum number of repeaters between any two stations: 4 repeaters.
  * Internal delay through each repeater: $2\ \mu\text{s}$.
  * The network can link up to 5 cable segments.
  Find the minimum frame size required for CSMA/CD to work correctly.
* **Step 1: Compute total worst-case one-way propagation delay ($\tau_{\text{end-to-end}}$):**
  $$\text{Cable delay} = 5 \text{ segments} \times \left(\frac{200\text{ m}}{100\text{ m}} \times 1\ \mu\text{s}\right) = 5 \times 2\ \mu\text{s} = 10\ \mu\text{s}$$
  $$\text{Repeater delay} = 4 \text{ repeaters} \times 2\ \mu\text{s} = 8\ \mu\text{s}$$
  $$\tau_{\text{end-to-end}} = 10\ \mu\text{s} + 8\ \mu\text{s} = 18\ \mu\text{s}$$
* **Step 2: Apply the CSMA/CD minimum transmission time invariant:**
  $$T_{\text{frame}} \ge 2\tau_{\text{end-to-end}} = 2 \times 18\ \mu\text{s} = 36\ \mu\text{s}$$
* **Step 3: Convert time to frame size in bits:**
  $$L_{\min} = T_{\text{frame}} \times R = 36 \times 10^{-6}\text{ s} \times 20 \times 10^6\text{ bps} = \mathbf{720\text{ bits}} \quad (90\text{ bytes})$$

### Archetype 2: BEB Collision Event Probability (Three Stations)
* **Problem:** Three stations (A, B, C) collide simultaneously on a 10BASE-T hub. Each station enters its 1st backoff retrial and chooses slot 0 or slot 1 with equal probability ($p = 0.5$). Calculate the probability that the next active event on the channel is also a collision (idle slots do not count as events).
* **Step 1: Enumerate all joint slot selection outcomes ($2^3 = 8$ equally likely outcomes):**
  * All choose 0: $(0, 0, 0) \implies$ Collision in slot 0 (1 outcome).
  * Exactly two choose 0: $(0, 0, 1), (0, 1, 0), (1, 0, 0) \implies$ Collision in slot 0 (3 outcomes).
  * Exactly one chooses 0: $(0, 1, 1), (1, 0, 1), (1, 1, 0) \implies$ Success in slot 0 (3 outcomes).
  * None choose 0: $(1, 1, 1) \implies$ Slot 0 is idle; all three transmit in slot 1 $\implies$ Collision in slot 1 (1 outcome).
* **Step 2: Identify outcomes where the first event is a collision:**
  $$\text{Colliding outcomes} = (0,0,0) + \text{three of } (2 \text{ zeros}) + (1,1,1) = 1 + 3 + 1 = 5 \text{ outcomes}$$
* **Step 3: Calculate event probability:**
  $$P(\text{Next event is collision}) = \frac{5}{8} = \mathbf{0.625} \quad (62.5\%)$$

---

### Archetype 3: Two-Station Backoff Parameter Optimization
* **Problem:** Two stations (A and B) collide and retransmit over a window of 2 slots (slot 0 and slot 1). Station A picks slot 0 with probability $p$; Station B picks slot 0 with probability $q$.
  1. If $p = 1/3$ and $q = 2/3$, what is the probability that the first active event on the channel is a success?
  2. How do you maximize the probability of success by choosing proper values for $p$ and $q$?
* **Step 1: Success probability in slot 0:**
  Success occurs if exactly one station transmits in slot 0:
  $$P(\text{Success}) = P(A=0, B=1) + P(A=1, B=0) = p(1 - q) + (1 - p)q$$
* **Step 2: Evaluate for $p = 1/3, q = 2/3$:**
  $$P(\text{Success}) = \left(\frac{1}{3}\right)\left(1 - \frac{2}{3}\right) + \left(1 - \frac{1}{3}\right)\left(\frac{2}{3}\right) = \left(\frac{1}{3} \times \frac{1}{3}\right) + \left(\frac{2}{3} \times \frac{2}{3}\right) = \frac{1}{9} + \frac{4}{9} = \mathbf{\frac{5}{9}}$$
* **Step 3: Optimization:**
  $$P(\text{Success}) = p + q - 2pq$$
  To maximize this probability, set the stations to pick completely different slots:
  $$(p = 1, q = 0) \quad \text{or} \quad (p = 0, q = 1) \implies P(\text{Success}) = \mathbf{1.0} \quad (100\%)$$

---

### Archetype 4: MARP Throughput Optimization
* **Problem:** A 1 Mbps wireless channel uses MARP to serve $n = 100$ devices. The data frame is 1000 bits long, of which 10 bits are carried directly inside the reservation mini-frame.
  1. If the reservation phase protocol achieves utilization $S_r = 0.8$, find the total throughput.
  2. If Slotted ALOHA is used for the reservation phase, find the optimal per-station transmission probability $p^*$ and the resulting maximum throughput.
* **Step 1: Timing parameters:**
  Total frame length $u = \frac{1000\text{ bits}}{10^6\text{ bps}} = 1000\ \mu\text{s}$.
  Reservation frame length $v = \frac{10\text{ bits}}{10^6\text{ bps}} = 10\ \mu\text{s}$.
  Remaining data payload time in Phase 2: $\mu = u - v = 1000 - 10 = 990\ \mu\text{s}$.
* **Step 2: Part 1 Calculation (Piggybacked MARP Formula):**
  $$S = \frac{u}{(u - v) + \frac{v}{S_r}} = \frac{1000}{990 + \frac{10}{0.8}} = \frac{1000}{990 + 12.5} = \frac{1000}{1002.5} \approx \mathbf{0.9975} \quad (99.75\%)$$
* **Step 3: Part 2 Optimization under Slotted ALOHA:**
  Slotted ALOHA utilization is maximized when offered load $G^* = 1.0$:
  $$S_{r,\max} = \frac{1}{e} \approx 0.3679$$
  $$p^* = \frac{G^*}{n} = \frac{1.0}{100} = \mathbf{0.01}$$
* **Step 4: Compute Maximum Throughput:**
  $$S_{\max} = \frac{u}{(u - v) + \frac{v}{S_{r,\max}}} = \frac{1000}{990 + 10e} = \frac{1000}{990 + 27.183} = \frac{1000}{1017.18} \approx \mathbf{0.9831} \quad (98.31\%)$$
