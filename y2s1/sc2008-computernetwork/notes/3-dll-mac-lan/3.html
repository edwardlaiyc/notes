3. Data Link Layer (DLL): Medium Access Control & LANs

This chapter covers Lectures 5 to 8 of Part I: LAN basics, medium access control (MAC), Ethernet and wireless LANs. The core question is:

Many stations share one channel. If two of them send at the same time, both frames are destroyed. How do the stations decide who sends, and when?

High-yield calculations from this chapter:

  • ALOHA throughput and the best transmission probability (by differentiation).
  • CSMA/CD minimum frame size and maximum cable length.
  • Binary exponential backoff probabilities.
  • MARP throughput.

1. LAN Basics

Mostly not examinable (Lecture 5 slide labels): WAN/MAN/LAN definitions, the IEEE 802 table, topologies, media, and static channel allocation. Read this section for context only. Section 2 onward is examinable.

  • A LAN (Local Area Network) joins devices in a small area, such as one building. A MAN covers a city. A WAN covers a country or the world.
  • IEEE 802 is the family of LAN standards. It splits the data link layer into two sub-layers:
    • LLC (Logical Link Control): the interface to the network layer above. It does flow and error control. The same LLC can sit on top of different MAC types.
    • MAC (Medium Access Control): builds frames with addresses and an error check. On receive, it checks the address and the error check. Its main job is to control access to the shared medium.
  • Important standards: 802.3 = Ethernet (CSMA/CD). 802.11 = Wi-Fi (CSMA/CA).

1.1 Where and how to control access (examinable)

  • Where:
    • Centralised: one controller grants access. It is simple, but it is a single point of failure and a bottleneck.
    • Distributed: the stations decide together. There is no single point of failure.
  • How:
    • Synchronous (static): each station gets a fixed share, for example a fixed time slot (TDM) or a fixed frequency (FDM). This wastes capacity when a station has nothing to send.
    • Asynchronous (dynamic): stations get capacity only when they need it. There are three kinds: round robin, reservation, and contention. Contention (ALOHA, CSMA) suits bursty traffic. It works well at light load and badly at heavy load.

2. The Multiple-Access Problem

2.1 Setting

  • One broadcast channel with rate RR bit/s is shared by many nodes.
  • If a node receives two or more signals at the same time, a collision happens. Both frames are lost.
  • There is no separate control channel. The nodes must coordinate through the same channel that carries the data.

2.2 The ideal MAC protocol

  1. When only one node has data, it sends at the full rate RR.
  2. When MM nodes have data, each one gets an average rate of R/MR/M.
  3. It is fully decentralised: no master node and no clock synchronisation.
  4. It is simple.

2.3 The three families

Family Idea Examples
Random access Send at the full rate RR with no planning. Detect collisions and recover. ALOHA, slotted ALOHA, CSMA, CSMA/CD, CSMA/CA
Controlled access Take turns, so no collisions happen. Reservation, polling, token passing
Channelisation Divide the channel into fixed pieces. FDMA, TDMA, CDMA

A random-access protocol must answer three design questions:

  1. Does a node listen to the channel before it sends?
  2. How does it send (at once, or with a probability)?
  3. How does it detect a collision, and what does it do after one?

3. Slotted ALOHA

ALOHA came from Norm Abramson’s ALOHAnet in Hawaii.

3.1 Assumptions

  • All frames have the same size.
  • Time is cut into equal slots. One slot = the time to send one frame.
  • Nodes start to send only at the start of a slot. (So the nodes must have synchronised clocks.)
  • If two or more nodes send in the same slot, all nodes detect the collision.

3.2 Operation

  • When a node has a new frame, it sends the frame in the next slot.
  • If there is no collision, the frame is delivered.
  • If there is a collision, the node sends the frame again in each later slot with probability pp, until it succeeds.

Each slot has one of three results: S (success, exactly one sender), C (collision, two or more senders), or E (empty, no sender).

4. Pure ALOHA

4.1 Operation

There are no slots. When a node has a frame, it sends at once. After a collision, it waits a random time and sends again.

4.2 The vulnerable time is two frame times

Let one frame take time TT. Node ii starts at time t0t_0 and ends at t0+Tt_0 + T.

  • Another frame that starts in [t0−T,t0][t_0 - T, t_0] is still on the channel when node ii starts. It overlaps.
  • Another frame that starts in [t0,t0+T][t_0, t_0 + T] starts before node ii ends. It overlaps.

So no other node may start in a window of length 2T2T.

4.3 Throughput

The window is two slots long, so the other N−1N-1 nodes must stay quiet for two slots:

P(S)=Np(1−p)N−1(1−p)N−1=Np(1−p)2(N−1)→Spure=Ge−2GP(S) = Np\,(1-p)^{N-1}(1-p)^{N-1} = Np(1-p)^{2(N-1)} \;\to\; \boxed{S_{\text{pure}} = G\,e^{-2G}}

dSdG=e−2G(1−2G)=0⇒G=12,Smax=12e≈𝟎.𝟏𝟖𝟒\frac{dS}{dG} = e^{-2G}(1 - 2G) = 0 \;\Rightarrow\; G = \tfrac{1}{2}, \qquad S_{\max} = \frac{1}{2e} \approx \mathbf{0.184}

The best transmission probability is p=1/(2N)p = 1/(2N).

A path through two shared channels. Suppose traffic crosses one channel that uses slotted ALOHA and then one that uses pure ALOHA. The path can carry no more than its slowest channel. So its largest throughput is the pure ALOHA peak, 1/(2e)=0.1841/(2e) = 0.184, at offered load G=0.5G = 0.5.

5. CSMA: Listen Before You Talk

5.1 The idea

CSMA (Carrier Sense Multiple Access): a node listens to the medium before it sends. If the medium is busy, it does not send.

In a LAN, the propagation delay is short compared with the frame time. So a node hears another node’s frame almost at once. But collisions can still happen: two nodes can start within one propagation time of each other. Each one hears silence because the other’s signal has not arrived yet.

The vulnerable time of CSMA = the maximum propagation time across the medium. A longer cable means a longer vulnerable time and more collisions.

5.2 The three persistence rules

The rules say what a node does when the medium is busy.

Rule Medium idle Medium busy Nickname
Non-persistent Send now. Wait a random time, then listen again. “Deferential”
1-persistent Send now. Keep listening. When it becomes idle, send at once (probability 1). “Selfish”
pp-persistent Send with probability pp. With probability 1−p1-p, wait one slot and repeat. (One slot = the maximum propagation delay.) Keep listening until idle, then use the idle rule. “Wise guy”

Trade-offs:

  • 1-persistent: no idle time is wasted. But if two nodes wait for the same busy period, both send the moment it ends. A collision is certain.
  • Non-persistent: fewer collisions, because waiting nodes spread out in time. But the channel can sit idle while nodes wait.
  • pp-persistent: a compromise. It reduces both collisions and idle time.

5.3 Why the curves look like this

  • ALOHA does not depend on aa (the normalised propagation delay). ALOHA nodes never listen to the channel. So the propagation delay does not change how they act or how often they collide.
  • CSMA gets worse as aa grows. Carrier sensing only works if a node hears other frames quickly. When aa is large, a node hears another node’s frame late, so collisions become common. At large aa, slotted ALOHA can beat CSMA.
  • Non-persistent beats 1-persistent at high load. 1-persistent nodes all jump in together at the end of a busy period, so they collide. Non-persistent nodes wait random times, so they spread out.

6. CSMA/CD: Stop When You Hear a Collision

6.1 The idea

In plain CSMA, colliding nodes send their whole frames. The channel is wasted for the full frame time.

CSMA/CD (Collision Detection) adds one rule: listen while you send. If you hear a collision, stop at once. Ethernet (IEEE 802.3) uses CSMA/CD.

How a node detects a collision:

  • On a cable: the transceiver sees more signal power on the wire than it sends itself.
  • At a hub: the hub sees input on two ports at the same time. It sends a “collision present” signal on all ports.

6.2 The protocol

  1. Use a persistence rule to decide when to start (Ethernet uses 1-persistent).
  2. While sending, keep listening.
  3. If a collision happens, stop sending and send a short jam signal (48 bits). The jam makes sure every station hears the collision and discards the broken frame.
  4. Wait a random backoff time (Section 8), then try again.

6.3 How long does detection take? Worst case 2τ2\tau

Let τ\tau be the one-way propagation time between the two stations that are farthest apart.

  1. At time t0t_0, A starts to send.
  2. Just before t0+τt_0 + \tau, A’s signal has nearly reached B. B still hears silence, so B starts to send.
  3. At t0+τt_0 + \tau, B hears A’s signal and detects the collision at once.
  4. B’s signal now travels back to A. It reaches A at about t0+2τt_0 + 2\tau.

So A can be sure there was no collision only after 2τ2\tau (one round trip).

6.4 Minimum frame size

A can only detect a collision while it is still sending. If A finishes before 2τ2\tau, it thinks the frame was delivered, but it was destroyed. So:

Tframe≥2τ⇔Lmin=2τ×R\boxed{T_{\text{frame}} \ge 2\tau \quad\Longleftrightarrow\quad L_{\min} = 2\tau \times R}

Here τ\tau includes every delay on the worst path: cable delay in every segment, plus the delay in every repeater or hub.

Classic Ethernet numbers: 10 Mbit/s, maximum round trip 2τ=51.2μ2\tau = 51.2\ \mus (about 2500 m). This gives 51.2μs×107=51251.2\ \mu\text{s} \times 10^7 = 512 bits = 64 bytes. Shorter frames get padding.

6.5 Using Tframe≥2τT_{\text{frame}} \ge 2\tau

The one condition L/R≥2τL / R \ge 2\tau links three values: the frame size LL, the data rate RR and the network size (through τ\tau). A question gives two of them and asks for the third. In every case, first find τ\tau on the worst path, the one between the two stations farthest apart.

Finding τ\tau on a chain of repeaters. nn repeaters join n+1n + 1 cable segments. The signal crosses every segment and waits in every repeater:

τ=(n+1)×(delay per segment)+n×(delay per repeater)\tau = (n+1) \times (\text{delay per segment}) + n \times (\text{delay per repeater})

Example 1: the minimum frame. 3 repeaters join cable segments of 250 m. The signal travels at 2×1082 \times 10^8 m/s, which is 200 m/µs. Each repeater adds 1 µs. The rate is 100 Mbit/s.

  • Four segments, each 250/200=1.25μ250 / 200 = 1.25\ \mus.
  • τ=4×1.25+3×1=8μ\tau = 4 \times 1.25 + 3 \times 1 = 8\ \mus, so 2τ=16μ2\tau = 16\ \mus.
  • Lmin=16μs×100Mbit/s=𝟏𝟔𝟎𝟎L_{\min} = 16\ \mu\text{s} \times 100\ \text{Mbit/s} = \mathbf{1600} bits.

Example 2: the longest bus. 100 Mbit/s, minimum frame 64 bytes, signal speed 200 m/µs.

  • Tframe=512/108=5.12μT_{\text{frame}} = 512 / 10^8 = 5.12\ \mus.
  • 2τ≤5.12μ2\tau \le 5.12\ \mus, so τ≤2.56μ\tau \le 2.56\ \mus.
  • Longest bus =2.56×200=𝟓𝟏𝟐= 2.56 \times 200 = \mathbf{512} m.

At 10 Mbit/s, the same frame lasts 10 times longer, so the bus can be 10 times longer. A faster rate forces a smaller network or a bigger minimum frame.

Example 3: a star with a hub. Each host has a cable of length ℓ\ell to the hub. The hub adds 1 µs. 100 Mbit/s, minimum frame 64 bytes, signal speed 200 m/µs.

  • The worst path is host → hub → host, so it crosses two cables: τ=ℓ/200+1+ℓ/200=ℓ/100+1\tau = \ell/200 + 1 + \ell/200 = \ell/100 + 1 µs.
  • 2τ≤5.12⇒ℓ/100+1≤2.56⇒ℓ≤𝟏𝟓𝟔2\tau \le 5.12 \Rightarrow \ell/100 + 1 \le 2.56 \Rightarrow \ell \le \mathbf{156} m.

If a switch replaces the hub, there are no collisions, so this limit no longer applies. Each switch port is its own collision domain. The switch stores frames in buffers and sends them one at a time, often in full-duplex.

Example 4: the fastest rate. The minimum frame is 1000 bits, and the worst one-way delay is 10 µs. So 2τ=20μ2\tau = 20\ \mus, and R≤1000/20μs=𝟓𝟎R \le 1000 / 20\ \mu\text{s} = \mathbf{50} Mbit/s.

7. Ethernet (IEEE 802.3)

Not examinable (Lecture 7 slide labels): history, physical layer, media, Manchester coding, 10BASE-5/2/T details, Fast/Gigabit/10G Ethernet. Examinable: MAC addresses, minimum frame size, BEB and collision probability, and counting collision and broadcast domains.

7.1 Frame format

Field Size Purpose
Preamble 7 bytes 10101010… The receiver uses it to lock its clock to the sender.
SFD (Start Frame Delimiter) 1 byte 10101011. “The frame starts now.”
DA (Destination Address) 6 bytes The MAC address of the receiver.
SA (Source Address) 6 bytes The MAC address of the sender.
Length/Type 2 bytes Tells the receiver which upper protocol (for example IP) gets the data.
Data + Pad 46 to 1500 bytes The payload. Padding brings short data up to 46 bytes.
FCS (Frame Check Sequence) 4 bytes A CRC over DA to Pad. It detects bit errors.

DA + SA + Type + 46 + FCS =6+6+2+46+4=64= 6 + 6 + 2 + 46 + 4 = 64 bytes, which is the minimum frame. The preamble and SFD are not counted.

7.2 MAC addresses

  • A MAC address has 48 bits, written as 6 hex bytes, for example 08:00:e4:b1:02:a2. The manufacturer burns it into the network card. Each manufacturer has its own range, so every card has a unique address.
  • Delivery type. Look at the lowest bit of the first byte (in practice, the second hex digit):
    • Unicast (to one station): the bit is 0. The second hex digit is even. Example: 4A:….
    • Multicast (to a group): the bit is 1. The second hex digit is odd. Example: 47:….
    • Broadcast (to all stations): all 48 bits are 1: FF:FF:FF:FF:FF:FF.
  • A receiver passes a frame up if the DA is its own address, the broadcast address, or a multicast group it belongs to. In promiscuous mode it passes up every frame.

7.3 Ethernet’s MAC algorithm

  • Idle line: send at once. A frame has at most 1500 bytes of data. Between two back-to-back frames, the station must wait 9.6 µs.
  • Busy line: wait until it is idle, then send at once (1-persistent).
  • Collision: stop, send the jam signal, then wait the binary exponential backoff time and try again.
  • After 16 failed attempts, the station discards the frame and reports an error.

8. Binary Exponential Backoff (BEB)

8.1 The rule

After the nn-th collision of a frame:

  1. Choose KK at random from {0,1,2,…,2n−1}\{0, 1, 2, \dots, 2^n - 1\}. Every value is equally likely.
  2. Wait K×51.2μK \times 51.2\ \mus (one slot time = 512 bit times at 10 Mbit/s).
  3. Try again.

The range stops growing after n=10n = 10 (so K≤1023K \le 1023). The station gives up after 16 attempts.

Why random? If all stations waited the same time, they would collide again in lock-step. Why does the range grow? A small range is fine for two stations, but with many stations they would keep colliding. Each collision is a sign of more traffic, so the range doubles.

8.2 Two stations

After the first collision, each station picks slot 0 or 1. They collide again if they pick the same slot:

P(collide again)=P(0,0)+P(1,1)=0.25+0.25=0.5P(\text{collide again}) = P(0,0) + P(1,1) = 0.25 + 0.25 = 0.5

After the second collision, each picks from 0 to 3:

P(collide again)=4×14×14=0.25P(\text{collide again}) = 4 \times \tfrac{1}{4}\times\tfrac{1}{4} = 0.25

In general, for two stations after the nn-th collision: P(collide again)=1/2nP(\text{collide again}) = 1/2^n.

8.3 Method for more stations: list the slot choices

The first event on the channel is the first slot in which someone sends. An empty slot is not an event.

The method has three steps:

  1. List every combination of slot choices. If each station picks from WW slots, there are WnW^n equally likely combinations for nn stations.
  2. For each combination, find the lowest slot that anyone picked. That slot holds the first event. It is a success if exactly one station picked it, and a collision if two or more did.
  3. Add up the probabilities.

nn stations, window of 2 slots. Group the 2n2^n combinations by how many stations pick slot 0:

Who picks slot 0 Ways First event
Exactly one nn Success in slot 0
Two or more 2n−n−12^n - n - 1 Collision in slot 0
Nobody 1 All nn send in slot 1: a collision (for n≥2n \ge 2)

P(first event is a success)=n2nP(\text{first event is a success}) = \frac{n}{2^n}

So the chance of success drops fast as more stations collide: 2/4=0.52/4 = 0.5 for two stations, 4/16=0.254/16 = 0.25 for four, and 8/256≈0.038/256 \approx 0.03 for eight. This is why BEB keeps doubling the window.

Two stations, window of 4 slots (after the second collision). The first event is a collision only if both stations pick the same slot, because then that slot is also the lowest one picked. That happens in 4 of the 16 combinations. So P(success)=1−4/16=0.75P(\text{success}) = 1 - 4/16 = 0.75.

Unequal choices. Some questions change BEB so that the stations do not pick slots with equal probability. The listing method still works. Let A pick slot 0 with probability pp and B pick slot 0 with probability qq, in a window of 2 slots:

A B Probability First event
0 0 pqpq Collision
0 1 p(1−q)p(1-q) Success
1 0 (1−p)q(1-p)q Success
1 1 (1−p)(1−q)(1-p)(1-q) Collision
  • P(success)=p(1−q)+(1−p)qP(\text{success}) = p(1-q) + (1-p)q. With p=0.25p = 0.25 and q=0.5q = 0.5: 0.125+0.375=0.50.125 + 0.375 = 0.5.
  • The success probability is largest when the two stations never pick the same slot: p=0,q=1p = 0, q = 1 or p=1,q=0p = 1, q = 0. Then P(success)=1P(\text{success}) = 1.

9. Collision Domains and Broadcast Domains

  • A collision domain is the part of a network where two frames sent at the same time collide.
    • Repeaters and hubs (layer 1) copy every signal to every port. They extend a collision domain.
    • Bridges, switches and routers (layers 2 and 3) do not pass collisions. Each port is a separate collision domain.
  • A broadcast domain is the part of a network that a broadcast frame (DA = FF:…:FF) reaches.
    • Hubs, repeaters, bridges and switches pass broadcasts.
    • Routers stop broadcasts. Each router interface is the edge of a broadcast domain.

How to count:

  1. Collision domains: count one for each port of each switch, bridge or router. A hub and everything on it counts as one domain (on whichever port it connects to).
  2. Broadcast domains: count one for each router interface (one for each network the router joins).

Hub versus switch:

  • A hub sends each signal out of every port except the one it came in on. Two stations that send at the same time collide.
  • A switch sends each frame only to the port of the destination. If two frames arrive at once, the switch stores them in buffers and sends them later. There is no collision.

10. Wireless LANs (802.11)

Mostly not examinable (Lecture 8 slide labels): standards, the architecture (BSS, ESS, AP), channels, association, DCF/PCF details and the frame format. MARP (Section 11) is examinable. You should still be able to explain the points below in a few sentences.

Why collision detection is hard in a WLAN:

  1. A station’s own signal is very strong at its antenna. The signal from a far station is very weak. While the station sends, it cannot hear the weak signal.
  2. The hidden terminal problem: A and C can both reach B, but they cannot hear each other (because of distance or a wall). Both see an idle channel and both send to B. The frames collide at B, but neither A nor C can detect this.

What a WLAN does instead: collision avoidance (CSMA/CA).

  • Every correct frame gets an ACK. No ACK means the frame failed, so the sender sends it again.
  • Optional RTS/CTS handshake: the sender sends a short RTS (Request To Send). The receiver answers with CTS (Clear To Send). Every station that hears the CTS (including hidden terminals) stays quiet for the time given in the frame (its NAV, network allocation vector). Only short RTS frames can collide, which wastes little time.
  • RTS/CTS does not solve the exposed terminal problem: a station that hears the RTS stays quiet, even when its own transmission would not have caused harm. That chance to send is wasted.

11. MARP: Multi-Access Reservation Protocol (examinable)

11.1 The idea

Contention protocols waste time on collisions of long data frames. MARP uses contention only for short reservation frames.

Each cycle has two phases:

  1. Reservation phase: stations send short trial (reservation) frames, each vv time units long. They use some MAC protocol with utilisation SrS_r (for example slotted ALOHA). The phase ends when one trial succeeds.
  2. Transmission phase: the station that won sends one data frame of uu time units. No collision is possible.

11.2 How many trials? (first principles)

Let XX be the number of trial frames until one succeeds. Each trial succeeds with probability SrS_r.

  • X=1X = 1 (the first trial succeeds) with probability SrS_r.
  • X=kX = k (the first k−1k - 1 trials fail, then the kk-th succeeds) with probability Sr(1−Sr)k−1S_r(1 - S_r)^{k-1}.

This is a geometric distribution, so E[X]=1/SrE[X] = 1/S_r. The reservation phase lasts v/Srv/S_r on average, and one cycle lasts:

window=u+vSr\text{window} = u + \frac{v}{S_r}

11.3 Throughput: two cases

Read the question carefully. The two cases use different formulas.

Case A. The reservation frame carries no user data. Only the uu part is useful:

S=uu+v/Sr\boxed{S = \frac{u}{u + v/S_r}}

Case B. The reservation frame carries some of the data bits. The data frame is uu long in total, and the first vv of it goes out inside the winning trial. So the transmission phase only needs u−vu - v:

S=u(u−v)+v/Sr\boxed{S = \frac{u}{(u - v) + v/S_r}}

13. Common Traps

  • Slotted ALOHA: S=Np(1−p)N−1→Ge−GS = Np(1-p)^{N-1} \to Ge^{-G}. Differentiate to get G=1G = 1, p=1/Np = 1/N, Smax=1/eS_{\max} = 1/e. With a small NN, use the exact formula, not the limit.
  • Pure ALOHA: S=Ge−2GS = Ge^{-2G}, so G=0.5G = 0.5, p=1/(2N)p = 1/(2N), Smax=1/(2e)S_{\max} = 1/(2e). Its vulnerable time is two frame times, not one.
  • ALOHA throughput does not depend on aa. CSMA throughput falls as aa grows.
  • 1-persistent CSMA does not avoid collisions after a busy period. It makes them certain when two stations wait.
  • CSMA/CD: Tframe≥2τT_{\text{frame}} \ge 2\tau, a round trip, not one way. Put every segment and repeater or hub delay into τ\tau. nn repeaters join n+1n + 1 segments.
  • In a star with a hub, the worst path crosses two cables.
  • A switch removes collisions, so the CSMA/CD length limit does not apply to it.
  • BEB: after the nn-th collision, KK is chosen from 0 to 2n−12^n - 1. Write out all slot choices. An empty slot is not an event.
  • MAC address: look at the second hex digit. Even = unicast, odd = multicast, all F = broadcast.
  • Domains: every switch, bridge or router port is a separate collision domain. Only a router interface separates broadcast domains. Hubs separate nothing.
  • WLANs avoid collisions (CSMA/CA). They cannot detect them. RTS/CTS fixes the hidden terminal problem, not the exposed terminal problem.
  • MARP: decide Case A or Case B before you put numbers in.
