Lecture 2, Part A: IP Addressing and Subnetting

This page covers Part II Lecture 2 in two parts. Part A is the first half (addressing, subnetting, IP settings, DHCP, NAT). Part B, further down, is the second half (forwarding, ARP, fragmentation, ICMP). It also keeps the Lecture 1 overview in Section A1.

Part I showed how a frame crosses one link. Part II shows how data crosses many networks and reaches the right program on the right computer. This part answers one question: how does an address tell a router where to send a packet?

In the exam you will:

  • find the network address, broadcast address and usable range from an address and a mask;
  • choose subnet sizes and give each router interface an address (equal-size subnetting and VLSM);
  • find the smallest subnet that holds two addresses, or one route that covers many networks;
  • fill in a NAT or DHCP packet table, and explain what a home router does.

How to use this page. Each section teaches one idea in a few lines, then gives the questions on it, with a general method. Tutorial 2.1 has official solutions. Tutorial 2.3 has none, so its answer is unofficial. Concept checks and extensions are unofficial too. Past-year papers are not on this page: use the original papers.

A1. Three layers, three addresses

Part I covered the physical and data link layers. Part II covers the next three.

Layer Delivers Address it uses Size Lecture
Data link node to node (one link) MAC address 48 bits Part I
Network host to host (the whole path) IP address 32 bits (IPv4) 2 and 3
Transport process to process Port number 16 bits 4

A node is any device on the path. A host is an end computer. A process is a program running on a host. All three addresses sit in the packet at once: the port in the transport header, the IP address in the IP header, and the MAC address in the frame header.

The two hosts run all five layers. A router runs only the physical, data link and network layers. At each router, the network layer picks the next hop. Then the data link layer carries the packet over that one link.

The network layer delivers data from process to process.

False. The network layer delivers host to host. The transport layer delivers process to process, using port numbers.

A router runs all five layers.

False. A router runs the physical, data link and network layers only. It forwards packets and never reads the transport header.

A2. IP basics

IP (Internet Protocol) is the network-layer protocol of the Internet. An IP packet (or datagram) has two parts:

  • the IP header: control information, including the source and destination IP addresses;
  • the payload: the data after the header, for example a TCP segment.

An Ethernet frame carries the packet over one link. At each router the packet goes into a new frame for the next link.

IP is connectionless: it sends each datagram on its own, with no set-up. IP is also best effort: packets can be lost, delayed, duplicated or reordered, and IP never resends them. TCP, above IP, adds reliability.

The Internet Protocol (IP) provides a reliable service.

False. IP is best effort. It can lose, delay, duplicate or reorder packets, and it does not resend them. TCP adds reliability.

A3. IPv4 addresses

The format

An IPv4 address is a 32-bit number given to a network interface (one Ethernet port, one Wi-Fi connection). We write it as four decimal numbers, one per byte (an octet, 0 to 255), with dots between them.

192    .168     .10      .77
11000000.10101000.00001010.01001101   (8 + 8 + 8 + 8 = 32 bits)

A router has one IP address on each interface, and each address belongs to the subnet on that side.

Network part and host part

A MAC address is flat: it says who a device is, not where. If IP addresses were flat too, every router would need one table entry for every computer on Earth. So an IP address has two parts, like a phone number with a country code:

  • the network prefix (the leading bits) names the network;
  • the host part (the remaining bits) names the interface inside it.

Example: in 155.69.8.3, “155.69” names NTU and “8.3” names one machine. A router far away needs only one route for the whole NTU block.

Subnet, prefix and mask

  • A subnet is a group of interfaces with the same network prefix. Hosts in one subnet talk directly, without a router.
  • A subnet mask is a 32-bit value. Its leading 1s mark the prefix. Its trailing 0s mark the host bits. The 1s must be one unbroken run.
  • Prefix notation writes /n after the address, where nn is the number of 1s in the mask.

Learn the mask octets: 128, 192, 224, 240, 248, 252, 254, 255. Each one adds the next bit (128, +64, +32, +16, +8, +4, +2, +1).

255.255.253.0 is a valid subnet mask.

False. 253 is 11111101. A 0 comes before a 1, so the 1s are not one unbroken run.

Network, broadcast and usable addresses

With hh host bits:

  • Network address: all host bits 0. First address of the block. It names the subnet.
  • Broadcast address: all host bits 1. Last address of the block. It means “every host on this subnet”.
  • Usable addresses: everything in between.

total=2h,usable=2h−2\text{total} = 2^h, \qquad \text{usable} = 2^h - 2

Always count the router interface. A LAN with 62 computers and 1 gateway needs 63 usable addresses. A /26 has only 62, so you need a /25.

A /24 subnet can hold 256 hosts.

False. A /24 has 256 addresses, but the network and broadcast addresses are not for hosts. It holds 254 interfaces, and a router interface is one of them.

CIDR and the old classes

CIDR (Classless Inter-Domain Routing) allows any prefix length. Use the prefix or mask that the question gives. Do not guess the boundary from the first number.

The old classful system fixed the boundary from the first bits. You still need to recognise the classes.

A4. From an address to its subnet

The question: given an address and a mask, which block is the address in?

Fast method (block size). The mask cuts the address space into equal blocks that start on multiples of the block size.

  1. Find the interesting octet: the one octet where the mask is neither 255 nor 0.
  2. Block size B=256−B = 256 - (mask value in that octet).
  3. List the block starts 0,B,2B,…0, B, 2B, \dots Find the block that holds the address.
  4. Network = the start of that block, with 0 in later octets. Broadcast = the next start −1- 1, with 255 in later octets.
Address Mask octet Block size Block Network Broadcast
192.168.10.77/26 192 (4th) 64 64–127 192.168.10.64 192.168.10.127
10.0.5.94/27 224 (4th) 32 64–95 10.0.5.64 10.0.5.95
172.20.142.98/22 252 (3rd) 4 140–143 172.20.140.0 172.20.143.255

Full method (bitwise AND). 1 AND 1=11 \text{ AND } 1 = 1. Every other pair gives 0. So address AND mask keeps the prefix and sets every host bit to 0. The result is the network address.

For 192.168.10.77/26: the last mask octet is 192. 01001101 (77) AND 11000000 (192) = 01000000 = 64. The network is 192.168.10.64/26.

Same subnet? AND each address with the mask and compare. With 192.168.10.77/26, the address .126 gives .64 (same, so local). The address .130 gives .128 (different, so remote).

Close is not local. 10.0.5.96 is not in 10.0.5.64/27. It starts the next block. And an address that ends in .0 is not always a network address: in 150.10.100.0/19 the block is .96.0 to .127.255, so .100.0 is an ordinary host.

Tutorial 2.1 Q2. An organization is assigned a /16 IP address block. The organization has created several subnets for its network. It is known that one of the subnets is 145.32.128.0/255.255.224.0. What is the broadcast address for this subnet?

Answer

The mask 255.255.224.0 has 19 ones, so the subnet is a /19. The interesting octet is the 3rd.

In binary, the 3rd octet of the subnet is 10000000 and the mask is 11100000. The first 3 bits (100) are the prefix. The other 5 bits and the whole 4th octet are host bits. Set every host bit to 1: 145.32.10011111.11111111.

Broadcast address = 145.32.159.255.

Check: B=256−224=32B = 256 - 224 = 32. The block starts at 128 and ends at 128+32−1=159128 + 32 - 1 = 159. ✓

General method: from an address and a mask to the whole range
  1. Turn /n into a mask, or read the mask. Find the interesting octet.
  2. B=256−B = 256 - mask value there.
  3. The network octet is the multiple of BB at or below the address octet. Later octets are 0.
  4. The broadcast octet is the network octet +B−1+ B - 1. Later octets are 255.
  5. Usable = network +1+1 to broadcast −1-1. The count is 2h−22^h - 2.
  6. If the question gives a network address, check that its octet is a multiple of BB. If not, it is not a network address.

A5. Equal-size subnetting

The question: how do I cut one block into smaller blocks of the same size?

Subnetting divides a parent block into non-overlapping child blocks by making the prefix longer. Going from /pp to /qq uses q−pq - p extra bits to number the children. So the parent holds 2q−p2^{q-p} children, each with 32−q32 - q host bits. More subnets means fewer addresses in each one. The total does not grow.

Method. Two things must both fit: the largest subnet, and the number of subnets (include future ones). Size first, then count.

  1. Interfaces needed = hosts + 1 for the router.
  2. Smallest hh with 2h−2≥2^h - 2 \ge interfaces. Prefix =32−h= 32 - h.
  3. Count check: 2q−p≥2^{q-p} \ge the number of subnets.

If the count check fails, you need a bigger parent or subnets of different sizes (Section A6).

Lecture example. Parent 10.20.0.0/20. There are 6 departments, each with up to 300 computers and 1 gateway.

  1. Size: 301 interfaces. 29−2=510≥3012^9 - 2 = 510 \ge 301, so h=9h = 9 and the prefix is /23.
  2. Count: 23−20=323 - 20 = 3 bits give 23=8≥62^3 = 8 \ge 6 subnets. ✓
  3. The 3rd octet goes up by 256−254=2256 - 254 = 2 each time.
Use Subnets
Departments 1 to 6 10.20.0.0/23, 10.20.2.0, 10.20.4.0, 10.20.6.0, 10.20.8.0, 10.20.10.0
Reserved 10.20.12.0/23 and 10.20.14.0/23

A6. VLSM: subnets of different sizes

The question: what if the LANs have very different sizes?

VLSM (Variable-Length Subnet Masking) gives each segment its own prefix. A big LAN gets a big block. A link between two routers needs only 2 addresses, so it gets a /30.

Method.

  1. List every segment that needs a subnet: every LAN and every router-to-router link.
  2. Size each one (hosts + router interfaces) and choose the smallest prefix.
  3. Check the total. The block sizes must add up to no more than the parent.
  4. Place fixed blocks first. If the question names a host address, the subnet must contain it. A block already in use is fixed too.
  5. Then largest first. Each block must start on a multiple of its own size. This leaves no unusable gaps.
  6. Give each router interface a usable address in its subnet. Both ends of a /30 take the two usable addresses. Skip any address a host already has.
  7. Check: enough capacity, aligned, no overlap, every address unique.

If the total does not fit, re-read what the host counts include. One extra address can double a block. State your assumption.

Lecture example. Parent 192.168.50.0/24. LAN A has 100 computers, LAN B 50, LAN C 20, LAN D 10. Each LAN also needs one gateway. Four routers R1–R4 are joined by four links.

LAN C 21 /27 .192/27 .193 – .222 R3: .193
LAN D 11 /28 .224/28 .225 – .238 R4: .225
R1–R2 2 /30 .240/30 .241 – .242 R1 .241, R2 .242

General method: two or more subnet sizes in one parent block
  1. Plan for the future count, not the present one.
  2. Find the prefix for each size (hosts + router interface).
  3. Measure every block in units of the smallest prefix. Add the units and compare with the parent.
  4. Place the biggest blocks first, each on a multiple of its own size. Then place the smaller ones.
  5. Write the free space as aligned blocks.

A7. Smallest subnet for two addresses, and route aggregation

The question: which one block holds these addresses?

Write the first octet where the addresses differ in binary. Count the leading bits that all of them share. The prefix is 8 for each full octet before it, plus the shared bits in that octet.

Extension A7.1. Find the smallest subnet (longest prefix) that holds both addresses, and give its mask. (a) 20.30.150.10 and 20.30.158.5. (b) 60.1.130.4 and 60.1.20.9.

Answer (Extension A7.1)

150 = 1001 0110
158 = 1001 1110

Ports and NAPT

A port number (16 bits, in the transport header) names the program on a host. IP:port names one end of a connection, for example 192.168.1.10:50000. A web server uses a well-known port (80 for HTTP, 443 for HTTPS). The client’s operating system picks a temporary source port for each connection.

  • NAT (Network Address Translation): a router changes the IP addresses of packets that cross between a private network and the Internet.
  • NAPT (Network Address and Port Translation), also called PAT: the router also changes the port. Many private hosts can then share one public IP address.

The router keeps a translation table:

  • Outgoing packet: it changes the source private IP:port to its public IP:new port, and saves the mapping.
  • Reply: it looks up the mapping and changes the destination back to the private IP:port.

Two hosts can use the same source port. The different public ports tell their connections apart.

DHCP

DHCP (Dynamic Host Configuration Protocol) gives a host its address, mask, gateway and DNS server. An administrator sets up a pool of addresses, for example .30–.50. The pool is only part of the subnet. A printer at a fixed .20 outside the pool is still valid. The host gets the address on a lease (for example 8 hours) and can renew it.

The problem: the host has no address yet, so how can it talk? It uses four messages, DORA.

  1. Discover: the client broadcasts “Is there a DHCP server?”
  2. Offer: the server offers an address and the settings.
  3. Request: the client asks for the offered address.
  4. Acknowledge: the server confirms the lease.

Routers do not forward a local broadcast. To reach a server on another LAN, a DHCP relay passes the messages on.

Suppose the server is 10.0.0.1 and offers 10.0.0.50. If the server replies by unicast:

B1. Forwarding

B1.1 Terms

  • Forwarding: the decision to send a packet out of a particular interface towards its destination. It is one lookup in a table for each packet.
  • Routing: the process that fills in that table (Lecture 3).
  • Next hop: the device that should get the packet next. It is either the destination itself (when the destination is on the same subnet) or a router.
  • Routing table: a list of entries. Each entry maps a destination prefix to an outgoing interface and, if needed, a next-hop router.
  • Default route: 0.0.0.0/0. It matches every destination.
  • Default gateway: the next-hop router for a host’s default route. The host uses it when no more specific route matches.

B1.2 How a host decides: local or remote

  1. AND the destination address with its own mask.
  2. Compare the result with its own network address.
  3. Same: the destination is local (on-link). Send the frame directly to the destination.
  4. Different: the destination is remote. Send the frame to the default gateway.

In both cases, the IP destination stays the final host. Only the next hop changes.

B1.3 Why the mask matters

The same two addresses can be local or remote. It depends only on the mask. A = 172.16.10.5 and the destination is 172.16.200.9.

B1.4 Longest-prefix match

Several entries can match one destination. The router chooses the match with the longest prefix, because it describes the most specific block. The default route /0 is the least specific, so it is the last choice.

Method:

  1. For each entry, check whether the destination is inside that block. (AND the destination with the entry’s mask and compare.)
  2. Among the matches, choose the one with the largest /n/n.

B2. ARP: From an IP Address to a MAC Address

B2.1 Why we need ARP

Forwarding gives the IP address of the next hop. But an Ethernet frame needs the next hop’s MAC address. ARP (Address Resolution Protocol) finds the MAC address for an IPv4 address on the local link.

B2.2 How ARP works

  1. The host looks in its ARP cache (a table of IP → MAC pairs it has learnt).
  2. If the pair is missing, it sends an ARP request as an Ethernet broadcast (destination MAC FF:FF:FF:FF:FF:FF): “Who has 192.168.10.20? Tell 192.168.10.10.”
  3. The device that owns that IP sends an ARP reply as a unicast: “192.168.10.20 is at MAC B.”
  4. The host saves the pair in its cache. The other device also learns the sender’s pair from the request.
Field ARP request ARP reply
Ethernet source A B
Ethernet destination FF:FF:FF:FF:FF:FF (broadcast) A
Sender IP 192.168.10.10 192.168.10.20
Target IP 192.168.10.20 192.168.10.10
  • ARP stays on the local link. Routers do not forward ARP broadcasts.
  • An ARP request is an Ethernet broadcast, not an IP broadcast.
  • Which IP does ARP ask for? The next-hop IP. For a remote destination, that is the gateway’s IP, not the final destination’s IP.

Remote server example: A is 192.168.10.10/24 with gateway .1, and the server is 203.0.113.80. ARP target = 192.168.10.1. Ethernet destination = the gateway’s MAC. IP destination = 203.0.113.80.

ARP cache next-hop IPv4 → MAC a host or router that builds a frame
Switch forwarding table MAC → switch port a switch that forwards a frame

The route lookup chooses the next hop. ARP finds its MAC. The switch chooses the output port.

B2.4 How an Ethernet switch learns

  • When a frame arrives, the switch learns its source MAC and the port it came in on.
  • For a known unicast destination, it forwards the frame only out of the learnt port. If that port is the incoming port, it does not forward the frame at all.
  • For a broadcast or an unknown unicast, it floods the frame out of every port except the incoming one.

The switch learns from source MACs and forwards on destination MACs. Don’t mix the two up.

An ARP request is sent to the target host as a unicast frame.

False. The sender does not know the target’s MAC yet, so the request goes to FF:FF:FF:FF:FF:FF. Only the reply is a unicast.

A switch learns a station’s MAC address from the destination field of a frame.

False. It learns from the source MAC. It uses the destination MAC to choose the output port.

A router forwards an ARP broadcast to its other interfaces.

False. ARP works on one link only. A router does not forward Ethernet broadcasts, so each LAN runs its own ARP.

B4. IPv4 Fragmentation

B4.1 MTU

The MTU (Maximum Transmission Unit) is the largest IP packet that a link can carry. It counts the IP header + IP data. It does not count the Ethernet header and trailer. Different links can have different MTUs. When a packet is bigger than the next link’s MTU, an IPv4 router can split it into fragments.

B4.2 The header fields

Field Meaning
Total Length The size of this packet or fragment in bytes: header + data.
IHL (Internet Header Length) The header length in 32-bit words. IHL = 5 means 5×4=205 \times 4 = 20 bytes.
Identification (ID) The same value in every fragment of one datagram. It groups them together.
Fragment Offset Where this fragment’s data starts in the original data, in units of 8 bytes.
DF (Don’t Fragment) DF = 1: the router must not fragment. If the packet is too big, the router drops it and normally sends ICMP “fragmentation needed”.
MF (More Fragments) MF = 1: more fragments follow. The last fragment has MF = 0.
  • Every fragment gets its own IP header.
  • Only the final destination puts the fragments back together (reassembly). Routers in between do not. The destination groups fragments by ID, source, destination and protocol.
  • Offsets put the data back in place even if fragments arrive out of order.

B4.3 Method

  1. Data size: original data = Total Length − header (usually 20 bytes). Read carefully whether the question gives the total length or the data length.
  2. Space per fragment: MTU − 20.
  3. Round down to a multiple of 8: max data per fragment =8×⌊(MTU−20)/8⌋= 8 \times \lfloor (\text{MTU} - 20)/8 \rfloor. Every fragment except the last must carry a multiple of 8 data bytes, because offsets count in 8-byte units.
  4. Number of fragments: ⌈data/max data⌉\lceil \text{data} / \text{max data} \rceil. The last fragment carries what is left.
  5. For each fragment: Total Length = data + 20. Offset = (start byte) / 8. MF = 1 except for the last. ID = the original ID.
  6. Check: the data adds up to the original; every Total Length ≤\le MTU; only the last has MF = 0.

  • Data =2420−20=2400= 2420 - 20 = 2400 bytes.
  • Space =1000−20=980= 1000 - 20 = 980, so max data =8×122=976= 8 \times 122 = 976 bytes.

B4.6 What if one fragment is lost?

The destination needs every fragment. If one is missing when the reassembly timer runs out, it discards the whole datagram. IP does not ask for the missing piece. TCP or the application must recover the data.

So the probability that the whole packet arrives is:

P(packet OK)=(1−p)nP(\text{packet OK}) = (1 - p)^{n}

for nn fragments, each lost with probability pp.

  • If the sender sends each fragment twice, a fragment is lost only if both copies are lost: p′=p2=0.0025p' = p^2 = 0.0025. Then P=0.99755=0.988P = 0.9975^5 = 0.988.

B4.7 Packet size is a trade-off

  • Large packets: fewer headers and fewer packets to process. But one loss destroys more data.
  • Small packets: less data lost per loss, and a shorter time to send each packet. But more header overhead. (Lecture: 5600 bytes as 4 × 1400 carries 80 header bytes; as 8 × 700 it carries 160.)

Fragmentation is not a way to make delivery more reliable.

B4.8 DF and Path MTU Discovery

  • DF = 0: the router may fragment. The destination must reassemble.
  • DF = 1: the router drops the oversized packet and normally reports ICMP “fragmentation needed”.
  • Path MTU Discovery uses that ICMP feedback, so the sender learns to send packets that fit. If the feedback is blocked, small pings work but large transfers fail.
  • A tunnel adds headers (for example 100 bytes). A 1500-byte inner packet becomes 1600 bytes and does not fit an MTU of 1500. The fix is to send 1400-byte inner packets.
Each router on the path reassembles the fragments before it forwards them.

False. Only the final destination reassembles. Routers forward each fragment on its own.

False. It counts units of 8 bytes. An offset of 60 means byte 60×8=48060 \times 8 = 480.

False. The datagram arrives only if every fragment arrives, so more fragments mean a lower chance: (1−p)n(1-p)^n.

B5. ICMP, Ping and Traceroute

B5.1 ICMP

ICMP (Internet Control Message Protocol) carries control and error messages inside IP packets. It reports problems. It does not repair them.

Message Meaning Example
Echo Request / Echo Reply Testing reachability ping
Destination Unreachable The packet could not be delivered No route; or fragmentation needed with DF = 1
Time Exceeded TTL reached 0 at a router traceroute uses this

B5.2 What ping tells you

  • A reply proves that ICMP worked for that probe. It does not prove that the application (for example the website) works.
  • A timeout only says that no reply came in time. It does not tell you the cause. Possible causes: a wrong gateway, a missing route on a router, a firewall rule, a wrong address or gateway on the server, or a server that is set not to answer pings.
  • DNS is not needed when you ping a numeric address.
  • In the output, time = the round-trip time, and TTL = the TTL left in the reply.

B5.3 TTL

TTL (Time To Live) is an IPv4 header field that limits how many routers a packet can pass. Each router decreases TTL by 1. When TTL reaches 0, the router discards the packet and normally sends ICMP Time Exceeded back to the source. This stops a packet from going round a routing loop for ever.

B5.4 How traceroute works

traceroute (tracert on Windows) sends probes with TTL = 1, then 2, then 3, and so on.

  • The TTL = 1 probe dies at the 1st router, which replies with Time Exceeded. Now we know router 1.
  • The TTL = 2 probe dies at the 2nd router. Now we know router 2.
  • This continues until a probe reaches the destination, which sends an Echo Reply.

Reading the output: each row is one hop. The three times are the round-trip times of three probes. Then comes the address of the router interface that replied.

  • A * means that no reply arrived before the timeout. The router may still forward traffic normally. (Many routers do not answer probes.)
  • Traceroute combines the replies to different probes. It is not one packet that reports its whole journey. Different probes can take different paths.

B5.5 Why the reverse trace shows different addresses

A router has several interfaces, each with its own IP address. In these questions, assume a router replies with the interface towards the source. So the same router shows a different address in the trace from A to B and in the trace from B to A.

B6. Rebuilding a Topology from Traceroutes

B6.1 Method

  1. For each trace, write the source, every hop in order, and the destination.
  2. The last line of a trace is the destination host. The first line is the source’s gateway (the interface on the source’s LAN).
  3. Group addresses by network (use the given masks). Two addresses on the same network are the two ends of one link, or two interfaces on one LAN.
  4. Find addresses that belong to the same router. Remember that a router replies with its interface towards the source, so the same router shows a different address in each direction.
  5. Draw one diagram that explains every trace. If masks are missing, state your assumption. Traces alone may not give one unique answer.

Common Traps

  • Host decision: AND the destination with its own mask. Local: ARP the destination. Remote: ARP the gateway.
  • Remote frames: the Ethernet destination is the gateway’s MAC, but the IP destination is still the final host.
  • What changes per hop: the MAC addresses change on every hop, and TTL decreases by 1 with a new checksum. IP addresses stay the same (no NAT).
  • ARP: the request is an Ethernet broadcast and the reply is a unicast. Routers never forward ARP.
  • Switch: it learns from the source MAC, forwards on the destination MAC, and floods broadcasts and unknown destinations.
  • One LAN at a time: a station sees only the frames on its own LAN.
  • Longest-prefix match: check that the entry matches first, then take the largest /n. The default route /0 is the last choice.
  • MTU counts the IP header and data, not the Ethernet header.
  • Fragments: data per fragment is a multiple of 8 (except the last). Offset = start byte / 8. Last MF = 0. Same ID in all. A fragment can be fragmented again. Reassembly happens only at the destination.
  • Read the size: check whether a size is the Total Length or the data length before you subtract the header.
  • Loss: P(all fragments arrive)=(1−p)nP(\text{all fragments arrive}) = (1-p)^n. One lost fragment loses the whole datagram.
  • Ping: a reply proves ICMP works, not that the application works. A timeout does not tell you the cause.
  • Traceroute: a router replies with the interface towards the source. * does not mean the router is broken.
