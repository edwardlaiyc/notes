The finals revision playbook for Part II, organised by the learning objectives in the lecturer’s revision guide. Each objective gives the facts that MCQs test, the calculation or trace method, and a model short answer where the paper asks you to explain.

Scope. Lectures 2, 3 and 4 and their tutorials are fully examinable. Lecture 5 is limited to five areas (Section 5). Lecture 1 is the overview that connects them. The live-lecture material is not directly examinable.

Format. Multiple-choice questions on the OMR sheet, plus short structured answers written into tables on the paper. Some answer spaces are deliberately small.

  • State the result or mechanism first, then the reasoning the question asks for.
  • Read each question’s assumptions and apply the course model (for example the Tahoe/Reno rules, or the lecture model for counting TCP segments).
  • Give the mechanism and its purpose in a few precise sentences. Exact slide wording is not needed.
  • Practise with changed values: the worked examples on this page use fresh numbers.

1. Lecture 2: IP

1.1 Prefixes, masks, subnet ranges and VLSM

Fact Detail
Address 32 bits, names an interface. A router has one address per interface, each from the subnet on that side
Mask /n nn ones then zeros, one unbroken run. Valid octets: 128, 192, 224, 240, 248, 252, 254, 255
Network / broadcast Host bits all 0 (address AND mask) / all 1 (address OR inverted mask). Usable =2h−2= 2^h - 2
Block size B=256−B = 256 - mask octet. Blocks start at multiples of BB
Private blocks 10/8, 172.16/12, 192.168/16. Not routed on the Internet
Classes (recognise only) A 0 (/8), B 10 (/16), C 110 (/24), D multicast, E reserved. Always use the given prefix
Subnets Separate subnets need routing between them. Restricting access needs a separate policy, such as filtering

Range of an address. Example: 192.168.50.170/27. Mask 255.255.255.224, B=32B = 32. 170 lies in 160–191: network 192.168.50.160, broadcast 192.168.50.191, usable .161–.190 (30 hosts).

Smallest subnet holding two addresses (“minimum subnet mask” = longest shared prefix). Example: 40.12.172.9 and 40.12.190.200. 172=10101100172 = 1010\,1100, 190=10111110190 = 1011\,1110: 3 bits match, so /19, mask 255.255.224.0, subnet 40.12.160.0/19. Reject any option that is not a valid mask (255.128.255.0).

Which block is wrong? The start octet must be a multiple of BB. 172.20.80.0/19: B=32B = 32, 80/32=2.580/32 = 2.5, so not a network address. 172.20.96.0/19 and 172.20.48.0/20 are fine.

Subnets of N hosts inside a block. 150.10.64.0/19, subnets of up to 1000 hosts: 210−2=1022≥10002^{10} - 2 = 1022 \ge 1000, so /22 (255.255.252.0); 222−19=82^{22-19} = 8 subnets; the last subnet ends where the parent ends, broadcast 150.10.95.255. Add 1 for a router interface if the LAN has one; it matters only at a boundary.

VLSM recipe.

  1. List every segment: each LAN (hosts + router interface) and each router-to-router link (/30).
  2. Smallest hh with 2h−2≥2^h - 2 \ge count. Add the block sizes; the total must fit the parent.
  3. Fixed blocks first: a given host address, an existing block, or a reserved block.
  4. Then largest first, each block on a multiple of its own size, no overlaps.
  5. Router interfaces take usable addresses in their subnet, never a host’s address.

Example with a reserved block. Parent 172.30.40.0/22 (40–43). A /23, B /24, C /26. Reserved 172.30.41.0/26.

Subnet Candidates Rejected Chosen
A /23 40.0/23, 42.0/23 40.0/23 holds the reserved block 172.30.42.0/23
B /24 40.0/24, 41.0/24 41.0/24 holds the reserved block 172.30.40.0/24
C /26 41.0, 41.64, 41.128, 41.192 41.0/26 is reserved 172.30.41.64/26

Example with links and a fixed host. 192.168.8.0/24. LAN P 100 hosts, Q 50, R 20 (each + 1 router); 3 router links; a host in R is fixed at .70. Sizes: P /25, Q /26, R /27, links 3 × /30; total 236. R must hold .70: R = .64/27. P cannot be .0/25 (holds R): P = .128/25. Q = .0/26. Links .96/30, .100/30, .104/30. Router on R takes .65, not .70.

Model short answer. “Why can’t the two departments’ subnets stop them talking to each other?” Separate subnets only change which traffic is local; with working routes the router forwards packets between them. To restrict access, add a filtering policy on the router or a firewall.

1.2 Choosing the next hop

  • A host ANDs the destination with its own mask. Same network: deliver directly. Different: send to the default gateway.
  • A router uses longest-prefix match: keep the routes that contain the destination, choose the largest /n. 0.0.0.0/0 matches everything and is the last choice.

Example. Destination 203.0.113.80. Routes: 0.0.0.0/0 → R1, 203.0.0.0/16 → R2, 203.0.113.0/24 → R3, 203.0.113.128/26 → R4. The /26 covers only .128–.191, so it does not match. Answer R3 (/24).

1.3 ARP, and the IP destination against the next-hop MAC

Fact Detail
ARP Finds the MAC of the local next hop. Request = Ethernet broadcast; reply = unicast. Routers never forward it
Remote destination ARP for the gateway. Ethernet destination = gateway MAC; IP destination = final host
Per hop (no NAT) New frame and new MAC pair, TTL − 1, checksum recalculated. IP addresses unchanged
Switch Learns the source MAC and port; forwards on the destination; floods broadcast and unknown
Wrong mask A host that thinks a remote host is local ARPs for it; nobody answers, so delivery fails

Frame table for a ping.

  1. Local or remote? (AND with the sender’s mask.) The ARP target is the destination or the gateway.
  2. On the sender’s LAN: ARP request, ARP reply, ping request, ping reply.
  3. Through a switch: learn the source, flood the broadcast, then forward to one port.
  4. Through a router: it learns A’s MAC from A’s ARP request, ARPs for B on the far LAN, and sends a new frame. A never sees the far-LAN frames.
  5. Skip any ARP whose answer is already cached.

Example question. A host is 10.20.30.70/26 with gateway 10.20.30.65. It wants 10.20.30.140; its ARP cache is empty. Which IP does it ARP for? The host is in 10.20.30.64/26 (.64–.127); .140 is outside, so the next hop is the gateway: 10.20.30.65. Matching the first three octets does not mean the same subnet.

Model short answer. “A host must send through its gateway but has no ARP entry for it. What does it do, and why?” It broadcasts an ARP request for the gateway’s IPv4 address. The gateway replies with its MAC address, so the host can address a local Ethernet frame to the gateway.

1.4 Private addressing, NAT and IP settings

  • NAPT (PAT): outgoing, the gateway changes the source private IP:port to its public IP and a new port, and records the mapping. The reply comes to public IP:port, and the gateway restores the private IP:port. The server never sees the private address.
  • Two hosts can share one public address because they get different public ports.
  • MAC addresses change on every link; IP and port change only at the NAT device.
  • DHCP gives the address, mask, gateway and DNS server: Discover, Offer, Request, Ack. The client sends Discover and Request from 0.0.0.0 to 255.255.255.255.
  • ipconfig showing the same address as gateway, DHCP server and DNS server means one box does all three; a private host address means that box also does NAT.

NAT header table. One column per link crossing (request inside, request outside, reply outside, reply inside). MACs = the two interfaces on that link. The router replaces the request’s source IP:port and restores the reply’s destination IP:port.

Inside, request Outside, request Outside, reply Inside, reply
Source 192.168.50.170:51000 198.51.100.14:40001 203.0.113.80:80 203.0.113.80:80
Destination 203.0.113.80:80 203.0.113.80:80 198.51.100.14:40001 192.168.50.170:51000

1.5 Fragmentation

Fact Detail
Why A later link’s MTU (IP header + data) is smaller than the packet
Fields Same ID in every fragment. Offset in 8-byte units. MF = 1 except the last. Each fragment has its own header
Reassembly Only at the destination. One lost fragment loses the datagram: P=(1−p)nP = (1-p)^n
DF = 1 The router drops the packet and normally returns an ICMP error

Recipe.

data=Total Length−20,max data=8⌊MTU−208⌋,n=⌈datamax data⌉\text{data} = \text{Total Length} - 20, \qquad \text{max data} = 8\left\lfloor \frac{\text{MTU} - 20}{8} \right\rfloor, \qquad n = \left\lceil \frac{\text{data}}{\text{max data}} \right\rceil

Offset = start byte / 8. Total Length = data + 20. Check: data adds up, every length is at most the MTU, only the last has MF = 0.

Example. Total Length 2400, ID 5, MTU 820. Data 2380, max data 800.

Fragment Data Total Length ID MF Offset
1 800 820 5 1 0
2 800 820 5 1 100
3 780 800 5 0 200

Read whether the size is the payload or the Total Length. If the question gives “2000 bytes of payload”, data = 2000; do not subtract a header. Count only: a 4000-byte packet (header included) at MTU 1000 gives ⌈3980/976⌉=5\lceil 3980/976 \rceil = 5 fragments.

1.6 Ping and traceroute

Evidence What it does and does not establish
Ping reply The probe reached a responding host and a reply came back. Not that the web application works
Ping timeout No reply in time. It does not give the cause
TTL Each router subtracts 1; at 0 it drops the packet and normally sends ICMP Time Exceeded
Traceroute Separate probes with TTL 1, 2, 3, …; each row is one hop with three RTTs
* * * on a hop That router did not reply. Not a broken path if later hops reply
Reply address A router replies with its interface towards the source, so the reverse trace shows different addresses

Reverse traceroute. The forward trace lists one address on each network from the source’s LAN to the destination’s LAN. The reverse trace visits the same networks in reverse order, through the routers’ other interfaces, and ends at the source host. Example: forward A → B is 60.1.10.1/24, 130.5.32.9/22, 200.8.4.77/23 (B). A possible reverse is 200.8.5.1; 130.5.35.200; 60.1.10.20. An option with 130.5.36.x fails, because 36 is outside 32–35.

Topology from traceroutes. The last line of a trace is the destination host; the first is the source’s gateway. Each middle hop is a router interface on the network towards the previous hop. Two routers with replies on the same network share that link. Use the given masks, or classful ones only if told to.

2. Lecture 3: Routing

2.1 Forwarding against routing

  • Forwarding: one table lookup per packet to choose the next hop. Routing: learning and selecting the routes that fill the table.
  • Routes come from directly connected networks, static configuration, or routing protocols. Manual routes suit a small, stable network only.
  • Inside an AS: RIP or OSPF. Between ASes: BGP, which exchanges reachability subject to each operator’s policy.

2.2 Distance vector (RIP)

dX(dest)=minN[cost(X→N)+dN(dest)]d_X(\text{dest}) = \min_N\big[\text{cost}(X \to N) + d_N(\text{dest})\big]

The next hop is the NN that gives the minimum. Use the link cost given (1 in plain RIP). Ignore your old table; your own entry is 0.

Example. X’s link costs: Y = 2, Z = 5, W = 1. Vectors in the order (X, Y, Z, W, P, Q): Y (2, 0, 3, 4, 6, 2), Z (5, 3, 0, 2, 1, 4), W (1, 4, 2, 0, 6, 7).

Dest Via Y (+2) Via Z (+5) Via W (+1) Best Next hop
Y 2 8 5 2 Y
Z 5 5 3 3 W
W 6 7 1 1 W
P 8 6 7 6 Z
Q 4 9 8 4 Y

The direct link to Z (5) loses to the path through W (3). If a neighbour’s report rises, recompute: the route switches to whichever neighbour now gives the minimum.

Fact Detail
RIP metric Hops; 16 = unreachable, so routes longer than 15 cannot be represented
Count to infinity Vectors carry no path, so after a failure two routers can each believe the other still has a route; packets loop and the distances climb
Poisoned reverse If a neighbour is my next hop for a destination, I tell it the destination is unreachable (16), even while the route works. Stops two-router loops only
Convergence Reaching consistent choices after a change. Not instantaneous

Model short answer. “Why does poisoned reverse stop the two-router loop?” B reaches Net1 through A, so B always tells A that Net1 is unreachable. When A’s own link fails, A does not mistake B for another route, so the two routers cannot count up through each other.

2.3 Link state (OSPF) and Dijkstra

  • Hello finds neighbours → each router describes its links in an LSA → LSAs are flooded through the area → every router builds the same LSDB (map) → each runs Dijkstra from its own position, so the tables differ.
  • After a failure: detect it, flood updated LSAs, update the map, rerun Dijkstra. Equal-cost paths can both be used.

Dijkstra recipe. Columns: settled set, then D(v)D(v), predecessor for each node. Settle the smallest tentative cost; update its neighbours if D(w)+c(w,v)D(w) + c(w, v) is smaller; repeat. Read paths back through predecessors. The next hop is the first router after the source.

Example. Links A–B 2, A–C 5, B–C 2, B–D 6, C–D 3, C–E 7, D–E 1, D–F 8, E–F 2. Source A.

Step Settled B C D E F
0 A 2, A 5, A ∞ ∞ ∞
1 A B 4, B 8, B ∞ ∞
2 A B C 7, C 11, C ∞
3 A B C D 8, D 15, D
4 A B C D E 10, E

Route to F: A–B–C–D–E–F, cost 10, next hop B. The direct link A–C (5) loses to A–B–C (4).

2.4 RIP against OSPF

RIP (distance vector) OSPF (link state)
Information Distances to destinations, from neighbours Links and costs, flooded through the area
Calculation Add the link cost to the neighbour’s distance Dijkstra on the shared map
Metric in our examples Hop count; 16 = unreachable Configured link cost, often from bandwidth
After a failure Stale reports can loop and count to infinity Flood the changed links and recalculate
Path chosen Fewest hops Lowest total cost

Justify a choice from the network’s needs: for example, RIP cannot represent a route longer than 15 hops as reachable.

2.5 BGP

Fact Detail
AS Networks under one routing administration. BGP advertises prefixes with their AS paths (path vector), over TCP
eBGP / iBGP Between ASes / inside one AS, to share selected external routes
Selection (course rule) Reject a path holding your own ASN. Highest local preference first. Then the shortest AS path
Advertising Prepend your own ASN. Export policy decides what goes to which neighbour
Transit A multihomed campus that re-advertises one provider’s routes to another may attract transit traffic. Export policy should match the service it intends to offer
Hijack A false, more specific prefix wins by longest-prefix match. RPKI checks the origin AS, not the whole path

Example. Route 1: AS path 64501 64503 64510, local preference 150. Route 2: 64502 64510, local preference 100. Route 1 wins: local preference is compared before path length, and a shorter AS path does not guarantee lower delay.

BGP table. For each prefix, one row per neighbour that can supply it: next hop = that neighbour’s address on the shared link, AS path starting with the neighbour’s ASN. Mark the preferred row. Leave out your own prefix.

3. Lecture 4: Transport

3.1 Ports and choosing TCP or UDP

  • IP Protocol field picks the transport (1 ICMP, 6 TCP, 17 UDP); the port picks the application endpoint. Ports are 16 bits; well-known 0–1023 (DNS 53, HTTP 80, HTTPS 443). An ephemeral port such as 58888 needs no registration.
  • A TCP connection is identified by source IP and port, destination IP and port. NAT changes the values seen on the public side.
TCP UDP
Delivery Reliable, ordered byte stream Datagrams; no guarantee of delivery or order
Set-up Connection before data None
Loss and rate Retransmission, flow and congestion control Anything extra comes from the application

Model short answer. “Should a live voice call use TCP or UDP?” UDP. Voice is only useful before its playback time; TCP would hold later audio while it resends a lost packet, so the call stalls. With UDP the application skips the lost packet and keeps playing. A file transfer needs complete data, so it uses TCP.

3.2 Headers and MSS

Header Size Contains
IPv4 20 bytes without options Addresses, Protocol, TTL, fragmentation fields
TCP 20 bytes minimum (up to 60) Ports, SN, AN, flags, advertised window, checksum
UDP 8 bytes Ports, length, checksum

MSS=MTU−20−20\text{MSS} = \text{MTU} - 20 - 20; with MTU 1500, MSS = 1460 bytes of TCP data. MSS limits one segment’s data; the window limits outstanding data across segments. Use the sizes the question gives.

3.3 Sequence and acknowledgement numbers

next SN=SN+data bytes(+1 for SYN)(+1 for FIN),AN=next byte expected\text{next SN} = \text{SN} + \text{data bytes}\ (+1 \text{ for SYN})\ (+1 \text{ for FIN}), \qquad \text{AN} = \text{next byte expected}

  • Setup: SYN (ISN), SYN+ACK (own ISN, AN = ISN + 1), ACK. First data bytes are ISN + 1 on each side.
  • Data: 600 bytes from SN 3401 occupy 3401–4000; the reply is AN = 4001.
  • Close: each direction closes separately with a FIN; each FIN uses one number; a pure ACK uses none. FIN+ACK, ACK, FIN+ACK, ACK; the middle two can combine.

Time-sequence diagram (fill the letters). SN counts the sender’s own bytes; AN counts the other side’s. A segment acknowledges only what had arrived when it left. After a loss, the receiver keeps sending the AN of the first missing byte; the sender’s SNs still move on.

3.4 Loss detection and retransmission

Signal What happens
Timeout The oldest unacknowledged data is not acknowledged before the RTO; the sender resends it. RTO = smoothed RTT plus a margin. Too short: needless resends; too long: slow recovery
Three duplicate ACKs Later segments arrive while a gap remains, so the receiver repeats the same AN. After the third duplicate (four ACKs with that AN), fast retransmit resends the missing segment
Loss near the end Too few later segments to make duplicates: recovery waits for the timeout
Head-of-line blocking Bytes after a gap wait in the buffer until the gap fills

Only the TCP endpoints recover data. Routers do not retransmit TCP segments.

Example. 100-byte segments from 3001; 3101 is lost; 3201, 3301, 3401 arrive. ACKs: 3101, then 3101 three more times; the sender resends 3101; the receiver then sends AN = 3501.

3.5 Flow control against congestion control

Flow control Congestion control
Protects the receiver: unread data fills its buffer Protects the network: traffic builds up in queues
Receiver advertises rwnd (bytes) Sender adjusts cwnd (MSS units in this course)

limit=min⁡(rwnd,cwnd×MSS),new data=limit−outstanding\text{limit} = \min(\text{rwnd},\ \text{cwnd} \times \text{MSS}), \qquad \text{new data} = \text{limit} - \text{outstanding}

Example. MSS 1000, cwnd 6 MSS, rwnd 4500, 2500 bytes outstanding. Limit = min(4500, 6000) = 4500; new data = 2000 bytes (two full segments). The sender cannot ignore a small rwnd because the network is uncongested.

Window right edge = AN + rwnd − 1; it can move left. Acknowledged does not mean read.

3.6 Congestion window: the course’s Tahoe/Reno rules

  • Slow start: double cwnd each round, capped at ssthresh.
  • Congestion avoidance: +1 MSS per round.
  • After a loss indication: ssthresh = ⌊cwnd / 2⌋.
Event Tahoe Reno
Timeout cwnd = 1 MSS cwnd = 1 MSS
Three duplicate ACKs cwnd = 1 MSS After recovery, cwnd = ssthresh

Three duplicate ACKs show later data is still arriving, so Reno continues with a reduced window rather than restarting from 1.

Trace. Initial cwnd 1, ssthresh 6, three duplicate ACKs at the end of round 6 (Reno):

Round 1 2 3 4 5 6 7 8
cwnd 1 2 4 6 7 8 4 5

Round 4 stops at 6, not 8. After round 6, ssthresh = 4. A timeout instead would start round 7 at 1.

Reading a cwnd plot. Doubling = slow start (the round that reaches ssthresh is the last slow-start round). +1 per round = congestion avoidance, starting the next round. Drop to half = three duplicate ACKs (Reno); drop to 1 = timeout. ssthresh after a loss = ⌊cwnd just before the drop / 2⌋. Segment nn: add cwnd round by round; the first round whose running total reaches nn sends it (rounds 1, 2, 4, 8, 16, 17, 18 give totals 1, 3, 7, 15, 31, 48, 66, so segment 60 goes in round 7).

Time to recover. Count rounds, multiply by RTT. cwnd 16, RTT 200 ms, timeout: ssthresh 8; 1→2→4→81 \to 2 \to 4 \to 8 (3 rounds) then 8→168 \to 16 (8 rounds) = 11 rounds = 2.2 s. For two events in a row, apply the second event to the cwnd at that moment.

3.7 Throughput and transfer time

throughput≈min⁡(bottleneck,WRTT),time≈file sizethroughput\text{throughput} \approx \min\!\left(\text{bottleneck},\ \frac{W}{\text{RTT}}\right), \qquad \text{time} \approx \frac{\text{file size}}{\text{throughput}}

Example. W = 48,000 bytes, RTT 60 ms: 800,000 bytes/s = 6.4 Mbit/s, even on a 100 Mbit/s link. A 24 MB file takes 30 s. Assumes constant window and RTT, no loss, negligible start-up and headers.

Largest RTT for a deadline. RTT ≤ W / (file / time limit). A 2 GB file in 25 minutes with 20 segments of 1000 bytes: W = 20,000 bytes; required 1.333 × 10⁶ bytes/s; RTT ≤ 15 ms.

Watch bits against bytes (× 8) and decimal against binary units (10910^9 or 2302^{30}); state the convention.

Model short answer. “Why is a download slow on a 1 Gbit/s plan?” Throughput is limited by the effective window divided by the RTT, not only the access link. With a 65,535-byte window and a 200 ms RTT the sender moves at most about 2.6 Mbit/s, so a larger window or a shorter RTT is needed; loss and the bottleneck link also matter.

4. Lecture 5: HTTP and DNS (five areas only)

Not examinable: detailed HTTP message formats, recall of status codes, how HTTPS works inside, persistent connections and their timing, cookies, caching, CDNs, HTTP/2 and HTTP/3, and the DNS hierarchy, delegation, record types, registration and TTLs.

Area What to say
1. Role of DNS The browser asks a DNS resolver for the IP address of the hostname. DNS supplies the address, not the page. The query (UDP 53) needs delivery too, often through the gateway
2. HTTP over TCP TCP setup, then the HTTP request (GET /index.html) and the response on that connection. IP: hosts. TCP: ordered bytes to the endpoint. HTTP: which resource and how to read it. The gateway forwards (and NATs); it is not a TCP endpoint
3. GET, POST, HTTPS GET: form data in the URL query (can stay in history). POST: data in the body. Neither encrypts. HTTPS (HTTP over TLS, port 443) encrypts, protects integrity, normally authenticates the server
4. Loading a page ARP (local next hop) → DNS query and reply → SYN, SYN+ACK, ACK → HTTP GET → response. Skip what is cached
5. Name-resolution failure Name fails but the IP works: suspect DNS. A ping reply does not prove the web service works

Model short answer. “Why does a login form need HTTPS even though it uses POST?” POST only moves the password from the URL into the request body, which is still readable on the wire. HTTPS runs HTTP over TLS, which encrypts the exchange in transit and authenticates the server.

5. TRUE or FALSE: Statements That Keep Appearing

Statement Verdict
UDP suits online games and video calls; TCP suits email True
Distance vector uses Bellman–Ford; link state uses Dijkstra True
BGP is an inter-AS routing protocol (and runs over TCP) True

6. Common Traps

  • Count the router interface, align every block, and place fixed or reserved blocks first.
  • Longest prefix wins only if it matches. The default route is the last choice.
  • ARP the next hop. Remote destination: gateway MAC, final host’s IP.
  • Fragments: payload or Total Length? Round data down to a multiple of 8; offsets in 8-byte units.
  • Traceroute * is a silent router, not a broken path. Reverse traces show other interfaces.
  • Distance vector: add the link cost, ignore the old table. RIP 16 = unreachable.
  • BGP: local preference before AS-path length; reject your own ASN.
  • SN/AN: SYN and FIN +1, pure ACK +0; AN is the next byte expected.
  • Segment counts: stated assumptions first; otherwise the lecture model.
  • Two windows: convert cwnd to bytes; subtract what is outstanding.
  • Slow start stops at ssthresh; ssthresh rounds down; Reno halves only on three duplicate ACKs.
  • DNS gives an address, not the page; POST does not encrypt; ping does not prove HTTP.
  • Units: bits against bytes, 10910^9 against 2302^{30}, ms against s.
