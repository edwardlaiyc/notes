Sorting

Formal definition of sorting

Let a sequence of nn input elements be represented as records r1,r2,…,rnr_1, r_2, \dots, r_n, where each record rir_i is associated with an identifiable key value kik_i.

Goal: Find permutation s=(s1,…,sn)s = (s_1, \dots, s_n) such that ks1≤ks2≤…≤ksnk_{s_1} \le k_{s_2} \le \dots \le k_{s_n}.

The 2 primitives of sorting are (1) key comparisons and (2) swapping/shifting the records.

Sorting Categories & Goals

  • Internal: Data resides completely in RAM (focuses on CPU comparisons & cache-friendly shifts). Algorithms in this course (such as Insertion Sort, Quicksort, Mergesort) focus on internal sorting.
  • External: Data exceeds RAM, resides on disk (focuses on minimizing the slow I/O read/write operations).

Evaluating sorting

  1. Space complexity: Striving for in-place sorting, where the algorithm uses O(1)O(1) auxiliary memory.
  2. Time complexity: Minimizing CPU execution time on the 2 primitives.

Insertion sort

https://visualgo.net/en/sorting

The algorithm:

  1. The array is logically split into two parts: a sorted subarray on the left and an unsorted subarray on the right.
  2. At every step, we remove one element from the unsorted portion and insert it into the correct position within the sorted portion.
  3. The sorted prefix expands by 1 element per iteration while maintaining its sorted order at all times.

C++ implementation

class ALIST {
    KeyType key; // value compared to decide ordering
    DataType data; // data payload carried along with the key
};

void InsertionSort (ALIST slot[], int n)
{ // slot is an array of n records; assume n > 1;
    for (int i = 1; i < n; i++) {
        for (int j = i; j > 0; j--) {
            if (slot[j].key < slot[j-1].key)
                swap(slot[j], slot[j-1]);
            else
                break;
        }
    }
}
  • The outer loop starts at i=1i = 1, because a single element (slot[0]) is trivially sorted.
  • The outer loop (from i=1i = 1 to n−1n - 1) selects the element at slot[i] to be inserted into the sorted subarray slot[0 ... i-1].
  • The inner loop (from j=ij = i to 1) steps backward through the sorted prefix to find the correct insertion spot.
    • If slot[j].key < slot[j-1].key, they are out of order, so we swap them.
    • If slot[j].key >= slot[j-1].key, we break out of the inner loop since we know slot[0 ... j] is already sorted.

Proof of correctness using loop invariant

A loop invariant is essentially mathematical induction applied to algorithms. It is used to prove that a loop computes what it is designed to compute.

A loop invariant is a formal predicate or property PP about the program state that satisfies three requirements:

  1. Initialization: The property PP is true before the very first iteration of the loop (analogous to the base case).
  2. Maintenance: If the property PP is true before iteration ii of the loop, it remains true before iteration i+1i + 1 (analogous to the inductive step).
  3. Termination: When the loop terminates, the invariant provides a useful property that helps prove the algorithm is correct.

For insertion sort, a candidate for the loop invariant is:

“At the start of each iteration of the outermost loop, the subarray slot[0 : i] (the first ii elements, i.e., slot[0 … i-1]) comprises the elements originally in slot[0 : i], but in sorted order.”

We can prove this invariant holds true:

  • Initialization: Before iteration i=1i = 1, slot[0 ... 0] has 1 element ⟹\implies trivially sorted.
  • Maintenance: Inner loop bubbles slot[i] left until its correct relative position. After incrementing ii, slot[0 ... i-1] contains ii sorted elements.
  • Termination: Terminates at i=ni = n. By invariant, slot[0 ... n-1] is sorted ⟹\implies entire array of nn elements is sorted.
