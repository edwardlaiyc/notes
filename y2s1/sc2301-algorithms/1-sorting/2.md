# Sorting
## Formal definition of sorting
Let a sequence of $n$ input elements be represented as records $r_1, r_2, \dots, r_n$, where each record $r_i$ is associated with an identifiable key value $k_i$.

**Goal:** Find permutation $s = (s_1, \dots, s_n)$ such that $k_{s_1} \le k_{s_2} \le \dots \le k_{s_n}$.

The 2 primitives of sorting are (1) key comparisons and (2) swapping/shifting the records.

### Sorting Categories & Goals
- **Internal:** Data resides completely in RAM (focuses on CPU comparisons & cache-friendly shifts). Algorithms in this course (such as Insertion Sort, Quicksort, Mergesort) focus on internal sorting.
- **External:** Data exceeds RAM, resides on disk (focuses on minimizing the slow I/O read/write operations).

### Evaluating sorting
1. Space complexity: Striving for in-place sorting, where the algorithm uses $O(1)$ auxiliary memory.
2. Time complexity: Minimizing CPU execution time on the 2 primitives.

# Insertion sort
https://visualgo.net/en/sorting

### The algorithm:
1. The array is logically split into two parts: a sorted subarray on the left and an unsorted subarray on the right.
2. At every step, we remove one element from the unsorted portion and insert it into the correct position within the sorted portion.
3. The sorted prefix expands by 1 element per iteration while maintaining its sorted order at all times.

### C++ implementation
```cpp
class ALIST {
    KeyType key; // value compared to decide ordering
    DataType data; // data payload carried along with the key
};

void InsertionSort (ALIST slot[], int n)
{ // slot is an array of n records; assume n > 1;
    for (int i = 1; i < n; i++) {
        for (int j = i; j > 0; j--) {
            if (slot[j].key < slot[j-1].key)
                swap(slot[j], slot[j-1]);
            else
                break;
        }
    }
}
```
- The outer loop starts at $i = 1$, because a single element (`slot[0]`) is trivially sorted.
- The outer loop (from $i = 1$ to $n - 1$) selects the element at `slot[i]` to be inserted into the sorted subarray `slot[0 ... i-1]`.
- The inner loop (from $j = i$ to 1) steps backward through the sorted prefix to find the correct insertion spot.
  - If `slot[j].key < slot[j-1].key`, they are out of order, so we swap them.
  * If `slot[j].key >= slot[j-1].key`, we `break` out of the inner loop since we know `slot[0 ... j]` is already sorted.

### Proof of correctness using loop invariant
A loop invariant is essentially mathematical induction applied to algorithms. It is used to prove that a loop computes what it is designed to compute.

A loop invariant is a formal predicate or property $P$ about the program state that satisfies three requirements:

1. Initialization: The property $P$ is true before the very first iteration of the loop (analogous to the base case).
2. Maintenance: If the property $P$ is true before iteration $i$ of the loop, it remains true before iteration $i + 1$ (analogous to the inductive step).
3. Termination: When the loop terminates, the invariant provides a useful property that helps prove the algorithm is correct.
   
For insertion sort, a candidate for the loop invariant is:
> "At the start of each iteration of the outermost loop, the subarray slot[0 : i] (the first $i$ elements, i.e., slot[0 ... i-1]) comprises the elements originally in slot[0 : i], but in sorted order."
We can prove this invariant holds true:

* **Initialization:** Before iteration $i = 1$, `slot[0 ... 0]` has 1 element $\implies$ trivially sorted.
* **Maintenance:** Inner loop bubbles `slot[i]` left until its correct relative position. After incrementing $i$, `slot[0 ... i-1]` contains $i$ sorted elements.
* **Termination:** Terminates at $i = n$. By invariant, `slot[0 ... n-1]` is sorted $\implies$ entire array of $n$ elements is sorted.

### Complexity Analysis

| Case | Condition | Comparisons | Swaps | Time | Space |
| :--- | :--- | :---: | :---: | :---: | :---: |
| **Best** | Already sorted | $n - 1$ | $0$ | $\Theta(n)$ | $O(1)$ |
| **Worst** | Reverse sorted | $\sum_{i=1}^{n-1} i = \frac{n(n-1)}{2}$ | $\frac{n(n-1)}{2}$ | $\Theta(n^2)$ | $O(1)$ |
| **Average** | Random order | $\frac{1}{2}\sum_{i=1}^{n-1} (i+1) = \frac{(n-1)(n+2)}{4}$ | $\approx \frac{n^2}{4}$ | $\Theta(n^2)$ | $O(1)$ |

* **Average Case Derivation:** Each element $i$ needs uniform $\frac{1}{i}\sum_{j=1}^i j = \frac{i+1}{2}$ comparisons (travels halfway). Summing over $i \in [1, n-1]$ yields $\frac{n^2 + n - 2}{4} = \Theta(n^2)$.

### Strengths & Weaknesses

| Strengths | Weaknesses |
| :--- | :--- |
| $\Theta(n)$ on nearly sorted data or verification | $\Theta(n^2)$ worst/average runtime; poor scaling |
| $O(1)$ auxiliary space (in-place) | Elements placed lack global order; requires repeated shifting |
| Low overhead / small constants for tiny arrays ($n < 30$) | Shifting large records (e.g., 10MB structs) in arrays is expensive |
| Fast with linked lists ($O(1)$ pointer insertion, no shifts) | Poor cache performance when swapping large structs contiguously |
