1. Asymptotic Notation

Asymptotic analysis describes how the resource consumption of an algorithm grows as the input size nn approaches infinity. Constant multiplicative factors and lower-order terms are ignored. All running time functions are assumed to be non-negative (f(n)≥0f(n) \ge 0).

Key Proof Templates

1. Two-Way Θ\Theta-Bounding Proof (⇔\iff)

To prove that f(n)=Θ(g(n))f(n) = \Theta(g(n)) if and only if f(n)=O(g(n))f(n) = O(g(n)) and f(n)=Ω(g(n))f(n) = \Omega(g(n)):

  1. Forward Direction (⟹\implies):
    • By definition of Θ(g(n))\Theta(g(n)), there exist constants c1,c2,n0>0c_1, c_2, n_0 > 0 such that c1g(n)≤f(n)≤c2g(n)c_1 g(n) \le f(n) \le c_2 g(n) for all n≥n0n \ge n_0.
    • Selecting constants (c2,n0)(c_2, n_0) satisfies the definition of O(g(n))O(g(n)).
    • Selecting constants (c1,n0)(c_1, n_0) satisfies the definition of Ω(g(n))\Omega(g(n)).
  2. Reverse Direction (⟸\impliedby):
    • If f(n)∈O(g(n))f(n) \in O(g(n)), there exist constants c4,n2>0c_4, n_2 > 0 such that f(n)≤c4g(n)f(n) \le c_4 g(n) for all n≥n2n \ge n_2.
    • If f(n)∈Ω(g(n))f(n) \in \Omega(g(n)), there exist constants c3,n1>0c_3, n_1 > 0 such that c3g(n)≤f(n)c_3 g(n) \le f(n) for all n≥n1n \ge n_1.
    • Set n3=max⁡(n1,n2)n_3 = \max(n_1, n_2) to merge the valid domains.
    • For all n≥n3n \ge n_3, the compound inequality c3g(n)≤f(n)≤c4g(n)c_3 g(n) \le f(n) \le c_4 g(n) holds, which proves that f(n)∈Θ(g(n))f(n) \in \Theta(g(n)).

2. Proving Two Functions Cannot Be Compared

We show that neither function bounds the other by using a function that alternates between odd and even inputs: f(n)=n,g(n)={1if n is evenn2if n is oddf(n) = n, \quad g(n) = \begin{cases} 1 & \text{if } n \text{ is even} \\ n^2 & \text{if } n \text{ is odd} \end{cases}

  1. Proof that f(n)∉O(g(n))f(n) \notin O(g(n)):
    • Assume for contradiction that f(n)∈O(g(n))f(n) \in O(g(n)), which implies n≤c⋅g(n)n \le c \cdot g(n) for all n≥n1n \ge n_1.
    • Choose an even integer n2n_2 such that n2>max⁡(n1,c)n_2 > \max(n_1, c).
    • For even integers, g(n2)=1g(n_2) = 1, leading to n2≤cn_2 \le c, which directly contradicts n2>cn_2 > c.
  2. Proof that g(n)∉O(f(n))g(n) \notin O(f(n)):
    • Assume for contradiction that g(n)∈O(f(n))g(n) \in O(f(n)), which implies g(n)≤c′⋅ng(n) \le c' \cdot n for all n≥n1′n \ge n_1'.
    • Choose an odd integer n2′n_2' such that n2′n_2' > max⁡(n1′,c′)\max(n_1', c').
    • For odd integers, g(n2′)=(n2′)2g(n_2') = (n_2')^2, leading to (n2′)2≤c′⋅n2′⟹n2′≤c′(n_2')^2 \le c' \cdot n_2' \implies n_2' \le c', which directly contradicts n2′>c′n_2' > c'.

2. Insertion Sort

Insertion Sort keeps a sorted section on the left side of the array and inserts items from the unsorted right side one by one into their correct places.

Canonical Implementation

void InsertionSort(ALIST slot[], int n) {
    for (int i = 1; i < n; i++) {
        for (int j = i; j > 0; j--) {
            if (slot[j].key < slot[j-1].key) {
                swap(slot[j], slot[j-1]);
            } else {
                break; // Target position found; slot[0 ... i] is sorted
            }
        }
    }
}

Complexity Breakdown

  • Best-Case Time: Θ(n)\Theta(n). This occurs when the array is already sorted, performing exactly n−1n - 1 key comparisons and 00 swaps.
  • Worst-Case Time: Θ(n2)\Theta(n^2). This occurs when the array is reverse sorted, performing ∑i=1n−1i=n(n−1)2\sum_{i=1}^{n-1} i = \frac{n(n - 1)}{2} comparisons and swaps.
  • Average-Case Time: Θ(n2)\Theta(n^2). Assuming all permutations are equally likely, an element moves halfway through the prefix on average, requiring n2+n−24\frac{n^2 + n - 2}{4} comparisons.
  • Auxiliary Space: O(1)O(1) (in-place).
  • Stability: Stable. Equal elements stop moving when compared via the < operator, preserving their original input order.

Invariants & Proof Templates

1. Loop Invariant for Array Sorting

  • Invariant Statement: At the start of each iteration of the outer loop, subarray slot[0 ... i-1] contains the original elements from those indices, but rearranged in fully sorted order.
  • Initialization: Prior to the first iteration (i=1i = 1), slot[0 ... 0] contains a single element, which is trivially sorted.
  • Maintenance: The inner loop shifts elements that are strictly greater than slot[i] one position to the right. When the loop halts, slot[i] is placed such that slot[0 ... i] is sorted. Incrementing ii preserves the invariant for the next outer iteration.
  • Termination: The loop terminates when i=ni = n. Substituting i=ni = n into the invariant establishes that slot[0 ... n-1] contains all original elements in sorted order.

2. Loop Invariant for Boolean Flags (Primality Test Example)

  • Invariant Statement: The boolean variable pp remains True if and only if there is no integer k∈[2,i−1]k \in [2, i-1] that divides nn.
  • Initialization: At i=2i = 2, the candidate range [2,1][2, 1] is empty, so no divisor exists and p=Truep = \text{True}.
  • Maintenance: If ii divides nn, pp becomes False, which correctly indicates that a divisor exists in [2,i][2, i]. If ii does not divide nn, pp retains its previous value, correctly extending the property to [2,i][2, i].
  • Termination: The loop terminates when i=⌊n⌋+1i = \lfloor\sqrt{n}\rfloor + 1. The variable pp is True if and only if no integer in [2,⌊n⌋][2, \lfloor\sqrt{n}\rfloor] divides nn, confirming that nn is prime.

Important Exam Mechanics

Comparison vs. Swap Counts in the Worst Case

  • The worst-case comparison count of n(n−1)2\frac{n(n-1)}{2} does not require the input to be strictly reversed.
  • Any arrangement where the ii-th element must be compared against all i−1i-1 preceding elements reaches the maximum comparison count.
  • Example: [n,n−1,…,3,1,2][n, n-1, \dots, 3, 1, 2] incurs maximum comparisons because the final element compares against all items, even if it does not trigger a swap on every step.

Behavior on Duplicate Elements

  • In the inner loop condition slot[j].key < slot[j-1].key, comparing two identical keys evaluates to false.
  • A duplicate key triggers the else break; statement immediately, requiring 1 comparison and 0 swaps to stay in place.

Steady Progress Under Interruption

  • Every swap executed by Insertion Sort eliminates exactly one out-of-order pair.
  • If the algorithm stops early, the total number of out-of-order pairs never increases.
  • Restarting Insertion Sort on a partially sorted array always makes forward progress toward complete sortedness.

3. Mergesort

Mergesort splits the array into two equal halves, sorts each half recursively, and merges the two sorted halves into one sorted array.

Canonical Implementation

void mergesort(ALIST slot[], int n, int m) {
    int mid = (n + m) / 2;
    if (m - n <= 0) {
        return; // Base case: 0 or 1 element
    } else if (m - n > 1) {
        // Optimization: skip recursion if subproblem size is exactly 2
        mergesort(slot, n, mid);
        mergesort(slot, mid + 1, m);
    }
    merge(slot, n, m);
}

In-Place merge() Procedure

void merge(ALIST slot[], int n, int m) {
    int mid = (n + m) / 2;
    int a = n;
    int b = mid + 1;

    while (a <= mid && b <= m) {
        if (slot[a].key < slot[b].key) {
            a++;
        } else if (slot[a].key > slot[b].key) {
            ALIST temp = slot[b];
            for (int k = mid; k >= a; k--) {
                slot[k + 1] = slot[k];
            }
            slot[a] = temp;
            a++;
            mid++;
            b++;
        } else {
            ALIST temp = slot[b];
            for (int k = mid; k >= a + 1; k--) {
                slot[k + 1] = slot[k];
            }
            slot[a + 1] = temp;
            a += 2;
            mid++;
            b++;
        }
    }
}

1. Derivation of Worst-Case Comparisons (n=2kn = 2^k)

When merging two subarrays of total length nn, each comparison places at least one element into its final position. The last comparison places two elements simultaneously, requiring at most n−1n - 1 comparisons.

Expanding the recurrence W(n)=2W(n/2)+n−1W(n) = 2W(n/2) + n - 1 by substitution: W(2k)=2W(2k−1)+2k−1=22W(2k−2)+(2k−2)+(2k−1)=2kW(1)+∑j=1k2k−∑i=0k−12i=0+k⋅2k−(2k−1)=nlg⁡n−n+1\begin{aligned} W(2^k) &= 2W(2^{k-1}) + 2^k - 1 \\ &= 2^2 W(2^{k-2}) + (2^k - 2) + (2^k - 1) \\ &= 2^k W(1) + \sum_{j=1}^k 2^k - \sum_{i=0}^{k-1} 2^i \\ &= 0 + k \cdot 2^k - (2^k - 1) \\ &= n \lg n - n + 1 \end{aligned}

2. Derivation of Best-Case Comparisons

The best case occurs when all elements in one subarray are strictly smaller than all elements in the other subarray. The merge loop finishes as soon as the first subarray is exhausted, requiring only ⌊n/2⌋\lfloor n/2 \rfloor comparisons.

Common Exam Problems & Algorithms

1. Finding Min and Max Together in 1.5n−21.5n - 2 Comparisons

When finding both the minimum and maximum of an array, comparing elements in pairs at the base level reduces the total work: W(n)=2W(n/2)+2,with W(2)=1W(n) = 2W(n/2) + 2, \quad \text{with } W(2) = 1 Expanding the recurrence for n=2kn = 2^k: W(n)=2k−1W(2)+2(2k−1−1)=n2+2(n2−1)=32n−2W(n) = 2^{k-1}W(2) + 2(2^{k-1} - 1) = \frac{n}{2} + 2\left(\frac{n}{2} - 1\right) = \frac{3}{2}n - 2 This takes about 1.5n1.5n comparisons, saving 25%25\% over the standard 2n−22n - 2 scan that checks elements one by one.

2. Checking for Duplicate Elements in an Array

  • General Method Using Comparisons: Sort the array using Mergesort in Θ(nlog⁡n)\Theta(n \log n) time. Make one linear pass (Θ(n)\Theta(n)) across the array to check if any two neighbor elements are equal (A[i] == A[i-1]). The total running time is Θ(nlog⁡n)\Theta(n \log n).
  • Faster Method for Small Integers (11 to 2n2n): If elements are integers within a known range like 11 to 2n2n, do not use comparison sorting. Create a count array of size 2n2n filled with zeros. Walk through the array once and increment the count for each number, stopping immediately if any count hits 22. This finds duplicates in Θ(n)\Theta(n) time using O(n)O(n) extra space.
