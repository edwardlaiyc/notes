## 1. Asymptotic Notation

Asymptotic analysis describes how the resource consumption of an algorithm grows as the input size $n$ approaches infinity. Constant multiplicative factors and lower-order terms are ignored. All running time functions are assumed to be non-negative ($f(n) \ge 0$).

### Core Mathematical Definitions

| Notation | Formal Definition | Intuition | Limit Test ($L = \lim_{n \to \infty} \frac{f(n)}{g(n)}$) |
| :--- | :--- | :---: | :---: |
| **$f(n) \in O(g(n))$** | $\exists\, c > 0, n_0 > 0 \text{ such that } 0 \le f(n) \le c \cdot g(n), \; \forall n \ge n_0$ | Upper bound ($\le$) | $L < \infty$ |
| **$f(n) \in \Omega(g(n))$** | $\exists\, c > 0, n_0 > 0 \text{ such that } 0 \le c \cdot g(n) \le f(n), \; \forall n \ge n_0$ | Lower bound ($\ge$) | $L > 0$ or $L = \infty$ |
| **$f(n) \in \Theta(g(n))$** | $\exists\, c_1, c_2, n_0 > 0 \text{ such that } 0 \le c_1 g(n) \le f(n) \le c_2 g(n), \; \forall n \ge n_0$ | Tight bound ($=$) | $0 < L < \infty$ |
| **$f(n) \in o(g(n))$** | $\forall\, c > 0, \exists\, n_0 > 0 \text{ such that } 0 \le f(n) < c \cdot g(n), \; \forall n \ge n_0$ | Strictly slower ($<$) | $L = 0$ |
| **$f(n) \in \omega(g(n))$** | $\forall\, c > 0, \exists\, n_0 > 0 \text{ such that } 0 \le c \cdot g(n) < f(n), \; \forall n \ge n_0$ | Strictly faster ($>$) | $L = \infty$ |

- **Quantifier Distinction:** Big bounds ($O, \Omega, \Theta$) require the condition to hold for at least one positive constant ($c$). Little bounds ($o, \omega$) must hold for all chosen positive constants ($c$).
- **Limit Test Fallback:** The limit test is a one-way test. If the ratio $f(n)/g(n)$ oscillates without a limit, you must prove the relationship using the formal inequality definition directly.

### Key Proof Templates

#### 1. Two-Way $\Theta$-Bounding Proof ($\iff$)
To prove that $f(n) = \Theta(g(n))$ if and only if $f(n) = O(g(n))$ and $f(n) = \Omega(g(n))$:
1. **Forward Direction ($\implies$):**
   - By definition of $\Theta(g(n))$, there exist constants $c_1, c_2, n_0 > 0$ such that $c_1 g(n) \le f(n) \le c_2 g(n)$ for all $n \ge n_0$.
   - Selecting constants $(c_2, n_0)$ satisfies the definition of $O(g(n))$.
   - Selecting constants $(c_1, n_0)$ satisfies the definition of $\Omega(g(n))$.
2. **Reverse Direction ($\impliedby$):**
   - If $f(n) \in O(g(n))$, there exist constants $c_4, n_2 > 0$ such that $f(n) \le c_4 g(n)$ for all $n \ge n_2$.
   - If $f(n) \in \Omega(g(n))$, there exist constants $c_3, n_1 > 0$ such that $c_3 g(n) \le f(n)$ for all $n \ge n_1$.
   - Set $n_3 = \max(n_1, n_2)$ to merge the valid domains.
   - For all $n \ge n_3$, the compound inequality $c_3 g(n) \le f(n) \le c_4 g(n)$ holds, which proves that $f(n) \in \Theta(g(n))$.

#### 2. Proving Two Functions Cannot Be Compared
We show that neither function bounds the other by using a function that alternates between odd and even inputs:
$$f(n) = n, \quad g(n) = \begin{cases} 1 & \text{if } n \text{ is even} \\ n^2 & \text{if } n \text{ is odd} \end{cases}$$
1. **Proof that $f(n) \notin O(g(n))$:**
   - Assume for contradiction that $f(n) \in O(g(n))$, which implies $n \le c \cdot g(n)$ for all $n \ge n_1$.
   - Choose an even integer $n_2$ such that $n_2 > \max(n_1, c)$.
   - For even integers, $g(n_2) = 1$, leading to $n_2 \le c$, which directly contradicts $n_2 > c$.
2. **Proof that $g(n) \notin O(f(n))$:**
   - Assume for contradiction that $g(n) \in O(f(n))$, which implies $g(n) \le c' \cdot n$ for all $n \ge n_1'$.
   - Choose an odd integer $n_2'$ such that $n_2'$ > $\max(n_1', c')$.
   - For odd integers, $g(n_2') = (n_2')^2$, leading to $(n_2')^2 \le c' \cdot n_2' \implies n_2' \le c'$, which directly contradicts $n_2' > c'$.

## 2. Insertion Sort

Insertion Sort keeps a sorted section on the left side of the array and inserts items from the unsorted right side one by one into their correct places.

### Canonical Implementation

    void InsertionSort(ALIST slot[], int n) {
        for (int i = 1; i < n; i++) {
            for (int j = i; j > 0; j--) {
                if (slot[j].key < slot[j-1].key) {
                    swap(slot[j], slot[j-1]);
                } else {
                    break; // Target position found; slot[0 ... i] is sorted
                }
            }
        }
    }

### Complexity Breakdown
- **Best-Case Time:** $\Theta(n)$. This occurs when the array is already sorted, performing exactly $n - 1$ key comparisons and $0$ swaps.
- **Worst-Case Time:** $\Theta(n^2)$. This occurs when the array is reverse sorted, performing $\sum_{i=1}^{n-1} i = \frac{n(n - 1)}{2}$ comparisons and swaps.
- **Average-Case Time:** $\Theta(n^2)$. Assuming all permutations are equally likely, an element moves halfway through the prefix on average, requiring $\frac{n^2 + n - 2}{4}$ comparisons.
- **Auxiliary Space:** $O(1)$ (in-place).
- **Stability:** **Stable**. Equal elements stop moving when compared via the `<` operator, preserving their original input order.

---

### Invariants & Proof Templates

#### 1. Loop Invariant for Array Sorting
- **Invariant Statement:** At the start of each iteration of the outer loop, subarray `slot[0 ... i-1]` contains the original elements from those indices, but rearranged in fully sorted order.
- **Initialization:** Prior to the first iteration ($i = 1$), `slot[0 ... 0]` contains a single element, which is trivially sorted.
- **Maintenance:** The inner loop shifts elements that are strictly greater than `slot[i]` one position to the right. When the loop halts, `slot[i]` is placed such that `slot[0 ... i]` is sorted. Incrementing $i$ preserves the invariant for the next outer iteration.
- **Termination:** The loop terminates when $i = n$. Substituting $i = n$ into the invariant establishes that `slot[0 ... n-1]` contains all original elements in sorted order.

#### 2. Loop Invariant for Boolean Flags (Primality Test Example)
- **Invariant Statement:** The boolean variable $p$ remains `True` if and only if there is no integer $k \in [2, i-1]$ that divides $n$.
- **Initialization:** At $i = 2$, the candidate range $[2, 1]$ is empty, so no divisor exists and $p = \text{True}$.
- **Maintenance:** If $i$ divides $n$, $p$ becomes `False`, which correctly indicates that a divisor exists in $[2, i]$. If $i$ does not divide $n$, $p$ retains its previous value, correctly extending the property to $[2, i]$.
- **Termination:** The loop terminates when $i = \lfloor\sqrt{n}\rfloor + 1$. The variable $p$ is `True` if and only if no integer in $[2, \lfloor\sqrt{n}\rfloor]$ divides $n$, confirming that $n$ is prime.

---

### Important Exam Mechanics

#### Comparison vs. Swap Counts in the Worst Case
- The worst-case comparison count of $\frac{n(n-1)}{2}$ does not require the input to be strictly reversed.
- Any arrangement where the $i$-th element must be compared against all $i-1$ preceding elements reaches the maximum comparison count.
- **Example:** $[n, n-1, \dots, 3, 1, 2]$ incurs maximum comparisons because the final element compares against all items, even if it does not trigger a swap on every step.

#### Behavior on Duplicate Elements
- In the inner loop condition `slot[j].key < slot[j-1].key`, comparing two identical keys evaluates to false.
- A duplicate key triggers the `else break;` statement immediately, requiring **1 comparison and 0 swaps** to stay in place.

#### Steady Progress Under Interruption
- Every swap executed by Insertion Sort eliminates exactly one out-of-order pair.
- If the algorithm stops early, the total number of out-of-order pairs never increases.
- Restarting Insertion Sort on a partially sorted array always makes forward progress toward complete sortedness.

## 3. Mergesort

Mergesort splits the array into two equal halves, sorts each half recursively, and merges the two sorted halves into one sorted array.

### Canonical Implementation

    void mergesort(ALIST slot[], int n, int m) {
        int mid = (n + m) / 2;
        if (m - n <= 0) {
            return; // Base case: 0 or 1 element
        } else if (m - n > 1) {
            // Optimization: skip recursion if subproblem size is exactly 2
            mergesort(slot, n, mid);
            mergesort(slot, mid + 1, m);
        }
        merge(slot, n, m);
    }

### In-Place `merge()` Procedure

    void merge(ALIST slot[], int n, int m) {
        int mid = (n + m) / 2;
        int a = n;
        int b = mid + 1;

        while (a <= mid && b <= m) {
            if (slot[a].key < slot[b].key) {
                a++;
            } else if (slot[a].key > slot[b].key) {
                ALIST temp = slot[b];
                for (int k = mid; k >= a; k--) {
                    slot[k + 1] = slot[k];
                }
                slot[a] = temp;
                a++;
                mid++;
                b++;
            } else {
                ALIST temp = slot[b];
                for (int k = mid; k >= a + 1; k--) {
                    slot[k + 1] = slot[k];
                }
                slot[a + 1] = temp;
                a += 2;
                mid++;
                b++;
            }
        }
    }

### Complexity & Recurrence Analysis

| Case | Recurrence Formulation | Work Done During Merge | Closed-Form Solution |
| :--- | :--- | :---: | :---: |
| **Worst Case** | $W(n) = W(\lfloor n/2 \rfloor) + W(\lceil n/2 \rceil) + n - 1$ | $n - 1$ comparisons | $W(n) = n \lg n - n + 1 = \Theta(n \log n)$ |
| **Best Case** | $B(n) = B(\lfloor n/2 \rfloor) + B(\lceil n/2 \rceil) + \lfloor n/2 \rfloor$ | $\lfloor n/2 \rfloor$ comparisons | $B(n) = \frac{1}{2} n \lg n = \Theta(n \log n)$ |
| **Average Case** | Squeezed between $B(n)$ and $W(n)$ | $\Theta(n)$ comparisons | $A(n) = \Theta(n \log n)$ |

- **Average-Case Squeeze:** Because both the best case and worst case take $\Theta(n \log n)$ time, the average case is squeezed between them ($B(n) \le A(n) \le W(n)$) and also takes $\Theta(n \log n)$ time.

#### 1. Derivation of Worst-Case Comparisons ($n = 2^k$)
When merging two subarrays of total length $n$, each comparison places at least one element into its final position. The last comparison places two elements simultaneously, requiring at most $n - 1$ comparisons.

Expanding the recurrence $W(n) = 2W(n/2) + n - 1$ by substitution:
$$\begin{aligned} W(2^k) &= 2W(2^{k-1}) + 2^k - 1 \\ &= 2^2 W(2^{k-2}) + (2^k - 2) + (2^k - 1) \\ &= 2^k W(1) + \sum_{j=1}^k 2^k - \sum_{i=0}^{k-1} 2^i \\ &= 0 + k \cdot 2^k - (2^k - 1) \\ &= n \lg n - n + 1 \end{aligned}$$

#### 2. Derivation of Best-Case Comparisons
The best case occurs when all elements in one subarray are strictly smaller than all elements in the other subarray. The merge loop finishes as soon as the first subarray is exhausted, requiring only $\lfloor n/2 \rfloor$ comparisons.

### Implementation Comparisons: In-Place vs. Standard Buffer

| Property | In-Place Mergesort (Lecture Slide Variant) | Standard Buffered Mergesort |
| :--- | :--- | :--- |
| **Auxiliary Space** | **$O(\log n)$ stack** (allocates no data buffer, but recursion call stack has depth $\lceil \lg n \rceil$) | **$O(n)$** ($O(n)$ data buffer dominates the $O(\log n)$ stack frames) |
| **Data Movements** | $O(n^2)$ shifts due to shifting elements rightward | $\Theta(n \log n)$ copies to and from the buffer |
| **Stability** | **Unstable** (inserting duplicate items directly at `a + 1` flips order) | **Stable** (ties consistently select from the left subarray first) |

### Common Exam Problems & Algorithms

#### 1. Finding Min and Max Together in $1.5n - 2$ Comparisons
When finding both the minimum and maximum of an array, comparing elements in pairs at the base level reduces the total work:
$$W(n) = 2W(n/2) + 2, \quad \text{with } W(2) = 1$$
Expanding the recurrence for $n = 2^k$:
$$W(n) = 2^{k-1}W(2) + 2(2^{k-1} - 1) = \frac{n}{2} + 2\left(\frac{n}{2} - 1\right) = \frac{3}{2}n - 2$$
This takes about $1.5n$ comparisons, saving $25\%$ over the standard $2n - 2$ scan that checks elements one by one.

#### 2. Checking for Duplicate Elements in an Array
- **General Method Using Comparisons:** Sort the array using Mergesort in $\Theta(n \log n)$ time. Make one linear pass ($\Theta(n)$) across the array to check if any two neighbor elements are equal (`A[i] == A[i-1]`). The total running time is $\Theta(n \log n)$.
- **Faster Method for Small Integers ($1$ to $2n$):** If elements are integers within a known range like $1$ to $2n$, do not use comparison sorting. Create a count array of size $2n$ filled with zeros. Walk through the array once and increment the count for each number, stopping immediately if any count hits $2$. This finds duplicates in $\Theta(n)$ time using $O(n)$ extra space.
