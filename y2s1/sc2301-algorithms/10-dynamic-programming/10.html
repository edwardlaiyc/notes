10. Dynamic Programming

This chapter covers the dynamic programming lectures (Weeks 9 and 10). Like divide and conquer (Chapter 2), dynamic programming (DP) solves a problem by solving smaller versions of it. The difference: in DP the smaller problems overlap, so a plain recursion solves the same small problem again and again. DP solves each one once, stores the answer, and reuses it.

This often turns an exponential-time algorithm into a polynomial-time one. The chapter has three parts. First, one small problem (Fibonacci numbers) shows the trouble and the fix, and gives a five-step recipe. Second, the same recipe solves the longest common subsequence and the 0/1 knapsack problem, step by step. Third, a short section on shortest paths in a DAG, and a table that compares DP with divide and conquer and greedy.

1. What Goes Wrong with Plain Recursion?

1.1 Divide and conquer against dynamic programming

Both strategies follow the same outline:

  1. Divide the problem into smaller sub-problems.
  2. Solve each sub-problem recursively.
  3. Combine the sub-solutions into a solution for the whole problem.

The difference is in the sub-problems:

  • Divide and conquer: the sub-problems are independent. In mergesort, the left half and the right half share no work.
  • Dynamic programming: the sub-problems overlap. The same sub-problem appears in many places. DP adds one rule:

Never compute the answer to the same sub-problem more than once.

1.2 The running example: Fibonacci numbers

We use the Fibonacci numbers for the first half of the chapter, because the repeated work is easy to see. The Fibonacci numbers F0,F1,F2,…F_0, F_1, F_2, \dots are defined by a rule that refers to two smaller numbers in the same list:

F0=0,F1=1,Fn=Fn−1+Fn−2 for n≥2.F_0 = 0, \qquad F_1 = 1, \qquad F_n = F_{n-1} + F_{n-2} \text{ for } n \ge 2.

Here nn is a whole number. The first two values are given (they are the base cases). Every later value is the sum of the two values before it. So the list is 0,1,1,2,3,5,8,…0, 1, 1, 2, 3, 5, 8, \dots

The rule can be turned into code with no change:

int fib(n) {
    if (n == 0 || n == 1) return n;
    else return fib(n - 1) + fib(n - 2);
}

Each call to fib(n) makes two more calls, one on n−1n-1 and one on n−2n-2. Drawing every call as a node gives the call tree for fib(6):

The tree computes the same value many times:

  • fib(4) is computed 2 times;
  • fib(3) is computed 3 times;
  • fib(2) is computed 5 times.

Counting every node of the tree for fib(6) gives 25 calls, but there are only 7 different values to find (F0F_0 to F6F_6). The extra calls repeat work that is already done.

Call fib(6) fib(5) fib(4) fib(3) fib(2) fib(1) fib(0)
Times made 1 1 2 3 5 8 5

The times made add up to 1+1+2+3+5+8+5=251+1+2+3+5+8+5 = 25. (Not in the lecture: these counts are read off the tree in the figure.)

1.3 How many calls in general?

We want a bound on the number RR of calls, for any nn. We cannot draw the tree for every nn, so we measure its depth (the number of steps from the root to the lowest node) in two ways. We use fib(6) as the check.

  • Shortest branch. The fastest way down is to subtract 2 each time: n,n−2,n−4,…n, n-2, n-4, \dots A call splits into two calls while its argument is at least 2. So every branch splits at least until depth n/2n/2. The top of the tree is therefore a full binary tree (every node has two children) down to depth n/2n/2. For fib(6), that is depth 3.
  • Deepest branch. The slowest way down is to subtract 1 each time: n,n−1,n−2,…,1n, n-1, n-2, \dots, 1. That path has depth n−1n-1. For fib(6), that is depth 5.

Now we need the size of a full binary tree. Level kk of a full binary tree holds 2k2^k nodes. A full tree of depth DD has levels 00 to DD, so it holds

1+2+4+…+2D=2D+1−1 nodes.1 + 2 + 4 + \dots + 2^D = 2^{D+1} - 1 \text{ nodes.}

The call tree contains a full tree of depth n/2n/2, and it fits inside a full tree of depth n−1n-1. So the number of calls RR lies between the two sizes. For n=6n = 6 (depths 3 and 5):

24−1<R<26−1,that is,15<25<63.2^4 - 1 < R < 2^6 - 1, \quad \text{that is,} \quad 15 < 25 < 63.

For general nn, put D=n/2D = n/2 in the lower bound and D=n−1D = n-1 in the upper bound:

2n/2+1−1<R<2n−1.2^{n/2 + 1} - 1 < R < 2^n - 1.

In words: the number of calls grows at least like 2n/22^{n/2} and at most like 2n2^n. Both are exponential, so the algorithm takes exponential time, O(2n)O(2^n). For n=50n = 50 the lower bound alone is 226−12^{26} - 1, about 67 million calls, to find one number.

The cause is clear. There are only n+1n + 1 different sub-problems, F0F_0 to FnF_n. Almost all the calls repeat a sub-problem that was already solved.

2. The Fix: Store Each Answer Once

2.1 The dictionary

The remedy is to keep a dictionary of answers already computed. It is usually an array indexed by the sub-problem. Before solving a sub-problem, look in the dictionary:

  • already solved: retrieve the stored answer, at O(1)O(1) cost;
  • not solved yet: solve it, then store the answer.

Here is the call tree for fib(6) with the dictionary in use:

Only one thin path of the tree is really computed. A purple node costs O(1)O(1), and the whole sub-tree below it disappears (the grey nodes).

The main feature of DP: it replaces an exponential-time computation by a polynomial-time one, by storing solutions and never recomputing them.

This is the same idea as DFS (Chapter 5). DFS explores only undiscovered vertices, and just checks the others. DP solves only unsolved sub-problems, and just retrieves the others.

There are two ways to use the dictionary. This section shows the first, top-down. Section 4 shows the second, bottom-up.

2.2 Top-down: memoization

Keep the recursion exactly as it is, and add the dictionary. The lecture’s steps:

  1. Write the problem PP in terms of smaller versions of itself, Q1,Q2,…Q_1, Q_2, \dots
  2. Turn this into a recursive function.
  3. Use a dictionary to store the solutions of sub-problems.
  4. In the recursive function:
    • before a recursive call on QiQ_i, check the dictionary. If QiQ_i is solved, retrieve its answer. Otherwise, make the call;
    • just before returning the solution of PP, store it in the dictionary.

Storing the result of each call this way is called memoization. Applied to Fibonacci:

int fibDP(n) {
    int f1, f2;
    if (n == 0 || n == 1) {
        store(Soln, n, n);
        return n;
    }
    if (not member(Soln, n - 1)) f1 = fibDP(n - 1);
    else                         f1 = retrieve(Soln, n - 1);
    if (not member(Soln, n - 2)) f2 = fibDP(n - 2);
    else                         f2 = retrieve(Soln, n - 2);
    f1 = f1 + f2;
    store(Soln, n, f1);
    return f1;
}

The dictionary Soln is an array with one cell for each value 00 to nn. Before the first call, every cell is set to −1-1, which means “not solved” (a real Fibonacci number is never negative). The three dictionary operations are one line each:

Operation Code
member(Soln, j) return Soln[j] != -1
store(Soln, j, s) Soln[j] = s
retrieve(Soln, j) return Soln[j]

Trace for fibDP(6). The first call goes down the left branch until it reaches the base cases, fibDP(1) and fibDP(0). Then each call returns and stores its answer. The table shows Soln[0..6] after every store. A dot means “still −1-1”.

Event Soln[0] Soln[1] Soln[2] Soln[3] Soln[4] Soln[5] Soln[6]
Start . . . . . . .
fibDP(1) stores base case . 1 . . . . .
fibDP(0) stores base case 0 1 . . . . .
fibDP(2) stores 1+01 + 0 0 1 1 . . . .

Look at fibDP(3). It first calls fibDP(2), which is new. For its second value, Soln[1] is already set, so it retrieves 1 and makes no call. The same happens in fibDP(4), fibDP(5) and fibDP(6): the first value needs a call, the second is retrieved. This is what prunes the tree in the figure.

Cost.

  • One call to fibDP, not counting the calls it makes, does a constant amount of work: two lookups, one addition, one store.
  • fibDP really runs only once for each value from 0 to nn, because after that the value is in the dictionary. That is n+1n + 1 calls.
  • Total: O(n)O(n) (constant work times n+1n + 1 calls). The plain recursion needed O(2n)O(2^n).

3. In What Order Do the Sub-problems Depend on Each Other?

Memoization lets the recursion find the right order by itself. To fill the dictionary without recursion we must know that order in advance. A picture of the dependencies gives it.

3.1 The subproblem graph

The subproblem graph of a recursive algorithm has:

  • one vertex for each different sub-problem;
  • an edge from II to JJ if solving II makes a recursive call directly on JJ.

For Fibonacci, sub-problem nn calls n−1n-1 and n−2n-2. Here is the graph for fib(6):

Compare this with the call tree of Section 1. The tree had 25 nodes and repeated values. The graph has 7 vertices, one for each different sub-problem.

3.2 What the graph tells you

  • It must be a DAG (a directed graph with no cycles, Chapter 5). A cycle would mean a sub-problem needs its own answer, and the recursion would never end.
  • Fill order. An answer must be ready before anything that uses it. So solve each sub-problem after every sub-problem it points to. That is a reverse topological order of the graph. For Fibonacci: 0,1,2,…,n0, 1, 2, \dots, n.
  • Number of vertices = number of different sub-problems = size of the dictionary.
  • Number of edges = total work spent combining answers.

These two counts give the running time:

time≈(number of sub-problems)×(work per sub-problem).\text{time} \approx (\text{number of sub-problems}) \times (\text{work per sub-problem}).

Read this as: each sub-problem is solved once, and each solution costs the work of combining its smaller answers. For Fibonacci: (n+1)×O(1)=O(n)(n+1) \times O(1) = O(n). We reuse this formula for every problem in the chapter.

4. Bottom-up: Tabulation

4.1 Fill the table in order

Fibonacci has a sequence of sub-problems, n,n−1,n−2,…n, n-1, n-2, \dots, so a one-dimensional array holds them. soln[j] needs only soln[j-1] and soln[j-2], so if we fill the array from j=0j = 0 upward, both are ready when we need them. No recursion is needed.

soln[0] = 0;
soln[1] = 1;
for j = 2 to n
    soln[j] = soln[j-1] + soln[j-2];

For n=6n = 6 the array fills left to right:

jj 0 1 2 3 4 5 6
soln[j] 0 1 1 2 3 5 8

The loop runs n−1n - 1 times with constant work each, so it is also O(n)O(n), and it has no recursion overhead.

Top-down against bottom-up. Both give the same answer with the same O(n)O(n) cost.

Top-down (memoization) Bottom-up (tabulation)
Form Recursion plus a dictionary Loops over a table
Who picks the order? The recursion You, from the subproblem graph
Sub-problems solved Only those that are reached All of them

4.2 Saving memory

The table does not always need every answer. Fibonacci looks back only two steps, so two variables are enough:

a = 0; b = 1;                 // F(0), F(1)
for j = 2 to n { c = a + b; a = b; b = c; }
return b;                     // for n >= 1

This uses O(1)O(1) memory. The same trick works whenever each part of the table depends only on the part just before it. But if you need to rebuild the solution itself (Sections 7.6 and 8.7), you must keep the whole table.

5. When Does DP Give the Optimal Answer?

Fibonacci has one correct answer. Many problems instead ask for the best answer of many possible ones: the longest, the shortest, the most profitable. These are optimization problems, and DP is mainly a tool for them. DP is correct for them only under one condition.

5.1 The principle of optimality

A problem satisfies the principle of optimality if:

The sub-solutions of an optimal solution are themselves optimal solutions of their sub-problems.

Example: if A→B→C→DA \to B \to C \to D is a shortest path from AA to DD, then A→B→CA \to B \to C is a shortest path from AA to CC. (Chapter 6, Lemma 1.)

Why it matters. DP builds the best answer for a big problem only from the best answers of smaller problems. It never looks at the second-best answers of a smaller problem. That is safe only if a best solution is always made of best parts.

5.2 How to show it for a problem

Use a cut-and-paste argument by contradiction:

  1. Take an optimal solution of the whole problem.
  2. Suppose one of its parts is not optimal for its sub-problem.
  3. Cut out that part, and paste in a better solution of the sub-problem.
  4. The whole solution is now better, and still valid.
  5. That contradicts “the solution was optimal”. So every part must be optimal.

In step 4, check that the pasted part still fits: it must not break any rule of the problem. Sections 7.2 and 8.2 use this argument.

5.3 The DP selection rule

Often the last decision has several possibilities, and we do not know which one is best.

When there are several possibilities, compute all of them and take the best.

This is the difference from a greedy algorithm (Chapter 6), which picks the choice that looks best now and never checks the others.

6. The Five-Step Recipe

The lecture gives one recipe for the bottom-up method. Here each step is shown on Fibonacci. Sections 7 and 8 repeat the same five steps on two harder problems.

Step What to do On Fibonacci
1 Formulate the problem in terms of smaller versions of itself: the sub-problems. Say in words what each one means. FjF_j for j=0…nj = 0 \dots n: the jj-th Fibonacci number.
2 Relate the sub-problems with a recursive function, and state its base cases. Fj=Fj−1+Fj−2F_j = F_{j-1} + F_{j-2}; F0=0F_0 = 0, F1=1F_1 = 1.
3 Draw the subproblem graph (it must be a DAG). Find the dependencies and a topological order. Vertex jj points to j−1j-1 and j−2j-2. Order: 0,1,…,n0, 1, \dots, n.
4 Use a dictionary (a table) to store the solutions. One entry for each sub-problem. A 1-D array soln[0..n].
5 Write an iterative function: set the base cases, fill the table in topological order, read the original problem from the table. If needed, use parent pointers to recover the actual solution, not just its value. The loop of Section 4.1. The answer is soln[n].

A final check, which the lecture does with each algorithm: state the time and space. By Section 3.2, time is (number of sub-problems) ×\times (work per sub-problem), and space is the table size.

The most common source of errors is step 1. A vague definition (“the best for the first part”) leaves step 2 with nothing exact to build on. Write exactly what the sub-problem asks for, and what its parameters mean.

7. Longest Common Subsequence (LCS)

7.1 The problem

A subsequence of a sequence keeps some of its characters, in their original order, and drops the rest. The kept characters do not have to be next to each other.

  • For ss = ACTTGCG: ACT, AG, ATTC, T and ACTTGC are subsequences.
  • TTA is not (the order is wrong: no A comes after the two Ts). AGGC is not (there is no C after the two Gs).

A common subsequence of two sequences xx and yy is a subsequence of both. A longest common subsequence (LCS) is a common subsequence of maximum length. It may not be unique: the lecture shows two sequences with several different common subsequences of the same maximum length.

The LCS length measures how similar two sequences are, for example two DNA strands or two versions of a document.

The problem. Given x=⟨x1,…,xn⟩x = \langle x_1, \dots, x_n \rangle and y=⟨y1,…,ym⟩y = \langle y_1, \dots, y_m \rangle, find LCS(n,m)LCS(n, m), the length of an LCS. (Section 7.6 shows how to get the subsequence itself.)

Brute force. List all subsequences of xx (up to 2n2^n of them, since each character is kept or dropped) and check each one against yy. This is exponential.

7.2 Step 1: the sub-problems, and where they come from

The sub-problem, in words. For 0≤i≤n0 \le i \le n and 0≤j≤m0 \le j \le m, let LCS(i,j)LCS(i, j) be the length of an LCS of the first ii characters of xx and the first jj characters of yy. These are the prefixes x1…xix_1 \dots x_i and y1…yjy_1 \dots y_j. The whole problem is LCS(n,m)LCS(n, m). A prefix of length 0 is the empty sequence.

Why prefixes? To split the problem we look at the last character of each sequence. Once we decide what to do with the last characters, what remains is a pair of shorter prefixes. So prefixes are exactly the sub-problems that the decision leaves behind.

Take xix_i and yjy_j, the last characters of the two prefixes. There are two cases. We use the lecture’s pair xx = ACGGA, yy = ACTG for the pictures; there LCS(5,4)LCS(5, 4) compares x5x_5 = A with y4y_4 = G.

Case 1: xi=yjx_i = y_j.

  • This character can be the last character of an LCS of the two prefixes. (Why: take any LCS. If it does not already end by using both xix_i and yjy_j, either it uses one of them matched with an earlier character, and we can re-match it to the other one, or it uses neither, and we can add the match at the end to make it longer. Either way, some LCS ends with this match. This short argument is standard, not in the lecture.)
  • Before that last character comes a common subsequence of x1…xi−1x_1 \dots x_{i-1} and y1…yj−1y_1 \dots y_{j-1}. It must be a longest one. If a longer one existed, we could paste it in front of the last character and get a common subsequence of the prefixes longer than the LCS. That is the cut-and-paste argument of Section 5.2.
  • So the length is one more than LCS(i−1,j−1)LCS(i-1, j-1).

Case 2: xi≠yjx_i \ne y_j.

  • The two characters differ, so they cannot both be the last character of a common subsequence. So at least one of them is not used: xix_i is not used, or yjy_j is not used, or neither.
  • If xix_i is not used, the LCS is an LCS of x1…xi−1x_1 \dots x_{i-1} and y1…yjy_1 \dots y_j. Its length is LCS(i−1,j)LCS(i-1, j).
  • If yjy_j is not used, the LCS is an LCS of x1…xix_1 \dots x_i and y1…yj−1y_1 \dots y_{j-1}. Its length is LCS(i,j−1)LCS(i, j-1).
  • We do not know which character to drop, so we compute both and take the larger. This is the DP selection rule (Section 5.3). “Neither is used” needs no third term, because both options already cover it.

In every case the shorter part must itself be an LCS of the shorter prefixes. If it were not, a longer one could replace it and give a longer common subsequence for (i,j)(i, j). So the principle of optimality holds for LCS.

7.3 Step 2: the recursive function

Now we write the two cases as one rule. The symbols: ii and jj are the prefix lengths, and xix_i, yjy_j are the last characters of the prefixes.

LCS(i,j)={0if i=0 or j=0,LCS(i−1,j−1)+1if i,j>0 and xi=yj,max⁡(LCS(i−1,j),LCS(i,j−1))if i,j>0 and xi≠yj.LCS(i, j) = \begin{cases} 0 & \text{if } i = 0 \text{ or } j = 0, \\[4pt] LCS(i-1, j-1) + 1 & \text{if } i, j > 0 \text{ and } x_i = y_j, \\[4pt] \max\big(LCS(i-1, j),\; LCS(i, j-1)\big) & \text{if } i, j > 0 \text{ and } x_i \ne y_j. \end{cases}

In words:

  • Line 1, the base case. An empty prefix has nothing in common with anything, so the length is 0.
  • Line 2. The last characters match: use them, and add 1 to the answer for both prefixes shortened by one.
  • Line 3. The last characters differ: drop the last character of one prefix, and keep the better result.

A plain recursive version of this rule is very slow, because the same pairs (i,j)(i, j) are reached again and again (the same trouble as in Section 1).

7.4 Steps 3 and 4: the subproblem graph and the table

Step 3. From the recursive function, sub-problem (i,j)(i, j) depends on at most three others:

  • (i−1,j−1)(i-1, j-1): diagonally up-left (used when the characters match);
  • (i−1,j)(i-1, j): above;
  • (i,j−1)(i, j-1): to the left.

Placing the sub-problems in a grid, with ii down the side and jj across, every vertex points up, left and diagonally up-left. This is the graph for LCS(6,5)LCS(6, 5):

Step 4. The dictionary is an (n+1)×(m+1)(n+1) \times (m+1) array c. Cell c[i][j] holds LCS(i,j)LCS(i, j). Row 0 and column 0 are the base cases.

Fill order. Every cell depends only on cells above it or to its left. So:

  • fill row 0 and column 0 with 0;
  • then fill row by row, from row 1 to row nn, and left to right within each row.

When the loop reaches a cell, all three cells it needs are already filled. (Filling column by column would also work.)

7.5 Step 5: the code, and the cost

int LCS(n, m) {
    for i = 0 to n  c[i][0] = 0;
    for j = 1 to m  c[0][j] = 0;
    for i = 1 to n
        for j = 1 to m
            if (x[i] == y[j])
                c[i][j] = c[i-1][j-1] + 1;
            else if (c[i-1][j] >= c[i][j-1])
                c[i][j] = c[i-1][j];
            else
                c[i][j] = c[i][j-1];
    return c[n][m];
}

The three branches are the three lines of the recursive function. The answer is the last cell, c[n][m].

Cost.

  • There are (n+1)(m+1)(n+1)(m+1) sub-problems, and each takes constant time (at most three lookups and one comparison).
  • The two loops run nmnm times. Time: O(nm)O(nm).
  • Space: O(nm)O(nm), for the (n+1)×(m+1)(n+1) \times (m+1) array.

7.6 Recovering the subsequence itself

The table gives only the length. To get the subsequence, keep a second array, the hint array h (parent pointers). Each cell records which case produced it, that is, where its value came from:

Hint Meaning Came from
\ xi=yjx_i = y_j; this character is in the LCS (i−1,j−1)(i-1, j-1)
| c[i][j]=c[i−1][j]c[i][j] = c[i-1][j] above
— c[i][j]=c[i][j−1]c[i][j] = c[i][j-1] the left
  • Column 0 is filled with |, and row 0 with —.
  • Tie rule: when c[i−1][j]=c[i][j−1]c[i-1][j] = c[i][j-1], the code takes from above (|), because it tests >=.

To read the LCS, start at h[n][m] and follow the hints back until you reach row 0 or column 0. Each hint tells you where the value came from, so following it undoes the fill:

getSequence(n, m) {
    s = empty stack;
    i = n; j = m;
    while (i != 0 and j != 0) {
        if (h[i][j] == '\')       { s.push(x[i]); i--; j--; }
        else if (h[i][j] == '|')  i--;
        else                      j--;
    }
    pop and output everything from s;     // the LCS, in order
}
  • Each diagonal step (\) gives one character of the LCS.
  • The characters come out last first, so a stack puts them back in order.
  • Each step lowers ii or jj (or both). So there are at most n+mn + m steps: O(n+m)O(n + m).

7.9 Filling an LCS table by hand

  1. Draw the table with xx down the side and yy across the top. Add a row 0 and a column 0 of zeros.
  2. For each cell, row by row:
    • if the row’s character equals the column’s character: take the upper-left value plus 1;
    • otherwise: take the larger of the cell above and the cell to the left. On a tie, take above.
  3. The length is the bottom-right cell.
  4. To get the subsequence, walk back from the bottom-right. On a match, go diagonally and record the character. Otherwise, move to the neighbour you copied from.

8. The 0/1 Knapsack Problem

8.1 The problem

  • A knapsack holds a total weight of at most CC, a positive integer (its capacity).
  • There are nn objects. Object ii has weight wiw_i and profit pip_i, all positive integers.
  • Find the largest total profit of a subset of the objects whose total weight is at most CC.

“0/1” means each object is either taken whole (1) or left (0). You cannot take part of an object, and you cannot take an object twice.

Example use: CC is an amount of money to invest, the wiw_i are the costs of possible investments, and the pip_i their expected returns.

Brute force. There are 2n2^n subsets of nn objects. Checking them all takes O(2n)O(2^n) time.

8.2 Step 1: the sub-problems, and where they come from

The sub-problem, in words. Let P(r,j)P(r, j) be the largest profit from a subset of the first jj objects when the knapsack has capacity rr. Here 0≤r≤C0 \le r \le C and 0≤j≤n0 \le j \le n. The whole problem is P(C,n)P(C, n). (The lecture writes CC for both the real capacity and the variable capacity. We write rr for the variable so the two do not mix.)

Why these two numbers? Look at the last object, object jj. The best solution either takes it or does not. What is left is a smaller problem: fewer objects, and a capacity that may have shrunk. So two numbers describe every sub-problem: how many objects are allowed, and how much capacity is left.

  • Take object jj (only possible if wj≤rw_j \le r):
    • it earns pjp_j;
    • it uses up wjw_j of the capacity, so r−wjr - w_j is left;
    • the rest of the profit comes from the first j−1j - 1 objects with capacity r−wjr - w_j. It must be the best possible for that sub-problem. Cut and paste (Section 5.2): if a better set existed for the sub-problem, swap it in. It weighs no more than r−wjr - w_j, so with object jj it still fits in rr, and the profit goes up. That would contradict optimality.
    • Total: pj+P(r−wj,j−1)p_j + P(r - w_j, j - 1).
  • Leave object jj:
    • the profit comes from the first j−1j - 1 objects with the full capacity rr, and by the same argument it must be the best one;
    • Total: P(r,j−1)P(r, j - 1).
  • If wj>rw_j > r, object jj does not fit, so only “leave” is possible.

We do not know which choice is better, so we compute both and take the larger (the DP selection rule, Section 5.3).

Both smaller sub-problems use only j−1j - 1 objects. So each object is decided once, and no object can be taken twice.

8.3 Step 2: the recursive function

Base cases. With no objects, or with no capacity, nothing can be taken:

P(r,0)=0,P(0,j)=0.P(r, 0) = 0, \qquad P(0, j) = 0.

Recursion. Let r≥1r \ge 1 be the capacity, j≥1j \ge 1 the number of objects allowed, wjw_j and pjp_j the weight and profit of object jj:

P(r,j)={max⁡(P(r,j−1),pj+P(r−wj,j−1))if wj≤r,P(r,j−1)if wj>r.P(r, j) = \begin{cases} \max\big(P(r, j-1),\; p_j + P(r - w_j, j-1)\big) & \text{if } w_j \le r, \\[4pt] P(r, j-1) & \text{if } w_j > r. \end{cases}

In words: the first term of the max is “leave object jj”, the second is “take object jj”. If the object is heavier than the capacity, only the “leave” term remains. The lecture shows the same choice as a tree: each sub-problem splits into “include the last object” and “do not include it”, and the answer is the maximum of the two.

8.4 Step 3: the subproblem graph

(r,j)(r, j) depends on two sub-problems, both in the previous object count j−1j - 1:

  • (r,j−1)(r, j-1): the same capacity (leave object jj);
  • (r−wj,j−1)(r - w_j, j-1): a smaller capacity (take object jj).

Only the sub-problems reachable from (C,n)(C, n) are needed. The lecture draws the graph for C=20C = 20 and four objects:

Object 1 2 3 4

Since every edge goes from jj to j−1j - 1, there are no cycles, so it is a DAG.

8.5 Steps 4 and 5: the table, the fill order and the code

Step 4. The dictionary is profit[C+1][n+1]:

  • rows are capacities r=0…Cr = 0 \dots C;
  • columns are object counts c=0…nc = 0 \dots n.

Cell profit[r][c] holds P(r,c)P(r, c). Row 0 and column 0 are the base cases.

Fill order. A cell in column cc needs two cells in column c−1c - 1: the same row, and a row with smaller number (r−wcr - w_c). So fill row 0 and column 0 with 0. Then fill each row r=1…Cr = 1 \dots C from left to right, c=1…nc = 1 \dots n. When you reach a cell, its column c−1c - 1 entries are done. (Any order that finishes column c−1c - 1 before column cc also works.)

int knapsack(int[] w, int[] p, int C, int n) {
    for c = 0 to n  profit[0][c] = 0;
    for r = 1 to C  profit[r][0] = 0;
    for r = 1 to C                         // capacity
        for c = 1 to n {                   // objects 1..c are allowed
            profit[r][c] = profit[r][c-1];                 // leave object c
            if (w[c] <= r)
                if (profit[r][c] < profit[r - w[c]][c-1] + p[c])
                    profit[r][c] = profit[r - w[c]][c-1] + p[c];   // take object c
        }
    return profit[C][n];
}

The code first sets the “leave” value, then replaces it with the “take” value if the object fits and the take value is larger. So each cell is max⁡(leave,take)\max(\text{leave}, \text{take}). The answer is profit[C][n].

8.8 Which objects were taken?

Like LCS, the table gives only the best value. To find the objects, walk back from profit[C][n]\text{profit}[C][n] and ask at each cell whether the value came from “leave” or “take”:

  • if profit[r][c]=profit[r][c−1]\text{profit}[r][c] = \text{profit}[r][c-1]: object cc was left. Move to column c−1c - 1, same row;
  • otherwise: object cc was taken. Move to row r−wcr - w_c, column c−1c - 1.

Stop at column 0. Or store a parent pointer in each cell while filling the table.

8.9 Cost, and why it is “pseudo-polynomial”

The table has (C+1)(n+1)(C+1)(n+1) cells, each filled in O(1)O(1) time:

time=space=O(nC).\text{time} = \text{space} = O(nC).

In words: the time grows with the number of objects nn and with the capacity CC. This looks polynomial, but it is not polynomial in the usual sense. The usual sense measures time against the size of the input, that is, the number of bits needed to write it down.

  • An algorithm is strongly polynomial if its time is a polynomial in the size of the input. Here the input holds nn weights and nn profits.
  • An algorithm is pseudo-polynomial if its time is a polynomial in the numeric value of the input. Here one number, CC, sets the table height.

The problem is that a number’s value can be exponentially larger than its size. Writing CC in binary takes about log⁡2C\log_2 C bits:

CC Bits to write CC Rows in the table
20 5 21
1,000 10 1,001
1,000,000 20 1,000,001
1,000,000,000 30 1,000,000,001

Adding 10 bits to the input multiplies the number of rows by about 1000. If bb is the number of bits of CC, then CC is about 2b2^b, and the time is about n⋅2bn \cdot 2^b. Measured against the input size, that is exponential.

The DP algorithm for 0/1 knapsack is pseudo-polynomial. It is fast only when CC is small.

9. Shortest Paths in a DAG

The lecture outline lists this topic, but its slides were not released. What follows is not from the lecture slides: it is the standard method, and it fits the five-step recipe.

  • Step 1, sub-problem: dist(v)dist(v), the shortest distance from the source ss to vertex vv. (A path’s length is the sum of its edge weights w(u,v)w(u, v).)
  • Step 2, recursion: the last edge of a shortest path into vv comes from some vertex uu with an edge (u,v)(u, v). By the principle of optimality, the path to uu is itself shortest. We do not know which uu is best, so we try every incoming edge and take the minimum:

dist(s)=0,dist(v)=min(u,v)∈E(dist(u)+w(u,v)).dist(s) = 0, \qquad dist(v) = \min_{(u, v) \in E} \big(dist(u) + w(u, v)\big).

In words: the distance to vv is the best, over all edges into vv, of the distance to the edge’s start plus the edge’s weight. A vertex other than ss with no incoming edge has distance ∞\infty (it cannot be reached).

  • Step 3, order: the graph is a DAG, so the subproblem graph (the same edges, reversed) has no cycles. Compute the distdist values in topological order (Chapter 5), so every uu is done before vv.
  • Cost: each edge is used once, so O(|V|+|E|)O(|V| + |E|).
  • Unlike Dijkstra (Chapter 6), this works with negative edge weights, because there is no cycle.

Replacing min with max gives the longest path in a DAG.

10. How the Shape of the Recursion Sets the Table and the Cost

After step 2 of the recipe, the sub-problem’s parameters decide the table. Use this to choose the table and the fill order. (This table is general guidance, not from the lecture.)

The sub-problem is indexed by Table Fill order
One number ii (a prefix, a size) 1-D array i=0,1,2,…i = 0, 1, 2, \dots
Two prefixes (i,j)(i, j), or a grid position 2-D array row by row, left to right
An interval (i,j)(i, j) of one sequence 2-D array by increasing length j−ij - i

The cost of one cell depends on how many other cells it reads:

  • If a cell looks at a fixed number of other cells (Fibonacci: 2; LCS: 3; knapsack: 2), each cell is O(1)O(1).
  • If a cell takes a max, min or sum over all smaller values (for example F(n)=∑k<nF(k)F(n) = \sum_{k < n} F(k)), each cell costs O(n)O(n). The total time is then (number of cells) ×O(n)\times\, O(n).

The plain recursion is usually exponential. To find the running time of the recursive version without a dictionary, write its cost as a recurrence, and solve it with Chapter 8’s methods. If each call makes two or more calls on sizes only slightly smaller, the cost grows like Fibonacci or faster: exponential (Section 1.3). With a dictionary, the cost drops to (number of different sub-problems) ×\times (work per sub-problem).

12. Common Traps

  • DP needs overlapping sub-problems. Without overlap, plain divide and conquer is enough.
  • DP gives the optimal answer only if the principle of optimality holds.
  • Memoization is top-down (recursion + dictionary). Tabulation is bottom-up (loops in a correct order). Both have the same complexity.
  • The subproblem graph must be a DAG. Fill the table in reverse topological order: dependencies first.
  • Time ≈\approx (number of sub-problems) ×\times (work per sub-problem). Do not forget the second factor when a cell loops over many choices.
  • Plain recursive Fibonacci makes O(2n)O(2^n) calls (between 2n/2+1−12^{n/2+1}-1 and 2n−12^n-1). With memoization: O(n)O(n) time. Bottom-up with two variables: O(1)O(1) space.
  • Define the sub-problem in words first. Most mistakes in steps 2 to 5 come from a vague step 1.
  • A subsequence keeps the order but need not be contiguous. A substring must be contiguous.
  • LCS: time and space O(nm)O(nm); traceback O(n+m)O(n + m). On a tie, the lecture code takes from above (|).
  • An LCS may not be unique. The tie rule decides which one the traceback finds.
  • LCS: a match uses the diagonal cell plus 1. A mismatch takes the larger of above and left, never the diagonal.
  • Keeping only two variables (or two rows) saves memory but loses the table, so you can no longer trace back the actual solution.
  • In the knapsack table, rows are capacities and columns are objects: profit[r][c].
  • The “take” option reads from the previous column (c−1c - 1), not the same column. Reading the same column would let an object be taken twice.
  • If an object is heavier than the capacity rr, the “take” option does not exist. Do not read a negative row.
  • 0/1 knapsack in O(nC)O(nC) is pseudo-polynomial, not polynomial, because CC is a value, not an input size.
  • Greedy by profit per unit weight does not solve 0/1 knapsack.
