## 1. Limits of Comparison Sorting

### The Decision Tree Model
- A decision tree is a full binary tree that represents the execution of any comparison-based sorting algorithm on an input of size $n$.
- Each internal node represents one comparison between two elements, written as $A[i] : A[j]$.
- Each branch leaving a node represents the outcome of the comparison (either $\le$ or $>$).
- Each reachable leaf represents a permutation that describes the final sorted order of the elements.
- Running a comparison sort on any input traces a single path from the root down to a leaf.

---

### Key Theorems & Proofs

#### 1. Why Comparison Sorts Cannot Beat $\Omega(n \log n)$ in the Worst Case
- **Theorem:** Every comparison-based sorting algorithm requires at least $\Omega(n \log n)$ comparisons in the worst case.
- **Proof:**
  1. An algorithm must be able to produce every possible ordering of $n$ items, meaning the tree must contain at least $n!$ reachable leaves ($l \ge n!$).
  2. A binary tree of height $h$ can have at most $2^h$ leaves, giving the inequality $n! \le l \le 2^h$.
  3. Taking the logarithm of both sides gives $h \ge \lg(n!)$.
  4. By Stirling's Approximation, $\lg(n!) = \Theta(n \log n)$, which means $h \ge \Omega(n \log n)$.
  5. The tree height $h$ represents the maximum number of comparisons on the longest path, so the worst-case running time is $\Omega(n \log n)$.

#### 2. Minimum Comparisons Needed Even in the Best Case ($n - 1$)
- **Theorem:** The shallowest possible leaf in a correct comparison sort decision tree has a depth of at least $n - 1$ comparisons.
- **Proof:**
  1. Assume for contradiction that a reachable leaf exists at depth $k < n - 1$.
  2. Build a comparison graph $G = (V, E)$ where vertices represent elements and edges represent comparisons made along that execution path.
  3. Since at most $k$ comparisons were made, the graph has $\vert{}E\vert{} \le k < n - 1$ edges.
  4. A graph with $n$ vertices and fewer than $n - 1$ edges cannot be connected, so it must contain at least two separate components, $A$ and $B$.
  5. Because no element in $A$ was ever compared with an element in $B$, the algorithm has no information about their relative order.
  6. An adversary can assign values such that the true order contradicts the permutation at that leaf. Therefore, every valid leaf requires at least $n - 1$ comparisons.

#### 3. Bypassing the Comparison Limit
Counting Sort and Radix Sort run in linear time $O(n)$ because they do not compare elements against each other. Instead, they use direct array indexing and arithmetic on digit values.

## 2. Heapsort & Priority Queues

A heap is an almost-complete binary tree stored sequentially in an array that satisfies the parent-child heap property.

### Heap Properties (1-Indexed)
- **Completeness:** Every level is completely filled, except possibly the bottom level, which is filled from left to right.
- **Max-Heap Property:** For every node $i > 1$, $\text{key}(\text{parent}(i)) \ge \text{key}(i)$. The largest key is always at root index $1$.
- **Min-Heap Property:** For every node $i > 1$, $\text{key}(\text{parent}(i)) \le \text{key}(i)$. The smallest key is always at root index $1$.

### Array Navigation Rules
For node $i$ in a heap of size $n$:
- **Parent:** $\lfloor i / 2 \rfloor$
- **Left Child:** $2i$
- **Right Child:** $2i + 1$
- **Leaf Check:** Node $i$ is a leaf if and only if $2i > n$.
- **Last Internal Node:** The highest index with children is $\lfloor n / 2 \rfloor$.
- **Heap Height:** A heap with $n$ elements has a height of $\lfloor \lg n \rfloor = \Theta(\log n)$.

---

### Canonical Course Implementation

    // Sinks element k down the heap to restore the max-heap property
    void fixHeap(ALIST H[], int currentSize, ALIST k) {
        int j = 1;     // Start at the root
        int cj = 2;    // Left child of j

        while (cj <= currentSize) {
            // Step 1: Find the larger of the two children
            if (cj < currentSize && H[cj].key < H[cj + 1].key) {
                cj++;  // Right child is larger
            }

            // Step 2: Stop if k is larger than or equal to both children
            if (k.key >= H[cj].key) {
                break;
            }

            // Step 3: Move the larger child up into empty slot j
            H[j] = H[cj];

            // Step 4: Move down to continue checking
            j = cj;
            cj = 2 * j;
        }
        H[j] = k; // Place k into its correct position
    }

    // Builds a max-heap in-place from an arbitrary array
    void constructHeap(ALIST H[], int n) {
        for (int i = n / 2; i >= 1; i--) {
            ALIST k = H[i];
            fixHeapSubtree(H, n, i, k); // Sinks k starting from index i
        }
    }

    // Sorts the array in ascending order
    void heapSort(ALIST array[], int n) {
        constructHeap(array, n);

        for (int i = n; i >= 1; i--) {
            ALIST curMax = array[1];   // Read the maximum element at the root
            ALIST k = array[i];        // Pick the last element in the active heap
            array[i] = curMax;         // Place the maximum element in its final sorted slot
            fixHeap(array, i - 1, k);  // Restore the heap for the remaining i - 1 items
        }
    }

---

### Complexity & Exact Derivations

| Operation | Best-Case Time | Worst-Case Time | Plain Explanation |
| :--- | :---: | :---: | :--- |
| **`fixHeap()`** | $O(1)$ | $O(\log n)$ | Makes at most 2 comparisons per level across tree height $\lfloor \lg n \rfloor$. |
| **`constructHeap()`** | $\Theta(n)$ | $\Theta(n)$ | Most nodes sit near the bottom with short sink distances. |
| **`deleteMax()`** | $O(\log n)$ | $O(\log n)$ | Replaces the root with the last element and sinks it down. |
| **`heapSort()`** | $\Theta(n \log n)$ | $\Theta(n \log n)$ | Performs $n$ extractions, each costing $O(\log n)$ time. |

#### 1. Why Heap Construction is Linear Time
Building a heap takes linear time $\Theta(n)$ because most nodes sit near the bottom of the tree where the sink distance is very short. Half of all nodes are leaves and sink 0 levels.
- The number of nodes at height $h$ is at most $\lceil n / 2^{h+1} \rceil$.
- Each node at height $h$ can sink down at most $h$ levels.
- Summing the work across all levels confirms the linear bound:
  $$\sum_{h=0}^{\lfloor \lg n \rfloor} \left\lceil \frac{n}{2^{h+1}} \right\rceil O(h) = O\left(n \sum_{h=0}^\infty \frac{h}{2^h}\right) = O(2n) = O(n)$$

#### 2. Exact Best-Case Heap Construction
- A reverse-sorted array (strictly descending order) provides the exact best-case input for `constructHeap`.
- Every parent is already strictly larger than both its children, so each call to `fixHeap` terminates immediately on its first comparison without swapping.
- Every internal node with two children makes $2$ comparisons, while a node with one child makes $1$ comparison.
- For any size $n$, the total comparison count is **exactly $n - 1$ comparisons and $0$ swaps**.

---

### Priority Queue Applications

#### 1. Merging $k$ Sorted Lists
- You can merge $k$ pre-sorted lists with a total of $n$ elements into one sorted list in $O(n \log k)$ time and $O(k)$ extra space.
- Step 1: Insert the first item of each list into a min-heap of size $k$ in $O(k)$ time.
- Step 2: Remove the minimum item from the root and write it to the output array.
- Step 3: Insert the next item from that same list into the root and call `fixHeap` in $O(\log k)$ time.
- Step 4: Repeat until all $n$ items are processed.

## 3. Quicksort

Quicksort is an in-place divide-and-conquer sorting algorithm. It picks a pivot element, partitions the array into values smaller than the pivot and values greater than or equal to the pivot, and places the pivot directly into its final position.

### Canonical Implementation

    void quicksort(int n, int m) {
        if (n >= m) return; // Base case: 0 or 1 element
        int pivot_pos = partition(n, m);
        quicksort(n, pivot_pos - 1);
        quicksort(pivot_pos + 1, m);
    }

    int partition(int low, int high) {
        int mid = (low + high) / 2;
        swap(low, mid); // Move the middle element to the front
        int pivot = slot[low];
        int last_small = low;

        for (int i = low + 1; i <= high; i++) {
            if (slot[i] < pivot) {
                last_small++;
                swap(last_small, i); // Add element to the smaller region
            }
        }
        swap(low, last_small); // Move pivot to its final sorted spot
        return last_small;
    }

---

### Partition Invariants & Tracing
During partition, the array is maintained in four distinct sections from left to right:
1. `slot[low]`: The pivot element.
2. `slot[low + 1 ... last_small]`: Elements strictly smaller than the pivot.
3. `slot[last_small + 1 ... i - 1]`: Elements greater than or equal to the pivot.
4. `slot[i ... high]`: Unexamined elements.

---

### Complexity & Recurrence Analysis

| Case | Recurrence | Time Complexity | Conditions |
| :--- | :--- | :---: | :--- |
| **Best Case** | $T(n) = 2T(n/2) + \Theta(n)$ | $\Theta(n \log n)$ | Pivot divides the array into two equal halves every time. |
| **Average Case** | $A(n) = (n - 1) + \frac{1}{n}\sum_{i=0}^{n-1}(A(i) + A(n-1-i))$ | $\Theta(n \log n)$ | All input orderings are equally likely. |
| **Worst Case** | $T(n) = T(n - 1) + \Theta(n)$ | $\Theta(n^2)$ | Pivot is always the extreme smallest or largest element. |

- **Auxiliary Space:** Uses no auxiliary data buffers. The recursion stack uses **$O(\log n)$** memory on average when splits are balanced, but can grow to **$O(n)$** in the worst case when the pivot is consistently an extreme element.
- **Stability:** **Unstable**. Swapping elements across long distances can disrupt the relative order of equal keys.

---

### Important Quicksort Variations

#### 1. Three-Way Partitioning (Dutch National Flag)
- Sorts an array containing only three distinct values (such as Red, White, Blue) in $\Theta(n)$ time using $O(1)$ extra space.
- Keeps three index pointers: $r$ (next position for Red), $u$ (current unexamined element), and $b$ (next position for Blue).

        void threeWayPartition(int A[], int n) {
            int r = 0, u = 0, b = n - 1;
            while (u <= b) {
                if (A[u] == 0) {
                    swap(A[r], A[u]);
                    r++;
                    u++;
                } else if (A[u] == 1) {
                    u++;
                } else {
                    swap(A[b], A[u]);
                    b--; // Do not advance u; the swapped item is still unexamined
                }
            }
        }

#### 2. Median-of-Three Pivot Selection
- Picks the median value among the first, middle, and last elements to avoid the worst case on already sorted arrays.
- While this improves average running times, an adversarial input designed around the median formula can still force the worst case of $\Theta(n^2)$ comparisons by ensuring the chosen median is always the second smallest element.

## 4. Non-Comparison Sorts

### Counting Sort
Counting Sort sorts $n$ integers that fall within a known range from $0$ to $k$ without comparing elements against one another.

    function CountingSort(A, k):
        for i := 0 to k do
            C[i] := 0                     // Initialize frequency array: Theta(k)

        for j := 0 to length[A] - 1 do
            C[A[j]] := C[A[j]] + 1        // Count frequencies: Theta(n)

        for i := 1 to k do
            C[i] := C[i] + C[i - 1]       // Compute running prefix sums: Theta(k)

        for j := length[A] - 1 downto 0 do // Loop backward to preserve stability: Theta(n)
            C[A[j]] := C[A[j]] - 1        // Decrement first to get the correct 0-based index
            B[C[A[j]]] := A[j]

        return B

- **Running Time:** $\Theta(n + k)$ across all cases. It runs in linear time $\Theta(n)$ when $k = O(n)$.
- **Auxiliary Space:** $\Theta(n + k)$ for the count array $C$ and the output array $B$.
- **Why We Decrement Counts First:** We decrement the count before placing an element to convert the 1-based count from the prefix sum array into a valid 0-based array index.
- **Scan Direction:**
  - Scanning backward from $n - 1$ down to $0$ ensures the sort is **stable**.
  - Scanning forward from $0$ up to $n - 1$ still sorts the array correctly, but **completely reverses the relative order of duplicate elements**.

---

### Radix Sort
Radix Sort breaks multi-digit numbers or fixed-length strings down and sorts them digit by digit using an underlying stable sort (typically Counting Sort).

    function RadixSort(A, d):
        for i := d downto 1 do
            sort array A on digit i using a stable sorting algorithm

- **Direction:** Operates from the least significant digit (LSD) up to the most significant digit (MSD).
- **Running Time:** $\Theta(d(n + k))$ where $d$ is the number of digits and $k$ is the number of possible values per digit.
- **Why Stability Matters:** When sorting on a higher-order digit, equal keys create ties. A stable underlying sort preserves the relative order established by earlier lower-order passes, keeping the numbers sorted overall.
