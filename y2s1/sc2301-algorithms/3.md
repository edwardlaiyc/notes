# Module 3: Graph Traversals, Shortest Paths & Minimum Spanning Trees

## 1. Graph Fundamentals & Traversals

### Ways to Store a Graph

| Storage Method | Memory Used | Time to Find Neighbors of $u$ | Time to Check Edge $(u, v)$ | Best Used For |
| :--- | :---: | :---: | :---: | :---: |
| **Adjacency Matrix** | $\Theta(\vert{}V\vert{}^2)$ | $\Theta(\vert{}V\vert{})$ | $\Theta(1)$ | Graphs with many edges ($\vert{}E\vert{} \approx \vert{}V\vert{}^2$) |
| **Adjacency List** | $\Theta(\vert{}V\vert{} + \vert{}E\vert{})$ | $\Theta(\text{deg}(u))$ | $O(\text{deg}(u))$ | Graphs with few edges ($\vert{}E\vert{} \ll \vert{}V\vert{}^2$) |

- Running Breadth-First Search (BFS) or Depth-First Search (DFS) on an Adjacency Matrix takes $\Theta(\vert{}V\vert{}^2)$ time because the code must read every entry in a row of size $\vert{}V\vert{}$ for each vertex.
- Running BFS or DFS on an Adjacency List takes $\Theta(\vert{}V\vert{} + \vert{}E\vert{})$ time because the code checks only neighbors that actually exist.
- A single run of BFS or DFS from one vertex visits only the vertices connected to that starting vertex.
- To visit every vertex in a disconnected graph, you must wrap the search inside a loop that checks every vertex in the graph.

---

### Tracking Search Progress with Colors
Vertices change colors to track how far the search has progressed:
- `White`: The vertex is unvisited.
- `Grey`: The vertex has been reached, but some of its neighbors are not checked yet (it is currently inside the queue or call stack).
- `Black`: The vertex and all of its direct neighbors are completely finished.

- **The Color Barrier Rule:** An edge can never point directly from a finished `Black` vertex to an unvisited `White` vertex. Any path from explored areas to unvisited areas must pass through a `Grey` vertex.
- **Finding Cycles:** A directed graph has a cycle if and only if DFS hits a neighbor that is currently colored `Grey` (an active ancestor on the call stack).

---

### Search Algorithms

#### 1. Breadth-First Search (BFS)
BFS visits vertices level by level using a queue (First-In, First-Out). It finds the shortest path in an unweighted graph.

    function BFS(Graph G, Vertex s):
        for each vertex u in G.V:
            u.d = infinity
            u.pi = null
            u.color = White
        s.d = 0
        s.color = Grey
        Queue Q = empty
        Q.enqueue(s)

        while Q is not empty:
            u = Q.dequeue()
            for each neighbor v in G.Adj[u]:
                if v.color == White:
                    v.color = Grey
                    v.d = u.d + 1
                    v.pi = u
                    Q.enqueue(v)
            u.color = Black

#### 2. Depth-First Search (DFS) and Ordering
DFS goes as deep as possible down one path before backtracking. Adding finished vertices to the front of a list produces a valid order of tasks for a directed graph without cycles (Topological Sort).

    function DFS(Graph G):
        for each vertex u in G.V:
            u.color = White
            u.pi = null
        List orderList = empty

        for each vertex u in G.V:
            if u.color == White:
                DFS_Visit(G, u, orderList)
        return orderList

    function DFS_Visit(Graph G, Vertex u, List orderList):
        u.color = Grey
        for each neighbor v in G.Adj[u]:
            if v.color == Grey:
                // A cycle exists
            else if v.color == White:
                v.pi = u
                DFS_Visit(G, v, orderList)
        u.color = Black
        orderList.insertFront(u)

## 2. Dijkstra's Algorithm (Shortest Paths from One Starting Vertex)

Dijkstra's algorithm finds the shortest path from a starting vertex $s$ to all other vertices. All edge weights must be zero or positive ($w \ge 0$).

### Code

    function Dijkstra(Graph G, Vertex s):
        for each vertex v in G.V:
            v.d = infinity
            v.pi = null
            S[v] = 0 // S[v] = 1 means the shortest path to v is finalized
        s.d = 0
        PriorityQueue Q = buildMinQueue(G.V) // Uses v.d as the key

        while Q is not empty:
            u = Q.extractMin()
            S[u] = 1

            for each neighbor v in G.Adj[u]:
                if S[v] == 0 and v.d > u.d + w(u, v):
                    v.d = u.d + w(u, v) // Found a shorter path to v
                    v.pi = u
                    Q.decreaseKey(v, v.d)

---

### Running Time & Execution Rules

| Priority Queue Used | Time to Pick Next Node (`extractMin`) | Time to Update Node (`decreaseKey`) | Total Running Time |
| :--- | :---: | :---: | :---: |
| **Simple Array** | $O(\vert{}V\vert{})$ | $O(1)$ | $O(\vert{}V\vert{}^2)$ |
| **Binary Min-Heap** | $O(\log \vert{}V\vert{})$ | $O(\log \vert{}V\vert{})$ | $O((\vert{}V\vert{} + \vert{}E\vert{}) \log \vert{}V\vert{})$ |

- **Subgraphs Rule:** If you delete edges or vertices to make a smaller graph, the shortest path between any two vertices can only stay the same or get longer.
- **Zero Weights Work:** Edges with weight equal to $0$ work correctly in Dijkstra's algorithm.
- **Why Negative Weights Break Dijkstra:** Dijkstra permanently locks in a vertex as finished the moment it extracts it from the priority queue. If an edge has a negative weight, a longer-looking path could become cheaper later, but Dijkstra will never revisit vertices already marked in set $S$.
- **Why Adding a Constant Number Fails:** You cannot fix negative weights by adding a constant number $+C$ to every edge. Paths with more edges get increased by more copies of $C$ than paths with fewer edges, which can change which path is the shortest.

---

### How to Count Shortest Paths
To count how many different paths tie for the shortest distance from $s$ to each vertex:
1. Set `v.paths = 0` for all vertices, and set `s.paths = 1`.
2. When checking neighbor $v$ from vertex $u$:
   - If `v.d > u.d + w(u, v)`: You found a strictly shorter path. Update `v.d = u.d + w(u, v)`, update `v.pi = u`, and reset `v.paths = u.paths`.
   - If `v.d == u.d + w(u, v)`: You found an extra path with the exact same shortest distance. Keep `v.d` unchanged and add to the count: `v.paths = v.paths + u.paths`.

## 3. Minimum Spanning Tree (MST) Rules

A Minimum Spanning Tree of a connected undirected graph is a tree that connects every vertex together with no cycles, using the minimum possible total edge weight. A graph with $\vert{}V\vert{}$ vertices always has exactly $\vert{}V\vert{} - 1$ edges in its tree.

### Core Rules

#### 1. The Cut Rule
If you split the vertices of a graph into two separate groups, the lightest edge connecting group 1 to group 2 is always part of a Minimum Spanning Tree.

#### 2. The Cycle Rule
In any cycle, the strictly heaviest edge can never be part of a Minimum Spanning Tree.

#### 3. Unique Weights Mean One Unique Tree
If every edge in the graph has a different weight, the graph has only one unique Minimum Spanning Tree.

#### 4. Negative Weights Work
Both Prim's algorithm and Kruskal's algorithm work correctly on graphs with negative edge weights. MST algorithms compare individual edge weights to each other rather than adding up distances along a path. Adding a constant number $+C$ to every edge leaves the chosen tree unchanged.

---

### How to Reconstruct a Graph and MST from Clues
When an exam question gives a list of edge weights, a target MST total weight, and specific distances between vertices, use these steps:
1. **Find the Tree Edges:** A graph with $\vert{}V\vert{}$ vertices must use exactly $\vert{}V\vert{} - 1$ edges. Pick the subset of $\vert{}V\vert{} - 1$ weights from the list that adds up to the target MST total weight.
2. **Use Distance Clues to Connect Vertices:** Match the given distance clues between vertices to edges in your chosen tree subset. For example, if the path distance between two vertices in the tree is 3, they are connected by a single edge of weight 3 or a path of tree edges adding up to 3.
3. **Draw the Spanning Tree Backbone:** Draw all $\vert{}V\vert{}$ vertices and connect them using your chosen $\vert{}V\vert{} - 1$ tree edges according to the distance clues.
4. **Add Remaining Edges to the Graph:** Place the unused edge weights between vertices as non-tree edges. Ensure each non-tree edge forms a cycle with the tree where it is the heaviest edge in that cycle, so it never gets chosen over a tree edge.

## 4. Prim's Algorithm

Prim's algorithm starts at one vertex and grows a single tree one edge at a time. In each step, it picks the lightest edge connecting a vertex in the tree to a vertex outside the tree.

### Code

    function Prim(Graph G, Vertex s):
        for each vertex v in G.V:
            v.d = infinity
            v.pi = null
            S[v] = 0 // S[v] = 1 means v is already in the tree
        s.d = 0
        PriorityQueue pq = buildMinQueue(G.V) // Uses v.d as the key

        while pq is not empty:
            u = pq.extractMin()
            S[u] = 1

            for each neighbor v in G.Adj[u]:
                if S[v] == 0 and w(u, v) < v.d:
                    v.d = w(u, v) // Saves the weight of the edge to the tree
                    v.pi = u
                    pq.decreaseKey(v, v.d)

- Dijkstra sets `v.d = u.d + w(u, v)` because it measures distance from the starting source.
- Prim sets `v.d = w(u, v)` because it only cares about the cost of the single edge attaching $v$ directly to the current tree.

## 5. Tracking Connected Groups (Union-Find)

Union-Find keeps track of which elements belong to which groups.

### Comparison of Methods

| Method | Time for `find(p)` | Time for `union(p, q)` | Key Implementation Detail |
| :--- | :---: | :---: | :--- |
| **QuickFind** | $\Theta(1)$ | $\Theta(N)$ | Save original IDs in temporary variables before running the loop. |
| **QuickUnion** | $O(N)$ | $O(N)$ | Follow parent links up to the root; trees can become long single chains. |
| **Weighted QuickUnion** | $O(\log N)$ | $O(\log N)$ | Always attach the smaller tree under the root of the larger tree. |
| **Weighted QuickUnion with Path Compression** | Almost $O(1)$ | Almost $O(1)$ | Flattens tree pointers directly toward the root whenever `find` is called. |

#### Why Weighted QuickUnion Keeps Trees Short
- A node only moves one level deeper when its tree is merged under a tree of equal or larger size.
- Every time a node's depth increases by $1$, the size of its group at least doubles.
- Starting from size $1$, a group can double at most $\log_2 N$ times before reaching the maximum size of $N$ items.
- Therefore, the height of the tree cannot exceed $\log_2 N$.

#### Correct QuickFind Code

    public void union(int p, int q) {
        int pid = id[p]; // Store IDs first so id[p] does not change mid-loop
        int qid = id[q];
        if (pid == qid) return;
        for (int i = 0; i < id.length; i++) {
            if (id[i] == pid) {
                id[i] = qid;
            }
        }
    }

## 6. Kruskal's Algorithm

Kruskal's algorithm sorts all edges from lightest to heaviest. It checks each edge one by one and adds it to the tree if it connects two previously separate groups.

### Code

    function Kruskal(Graph G):
        List mstEdges = empty
        sort G.E from lightest to heaviest // Takes O(|E| log |E|)
        DisjointSet uf = new DisjointSet(G.V) // Starts with |V| separate groups

        for each edge (u, v) in sorted G.E:
            if not uf.connected(u, v):
                uf.union(u, v)
                mstEdges.add((u, v))
                if mstEdges.size() == G.V.size() - 1:
                    break // Stop when we have |V| - 1 edges
        return mstEdges

---

### How the Number of Groups Shrinks
- At the start, there are $\vert{}V\vert{}$ separate groups.
- Each time an edge is accepted, it connects two previously separate groups into one group.
- The total number of groups drops by **exactly 1 for every accepted edge**: $\vert{}V\vert{} \to \vert{}V\vert{} - 1 \to \dots \to 1$.
- When the algorithm finishes, there is exactly 1 group containing all vertices.

### Faster Sorting for Small Integer Weights
- If all edge weights are small integers (such as numbers between $1$ and $\vert{}V\vert{}$), sort the edges using Counting Sort instead of a comparison sort.
- Counting Sort takes $O(\vert{}E\vert{} + \vert{}V\vert{})$ time.
- Processing edges with Union-Find costs $O(\vert{}E\vert{} \log^* \vert{}V\vert{})$, reducing the overall runtime to near-linear time: $O(\vert{}E\vert{} \log^* \vert{}V\vert{})$.

### Finding the Maximum Spanning Tree
- To find a Maximum Spanning Tree instead of a minimum one, sort the edges from heaviest to lightest before running the loop, or negate all edge weights.

## 7. Direct Comparison: Dijkstra vs. Prim vs. Kruskal

| Detail | Dijkstra | Prim | Kruskal |
| :--- | :--- | :--- | :--- |
| **Problem Solved** | Shortest paths from one source | Minimum Spanning Tree | Minimum Spanning Tree |
| **Graph Types** | Directed or Undirected | Connected, Undirected | Connected, Undirected |
| **Works with Negative Weights?** | No | Yes | Yes |
| **How It Chooses Next** | Smallest total distance: $u.d + w(u, v)$ | Lightest edge to tree: $w(u, v)$ | Lightest edge overall: $w(e)$ |
| **Data Structure Used** | Priority Queue | Priority Queue | Priority Queue + Union-Find |
| **Standard Running Time** | $O((\vert{}V\vert{} + \vert{}E\vert{}) \log \vert{}V\vert{})$ | $O((\vert{}V\vert{} + \vert{}E\vert{}) \log \vert{}V\vert{})$ | $O(\vert{}E\vert{} \log \vert{}E\vert{})$ |
| **Best Graph Type** | Any graph with non-negative weights | Dense graphs (many edges) | Sparse graphs (few edges) |
