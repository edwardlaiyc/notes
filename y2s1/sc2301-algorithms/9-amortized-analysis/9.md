# 9. Amortized Analysis

This chapter covers Lecture 9, Amortized Analysis. Chapter 8 found the cost of **one** call of a recursive algorithm. This chapter looks at a different question: the total cost of a **sequence** of operations on a data structure.

Some operations are usually cheap but **sometimes** very expensive. If we charge every operation the expensive price, the bound is far too high. **Amortized analysis** finds the total cost of the whole sequence, then shares it out over the operations.

The lecture gives four methods. They always give the **same** answer. They differ only in how you keep the books.

---

## 1. Why Is Worst-Case-Per-Operation Too Pessimistic?

### 1.1 Three kinds of analysis

| Analysis | The question it answers |
| :--- | :--- |
| Worst case | What is the **largest** cost of one operation? |
| Average case | What is the **expected** cost, over random inputs? |
| Amortized | What is the cost **per operation**, over a whole sequence, in the worst case? |

### 1.2 The running example: a growing array

An array has a fixed size in memory. Suppose we keep inserting elements, and we do not know how many will come. When the array is full, we must:

1. allocate a new, larger array;
2. copy every element into it;
3. insert the new element.

**Growing by one slot is too slow.** Every insertion copies all the elements so far. For $n$ insertions:

$$1 + 2 + \dots + n = \frac{n(n+1)}{2} = \Theta(n^2).$$

**Table doubling.** When the array is full, make the new array **twice** as large. Now copying happens only when the size reaches $1, 2, 4, 8, \dots$

### 1.3 The worst case of one insertion is misleading

With doubling:

* Most insertions cost **1**: write the element.
* An insertion that finds the array full, holding $n$ elements, costs **$n + 1$**: copy $n$, write 1.

So one insertion costs $\Theta(n)$ in the worst case. Multiplying gives $O(n^2)$ for $n$ insertions. That bound is true, but far from tight.

The expensive insertions are **rare**. After a doubling to size $2n$, the next $n - 1$ insertions are all cheap.

![Cost of each insertion with table doubling. Most insertions cost 1. A spike happens at each resize. The flat line is the amortized cost: the total spread evenly.](9-artifacts/doubling-cost-chart.png){width=75%}

### 1.4 What "amortized cost" means

The **amortized cost** of an operation is its fair share of the total cost of a sequence, **in the worst case over all sequences**.

* It is **not** an average over random inputs. No probability is involved.
* It is a guarantee: **any** sequence of $n$ operations costs at most $n$ times the amortized cost.
* One single operation can still be expensive. Only the **total** is bounded.

## 2. Method 1: The Aggregate Method

### 2.1 The idea

Find the **total** actual cost $T(n)$ of $n$ operations, in the worst case. Then divide:

$$\text{amortized cost per operation} = \frac{T(n)}{n}.$$

### 2.2 Table doubling

Start with an array of size 1, and insert $n$ elements. Count the two kinds of work separately.

* **Writing new elements:** 1 per insertion, so $n$ in total.
* **Copying:** at each doubling, the array copies 1, then 2, then 4 elements, and so on, up to the largest power of 2 below $n$. This geometric sum is less than $2n$:

$$1 + 2 + 4 + \dots + 2^{\lfloor \lg n \rfloor} < 2n.$$

Why: $1 + 2 + \dots + 2^j = 2^{j+1} - 1$. Here the largest term is at most $n$, so the sum is at most $2n - 1$.

So

$$T(n) < n + 2n = 3n = O(n), \qquad \frac{T(n)}{n} < 3 = O(1).$$

### 2.3 The lecture's numbers: 8 insertions

| | Cost |
| :--- | :--- |
| Writing 8 elements | $8$ |
| Copying at the doublings | $1 + 2 + 4 = 7$ |
| **Total** $T(8)$ | $15$ |
| Most expensive single insertion (the 5th: copy 4, write 1) | $5$ |

Worst-case-per-operation thinking says $8 \times 5 = 40$. The true total is 15, less than 2 per insertion.

### 2.4 When to use it

The aggregate method works well when you can **count** how often the expensive step happens, and how much it costs each time. Then:

1. add up the cheap steps;
2. add up the expensive steps, often as a geometric sum;
3. divide the total by $n$.

It gives one amortized cost for all operations. If there are several kinds of operation with different costs, the other methods can give each kind its own amortized cost.

## 3. Method 2: The Accounting Method

### 3.1 The idea

Charge each operation a fixed **amortized cost**. It may be more than the actual cost.

* The extra is saved as **credit**. Think of coins in a bank.
* Later, an expensive operation spends the saved coins to pay for its extra work.

The one rule:

> **The bank balance must never go negative.**

If it never goes negative, the total charged is always at least the total actual cost. So the total charged is a valid upper bound.

### 3.2 Table doubling

Charge every insertion **3**:

* **1** pays for writing the new element now.
* **2** are saved as credit, to pay for future copying.

**Why is 2 enough?** Look at the moment the array doubles from size $m$ to $2m$:

* The previous doubling left the array of size $m$ holding $m/2$ elements.
* Since then, $m/2$ new elements were inserted. Each saved 2 coins: $2 \cdot \frac{m}{2} = m$ coins.
* The doubling copies $m$ elements, which costs $m$.

The saved coins pay for the copy exactly. The balance never goes negative.

The lecture writes the same check with $c = 2$ coins per insertion. A doubling with $n$ elements costs $n$. The $n/2$ insertions since the last doubling saved $c \cdot \frac{n}{2} = n$ coins. So the doubling costs $n - n = 0$ beyond what was saved.

**Result.** The total charged is $3n$, so $T(n) \le 3n$. The amortized cost per insertion is $1 + 2 = 3 = O(1)$.

## 4. Method 3: The Charging Method

### 4.1 The idea

When an expensive operation happens, send its bill **back to earlier operations**. Then show that no operation is billed too much in total.

$$\text{amortized cost} = \text{actual cost} - \text{cost it charged to past operations} + \text{cost charged to it by future operations}.$$

### 4.2 Table doubling

* When the array doubles from $m$ to $2m$, the copy costs $\Theta(m)$.
* Charge that cost to the $m/2$ insertions made **since the last doubling**. Each is charged $\Theta(1)$, about 2.
* An insertion is charged **only once**: the next doubling bills only the insertions that come after this one.

So each insertion costs 1 for itself, plus about 2 billed by a later doubling:

$$\text{amortized cost} = 1 + 2 = 3 = O(1).$$

![The charging method on 8 insertions. Each insertion pays 1 for itself and is charged 1 more for a future copy. Each resize spends those charges.](9-artifacts/charging-method.png){width=75%}

### 4.3 Accounting against charging

The two methods are close relatives:

* **Accounting** pays **in advance**: save credit now, spend it later.
* **Charging** bills **afterwards**: the expensive operation sends its bill back to earlier ones.

## 5. Method 4: The Potential Method

### 5.1 The idea

Instead of tracking individual coins, keep **one number**, the **potential** $\Phi$.

* $\Phi$ depends only on the **current state** of the data structure.
* Think of it as stored energy. Cheap operations raise it a little. An expensive operation releases it to pay for itself.

The amortized cost of operation $i$ is its actual cost $c_i$ plus the change in potential:

$$\hat{c}_i = c_i + \Delta\Phi = c_i + \left(\Phi_{\text{after}} - \Phi_{\text{before}}\right).$$

### 5.2 Why this gives a valid bound

Add up the amortized costs of $n$ operations. Each $\Phi_{\text{after}}$ cancels the next $\Phi_{\text{before}}$. Only the first and the last values remain:

$$\sum_{i=1}^{n} \hat{c}_i = \sum_{i=1}^{n} c_i + \Phi_{\text{final}} - \Phi_{\text{initial}}.$$

So if the potential never falls below its starting value ($\Phi_{\text{final}} \ge \Phi_{\text{initial}}$), then

$$\sum_{i=1}^{n} c_i \le \sum_{i=1}^{n} \hat{c}_i.$$

The total amortized cost is an upper bound on the total actual cost. Usually we choose $\Phi$ that starts at 0 and is never negative.

### 5.3 How to choose $\Phi$

Choose $\Phi$ so that:

* it is **low** right after an expensive operation (the expensive operation used it up);
* it **rises** a little with each cheap operation (saving for the next expensive one);
* it is **never below** its starting value.

### 5.4 Table doubling

Let $n$ be the number of elements and $m$ the capacity. Choose

$$\Phi(n, m) = 2n - m.$$

* Right after a doubling, the array is half full: $n = m/2$, so $\Phi = 0$.
* As it fills up, $\Phi$ rises to $m$ (when $n = m$).

**Insertion without doubling.** Actual cost 1. $n$ goes up by 1 and $m$ stays the same:

$$\Delta\Phi = \big(2(n+1) - m\big) - \big(2n - m\big) = 2, \qquad \hat{c} = 1 + 2 = 3.$$

**Insertion with doubling.** Before: $n$ elements, full, so $m = n$. Actual cost: copy $n$, write 1, so $n + 1$. After: $n + 1$ elements, capacity $2n$.

$$\Delta\Phi = \big(2(n+1) - 2n\big) - \big(2n - n\big) = 2 - n,$$

$$\hat{c} = (n + 1) + (2 - n) = 3.$$

Every insertion has amortized cost 3. So the amortized cost is $O(1)$.

![The potential method on 8 insertions. Each column shows n, m, the potential, the actual cost and the change in potential. Every amortized cost is 3 (the first is 2).](9-artifacts/potential-method.png){width=90%}

The potential method is the most systematic of the four. Once you have $\Phi$, each operation's amortized cost is a short calculation.

## 6. The Binary Counter

### 6.1 The setting

A $k$-bit binary counter starts at 0. INCREMENT adds 1. To add 1:

* flip the **trailing 1s** (the run of 1s at the right end) to 0;
* then flip the first 0 to 1.

Examples:

* $0111 \to 1000$ flips 4 bits.
* $1000 \to 1001$ flips 1 bit.

So the actual cost of one increment is

$$c = 1 + (\text{number of trailing 1s}).$$

In the worst case that is $k$ flips. A naive bound for $n$ increments is $O(nk)$.

### 6.2 The aggregate method

Count how often **each bit** flips over $n$ increments:

* bit 0 (the rightmost) flips every time: $n$ times;
* bit 1 flips every second time: $n/2$ times;
* bit 2 flips every fourth time: $n/4$ times;
* and so on.

$$\text{total flips} \le n + \frac{n}{2} + \frac{n}{4} + \dots < 2n.$$

So the amortized cost of one increment is less than 2: $O(1)$.

### 6.3 The potential method (lecture)

**The problem.** An expensive increment flips many 1s to 0. We want a potential that drops by the same amount, so it pays for those flips.

So choose $\Phi$ = the **number of 1s** in the counter. (The lecture writes $c \times$ this number. With cost counted in bit flips, $c = 1$.)

Suppose an increment meets $t$ trailing 1s.

* **Actual cost:** $1 + t$ flips.
* **Change in potential:** $t$ ones become zeros, and one zero becomes a one. So $\Delta\Phi = 1 - t$.
* **Amortized cost:** $\hat{c} = (1 + t) + (1 - t) = 2$.

The $t$ cancels. Every increment costs 2, however many bits it flips. So the amortized cost is $O(1)$.

The counter starts at 0, so $\Phi$ starts at 0. $\Phi$ is never negative. So the bound is valid.

### 6.4 A bound holds only for the operations it was proved for

Every argument above relied on the expensive operation being **rare**: after an expensive step, the structure is in a "cheap" state, and many cheap steps must happen before the next expensive one.

If you add a **new** operation that can put the structure straight back into an expensive state, that reasoning breaks. An adversary can then make **every** operation expensive, and the amortized bound no longer holds. So when a data structure gains a new operation, you must redo the amortized analysis.

## 7. Growing and Shrinking a Table

### 7.1 Why not halve at half full?

Deleting elements leaves the array mostly empty, which wastes memory. A first idea: halve the array when it becomes half full.

This fails. Take an array that is exactly full:

1. Insert one element: it doubles, and is now just over half full.
2. Delete two elements: it is half full, so it halves, and is full again.
3. Repeat.

Each operation can trigger a resize costing $\Theta(n)$. There is no saving at all.

### 7.2 The fix: halve at a quarter full (lecture)

* **Double** when the array is full: from $m$ to $2m$.
* **Halve** when it is only **1/4 full** ($n = m/4$): from $m$ to $m/2$.

After **any** resize, the array is exactly **half full**. So many operations must happen before the next resize:

* to double again, at least $m/2$ insertions since the last resize;
* to halve, more than $m/4$ deletions since the last resize.

### 7.3 The charging argument

* A **doubling** from $m$ to $2m$ costs $\Theta(m)$. Charge it to the $m/2$ insertions since the last resize: $\Theta(1)$ each.
* A **halving** from $m$ to $m/2$ costs $\Theta(m)$. Charge it to the more than $m/4$ deletions since the last resize: $\Theta(1)$ each.
* Each insertion or deletion is charged **only once**.

So both INSERT and DELETE have amortized cost $O(1)$.

### 7.4 The general recipe for any resizing rule

Other rules are possible: grow or shrink at other fill levels, or by other factors. The same reasoning works if you check three things:

1. **After any resize, the table is at a fill level that is far from both triggers.** For example, half full, with triggers at full and at a quarter full.
2. **So reaching the next trigger takes $\Omega(m)$ operations.** Count how many: the gap between the fill level after a resize and the trigger, times the capacity.
3. **The resize costs $O(m)$** (it copies the current elements).

Then the resize cost divided by the number of operations since the last resize is a constant. So each operation's amortized cost is $O(1)$.

With the potential method, choose a $\Phi$ that is **0 right after a resize** and **grows** as the fill level moves away from it, in either direction. For the rule in Section 7.2, one such choice is

$$\Phi = \big|\,2n - m\,\big|.$$

* Right after any resize, $n = m/2$, so $\Phi = 0$.
* Each insertion or deletion without a resize changes $\Phi$ by at most 2. So its amortized cost is $O(1)$.
* At the doubling trigger ($n = m$), $\Phi = m$: enough to pay for copying $m$ elements.
* At the halving trigger ($n = m/4$), $\Phi = m/2$: more than enough to pay for copying $m/4$ elements.

For another rule, change the constant in front of $n$ so that $\Phi$ is 0 at the new "after resize" fill level. Then scale $\Phi$ so that its value at each trigger covers the copying cost.

## 8. Summary of the Four Methods

| Method | What you do | Table doubling result |
| :--- | :--- | :--- |
| Aggregate | Total cost $T(n)$, divided by $n$ | $T(n) < 3n$, so $O(1)$ |
| Accounting | Charge a fixed price; save the extra as credit; credit never negative | Charge 3: 1 now, 2 saved |
| Charging | Expensive operation bills earlier operations; each billed once | 1 + about 2 billed = 3 |
| Potential | $\hat{c}_i = c_i + \Phi_{\text{after}} - \Phi_{\text{before}}$; $\Phi$ never below its start | $\Phi = 2n - m$ gives 3 |

All four give the same amortized bound.

---

## 9. Common Traps

* Amortized cost is **not** average-case cost. It needs no probability. It bounds the total of **any** sequence, in the worst case.
* A single operation can still cost much more than its amortized cost.
* Table doubling: one insertion is $\Theta(n)$ in the worst case, but $O(1)$ amortized.
* Growing the array by a **constant** number of slots gives $\Theta(n^2)$ total. Growing by a constant **factor** gives $O(n)$ total.
* In the accounting method, the credit must never go negative.
* In the potential method, use $\hat{c} = c + \Phi_{\text{after}} - \Phi_{\text{before}}$. Check that $\Phi$ never falls below its initial value.
* $\Delta\Phi$ is "after minus before". Getting the sign backwards gives nonsense, such as negative amortized costs for cheap operations.
* Shrink at **1/4 full**, not 1/2 full. Halving at 1/2 lets insert-delete pairs trigger a resize every time.
* An amortized bound is proved for a fixed set of operations. Adding an operation can break it.
* Amortized analysis never makes an algorithm faster. It only shows that the total was smaller than the per-operation worst case suggested.
* All four methods give the same answer.
