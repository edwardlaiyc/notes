All topics

1. Foundations: asymptotic notation, insertion sort

Facts

Give the formal definitions of f=O(g), f=\Omega(g) and f=\Theta(g).

Answer
  • f = O(g): there exist c>0 and n_0 with 0 \le f(n) \le c\,g(n) for all n \ge n_0.
  • f = \Omega(g): there exist c>0 and n_0 with 0 \le c\,g(n) \le f(n) for all n \ge n_0.
  • f = \Theta(g): there exist c_1, c_2 > 0 and n_0 with c_1 g(n) \le f(n) \le c_2 g(n) for all n \ge n_0. Equivalently, f = O(g) and f = \Omega(g).

How do o and \omega differ from O and \Omega in the definition?

Answer

O, \Omega, \Theta need some constant c (\exists c). o and \omega need the inequality for every constant c>0 (\forall c), with n_0 depending on c. So f=o(g) means f is strictly smaller in growth: f(n)/g(n)\to 0.

State the limit test with L=\lim_{n\to\infty} f(n)/g(n). When does it fail?

Answer
  • L=0: f=o(g) (so also O(g)).
  • 0<L<\infty: f=\Theta(g).
  • L=\infty: f=\omega(g) (so also \Omega(g)).

It fails when the limit does not exist (for example f oscillates). Then go back to the definition with explicit c and n_0.

Is \log_2 n=\Theta(\log_{10} n)? Is 2^n=\Theta(3^n)?

Answer

The first is true: \log_a n=\log_b n/\log_b a, a constant factor, so the base does not matter inside \Theta. The second is false: 3^n/2^n=(3/2)^n\to\infty. A base in an exponent changes the growth rate.

Order these from slowest to fastest growth: n!,\ n^2,\ \log n,\ 2^n,\ n\log n,\ n,\ n^3,\ 1.

Answer

1 < \log n < n < n\log n < n^2 < n^3 < 2^n < n!

What is the best-case and worst-case input for insertion sort, with comparison counts?

Answer
  • Best: already sorted. n-1 comparisons, 0 swaps, \Theta(n).
  • Worst: strictly decreasing. \frac{n(n-1)}{2} comparisons and swaps, \Theta(n^2).

How is the number of swaps in insertion sort related to inversions?

Answer

The number of swaps equals the number of inversions (pairs i<j with a_i>a_j). Each swap fixes exactly one inversion. So swaps \le comparisons always.

Define a stable sort and an in-place sort. Which sorts in this course are stable? In-place?

Answer
  • Stable: equal keys keep their input order.
  • In-place: uses only O(1) extra memory (quicksort’s recursion stack is usually still counted as in-place).
  • Stable: insertion sort, mergesort (with the usual “take left on ties” merge; the lecture’s merge pseudocode is not stable with duplicates, see AY21/22 S2 1(b)), counting sort (backward loop), radix sort. Not stable: heapsort, quicksort.
  • In-place: insertion sort, heapsort, quicksort. Mergesort needs an O(n) buffer.

Write the three steps of a loop invariant proof.

Answer
  • Initialisation: the invariant is true before the first iteration.
  • Maintenance: if it is true before an iteration, it is true before the next.
  • Termination: when the loop stops, the invariant plus the exit condition gives the property we want (correctness).

What is the loop invariant of insertion sort’s outer loop?

Answer

At the start of the iteration for index i, the subarray A[0..i-1] holds the original first i elements, in sorted order. At termination i=n, so the whole array is sorted.

Prove: if f_1=O(g) and f_2=O(g), then f_1+f_2=O(g). Which constants do you pick?

Answer

Take f_1\le c_1 g for n\ge n_1 and f_2\le c_2 g for n\ge n_2. For n\ge\max(n_1,n_2) both hold, so f_1+f_2\le(c_1+c_2)g. The witnesses are c=c_1+c_2 and n_0=\max(n_1,n_2).

Problems

Problem 1: a function that defeats the limit test

(a) Let f(n)=n(2+\sin n) and g(n)=n. Does \lim f/g exist? Which of O, \Omega, \Theta relate f and g?

Answer

f/g=2+\sin n oscillates between 1 and 3, so the limit does not exist. But 1\cdot g\le f\le 3g for all n\ge1, so f=\Theta(g) with c_1=1, c_2=3, n_0=1. The limit test only fails to decide; it does not say the relation is false.

(b) Now f(n)=n^{1+\sin n} (an exponent that oscillates) and g(n)=n. Is f=O(g)? Is f=\Omega(g)?

Answer

Neither. When \sin n is close to 1, f\approx n^2, which beats every c\,n. When \sin n is close to -1, f\approx n^0=1, which falls below every c\,n. Since n takes values arbitrarily close to both extremes infinitely often, no c,n_0 work in either direction. This is the “two functions that cannot be compared” case of Tutorial 1.

(c) Link to sorting: insertion sort runs on an array with exactly k inversions. State its running time in terms of n and k.

Answer

\Theta(n+k). It makes one pass for the n-1 outer iterations plus exactly k swaps. So it is linear when k=O(n) (“nearly sorted”) and quadratic when k=\Theta(n^2). This is why insertion sort is used for small or almost-sorted arrays.

AY24/25 S2 1(a) To sort the input array into ascending order, give the number of key comparisons and the number of swaps made by in-place Insertion Sort (lecture version). (i) The input array is [1,2,3,4,5,6]. (ii) The input array is [1,2,1,2,1,2].

Answer

Lecture code: for each i, swap slot[j] with slot[j-1] while slot[j] < slot[j-1]; stop at the first comparison that fails (or when j=0). Each comparison counts once, and each swap happens only when its comparison is true.

  • (i) 5 comparisons, 0 swaps. Each of the 5 keys is compared once with its left neighbour, which is smaller, so the loop stops at once.
  • (ii) 8 comparisons, 3 swaps.
i key array after the step comparisons swaps
1 2 1 2 1 2 1 2 1 0
2 1 1 1 2 2 1 2 2 1
3 2 1 1 2 2 1 2 1 0
4 1 1 1 1 2 2 2 3 2
5 2 1 1 1 2 2 2 1 0

Equal keys never swap (the test is strict), so the duplicates also show that insertion sort is stable.

Link. Swaps = number of inversions: [1,2,1,2,1,2] has exactly 3 pairs out of order (the 2 at index 1 with the 1s at indices 2 and 4, and the 2 at index 3 with the 1 at index 4). Comparisons = swaps + one failing comparison per key that does not reach the front, here 3+5=8. Both counts come from the inversion count, which mergesort can also compute (see the mixed page).

AY23/24 S2 1(a) Consider the in-place Insertion Sort algorithm taught in the lecture. (i) If the input array has n elements, how many key comparisons are required exactly for the best case? (ii) … exactly for the worst case? (iii) … exactly for the average case?

Answer

Lecture code: for each i=1..n-1, swap slot[j] with slot[j-1] while slot[j] < slot[j-1], starting at j=i; stop at the first failing comparison or when j=0. Every test counts as one comparison.

  • (i) Best: n-1. Sorted input: each key is compared once with its left neighbour and stays.
  • (ii) Worst: n(n-1)/2. Reversed input: key i travels all the way to the front, making i comparisons (it never fails, since it stops at j=0 without a test): 1+2+\dots+(n-1).
  • (iii) Average: \dfrac{n^2+3n}{4}-H_n\approx\dfrac{n^2}4, where H_n=1+\frac12+\dots+\frac1n.

Derivation of (iii). Comparisons = swaps + (one failing comparison for every key that does not reach the front).

  1. Swaps = number of inversions. Each of the \binom n2 pairs is inverted with probability \frac12, so the average is \frac{n(n-1)}4.
  2. Key i (0-indexed, i\ge1) reaches the front exactly when it is smaller than all i keys before it, which has probability \frac1{i+1}. The expected number of such keys is \sum_{i=1}^{n-1}\frac1{i+1}=H_n-1.
  3. So the average is \frac{n(n-1)}4+(n-1)-(H_n-1)=\frac{n(n-1)}4+n-H_n=\frac{n^2+3n}4-H_n.

Checked against all n! permutations for n=2..8 (for example n=6: 11.05, n=8: 19.28). If your course counts “swaps +\,(n-1)” and ignores the early stop at the front, the average is \frac{n(n-1)}4+n-1; both are \Theta(n^2), about n^2/4.

Link. Best, average and worst are n-1, \approx n^2/4 and n^2/2: the average is exactly half the worst to first order, because a random pair is inverted with probability \tfrac12. The same inversion count controls bubble sort’s swaps (see AY2324 S1 1(b)).

AY23/24 S1 1(a)(i) True or False? Suppose we run Insertion Sort on N elements. If we use an “insert” operation on a linked list instead of “swap” on continuous memory, we can achieve better than O(N^2) time complexity.

Answer

False. A linked list makes the move cheap: once the position is known, the key is linked in with O(1) work and nothing is shifted. But the algorithm must still find the position by comparing the key with the sorted part one key at a time, because a list has no random access (binary search is impossible). That costs \sum_{i=1}^{N-1} i=N(N-1)/2 comparisons in the worst case and about N^2/4 on average, so the total is still \Theta(N^2).

Link. Insertion sort pays for finding the place plus making room. An array can binary-search the place (O(\lg i)) but must shift (O(i)). A linked list inserts in O(1) but must scan (O(i)). One of the two is always linear, so both are \Theta(N^2). Only a structure where both are logarithmic (a heap or a balanced tree) breaks the barrier. That is the idea of heapsort.

AY23/24 S1 1(b) Use big-O notation to analyse the sorting algorithm bubbleSort in Figure Q1. (i) What is the best-case time complexity in terms of the “swap” operation? When does the best case happen? (ii) What are the best-case, average-case and worst-case time complexities in terms of the number of comparisons?

Answer

Each pass of the for loop bubbles the largest remaining key to the end, so n = n-1 shrinks the range by one. The repeat loop stops after the first pass that makes no swap.

(i) O(1), in fact exactly 0 swaps. It happens when the input is already sorted: the first pass finds no arr[i-1] > arr[i], swapped stays false, and the loop ends. (Swaps always equal the number of inversions, so 0 swaps means sorted.)

(ii)

case input comparisons complexity
best sorted: one pass n-1 O(n)
worst reversed: every pass swaps; pass p makes n-p comparisons (n-1)+(n-2)+\dots+1=\dfrac{n(n-1)}2 O(n^2)
average random order between those two; see below O(n^2) (in fact \Theta(n^2))

Why the average is quadratic. Each pass reduces by exactly 1 the count of larger keys to the left of every key, so the number of passes is 1+\max_j L_j, where L_j is that count for key j (checked for all permutations of up to 7 keys). In a random permutation L_n for the last position is uniform on 0,\dots,n-1, so with probability at least \tfrac12 there are more than n/2 passes. Each of the first n/2 passes makes at least n/2 comparisons. So the cost is at least n^2/4 with probability at least \tfrac12, and the average is \Omega(n^2). With the O(n^2) worst case this gives \Theta(n^2). Exact averages over all inputs: 13.88 comparisons for n=6 (worst 15) and 26.0 for n=8 (worst 28).

(The circulated solution writes the worst case as n(n-1). That forgets the line n = n-1; the correct count is n(n-1)/2. The big-O is the same.)

Link. Bubble sort and insertion sort make the same number of swaps on every input (both equal the number of inversions). Bubble sort compares more: averaged over all 8! inputs of 8 keys, 26.0 comparisons against 19.3 for the lecture insertion sort, because bubble sort keeps scanning the sorted tail while insertion sort stops at the first smaller key. Both are \Theta(n) on sorted input and \Theta(n^2) otherwise. Code: verify/v_pyp_2324.py.

AY22/23 S2 1(a) Consider the in-place Insertion Sort algorithm taught in the lecture. (i) If the input array has n elements, how many iterations (of the outer loop) are needed to sort the input array in ascending order? (ii) What are the time complexities, in big-O, for the best, worst and average cases? (iii) If the input array A has seven elements 1,3,5,7,2,4,6, what is the order of the elements to be the best case? What is the order to be the worst case? Give an example of the order for the two cases.

Answer

(i) n-1. The outer loop runs i=1,2,\dots,n-1 (the first element is already a sorted prefix of length 1), whatever the input.

(ii) Best case O(n) (sorted input: n-1 comparisons, no swaps). Worst case O(n^2) (reversed input: n(n-1)/2 comparisons and swaps). Average case O(n^2) (about n^2/4 swaps, each pair being inverted with probability \tfrac12).

(iii) The seven keys are \{1,2,3,4,5,6,7\}.

  • Best case: already ascending: [1,2,3,4,5,6,7], with 6 comparisons and 0 swaps.
  • Worst case: descending: [7,6,5,4,3,2,1], with 21 comparisons and 21 swaps.

For reference the given order [1,3,5,7,2,4,6] needs 12 comparisons and 6 swaps (it has 6 inversions: each of 3, 5 and 7 is above the 2, and 5 and 7 are above the 4, and 7 is above the 6, making 3+2+1=6) (checked by code).

Link. The count of outer iterations is fixed (n-1); what varies is the inner loop, from 1 test per key to i tests per key. Best and worst correspond to 0 and \binom n2 inversions. See the average-case formula \frac{n^2+3n}4-H_n on the AY2324 S2 1(a) answer.

AY21/22 S1 1(a) (MCQ, choose one) A weak point of the InsertionSort algorithm is: A. Perform poorly when the unordered list is almost sorted. B. When starting, some entries may not be in the final position. C. For a new insertion, movements for inserted entries in ordered list are always performed. D. When an entry is inserted, it may still not be in the final position. E. For a new insertion, movements for inserted entries in ordered list are not performed. F. When completed, some entries may still not be in the final position.

Answer

D.

  • A false: insertion sort is good on an almost sorted list, about one comparison per key (\approx n in total).
  • B is true of any algorithm before it has finished, so it is not a weakness of this one.
  • C false: if the new key is already at least as large as the end of the sorted part, nothing moves.
  • D true: the sorted prefix is only sorted, not final. A later, smaller key pushes earlier keys one place to the right, so a key can move many times.
  • E false: movements happen whenever the new key is smaller than its left neighbour.
  • F false: when the algorithm has finished, every key is in its final position.

Link. Take [3,1,2]: the 3 moves from index 0 to 1 when 1 is inserted, and moves again to index 2 when 2 is inserted. Contrast selection sort, which puts each key in its final place and never moves it again. This repeated movement is why insertion sort makes \Theta(n^2) moves on reversed input, and why it is still the right tool when the input is nearly sorted (few keys have to move).

AY18/19 S2 1(a) Let f(n)=10^n and g(n)=n!, where n is a positive integer. State whether f is in O(g); whether f is in \Omega(g); and whether f is in \Theta(g). Justify your answers.

Answer

Compare the growth with the ratio \frac{f(n)}{g(n)}=\frac{10^n}{n!}=\frac{10}1\cdot\frac{10}2\cdot\frac{10}3\cdots\frac{10}n. The first ten factors are at least 1 (\frac{10}j\ge1 for j\le10), but from j=11 on each factor is below 1, and for j\ge20 each factor is at most \frac12. So for n>20 \frac{10^n}{n!}=\frac{10^{20}}{20!}\prod_{j=21}^{n}\frac{10}j\le\frac{10^{20}}{20!}\Big(\frac12\Big)^{n-20}\longrightarrow0. (The ratio rises to its maximum \approx2756 at n=9 and n=10 and then falls: 41.1 at n=20, 0.0038 at n=30.)

  • f\in O(g): true. The ratio tends to 0, so it is bounded: 10^n\le c\cdot n! for all n\ge1 with c=2756 (its maximum).
  • f\in\Omega(g): false. 10^n\ge c\,n! would need the ratio to stay above c>0, but it tends to 0.
  • f\in\Theta(g): false, since \Omega fails.

Link. The factorial beats every exponential c^n (the factors c/j eventually go below 1), but the crossover can be late: here 10 and the maximum is at n=10. Exponentials are not “one level”: 2^n\ll3^n\ll n!\ll n^n. Compare AY1819 S1 2(a)(ii), where the exponentials a^{n+1} and (a+1)^n have a limit 0 for the same reason.

AY18/19 S1 1(a) State TRUE or FALSE for each of the following statements. (i) If f(n)\in O(g(n)), f(n) is bounded above by the function g(n). (ii) If f(n)\in\Omega(g(n)) and g(n)\in\Omega(f(n)), then f(n)\in\Theta(g(n)). (iii) The best-case time complexity of binary search is \Theta(\log n). (iv) The worst-case time complexity of inserting a new item into a hash table using chained hashing is n, where n is the number of items in the hash table. (v) If any NP-complete problem is in P, we have P=NP.

Answer

(i) True, in the sense of the definition: f(n)\le c\,g(n) for some constant c>0 and all n\ge n_0. (Strictly, “bounded above by g” hides the constant c and the threshold n_0.)

(ii) True. g\in\Omega(f) means g(n)\ge c_1f(n) for large n, i.e. f(n)\le\frac1{c_1}g(n), so f\in O(g). Together with f\in\Omega(g) this is f\in\Theta(g).

(iii) False. The best case of binary search is \Theta(1): the key is the middle element and is found at the first probe. \Theta(\log n) is the worst and the average case. (The circulated solution marks (iii) as True. That is correct only for a version of binary search that never stops early and always narrows the range to one element; the lecture’s analysis, W(n)=W(n/2)+2, is for the worst case.)

(iv) True (hash tables are not in your course). If the insertion first checks that the key is absent, the whole chain must be scanned; in the worst case all n items hash to the same slot, so the chain has n items: \Theta(n). (If duplicates are not checked, inserting at the head of the chain is O(1).)

(v) True. Every problem in NP reduces to an NP-complete problem in polynomial time. If that problem is solvable in polynomial time, then so is every problem in NP, so NP \subseteq P, and P \subseteq NP always holds.

Link. Statement (ii) is the symmetric characterisation of \Theta: f\in\Theta(g) exactly when each bounds the other from above (equivalently each from below). Statement (v) is the reason all NP-complete problems stand or fall together (AY2324 S2 4(b)(ii)).

AY18/19 S1 2(a) For each of the following pairs of functions f(n) and g(n), show with a formal justification whether f is in O(g), whether f is in \Omega(g) and whether f is in \Theta(g). (i) f(n)=\log_2n, g(n)=\log_4(n^2). (ii) f(n)=a^{n+1}, g(n)=(a+1)^n.

Answer

(i) g(n)=\log_4(n^2)=2\log_4n=2\cdot\dfrac{\log_2n}{\log_24}=2\cdot\dfrac{\log_2n}2=\log_2n=f(n). So f(n)=g(n) for all n, and with c=1, n_0=1 both f\le g and f\ge g hold. f\in O(g): true. f\in\Omega(g): true. f\in\Theta(g): true.

(ii) Take a to be a positive constant. Then \frac{f(n)}{g(n)}=\frac{a\cdot a^n}{(a+1)^n}=a\Big(\frac a{a+1}\Big)^n\longrightarrow0\quad(n\to\infty), because 0<\frac a{a+1}<1.

  • f\in O(g): true. With c=a and n_0=1: a^{n+1}=a\cdot a^n\le a\,(a+1)^n.
  • f\in\Omega(g): false. Suppose f(n)\ge c\,g(n) for some c>0 and all large n. Then a(\frac a{a+1})^n\ge c, which fails once n>\log_{(a+1)/a}(a/c), since the left side tends to 0.
  • f\in\Theta(g): false, since \Omega fails.

Link. Both parts reduce to one rule: look at the limit of f/g. A limit of a positive constant gives \Theta (here (i), the limit is 1); a limit of 0 gives O but not \Omega (here (ii)); a limit of \infty gives the reverse. The base of an exponential matters (a^n versus (a+1)^n), the base of a logarithm does not.

AY17/18 S1 2(a) For each of the following pairs of functions f(n) and g(n), show with a brief justification whether f is in O(g), whether f is in \Omega(g) and whether f is in \Theta(g). (i) f(n)=\log_2n; g(n)=\log_4(n^4+n). (ii) f(n)=2^n; g(n)=3^{n/2}.

Answer

(i) g(n)=\log_4(n^4+n)=\log_4\!\big(n^4(1+n^{-3})\big)=4\log_4n+\log_4(1+n^{-3})=2\log_2n+o(1). Hence \frac{f(n)}{g(n)}=\frac{\log_2n}{2\log_2n+o(1)}\longrightarrow\frac12. A positive constant limit means f\in\Theta(g): O true, \Omega true, \Theta true. (Numerically 0.4999, 0.5, 0.5, 0.5 for n=10,10^3,10^6,10^{12}.)

(ii) g(n)=3^{n/2}=(\sqrt3)^n\approx1.732^n, so \frac{f(n)}{g(n)}=\Big(\frac2{\sqrt3}\Big)^n\longrightarrow\infty, because \frac2{\sqrt3}\approx1.155>1. So f grows faster: O false, \Omega true, \Theta false.

Link. The same recipe as AY1819 S1 2(a): take the limit of f/g. In (ii) the trap is the exponent n/2: 3^{n/2} is smaller than 2^n (since \sqrt3<2), although “3 is bigger than 2”.

Answer

AY17/18 S1 3(d) A sorting algorithm is called stable if elements of equal keys remain their original order after being sorted by the algorithm. For each of the three sorting algorithms (i.e. Insertion sort, Mergesort and Quicksort), decide if it is stable. If you believe an algorithm is not stable, give an example to show that the order of two elements with equal keys is changed by the algorithm.

Answer
  • Insertion sort: stable. A key moves left only while it is strictly smaller than its left neighbour, so an equal key stops behind its twin.
  • Mergesort: stable with the usual merge (on equal heads take the left one first): equal keys never overtake each other and each half is stable by induction. This is the intended answer. Caveat: the lecture’s merge pseudocode takes one equal head from each half; with duplicates in the left half that can reorder them, e.g. [2_a,2_b,2_c]\to[2_a,2_c,2_b] (see AY21/22 S2 1(b)).   • Quicksort: not stable, because partitioning swaps keys that are far apart. The two 1’s have changed order (1_b before 1_a). (Checked by running the lecture partition.)

Link. What makes quicksort and heapsort unstable is the same: a swap over a distance jumps a key over equal keys in between. Insertion sort (adjacent swaps) and the stable merge never do. Radix sort needs the stable kind (Tutorial 3 Q2 and the links page, Problem 5).

AY16/17 S2 1(a) State TRUE or FALSE for each of the following statements. (i) Given that f(n)\in O(g(n)), we say that f(n) is the asymptotic upper bound for g(n). (ii) If f(n)\in\Omega(g(n)), then g(n)\in\Theta(f(n)). (iii) Given f(n)=100n+3\log(n), then f(n)\in\Omega(n). (iv) The average time complexity of searching in a hash table using chained hashing is O(l), where l is the load factor of the table. (v) If a problem is in NP, it cannot be solved by a deterministic algorithm in polynomial time.

Answer

(i) False. The roles are reversed: f\in O(g) means g is an asymptotic upper bound for f.

(ii) False. f\in\Omega(g) only says g\in O(f) (g grows no faster than f). g\in\Theta(f) would need the reverse bound too. Counter-example: f=n^2, g=n: f\in\Omega(g) but g\notin\Theta(f).

(iv) True in the usual reading (hash tables are not in your course). With chaining and a good hash function the expected cost of a search is \Theta(1+l): the table lookup plus an expected chain of length l. (v) False. Every problem in P is also in NP (P\subseteq NP): a polynomial-time algorithm is its own verifier. What is not known is whether all NP problems can be solved in polynomial time.

Link. (i) and (ii) test the direction of the notation: f\in O(g) reads “f is at most g”, \Omega is the reverse, and \Theta is both. Compare AY1819 S1 1(a)(ii), where \Omega in both directions gave \Theta.

AY16/17 S2 2(b) Given three functions f(n), g(n) and h(n) such that f(n)\in\Theta(h(n)) and g(n)\in\Theta(h(n)), show that f(n)+g(n)\in\Theta(h(n)) with a formal proof.

Answer

Assume the functions are non-negative (as running times are). By definition of \Theta there are constants c_1,c_2,n_1 and d_1,d_2,n_2 with c_1h(n)\le f(n)\le c_2h(n)\ (n\ge n_1),\qquad d_1h(n)\le g(n)\le d_2h(n)\ (n\ge n_2). For all n\ge n_0=\max(n_1,n_2) add the inequalities: (c_1+d_1)\,h(n)\le f(n)+g(n)\le(c_2+d_2)\,h(n). The constants c_1+d_1>0 and c_2+d_2 do not depend on n, so f(n)+g(n)\in\Theta(h(n)). \blacksquare

Link. This is the “sum rule”: the cost of two phases of the same order is that order. It is why a loop followed by a loop is not worse than the larger one, and why building a heap (\Theta(n)) before n deletions (\Theta(n\lg n)) leaves heapsort at \Theta(n\lg n). (For sums of different orders the larger wins, which is a different rule.)

AY16/17 S2 3(a) A sorting algorithm is called stable if it preserves the original order of any two equal elements in its input. For each of the two sorting algorithms, Mergesort and Quicksort, is it stable or not? Briefly justify your answers.

Answer

Quicksort is not stable. Partitioning swaps keys that are far apart, so an equal key can jump over another one. Example with the lecture’s partition (middle pivot, keys < pivot go left): [3,5,1_a,1_b]\to[1_b,3,1_a,5]; the two 1’s changed order. (Checked by running the partition.)

Mergesort is stable when the merge takes the left element first on equal keys. Every merge outputs the left list’s key before an equal key of the right list, and by induction each half is already stable, so equal keys keep their order. Example: [4,3_a,3_b,5,1] sorts to [1,3_a,3_b,4,5]. The same algorithm becomes unstable if the merge takes the right element first on a tie ([1,3_b,3_a,4,5]).

Caveat on the lecture: the lecture’s merge pseudocode takes one equal head from each half on a tie. With duplicates inside the left half that can reorder them ([2_a,2_b,2_c]\to[2_a,2_c,2_b]); see AY21/22 S2 1(b). The intended answer to this question is “stable”.

Link. Stability is a property of the tie rule of the merge, not of divide and conquer. It matters when you sort records by one field after another (radix sort needs it).

AY16/17 S2 3(c) Show that the average-case time complexity of Insertion sort, measured in the number of key comparisons performed on an array of size n, is approximately n^2/4.

Answer

Insertion sort makes one swap per inversion (a pair i<j with A[i]>A[j]), and the number of comparisons is the number of swaps plus at most one failing comparison per key, so \#\text{inversions}\ \le\ \#\text{comparisons}\ \le\ \#\text{inversions}+(n-1). For a random permutation each of the \binom n2 pairs is inverted with probability \frac12 (swapping the two values turns an inverted pair into a non-inverted one, so the two cases are equally many). By linearity of expectation E[\#\text{inversions}]=\frac12\binom n2=\frac{n(n-1)}4. Therefore the average number of comparisons is \dfrac{n(n-1)}4+O(n)=\dfrac{n^2}4+O(n)\approx\dfrac{n^2}4. \blacksquare

Exact value (derived on AY2324 S2 1(a)): \dfrac{n^2+3n}4-H_n with H_n=1+\frac12+\dots+\frac1n. Brute-force averages over all n! permutations: 4.92, 7.72, 11.05, 14.91 for n=4,5,6,7 against n^2/4=4,6.25,9,12.25; the gap is the O(n) term. (The circulated solution gets \frac{n^2+n}4-\frac12 by averaging i comparisons per key with probability \frac1i each, which has the same leading term.)

Link. The best case is n-1, the worst case n(n-1)/2 and the average \approx n^2/4 comparisons, exactly the midpoint: a random input has half of the possible inversions.

AY15/16 S2 1(a) State TRUE or FALSE for each of the following statements. (i) Given that f(n)\in\Omega(g(n)), we can derive that f(n) is the asymptotic upper bound for g(n). (ii) If f(n)\in O(g(n)), then f(n)\in\Theta(g(n)). (iii) If f(n)\in O(g(n)) and g(n)\in\Theta(h(n)), then f(n)\in O(h(n)). (iv) NP means Non-Polynomial time complexity. (v) If an NP-Hard problem can be solved in polynomial time, it implies that P = NP.

Answer

(i) True. f\in\Omega(g) means f(n)\ge c\,g(n) for large n, i.e. g(n)\le\frac1cf(n), so g\in O(f): f is an asymptotic upper bound for g.

(ii) False. O is only an upper bound. Counter-example: f(n)=n, g(n)=n^2: f\in O(g) but f\notin\Theta(g).

(iii) True. f\le c_1g and g\le c_2h for large n (the \Theta gives an upper bound with some c_2), so f\le c_1c_2h.

(iv) False. NP means Nondeterministic Polynomial time: decision problems whose YES answers can be verified in polynomial time. It does not mean “not polynomial” (every problem in P is in NP).

(v) True. Every problem in NP reduces in polynomial time to an NP-hard problem. If the NP-hard problem has a polynomial-time algorithm, so does every NP problem: NP \subseteq P, and since P \subseteq NP, P = NP.

Link. (i) and (iii) are the transitivity and reversal rules of O/\Omega/\Theta, and (v) is the reduction logic of the NP page. Compare AY1617 S2 1(a) and AY1819 S1 1(a), which test the same notation.

AY15/16 S2 3(b) Given an array A of n elements, an inversion in A is defined as a pair of indices (i,j) such that i<j and A[i]>A[j]. (i) Give an example array of n elements with \Theta(n^2) inversions. Justify your answer. (ii) Show that the running time of the Insertion sort algorithm, measured by the number of swaps between array elements, is O(n+I), where I is the number of inversions in the input array of n elements.

Answer

(i) The reversed array [n,n-1,\dots,1]: every pair i<j is an inversion, so there are \binom n2=\frac{n(n-1)}2=\Theta(n^2) inversions. (Check for n=6: 15.)

(ii) Insertion sort swaps adjacent keys A[j-1]>A[j], and each such swap removes exactly one inversion (the pair that was swapped) and creates none. The sorted array has 0 inversions, so the number of swaps is exactly I. The remaining work is the outer loop (n-1 iterations) and at most one failing comparison per key, \le n-1. So the total is \#\text{swaps}+\#\text{comparisons}\le I+(I+n-1)=O(n+I).\ \blacksquare (Verified on 300 random arrays: swaps =I and comparisons \le I+n-1 every time.)

Tutorial 1 Q1. Other worst cases for insertion sort

The worst case for insertion sort occurs when the input list contains the keys a_1 < \dots < a_n in decreasing order: [a_n, \dots, a_1]. Suppose the performance of insertion sort is measured by the total number of comparisons between array elements (not counting the number of swaps). Show at least two other initial arrangements of keys that are also worst cases for insertion sort.

Concepts: when does one insertion make the most comparisons?

Insertion sort takes the next element, slot[i], and compares it with its left neighbour, again and again.

  • If the left neighbour is bigger, the two swap.
  • If the left neighbour is not bigger, the loop stops. That costs one comparison.
  • If the element reaches index 0, the loop stops with no further comparison.

So iteration i makes between 1 and i comparisons. The worst total is 1 + 2 + \dots + (n-1) = \frac{n(n-1)}{2}. Every iteration must make i comparisons to reach it.

Answer

Two other worst cases:

(n, n-1, n-2, \dots, 3, 1, 2) \qquad \text{and} \qquad (1, n, n-1, n-2, \dots, 2).

In each list, the i-th key still needs i comparisons to find its place. But a comparison is not always followed by a swap.

  • (n, n-1, \dots, 3, 1, 2). Every key up to 1 is smaller than everything on its left, so it travels to index 0. The last key, 2, swaps past n, \dots, 3. Then it compares with 1, which is smaller, and stops. That last comparison has no swap, but it is still the i-th comparison.
  • (1, n, n-1, \dots, 2). Each new key is smaller than every key on its left except 1. It swaps all the way to index 1, then compares with 1 and stops. Again i comparisons.
General method: test an input for the comparison worst case

Iteration i makes all i comparisons exactly when the new element reaches index 1. After that, either it moves to index 0, or the element at index 0 stops it. Both cost i comparisons.

So an input is a worst case for comparisons when each new element is smaller than every element on its left, except possibly the smallest one.

  • Check this for each position from left to right.
  • Comparisons and swaps are different counts. Swaps equal the number of inversions (pairs in the wrong order). Only the reversed array has the most swaps, \frac{n(n-1)}{2}.

Extension 1.1. Insertion sort runs on the array [2, 4, 3, 1]. Count the comparisons and the swaps. Is this array a worst case for comparisons? Is it a worst case for swaps?

Answer (Extension 1.1)
Iteration Element What happens Comparisons Swaps
1 4 4 against 2: not smaller, stop 1 0
2 3 swaps past 4, then 3 against 2: stop 2 1
3 1 swaps past 4, 3 and 2, reaches index 0 3 3

Comparisons: 1 + 2 + 3 = 6 = \frac{4 \cdot 3}{2}. So it is a worst case for comparisons. Each new element is smaller than everything on its left except the smallest, as the method says.

Swaps: 4, which equals the inversions (2,1), (4,3), (4,1), (3,1). The maximum is 6. So it is not a worst case for swaps.

Tutorial 1 Q2. Theta is O and Omega together

Prove that, for any two functions f(n) and g(n), we have f(n) = \Theta(g(n)) if and only if f(n) = O(g(n)) and f(n) = \Omega(g(n)).

Answer

The → direction. Suppose f(n) = \Theta(g(n)). By definition, there are c_1, c_2, n_0 > 0 such that

0 \le c_1 g(n) \le f(n) \le c_2 g(n) \quad \text{for all } n \ge n_0.

Pick the constants from here. The pair c_2, n_0 satisfies the definition of O(g(n)). The pair c_1, n_0 satisfies the definition of \Omega(g(n)). So f(n) lies in both sets.

The ← direction. Suppose f(n) = O(g(n)) and f(n) = \Omega(g(n)). Then, for some constants c_3 and c_4:

0 \le c_3 g(n) \le f(n) \quad \text{for all } n \ge n_1,

0 \le f(n) \le c_4 g(n) \quad \text{for all } n \ge n_2.

Pick n_3 = \max\{n_1, n_2\}. Both inequalities hold from n_3 on, so merge them:

0 \le c_3 g(n) \le f(n) \le c_4 g(n) \quad \text{for all } n \ge n_3.

That is the definition of f(n) = \Theta(g(n)).

General method: prove a fact about O, Omega and Theta
  1. Write out each definition you are given, with its own constants: “\exists\, c, n_0 such that … for all n \ge n_0”. Give each one a new name (c_1, n_1, then c_2, n_2).
  2. Write out the definition you must reach.
  3. Build its constants from the ones you have. Two tools cover most proofs:
    • Take the maximum of the thresholds. Each fact holds from its own n_i. All of them hold from \max_i n_i.
    • Multiply or add the constants. If f \le c_1 g and g \le c_2 h, then f \le c_1 c_2 h.

Extension 2.1. Prove that O is transitive: if f(n) = O(g(n)) and g(n) = O(h(n)), then f(n) = O(h(n)).

Answer (Extension 2.1)

From the first fact: 0 \le f(n) \le c_1 g(n) for all n \ge n_1. From the second: 0 \le g(n) \le c_2 h(n) for all n \ge n_2.

Take n_0 = \max\{n_1, n_2\}. For n \ge n_0, both hold, so

0 \le f(n) \le c_1 g(n) \le c_1 c_2\, h(n).

With c = c_1 c_2, this is the definition of f(n) = O(h(n)). The proof used both tools of the method: the maximum threshold and the product of constants.

Tutorial 1 Q3. Two functions that cannot be compared

Give an example of non-negative functions f(n) and g(n) such that f(n) \notin O(g(n)) and g(n) \notin O(f(n)).

Answer

Take

f(n) = n \qquad \text{and} \qquad g(n) = \begin{cases} 1 & \text{if } n \text{ is even}, \\ n^2 & \text{otherwise}. \end{cases}

Proof that f(n) \notin O(g(n)). Suppose, for a contradiction, that f(n) \in O(g(n)). Then for some positive constants c and n_1:

0 \le n \le c\,g(n) \quad \text{for all } n \ge n_1. \qquad (*)

Let n_2 be the smallest even number strictly larger than \max\{n_1, c\}. In particular, n_2 > c. (**)

Put n_2 into (*). Since n_2 is even, g(n_2) = 1, so 0 \le n_2 \le c. This contradicts (**).

Proof that g(n) \notin O(f(n)). The official solution leaves this as an exercise. The proof is the same, with an odd number. Suppose g(n) \le c\,n for all n \ge n_1. Let n_2 be an odd number larger than \max\{n_1, c\}. Then g(n_2) = n_2^2, so n_2^2 \le c\,n_2, which gives n_2 \le c. This contradicts n_2 > c.

General method: show that f is not O(g)
  1. Assume the constants exist: f(n) \le c\,g(n) for all n \ge n_0.
  2. Choose one value of n that is larger than n_0 and breaks the inequality. Usually you pick n larger than both n_0 and c, from the part of the domain where g is small.
  3. Put it in and reach a contradiction such as n \le c with n > c.

To build two functions that cannot be compared, make one of them jump between a value below the other and a value above it, for example on even and odd n.

Extension 3.1. Let f(n) = n and g(n) = n^{1.5} for even n and g(n) = n^{0.5} for odd n. Is f(n) = O(g(n))? Is g(n) = O(f(n))?

Answer (Extension 3.1)

Neither.

  • f \ne O(g): suppose n \le c\,g(n) for n \ge n_0. Take an odd n > \max\{n_0, c^2\}. Then n \le c\sqrt{n}, so \sqrt{n} \le c, so n \le c^2. Contradiction.
  • g \ne O(f): suppose g(n) \le c\,n for n \ge n_0. Take an even n > \max\{n_0, c^2\}. Then n^{1.5} \le c\,n, so \sqrt{n} \le c. Contradiction.

Here g jumps above f on even n and below it on odd n, as the method says.

Tutorial 1 Q4. A loop invariant for a primality test

Consider the following function for testing primality of a natural number n > 1:

def isPrime(n):
    p = True
    for i = 2 to floor(sqrt(n)):
        if n is divisible by i then:
            p = False
    return p

State a (non-trivial) loop invariant for the function above, and use your invariant to prove the function’s correctness.

Concepts: the three parts of a loop-invariant proof

A loop invariant is a statement that is true before every iteration of the loop.

  1. Initialization: it is true before the first iteration.
  2. Maintenance: if it is true before one iteration, it is true before the next.
  3. Termination: when the loop stops, the invariant shows that the answer is correct.
Answer

First rewrite the for loop as a while loop. Then you can see the value of i when the loop stops.

def isPrime(n):
    p = true
    i = 2
    while (i <= floor(sqrt(n))):
        if n is divisible by i then:
            p = false
        i++
    return p

Invariant: “p is true if and only if there is no integer k such that 2 \le k < i and k divides n.”

Initialization. At the start, i = 2. No integer k satisfies 2 \le k < 2, and p is true. So the invariant holds before the loop.

Maintenance. After one full iteration, i has grown by 1. The iteration tested the number that is now i - 1. There are two cases.

  • If i - 1 divides n, the code set p to false. The invariant for the new i holds, because k = i - 1 divides n.
  • If i - 1 does not divide n, p is unchanged. By the inductive hypothesis, the old value of p was correct for the range 2 \le k < i - 1. The range grew by one number, i - 1, and that number does not divide n. So the answer to “is there a divisor in the range?” did not change, and p is still correct. (The official solution asks “why?”. This is the reason.)

Termination. The loop stops when i = \lfloor \sqrt{n} \rfloor + 1. By the invariant, p is true if and only if no integer k with 2 \le k < \lfloor \sqrt{n} \rfloor + 1 divides n.

This condition means n is prime, for every n > 1. (The official solution says “prove it!”. Here is the proof.) Suppose n is not prime, so n = a \cdot b with 2 \le a \le b. Then a \cdot a \le a \cdot b = n, so a \le \sqrt{n}, and a \le \lfloor \sqrt{n} \rfloor because a is a whole number. So a composite n always has a divisor in the range, and p is false. A prime n has no divisor in the range, and p stays true.

General method: write a loop-invariant proof
  1. Rewrite a for loop as a while loop, so the loop variable has a clear value at every check and at the end.
  2. State the invariant as what the loop has done so far, in terms of the loop variable: “the first i elements are sorted”, “m is the largest of A[0..i-1]”, “no divisor below i”.
  3. Initialization: put in the start value of the loop variable. The range is usually empty, so the statement is easy.
  4. Maintenance: follow one iteration. Split into cases by the if inside the loop.
  5. Termination: put in the stop value. The invariant must now say exactly what the function returns.

Extension 4.1. State a loop invariant for the function below, and use it to prove that the function returns the largest element of A[0..n-1], for n \ge 1.

def findMax(A, n):
    m = A[0]
    i = 1
    while i < n:
        if A[i] > m:
            m = A[i]
        i = i + 1
    return m
Answer (Extension 4.1)

Invariant: “m is the largest element of A[0..i-1].”

  • Initialization. i = 1, and m = A[0], the largest (only) element of A[0..0].
  • Maintenance. The iteration looks at A[i]. If A[i] > m, then A[i] is the new largest of A[0..i], and m becomes A[i]. Otherwise m is still the largest. Then i grows by 1, so m is the largest of A[0..i-1] for the new i.
  • Termination. The loop stops at i = n. Then m is the largest of A[0..n-1], the whole array.
