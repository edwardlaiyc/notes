11. String matching

Facts

Define the string matching problem and the simple scan’s worst case.

Answer

Given a text T of length n and a pattern P of length m, find a position where P occurs in T. The simple scan puts P at position 0, compares left to right, and on a mismatch shifts P by one and restarts from the first pattern character. Worst case \Theta(m(n-m+1)), for example P=\text{AAA..AB} in T=\text{AAA..A}.

What is Horner’s rule, and why is it used in Rabin-Karp?

Answer

It evaluates a length-m string as a base-d number: t=(\dots((P_1d+P_2)d+P_3)\dots)d+P_m, using m-1 multiplications and additions, \Theta(m). Each character is mapped to a digit 0..d-1 first. Rabin-Karp compares numbers instead of strings.

Write the rolling update that moves the window one character to the right.

Answer

t_{s+1}=\big(d\,(t_s-T[s]\,d^{m-1})+T[s+m]\big), reduced mod q at every step. Remove the leading digit, shift left by multiplying by d, add the new digit. \Theta(1) per window. Precompute dM=d^{m-1}\bmod q.

Why add q in rehash, and why is dM=d^{m-1} and not d^m?

Answer

After subtracting the old leading term the value mod q can be negative, and % of a negative number may be negative in C/Java, so add q first to keep it in range. dM is d^{m-1} because the leading digit has weight d^{m-1} (the last digit has weight d^0).

What is a spurious hit, and what must Rabin-Karp do on every hash match?

Answer

A window whose hash equals the pattern’s hash but whose characters differ. Different values can have the same remainder mod q. On every hash match, compare the characters (\Theta(m)) to confirm. Different hashes prove a mismatch; equal hashes prove nothing.

Running time of Rabin-Karp: preprocessing, expected, worst case.

Answer

Preprocessing \Theta(m) (two hashes). Expected O(n+m) with a large prime q (few spurious hits). Worst case \Theta((n-m+1)m) when every window is a hit, no better than the simple scan.

What makes a good q and a good hash?

Answer

q a large prime (few collisions; q should share no factor with d). The hash must use position (Horner’s rule gives each digit a different weight); a plain sum of characters gives every anagram the same value.

Boyer-Moore: in which direction does it compare, and in which direction does the pattern move?

Answer

It compares the pattern right to left, but moves the pattern along the text left to right. A mismatch at pattern position k lets it jump ahead without examining the skipped text characters.

Define charJump for a pattern P of length m.

Answer

For a character c: \text{charJump}[c]=m-i where i is the position (from 1) of the rightmost occurrence of c in P; \text{charJump}[c]=m if c is not in P. So the last pattern character has \text{charJump}=0.

Define matchJump[k] and give its three slide cases.

Answer

After a mismatch at position k with the suffix P[k+1..m] already matched, \text{matchJump}[k]=(m-k)+\text{Slide}[k] (jump of j). \text{Slide}[k] is the smallest shift that is consistent with the matched suffix and does not pair the mismatched position with the same character:

  1. the suffix reoccurs earlier in P, preceded by a character different from P[k];
  2. otherwise a prefix of P matches a tail of the suffix;
  3. otherwise \text{Slide}[k]=m.

Also \text{matchJump}[m]=1.

How do the two tables combine, and what is the running time?

Answer

On a mismatch, j\leftarrow j+\max(\text{charJump}[T[j]],\ \text{matchJump}[k]) and k\leftarrow m. The scan is often sublinear: many text characters are never examined. Best case about n/m comparisons. With both tables, worst case is O(n+m) for the first occurrence (a known result, beyond the lecture); with charJump alone it can be \Theta(mn).

When would you choose each of the simple scan, Rabin-Karp and Boyer-Moore?

Answer

Simple scan for very short patterns (no preprocessing). Rabin-Karp when you must search for many patterns of the same length at once (hash them all) or for a tolerant variant (wildcards). Boyer-Moore for ordinary text and long patterns, where its large jumps help most. For small alphabets (such as binary strings) charJump values are tiny, so KMP is recommended.

Problems

Problem 1: Rabin-Karp by hand

Pattern P=31415, text T=2359023141526739921, base d=10, modulus q=13.

(a) Compute the pattern hash h_p and the hash of the first window 23590.

Answer

h_p=31415\bmod13=7 (since 13\cdot2416=31408 and 31415-31408=7). The first window: 23590\bmod13=8 (13\cdot1814=23582, remainder 8). Since 8\ne7, no comparison is needed.

(b) Which windows have hash 7, and which of them are real matches?

Answer

Two windows have hash 7: the window starting at index 6 (text 31415, a real match) and the window starting at index 12 (text 67399, a spurious hit: 67399\bmod13=7 but the characters differ). So Rabin-Karp does two character comparisons of length 5 (the second one fails on its first character). All 15 windows were examined, and every other window was rejected by its hash alone. (Checked by computing all windows.)

(c) The rolling update from window “36415” (hash 1, with q=7) to “64152”. Compute the new hash.

Answer

With q=7, d=10, m=5: dM=10^4\bmod7=4. The leading digit 3 contributes 3\cdot4\bmod7=5. Remove it: (1+7-5)\bmod7=3. Shift and add the new digit 2: (3\cdot10+2)\bmod7=4. Direct check: 64152\bmod7=4.

Problem 2: Boyer-Moore tables

(a) Build charJump and matchJump for P=\text{BANANA} over the alphabet A..Z.

Answer

m=6. charJump: A 0, B 5, N 1, every other letter 6.

k 1 2 3 4 5 6
P_k B A N A N A
matchJump 11 10 5 8 5 1

Check k=5: suffix “A” is matched, the mismatch is against N. The nearest earlier A preceded by a letter other than N is the A at position 2 (preceded by B), so Slide is 6-2=4 and matchJump is (6-5)+4=5. (These agree with the tutorial solution.)

(b) Use the tables from (a) to scan the text “BANANBANANA” for BANANA. Count the comparisons.

Answer

Text: B A N A N B A N A N A (n=11, positions 1 to 11).

  • j=6, k=6: T[6]=\text{B} against P[6]=\text{A}: mismatch (1 comparison). charJump[B] =5, matchJump[6] =1, so jump 5 and j=11.
  • j=11: compare right to left. T[11..6] read backwards (A, N, A, N, A, B) equals P[6..1] (A, N, A, N, A, B): all six match (6 comparisons).

The pattern is found at position 6 after 1+6=7 comparisons. The simple scan needs 16 comparisons on the same text (6 at shift 1, then 1 each at shifts 2 to 5, then 6 at shift 6). (Both counts were also checked by running the scans.)

(c) For P=\text{AAA...AB} (m-1 A’s then one B) and text T=\text{AAA...A} (n A’s), give charJump, matchJump and the number of comparisons of the full Boyer-Moore scan.

Answer

charJump: A 1, B 0, all others m. matchJump for k=1..m: 2m-1,2m-2,\dots,m+2,m+1,1. The first comparison, text A against pattern B at k=m, fails, and charJump[A]=1 and matchJump[m]=1 give a jump of only 1. This repeats at every shift, so the number of comparisons is n-m+1, the same as the simple scan. This is the case where Boyer-Moore does no better than brute force.

(d) (Tutorial 11, Problem 3, second pattern.) Build charJump and matchJump for P=\text{POTATO} over the alphabet A..Z. Compare with BANANA: which entries are the same, and why?

Answer

m=6. charJump: A 2, O 0, P 5, T 1, every other letter 6.

k 1 2 3 4 5 6
P_k P O T A T O
matchJump 11 10 9 8 5 1

Check k=5: suffix “O” matched and the mismatch is against T. The earlier O (position 2) is preceded by P, not T, so it is a valid reoccurrence: Slide =6-2=4, matchJump =(6-5)+4=5. For k=1 to 4 the matched suffix (“OTATO”… down to “TO”) does not occur earlier and no prefix equals a tail, so Slide =m=6 and matchJump =(m-k)+6: 11, 10, 9, 8.

Compare BANANA (11, 10, 5, 8, 5, 1): both end in 5,1, and the two rows differ only at k=3 (BANANA 5, POTATO 9), because BANANA repeats inside itself. At k=3 the matched suffix “ANA” also occurs earlier, at positions 2 to 4 and preceded by B (not N), so Slide is 6-4=2 and matchJump is 3+2=5. POTATO’s suffixes “ATO” and longer never reoccur, so those entries stay at the maximum (m-k)+m. A repeat inside the pattern is what makes matchJump smaller than 2m-k. Problem 3: wildcard Rabin-Karp

Modify Rabin-Karp so that the middle character of an odd-length pattern matches anything. State the hash and the rehash.

Answer

Replace the middle digit’s contribution by 0 in both the pattern hash and every window hash. In hash, at the middle index multiply by d but add nothing. For rehash when the window moves one right: h'=\Big(\big(h-T[i]\,d^{m-1}+T[i+\lfloor m/2\rfloor]\,d^{\lfloor m/2\rfloor}\big)\,d-T[i+1+\lfloor m/2\rfloor]\,d^{\lfloor m/2\rfloor}+T[i+m]\Big)\bmod q. Remove the leading digit, add back the old middle digit (so it was effectively 0 before), shift, then remove the new middle digit before adding the last digit. Example from the tutorial: window “36415” with the middle digit zeroed hashes to 0 mod 7. With d=10, q=7, dM=4, d^{\lfloor m/2\rfloor}\bmod7=2, the update gives 2, and “64152” with its middle digit zeroed (“64052”) also hashes to 2. Matching windows still need a character check on all positions except the middle.

Past-year questions

Questions from past papers (SC2001/CZ2101/CE2001). Every answer was worked out and checked by code; where a circulated official solution exists it was compared, and disagreements are flagged.

AY25/26 S2 3(b) For SimpleScan (brute-force) string matching, give the time complexity of (i) the best case and (ii) the worst case. Describe the situation in which each occurs and give an example.

Answer

(i) Best case O(m) (precisely m comparisons): the pattern occurs at the very start of the text. Example: T=\text{ABCDEF}, P=\text{ABC}: 3 comparisons. (If the pattern is absent but the first pattern character never matches, the cost is n-m+1, also at most O(n).)

(ii) Worst case O(mn), exactly m(n-m+1) comparisons: at every shift all but the last pattern character match. Example: T=\text{AAAAAAAA}, P=\text{AAAB}: every shift compares 4 characters before failing.

AY25/26 S1 3(b)(ii) A text has n characters and a pattern m characters. The pattern does not appear in the text. Fill in: A. The minimum number of character comparisons by the Simple Scan method is . B. … by the Rabin-Karp algorithm is . C. … by the Simple Boyer-Moore algorithm is . D. … by the Boyer-Moore algorithm is .

Answer
  • A. n-m+1: at each of the n-m+1 shifts the first comparison can fail, one comparison per shift.
  • B. 0: the hash of every window differs from the pattern hash, so no character comparison is ever made.
  • C. about \lfloor n/m\rfloor: every comparison hits a text character that is not in the pattern, so charJump =m and the pattern jumps by m each time (j=m,2m,\dots).
  • D. about \lfloor n/m\rfloor: the same, because matchJump is at most as large as charJump at the first comparison and \max takes m.

Caution: that n/m best case needs text characters that are not in the pattern. In this question’s alphabet every letter appears in “GCTAGC”, so the realistic jumps are at most 3 at the first comparison; n/m is the general best-case answer the question expects. (Boyer-Moore best case \approx n/m is not in the lecture, but the lecture notes that the scan is often sublinear.)

AY24/25 S2 3(b)(i) Apply the Rabin-Karp string matching algorithm (no hash) to search for the occurrence of the four-character pattern “1010” in the binary digit string “11010101”. Clearly state how you compute the number for each four-character text segment.

Answer

Treat each binary string as a number with base d=2. Pattern: 1010_2=10. There are n-m+1=8-4+1=5 windows.

First window: 1101_2=13. Rolling update when the window moves right by one: t_{i+1}=2\,(t_i-\text{lead}\cdot2^{m-1})+\text{new}. (Remove the leading bit times 2^3=8, shift left, add the new bit.)

window text computed direct value equals 10?
0 1101 13 13 no
1 1010 2(13-8)+0=10 10 yes
2 0101 2(10-8)+1=5 5 no
3 1010 2(5-0)+0=10 10 yes
4 0101 2(10-8)+1=5 5 no

Matches at shifts 1 and 3 (0-based). With no hash modulus the numbers are exact, so a number match is a true match and no character check is needed.

Link. The two matches overlap (shift 3 minus shift 1 is 2): “1010” matches itself after a shift of 2. Boyer-Moore’s matchJump slide uses the same self-overlap of the pattern. With a modulus q (as in the lectures), equal hashes need a character check, because different windows can collide.

AY24/25 S2 3(b)(iii) What is the best-case time complexity of the Boyer-Moore string matching algorithm? Explain in what kind of situation the best case occurs, with an example.

Answer

O(n/m) comparisons (n text length, m pattern length, excluding preprocessing).

It occurs when the text character compared against the last pattern character is not in the pattern at all, at every shift. Then charJump =m and the pattern jumps a whole m positions after a single comparison. Example: P= “ABC” (m=3), T= “XXXXXXXXX” (n=9). Compare T[2]=X with C: mismatch, charJump[X]=3, jump to the next block. Only n/m=3 comparisons for 9 characters.

(Flag: the n/m best case needs text characters that do not occur in the pattern. If the text characters are in the pattern the jumps are smaller. Same remark as AY2526 S1 3(b)(ii).)

Link. The opposite extreme is on the tutorial 11 page: T=A^n and P=A^{m-1}B give jumps of only 1, so Boyer-Moore makes n-m+1 comparisons, no better than the simple scan. Its speed depends on how the text characters sit against the pattern’s characters, not on the sizes alone.

AY24/25 S1 3(c) Pattern P=\text{"19191"}. Text T has 20 characters, all ‘3’. Apply the simple string matching (brute force) algorithm, the Rabin-Karp algorithm and the Boyer-Moore algorithm to search for an occurrence of P in T. Use 10^2 in the hash function in Rabin-Karp, e.g. hash(“19191”) = 91. How many character comparisons do the three algorithms make, respectively?

Answer

16, 0 and 4.

  • Simple scan: there are n-m+1=20-5+1=16 shifts, and at each one the first comparison (‘1’ against ‘3’) fails: 16.
  • Rabin-Karp: the pattern hash is 19191\bmod100=91. Every window “33333” hashes to 33\ne91, so no window ever matches the hash and the characters are never compared: 0 (the 16 hash comparisons are not character comparisons).
  • Boyer-Moore: the text character ‘3’ is not in the pattern, so charJump =5 and the pattern jumps 5 places after each mismatch. It compares at text positions 5, 10, 15, 20: 4 =\lfloor n/m\rfloor.

AY24/25 S1 3(d) If the hash() and rehash() functions in the Rabin-Karp algorithm are changed from the ones on the left to the ones on the right, what are the advantage and disadvantage? The idea on the right is to perform hash() and rehash() on the sum of the digits.

Answer

Advantage: simpler and faster per step. The right version drops the multiplications by d and by dM (and needs no d^{m-1}\bmod q), so each hash and rehash is a couple of additions.

Disadvantage: the sum ignores digit order, so any rearrangement of the same digits has the same hash (“19191” and “11199” collide, as would every permutation). Also the hash values lie in a tiny range (at most 9m), so many windows collide even when they are different strings. Each false match costs a full O(m) comparison, and the expected linear time degrades towards the simple scan’s O(mn) on texts where many windows have equal digit sums.

AY23/24 S2 3(b) For the Boyer-Moore string matching algorithm, what is the time complexity of each case below? Describe the situation in which each case occurs, and give an example. (i) Best case. (ii) Worst case.

Answer

Let n be the text length and m the pattern length.

(i) Best case: O(n/m) comparisons (excluding preprocessing). It occurs when the text character compared with the last pattern character is not in the pattern at all, at every alignment: charJump =m, so the pattern jumps a whole m places after one comparison. Example: P= “ABC” (m=3), T= “XXXXXXXXX” (n=9): the comparisons are at T[3],T[6],T[9], so 3 =n/m in total.

(ii) Worst case: O(mn) comparisons. It occurs on a near match: most of the pattern matches at every alignment, but the shift is only 1. Example: P= “ABB”, T= “BBBBBBBBBB” (n=10). At every alignment B and B match, then B against B matches, then B against A fails, and the jump moves the pattern one place. For the simplified version (charJump only) the count is (n-m+1)\,m=8\cdot3=24 (checked by code, also for n=12: 30). When all occurrences are wanted, P=\text{A}^m in T=\text{A}^n needs (n-m+1)\,m comparisons for any scan that verifies each occurrence character by character.

(Flags. The lecture slides give no formulas for either case, only “often sublinear”. The worst case O(mn) is what a course expects. A finer fact beyond the lecture: with matchJump included, the search for the first occurrence of P (or for its absence) is linear in n+m: on the same input “ABB” in B^{10} the full algorithm needs only 9 comparisons, and in an exhaustive check over all binary texts of length 10 and 12 and patterns of length 3 and 4, the full algorithm never needed more than 16 comparisons.)

Link. The best case needs the text and the pattern to disagree (the characters never match), the worst case needs them to almost agree. Rabin-Karp’s worst case is also a near match (many equal hashes), so near matches are the hard instances for every string-matching method in the course.

AY23/24 S2 3(d) Apply the Rabin-Karp string matching algorithm to search for the occurrence of the pattern “26” in the text “315265”. Clearly show the hashing process.

Answer

Treat each digit string as a base-d=10 number. Pattern: \text{hash}(26)=2\cdot10+6=26. The text has n-m+1=6-2+1=5 windows. Compute the first window directly and then roll: drop the leading digit, shift, add the new digit: h_{i+1}=10\,(h_i-10\cdot T[i])+T[i+2].

window text computed equals 26?
0 31 3\cdot10+1=31 no
1 15 10\,(31-30)+5=15 no
2 52 10\,(15-10)+2=52 no
3 26 10\,(52-50)+6=26 yes
4 65 10\,(26-20)+5=65

The first occurrence is at index 3 (0-based; position 4 counting from 1). Window 3 is checked character by character, which confirms “26”, and the search stops (or goes on to window 4 if all occurrences are wanted: 65, no).

With a modulus (the lecture’s version keeps numbers small by working mod a prime q): take q=13. The pattern hashes to 26\bmod13=0 and the windows hash to 5,2,0,0,0. Now windows 2 (52), 3 (26) and 4 (65) all collide with the pattern’s hash, so windows 2 and 4 are spurious hits: each costs a full character comparison that fails. Only window 3 is real. With q=7 (pattern hash 5, windows 3, 1, 3, 5, 2) the only hit is the real one.

Link. The exact version never has false hits but needs numbers that grow as d^m. The modular version keeps numbers small at the price of spurious hits, and a bad choice of q (here 13 divides both 26 and 52 and 65) makes the algorithm slow. That is why q is chosen as a large prime: the expected time is O(n+m), but the worst case with many collisions is O(mn).

AY23/24 S1 3(b) During the preprocessing step in the Boyer-Moore algorithm, the arrays charJump and matchJump for the pattern “WOWWOW” are computed. It is found that charJump[‘O’]=1, charJump[‘W’]=0, charJump[x]=6 where x is any character in the alphabet that is not ‘O’ and ‘W’. The matchJump is [8,7,6,7,3,1]. The simple Boyer-Moore algorithm and the Boyer-Moore algorithm are applied respectively to search for the pattern in the text “BOWNOWOWWWOLOWL”. How many character comparisons are done in each case?

Answer

Pattern P= WOWWOW, m=6. Text T (1-indexed): B O W N O W O W W W O L O W L (n=15). Matching goes right to left: j indexes the text, k the pattern. On a mismatch:

  • simple (charJump only, lecture slide 32): j\leftarrow j+\max(\text{charJump}[T[j]],\,m-k+1) and k\leftarrow m;
  • full: j\leftarrow j+\max(\text{charJump}[T[j]],\,\text{matchJump}[k]) and k\leftarrow m.

Simple Boyer-Moore: 7 comparisons.

# j k T[j] vs P[k] result jump
1 6 6 W vs W match
2 5 5 O vs O match

AY22/23 S2 3(b)(i) Apply the Rabin-Karp string matching algorithm to search for the occurrence of the binary string pattern “01101” in the text “01001101”. Clearly state how you compute the number for each five-character text segment.

Answer

Treat each binary string as a base-2 number. Pattern: 01101_2=13. There are 8-5+1=4 windows. First window: 01001_2=9. Rolling update when the window moves right by one: remove the leading bit times 2^{m-1}=16, shift left, add the new bit: t_{i+1}=2\,(t_i-16\cdot\text{lead})+\text{new}.

window text computed direct value equals 13?
0 01001 9 9 no
1 10011 2(9-0)+1=19 19 no
2 00110 2(19-16)+0=6 6 no
3 01101 2(6-0)+1=13 13 yes

The pattern occurs at index 3 (0-based). With no modulus the numbers are exact, so equal numbers mean a true match; no character check is needed.

AY22/23 S2 3(b)(iii) What is the worst case time complexity of the Boyer-Moore string matching algorithm to find all occurrences? In what situation does the worst case occur?

Answer

O(mn) (n text length, m pattern length). It occurs when many alignments are almost or fully matches, so most pattern characters are compared at every alignment and the pattern advances by only one place. Example: T=\text{AAAA...A} (n letters) and P=\text{AAA} (m letters): every alignment is a full match, there are n-m+1 of them, and each is verified with m character comparisons, so (n-m+1)\,m comparisons. Another example for the simplified (charJump-only) version is P=\text{ABB} in T=\text{BBBB...B}: at every alignment two characters match and the third fails, and the pattern moves one place (24 comparisons for n=10, checked by code).

(Flag: the lecture does not state the worst case. O(mn) is the standard textbook answer. With matchJump and a refinement that avoids re-comparing known characters, the all occurrences search is linear, but that is beyond the lecture.)

Link. The best case (O(n/m)) needs the text to share no letters with the pattern, and the worst case needs the text to be the pattern repeated. These are the two ends of the same spectrum: the more the text looks like the pattern, the slower Boyer-Moore, Rabin-Karp and the plain scan all become.

AY22/23 S1 3(c)(i) Apply the Rabin-Karp string matching algorithm to search for the occurrence of the pattern “00101” in the text “00100000101”. How many character comparisons are done between the pattern and the text if 11 is used in the hash operation?

Answer

Read each 5-bit window as a binary number and hash it with 11 (a modulus, q=11). The pattern is 00101_2=5, with hash 5\bmod11=5. There are 11-5+1=7 windows:

window text value hash mod 11 equals 5?
0 00100 4 4 no
1 01000 8 8 no
2 10000 16 5 hit: characters compared (spurious)
3 00000 0 0 no
4 00001 1 1 no
5 00010 2 2 no
6 00101 5 5 hit: characters compared, match

Characters are compared only at the two hash hits, windows 2 and 6. The pattern is found at index 6.

  • Counting a full equality test as m=5 comparisons (the lecture’s equal_string called for each hash hit, and the way the circulated solution counts): 5+5= 10.
  • If the string comparison stops at the first different character, window 2 (“10000” against “00101”) fails at the first character, so it costs 1, and the true match costs 5: 1+5=6.

(Flag: the question does not say how equal_string stops. Answer 10 and state that the spurious hit at window 2 is what costs an extra comparison, or give both counts.)

Link. The spurious hit exists because 16\equiv5\pmod{11}: two different bit strings (10000 and 00101) collide. A different prime would avoid this one. With a prime larger than every window value (here q>31) there are no collisions at all.

AY22/23 S1 3(c)(ii) The worst case number of character comparisons for the straightforward string matching algorithm and for the Rabin-Karp algorithm are both m(n-m+1), where m is the pattern length and n the text length. Explain this statement and the advantage of the Rabin-Karp algorithm.

Answer

There are n-m+1 possible alignments (windows) of the pattern in the text.

  • Straightforward scan. At each alignment it compares up to m characters. The worst case is a near match everywhere (for example P=\text{AAAAC} in T=\text{AAAA...A}): every alignment matches m-1 characters before failing, so about m(n-m+1) comparisons.
  • Rabin-Karp. It compares characters only when the hash values are equal. The worst case is when every window has the same hash as the pattern but is not the pattern (all hits are spurious, as happens with a very small modulus q). Then every window costs a full m-character comparison, m(n-m+1) again.

Advantage. Normally almost no windows collide, so Rabin-Karp does only one hash comparison per window and character comparisons only at real hits. With the rolling hash each window’s hash costs O(1) from the previous one, so the expected time is O(n+m) for a good large prime q, against O(mn) for the plain scan in bad cases. It also extends naturally to searching for several patterns of the same length at once (see AY2324 S1 3(c)).

Link. Both worst cases are triggered by the same thing: near matches. Rabin-Karp changes which text patterns count as near matches (equal hash instead of equal prefix), so a text that is bad for brute force is usually harmless for Rabin-Karp, and the reverse.

AY21/22 S2 3(c) To find all DNA pattern P= “ATTAT” in DNA sequence T= “GCTATACATTATCGT”: (i) How does the Boyer-Moore (BM) algorithm construct charJump and matchJump? (ii) How many comparisons are needed by the Boyer-Moore algorithm? (iii) Give an example of the worst case of the BM algorithm with the pattern/string size identical to P/T. Is it also the worst case of the Rabin-Karp algorithm? If not, give a worst-case example for Rabin-Karp. (iv) What is the time complexity of these two algorithms on their worst case? (v) Which algorithm do you think will run slower in practice on its worst case? Justify your answers.

Answer

(i) Construction (m=|P|=5, positions from 1).

  • charJump is indexed by the alphabet. Start with m for every letter, then scan P from left to right and set \text{charJump}[P[k]]=m-k; a later copy of a letter overwrites an earlier one, so the value comes from the rightmost occurrence. It says how far to jump when the text letter that failed occurs in the pattern. For “ATTAT”: A (rightmost position 4) gives 1, T (position 5) gives 0, and C and G give 5.
  • matchJump has one entry per pattern position k for a mismatch at k after the suffix P[k+1..m] matched: \text{matchJump}[k]=(m-k)+\text{Slide}[k], where Slide is the smallest shift that makes the matched suffix reappear under a different letter than the one that failed (or a prefix of P line up with a tail of that suffix), and m if neither exists. \text{matchJump}[m]=1.
k matched suffix other fit Slide matchJump
1 TTAT none; prefix AT equals the tail AT 3 4+3=7
2 TAT none; prefix AT equals the tail AT 3 3+3=6

4 T position 3, preceded by T not A 2 1+2=3
5 1

So charJump: A 1, T 0, C 5, G 5; matchJump: [7,6,5,3,1] (computed by code).

(ii) Comparisons. T (1-indexed): G C T A T A C A T T A T C G T (n=15). Matching goes right to left. The pattern occurs once, at position 8.

1-3 5, 4, 3 5, 4, 3 T=T, A=A, T=T match

5 8 5 A vs T mismatch \max(1,\,1)=1, so j=9
6-7 9, 8 5, 4 T=T, A=A match

13 comparisons for Boyer-Moore with both tables (finding the first occurrence). The simple version (charJump only) needs 10 here (jumps of 5 and 5 land it on the right alignment sooner), and the brute-force scan needs 20. If the search has to continue to the end to prove there is no second occurrence, after the match the pattern can move by m-2=3 places (the border “AT”), and 2 more comparisons (T=T, then G\ne A) finish the text: 15 for Boyer-Moore and 12 for the simple version. (The lecture code stops at the first match; the continuation is beyond the lecture.)

(iii) Worst case. For Boyer-Moore take the text T=\text{A}^{15} and the pattern P=\text{AAAAA}: every one of the 15-5+1=11 alignments is a full match, and each costs 5 comparisons, so 11\times5=55 comparisons =m(n-m+1). For the simplified Boyer-Moore also P=\text{BAAAA} in T=\text{A}^{15}: five comparisons at each of 11 alignments, again 55.

Is it also a worst case for Rabin-Karp? For P=\text{AAAAA} in \text{A}^{15} with all occurrences required, yes: every window hashes equal to P and is a real match, so each window costs m character comparisons: 55. If only the first occurrence is wanted, \text{A}^{15} is not a worst case for Rabin-Karp (the first window already matches). And P=\text{BAAAA} is not a worst case for Rabin-Karp at all: the hash of BAAAA differs from the hash of AAAAA, so no window triggers a character comparison (0 comparisons). A Rabin-Karp worst case needs many windows with the same hash as P but different from P (spurious hits), which depends on the hash function and a bad modulus q (for example q=2 with a base-4 value, which makes every window ending in C or T collide with ATTAT).

(iv) Worst-case time. Both are O(mn) (in comparisons; for m=5, n=15 this is 55).

(v) Slower in practice: Rabin-Karp. On its worst case, Rabin-Karp does the same m(n-m+1) character comparisons as the brute force plus a hash and a rehash for every window (multiplications and mod, which are slow operations), while Boyer-Moore’s worst case costs only character comparisons. The lecture’s own experiment agrees: Rabin-Karp “behaved much worse” because of function calls, division and character-to-number conversion, while brute force and Boyer-Moore did better than their worst-case bounds suggest because worst cases are rare.

Link. Boyer-Moore’s worst case needs the text to look like the pattern (every alignment almost or fully matches), and Rabin-Karp’s needs the hash to look like the pattern’s. Compare AY2223 S1 3(c)(ii) and AY2324 S2 3(b).
