Algorithm design and analysis evaluates how resource consumption—primarily execution time and memory—scales as problem sizes grow arbitrarily large. Rather than measuring wall-clock time on specific hardware, computer scientists classify algorithms by their asymptotic growth rates.

This chapter establishes the mathematical foundations of algorithm analysis: asymptotic notations (O,Ω,Θ,o,ωO, \Omega, \Theta, o, \omega), the core principles of internal sorting, the mechanics and cost analysis of Insertion Sort, and formal correctness proofs via loop invariants.

1. Asymptotic Notation

Asymptotic analysis evaluates algorithm performance for large input sizes n→∞n \to \infty. It ignores hardware-dependent constant factors and lower-order terms that become negligible as nn scales.

The Five Standard Notations

Each asymptotic notation represents a set of functions with a specific rate of growth. All functions analyzed in this course are non-negative (f(n)≥0f(n) \ge 0).

[!IMPORTANT] Quantifier Difference Between Big and Little Notations:

  • For Big-OO and Big-Ω\Omega, the inequality must hold for at least one constant c>0c > 0 (“∃c>0\exists\, c > 0”).
  • For little-oo and little-ω\omega, the inequality must hold for every positive constant c>0c > 0, however arbitrarily small (“∀c>0\forall\, c > 0”).

Example: 2n=O(n)2n = O(n) because c=3c = 3 works (2n≤3n2n \le 3n for n≥1n \ge 1). However, 2n≠o(n)2n \ne o(n) because choosing c=1c = 1 fails (2n<n2n < n is false for all n>0n > 0). Conversely, 2n=o(n2)2n = o(n^2) because for any c>0c > 0, 2n<cn22n < c n^2 holds whenever n>2/cn > 2/c.

The Limit Test

When the limit L=lim⁡n→∞f(n)g(n)L = \lim_{n \to \infty} \frac{f(n)}{g(n)} exists, you can establish the relationship directly without choosing constants:

limn→∞f(n)g(n)=L⟹{L=0⟹f(n)=o(g(n)) and f(n)=O(g(n))0<L<∞⟹f(n)=Θ(g(n))L=∞⟹f(n)=ω(g(n)) and f(n)=Ω(g(n))\lim_{n \to \infty} \frac{f(n)}{g(n)} = L \implies \begin{cases} L = 0 & \implies f(n) = o(g(n)) \text{ and } f(n) = O(g(n)) \\ 0 < L < \infty & \implies f(n) = \Theta(g(n)) \\ L = \infty & \implies f(n) = \omega(g(n)) \text{ and } f(n) = \Omega(g(n)) \end{cases}

[!WARNING] Limit Test Fails When Limits Do Not Exist: If lim⁡n→∞f(n)g(n)\lim_{n \to \infty} \frac{f(n)}{g(n)} oscillates or does not exist (e.g. functions with alternating trigonometric terms or piecewise parity), the limit test is inconclusive. You must return to the formal definitions and choose explicit witness constants c,n0c, n_0.

From slowest to fastest growing:

O(1)<O(log⁡log⁡n)<O(log⁡n)<O(nc) (0<c<1)<O(n)<O(nlog⁡n)<O(n2)<O(nk)<O(2n)<O(n!)<O(nn)O(1) < O(\log \log n) < O(\log n) < O(n^c) \text{ ($0 < c < 1$)} < O(n) < O(n \log n) < O(n^2) < O(n^k) < O(2^n) < O(n!) < O(n^n)

  • Logarithm Bases: For any base a,b>1a, b > 1, log⁡an=log⁡bnlog⁡ba=Θ(log⁡bn)\log_a n = \frac{\log_b n}{\log_b a} = \Theta(\log_b n). The base changes only a constant factor, so we omit it in asymptotic notations (conventionally writing lg⁡n\lg n for log⁡2n\log_2 n).
  • Exponential Bases: Bases matter asymptotically. For a<ba < b, an=o(bn)a^n = o(b^n) because lim⁡n→∞(a/b)n=0\lim_{n \to \infty} (a/b)^n = 0. For instance, 2n≠Θ(3n)2^n \ne \Theta(3^n).

Step-by-Step Method: Asymptotic Proofs

  1. Write the Given Definitions: Assign distinct variable names to given constants (e.g., c1,n1c_1, n_1 and c2,n2c_2, n_2).
  2. State Target Definition: Identify the inequalities and constants (c,n0)(c, n_0) needed to prove the target assertion.
  3. Combine Constants:
    • Domain Threshold: Set n0=max⁡(n1,n2)n_0 = \max(n_1, n_2) so that both inequalities hold simultaneously for all n≥n0n \ge n_0.
    • Constant Scaling: Add or multiply the constants depending on whether functions are summed or composed.
  4. Disproving Asymptotic Bounds (Counterexamples):
    • Assume for contradiction that constants c>0,n0>0c > 0, n_0 > 0 exist such that f(n)≤cg(n)f(n) \le c\,g(n) for all n≥n0n \ge n_0.
    • Select a specific value of nn (often depending on cc and n0n_0) where the inequality breaks.

2. The Sorting Problem

Given an input sequence of nn records R1,R2,…,RnR_1, R_2, \dots, R_n with associated keys k1,k2,…,knk_1, k_2, \dots, k_n drawn from a totally ordered set, sorting rearranges the records into a permutation (s1,s2,…,sn)(s_1, s_2, \dots, s_n) such that:

ks1≤ks2≤…≤ksnk_{s_1} \le k_{s_2} \le \dots \le k_{s_n}

Algorithmic Properties

  • Internal vs. External Sorting: Internal sorts hold all records entirely in random-access main memory. External sorts process massive datasets that reside on secondary storage (disks/SSDs).
  • In-Place Sort: An algorithm is in-place if it requires only O(1)O(1) auxiliary storage beyond the original array (or O(log⁡n)O(\log n) auxiliary space on the call stack for recursion).
  • Stability: An algorithm is stable if records with identical keys preserve their original relative order: If ki=kj and i<j, then Ri precedes Rj in the sorted output.\text{If } k_i = k_j \text{ and } i < j, \text{ then } R_i \text{ precedes } R_j \text{ in the sorted output.} Stability is essential when sorting objects by multiple criteria sequentially (e.g. sorting by name, then by year).

3. Insertion Sort

Insertion Sort operates incrementally, mimicking how a player sorts cards in hand. It maintains a sorted prefix on the left and expands it one element at a time.

void InsertionSort(ALIST slot[], int n) {
    for (int i = 1; i < n; i++) {           // slot[i] is the key to insert
        for (int j = i; j > 0; j--) {     // slide left across sorted prefix
            if (slot[j].key < slot[j-1].key)
                swap(slot[j], slot[j-1]);
            else
                break;                    // left neighbor is smaller/equal: stop
        }
    }
}

Operational Characteristics

  • In-Place: Yes. It requires only O(1)O(1) auxiliary memory.
  • Stable: Yes. When comparing equal keys (slot[j].key < slot[j-1].key), the strict inequality fails, triggering break. Equal keys never swap past one another.
  • Adaptive: Yes. Performance scales directly with the degree of sortedness of the input array.

Step-by-Step Method: Counting Comparisons and Swaps

  1. Distinguish Key Comparisons from Swaps:
    • A comparison occurs every time slot[j].key < slot[j-1].key evaluates.
    • A swap occurs only when the comparison evaluates to true.
    • Therefore, Swaps≤Comparisons\text{Swaps} \le \text{Comparisons} always.
  2. Inversion Counting:
    • An inversion is a pair of indices (i,j)(i, j) such that i<ji < j and A[i]>A[j]A[i] > A[j].
    • Each adjacent swap eliminates exactly one inversion and creates no new inversions.
    • Total swaps made by Insertion Sort equals the exact number of inversions in the input array.
  3. Iteration Cost Bounds: In iteration ii (for i=1,2,…,n−1i = 1, 2, \dots, n-1):
    • If slot[i] stops before index 0 (because slot[j] >= slot[j-1]), it makes ss swaps and s+1s + 1 comparisons.
    • If slot[i] slides all the way to index 0, it makes ii swaps and ii comparisons (no terminating comparison).

Tutorial 1 Q1: Alternative Comparison Worst Cases in Insertion Sort

Question: The worst case for insertion sort occurs when the input list contains keys in decreasing order: [an,…,a1][a_n, \dots, a_1]. Suppose performance is measured by the total number of comparisons between array elements (not counting swaps). Show at least two other initial arrangements of keys that are also worst cases for insertion sort.

Solution:

To achieve the maximum comparison count of ∑i=1n−1i=n(n−1)2\sum_{i=1}^{n-1} i = \frac{n(n-1)}{2}, every iteration ii must perform the maximum possible ii comparisons. This occurs whenever each inserted element travels either to index 0 (taking ii comparisons and ii swaps) or to index 1 (taking i−1i-1 swaps followed by 1 non-swapping comparison against the element at index 0).

Two distinct initial arrangements that achieve this maximum comparison count are:

  1. Arrangement 1: (n,n−1,n−2,…,3,1,2)(n, n-1, n-2, \dots, 3, 1, 2)
    • Elements n,n−1,…,1n, n-1, \dots, 1 enter in strictly decreasing order, each sliding completely to index 0 (ii comparisons and ii swaps per element).
    • The final element 22 compares against n,n−1,…,3n, n-1, \dots, 3 (swapping n−2n-2 times), and finally compares against 11 at index 0. Because 2>12 > 1, the inner loop terminates.
    • Total comparisons on the final step = (n−2)+1=n−1(n-2) + 1 = n-1. Thus, every iteration makes its maximal comparison count.
  2. Arrangement 2: (1,n,n−1,n−2,…,3,2)(1, n, n-1, n-2, \dots, 3, 2)
    • The smallest element 11 starts at index 0.
    • For every subsequent element ii (keys n,n−1,…n, n-1, \dots), the key is smaller than all keys in A[1..i−1]A[1..i-1] and swaps past them (i−1i-1 swaps).
    • It then makes its ii-th comparison against A[0]=1A[0] = 1, where A[1]>1A[1] > 1 stops the loop without swapping.
    • Total comparisons = ∑i=1n−1i=n(n−1)2\sum_{i=1}^{n-1} i = \frac{n(n-1)}{2}.

Note on Swaps: While both arrangements achieve the worst-case comparison count n(n−1)2\frac{n(n-1)}{2}, only the strictly reversed list (n,n−1,…,1)(n, n-1, \dots, 1) achieves the worst-case swap count (n(n−1)2\frac{n(n-1)}{2} inversions).

4. Correctness via Loop Invariants

A loop invariant is a formal predicate concerning program variables that evaluates to true immediately before and after each iteration of a loop. Proving algorithm correctness using loop invariants mirrors mathematical induction across three mandatory phases:

flowchart LR
    Init["1. Initialization<br/>(Base Case: True before loop)"] --> Maint["2. Maintenance<br/>(Inductive Step: Preserved across iterations)"]
    Maint --> Term["3. Termination<br/>(Exit Condition: Implies algorithm correctness)"]
  1. Initialization: Show the invariant holds prior to the first iteration of the loop.
  2. Maintenance: Prove that if the invariant holds prior to iteration kk, it remains true prior to iteration k+1k+1.
  3. Termination: When the loop terminates, the invariant provides a substantive condition that demonstrates the algorithm achieved its stated goal.

Step-by-Step Method: Formulating Invariant Proofs

  1. Convert to Explicit Form: Rewrite for loops into equivalent while loops so the loop counter’s terminal value is unambiguous upon loop exit.
  2. Define Invariant Over Processed History: Express what the algorithm has established over the prefix A[0..i−1]A[0..i-1].
  3. Verify the Three Steps:
    • Base: Evaluate at the initial counter value (often an empty or single-element subproblem).
    • Step: Trace the inner loop logic to show the new element A[i]A[i] is correctly integrated while preserving prefix properties.
    • Termination: Substitute the terminal counter value i=ni = n into the invariant to establish whole-array correctness.
Tutorial 1 Q4: Loop Invariant Correctness Proof for Primality Test

Question: Consider the following function for testing primality of a natural number n>1n > 1:

def isPrime(n):
    p = True
    for i = 2 to floor(sqrt(n)):
        if n % i == 0:
            p = False
    return p

State a non-trivial loop invariant and prove the function’s correctness.

Solution:

Rewrite the loop with an explicit counter:

def isPrime(n):
    p = True
    i = 2
    while i <= floor(sqrt(n)):
        if n % i == 0:
            p = False
        i = i + 1
    return p

  • Loop Invariant: At the start of each iteration of the while loop (with counter value ii): > p=Truep = \text{True} if and only if no integer k∈{2,3,…,i−1}k \in \{2, 3, \dots, i - 1\} divides nn.

  • 1. Initialization: Before the first iteration, i=2i = 2. The candidate divisor set {k∈ℤ:2≤k<2}=∅\{k \in \mathbb{Z} : 2 \le k < 2\} = \emptyset is empty. Vacuously, no integer in this set divides nn, and p=Truep = \text{True}. The invariant holds.

  • 2. Maintenance: Assume the invariant holds at the start of an iteration with counter value ii. During the iteration, the algorithm checks whether ii divides nn:

    • Case 1 (ii divides nn): The algorithm executes p=Falsep = \text{False}. The set of tested candidates expands to {2,…,i}\{2, \dots, i\}. Since ii divides nn, there now exists a divisor in this range, so p=Falsep = \text{False} correctly reflects the state.
    • Case 2 (ii does not divide nn): The value of pp is unchanged. By hypothesis, no number in {2,…,i−1}\{2, \dots, i-1\} divides nn, and ii does not divide nn. Hence, no number in {2,…,i}\{2, \dots, i\} divides nn, and pp retains its correct truth value. At the end of the iteration, ii is incremented to i+1i+1. The invariant holds for the next iteration.

  • 3. Termination: The loop terminates when i=⌊n⌋+1i = \lfloor \sqrt{n} \rfloor + 1. Substituting this into the invariant: > p=Truep = \text{True} if and only if no integer k∈{2,3,…,⌊n⌋}k \in \{2, 3, \dots, \lfloor \sqrt{n} \rfloor\} divides nn.

    Correctness: If an integer n>1n > 1 is composite, it can be written as n=a⋅bn = a \cdot b with 2≤a≤b2 \le a \le b. If a>na > \sqrt{n}, then a⋅b>n⋅n=na \cdot b > \sqrt{n} \cdot \sqrt{n} = n, a contradiction. Thus, any composite number must possess a divisor a≤na \le \sqrt{n}. Since the algorithm tests all integers up to ⌊n⌋\lfloor \sqrt{n} \rfloor, pp will be False if and only if nn is composite, and True if and only if nn is prime. The returned value is correct.
