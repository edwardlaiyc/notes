10. Dynamic Programming

This chapter covers the dynamic programming lectures (Weeks 9 and 10). Like divide and conquer (Chapter 2), dynamic programming (DP) solves a problem through smaller versions of it. The difference: in DP the sub-problems overlap, so plain recursion solves the same one again and again. DP solves each sub-problem once, stores the answer, and reuses it. This often turns exponential time into polynomial time.

Fibonacci numbers show the trouble and the fix. A five-step recipe follows, and then it solves two problems: longest common subsequence and 0/1 knapsack.

1. Why Plain Recursion Fails

Divide and conquer: the sub-problems are independent. Mergesort’s two halves share no work. Dynamic programming: the sub-problems overlap. DP adds one rule:

Never compute the answer to the same sub-problem more than once.

Running example: Fibonacci

F0=0,F1=1,Fn=Fn−1+Fn−2(n≥2).F_0 = 0, \qquad F_1 = 1, \qquad F_n = F_{n-1} + F_{n-2} \quad (n \ge 2).

int fib(n) {
    if (n == 0 || n == 1) return n;
    else return fib(n - 1) + fib(n - 2);
}

Each call makes two more calls. The call tree for fib(6) repeats the same values:

Call fib(6) fib(5) fib(4) fib(3) fib(2) fib(1) fib(0)
Times made 1 1 2 3 5 8 5

That is 25 calls for only 7 different values. (The counts are read off the tree; they are not in the lecture.)

How many calls?

Let RR be the number of calls. Bound the tree depth two ways:

  • Shortest branch: subtract 2 each time. Every node splits while its argument is at least 2, so the top of the tree is a full binary tree down to depth n/2n/2.
  • Deepest branch: subtract 1 each time, giving depth n−1n - 1.

A full binary tree of depth DD has 1+2+…+2D=2D+1−11 + 2 + \dots + 2^D = 2^{D+1} - 1 nodes. So

2n/2+1−1<R<2n−1.2^{n/2 + 1} - 1 < R < 2^n - 1.

For n=6n = 6: 15<25<6315 < 25 < 63. Both bounds are exponential, so plain fib takes O(2n)O(2^n) time. For n=50n = 50 the lower bound alone is about 67 million calls. Only n+1n + 1 different sub-problems exist, so almost every call repeats work.

2. The Fix: Store Each Answer

Keep a dictionary (usually an array indexed by sub-problem) of solved answers. Before solving a sub-problem, look it up:

  • solved: retrieve the answer in O(1)O(1);
  • not solved: solve it, then store the answer.

A purple node costs O(1)O(1), and the whole sub-tree under it disappears.

DP replaces an exponential-time computation by a polynomial-time one, by storing solutions and never recomputing them.

This is the idea of DFS (Chapter 5): DFS explores only undiscovered vertices, and DP solves only unsolved sub-problems.

Top-down: memoization

Keep the recursion and add the dictionary. Check it before each recursive call. Store the answer just before returning.

int fibDP(n) {
    int f1, f2;
    if (n == 0 || n == 1) { store(Soln, n, n); return n; }
    if (not member(Soln, n - 1)) f1 = fibDP(n - 1);
    else                         f1 = retrieve(Soln, n - 1);
    if (not member(Soln, n - 2)) f2 = fibDP(n - 2);
    else                         f2 = retrieve(Soln, n - 2);
    f1 = f1 + f2;
    store(Soln, n, f1);
    return f1;
}

Soln[0..n] starts at −1-1 (“not solved”). member tests Soln[j] != -1, store sets Soln[j] = s, and retrieve returns Soln[j].

Cost: one call does constant work, and fibDP really runs once per value 0…n0 \dots n. Total: O(n)O(n), against O(2n)O(2^n).

3. The Order of Sub-problems

The subproblem graph

  • One vertex for each different sub-problem.
  • An edge I→JI \to J if solving II makes a recursive call directly on JJ.

The call tree had 25 nodes. The graph has 7 vertices.

  • It must be a DAG (Chapter 5). A cycle means a sub-problem needs its own answer.
  • Fill order: solve each sub-problem after everything it points to: a reverse topological order. For Fibonacci: 0,1,…,n0, 1, \dots, n.
  • Vertices = number of sub-problems = dictionary size.

time≈(number of sub-problems)×(work per sub-problem).\text{time} \approx (\text{number of sub-problems}) \times (\text{work per sub-problem}).

For Fibonacci: (n+1)×O(1)=O(n)(n+1) \times O(1) = O(n). We reuse this formula for every problem below.

Bottom-up: tabulation

Fill the table in that order with loops. No recursion is needed.

soln[0] = 0;
soln[1] = 1;
for j = 2 to n
    soln[j] = soln[j-1] + soln[j-2];
jj 0 1 2 3 4 5 6
soln[j] 0 1 1 2 3 5 8

Saving memory. Fibonacci looks back two steps, so two variables are enough: O(1)O(1) space. But to rebuild the solution itself (LCS, knapsack), you must keep the whole table.

4. When Is DP Correct? The Principle of Optimality

Many problems ask for the best answer: longest, shortest, most profitable. These are optimization problems. DP is correct for them only if the principle of optimality holds:

The sub-solutions of an optimal solution are themselves optimal solutions of their sub-problems.

Example: if A→B→C→DA \to B \to C \to D is a shortest path, then A→B→CA \to B \to C is a shortest path from AA to CC (Chapter 6).

DP builds the best answer only from the best answers of smaller problems, never from second-best ones. That is safe only if best solutions are made of best parts.

Cut-and-paste proof. Take an optimal solution. Suppose one part is not optimal for its sub-problem. Paste in a better part. The whole is now better and still valid, which contradicts optimality. Check that the pasted part still fits the rules.

The DP selection rule. When the last decision has several possibilities, compute all of them and take the best. A greedy algorithm (Chapter 6) picks what looks best now and never checks the others.

6. Longest Common Subsequence (LCS)

A subsequence keeps some characters in their original order, not necessarily adjacent. For ACTTGCG: ACT, AG and ATTC are subsequences. TTA is not (no A after the two Ts). A common subsequence of xx and yy is a subsequence of both. An LCS is a common subsequence of maximum length. It may not be unique.

Problem. For x=⟨x1…xn⟩x = \langle x_1 \dots x_n \rangle and y=⟨y1…ym⟩y = \langle y_1 \dots y_m \rangle, find the length LCS(n,m)LCS(n, m). Brute force checks all 2n2^n subsequences of xx.

Steps 1 and 2: sub-problem and recursion

LCS(i,j)LCS(i, j) is the length of an LCS of the prefixes x1…xix_1 \dots x_i and y1…yjy_1 \dots y_j (0≤i≤n0 \le i \le n, 0≤j≤m0 \le j \le m). Prefixes appear because we look at the last character of each, and what remains is a pair of shorter prefixes. Compare xix_i with yjy_j:

  • xi=yjx_i = y_j. Some LCS ends with this match (standard argument, not in the lecture). Before it must come an LCS of x1…xi−1x_1 \dots x_{i-1} and y1…yj−1y_1 \dots y_{j-1}, or cut-and-paste gives a longer one. Length: LCS(i−1,j−1)+1LCS(i-1, j-1) + 1.
  • xi≠yjx_i \ne y_j. They cannot both end a common subsequence. So xix_i is unused, giving LCS(i−1,j)LCS(i-1, j), or yjy_j is unused, giving LCS(i,j−1)LCS(i, j-1). We do not know which, so compute both and take the larger.

LCS(i,j)={0i=0 or j=0,LCS(i−1,j−1)+1xi=yj,max⁡(LCS(i−1,j),LCS(i,j−1))xi≠yj.LCS(i, j) = \begin{cases} 0 & i = 0 \text{ or } j = 0, \\[4pt] LCS(i-1, j-1) + 1 & x_i = y_j, \\[4pt] \max\big(LCS(i-1, j),\; LCS(i, j-1)\big) & x_i \ne y_j. \end{cases}

Steps 3 to 5: graph, table, code

Cell (i,j)(i, j) depends on up-left (i−1,j−1)(i-1, j-1), above (i−1,j)(i-1, j) and left (i,j−1)(i, j-1).

The table c[0..n][0..m] has row 0 and column 0 equal to 0. Fill row by row, left to right, so the three cells are ready.

int LCS(n, m) {
    for i = 0 to n  c[i][0] = 0;
    for j = 1 to m  c[0][j] = 0;
    for i = 1 to n
        for j = 1 to m
            if (x[i] == y[j])
                c[i][j] = c[i-1][j-1] + 1;
            else if (c[i-1][j] >= c[i][j-1])
                c[i][j] = c[i-1][j];
            else
                c[i][j] = c[i][j-1];
    return c[n][m];
}

Cost: (n+1)(m+1)(n+1)(m+1) cells at O(1)O(1) each. Time O(nm)O(nm), space O(nm)O(nm).

Recovering the subsequence

Keep a hint array h that records where each cell’s value came from:

Hint Meaning Came from
\ xi=yjx_i = y_j; character is in the LCS (i−1,j−1)(i-1, j-1)
| c[i][j]=c[i−1][j]c[i][j] = c[i-1][j] above
— c[i][j]=c[i][j−1]c[i][j] = c[i][j-1] left

Tie rule: if c[i−1][j]=c[i][j−1]c[i-1][j] = c[i][j-1], take above (|), because the code tests >=.

Start at h[n][m] and follow the hints back until row 0 or column 0. Each \ gives one character, and they come out last first, so use a stack.

getSequence(n, m) {
    s = empty stack;  i = n;  j = m;
    while (i != 0 and j != 0) {
        if (h[i][j] == '\')       { s.push(x[i]); i--; j--; }
        else if (h[i][j] == '|')  i--;
        else                      j--;
    }
    pop and output everything from s;     // the LCS, in order
}

Each step lowers ii or jj, so the traceback is O(n+m)O(n + m).

By hand

  1. Write xx down the side and yy across the top. Add a row 0 and a column 0 of zeros.

7. The 0/1 Knapsack Problem

A knapsack holds total weight at most CC (a positive integer). Object ii has weight wiw_i and profit pip_i (positive integers). Find the largest total profit of a subset with total weight at most CC. “0/1” means each object is taken whole or left, never split or repeated. Brute force checks 2n2^n subsets.

Steps 1 and 2: sub-problem and recursion

P(r,j)P(r, j) is the largest profit from the first jj objects with capacity rr (0≤r≤C0 \le r \le C, 0≤j≤n0 \le j \le n). The answer is P(C,n)P(C, n). (The lecture writes CC for both; rr is the variable capacity.) Look at the last object jj. The best solution takes it or leaves it:

  • Take (needs wj≤rw_j \le r): profit pjp_j, capacity left r−wjr - w_j, so pj+P(r−wj,j−1)p_j + P(r - w_j, j-1). The rest must be optimal by cut and paste: a better set of weight at most r−wjr - w_j still fits with object jj.
  • Leave: P(r,j−1)P(r, j-1).
  • If wj>rw_j > r, only “leave” is possible.

We do not know which is better, so compute both and take the larger.

P(r,0)=P(0,j)=0,P(r,j)={max⁡(P(r,j−1),pj+P(r−wj,j−1))wj≤r,P(r,j−1)wj>r.P(r, 0) = P(0, j) = 0, \qquad P(r, j) = \begin{cases} \max\big(P(r, j-1),\; p_j + P(r - w_j, j-1)\big) & w_j \le r, \\[4pt] P(r, j-1) & w_j > r. \end{cases}

Both sub-problems use j−1j - 1 objects, so each object is decided once and never taken twice.

Steps 3 to 5: graph, table, code

(r,j)(r, j) points to (r,j−1)(r, j-1) (leave) and (r−wj,j−1)(r - w_j, j-1) (take). Every edge lowers jj, so it is a DAG. Example: C=20C = 20 with four objects.

Object 1 2 3 4
Weight ww 4 6 8 6
Profit pp 7 6 9 5

The table profit[C+1][n+1] has rows = capacities and columns = objects. Row 0 and column 0 are 0. Fill so that column c−1c-1 is done before column cc.

int knapsack(int[] w, int[] p, int C, int n) {
    for c = 0 to n  profit[0][c] = 0;
    for r = 1 to C  profit[r][0] = 0;
    for r = 1 to C                         // capacity
        for c = 1 to n {                   // objects 1..c are allowed
            profit[r][c] = profit[r][c-1];                 // leave object c
            if (w[c] <= r)
                if (profit[r][c] < profit[r - w[c]][c-1] + p[c])
                    profit[r][c] = profit[r - w[c]][c-1] + p[c];   // take object c
        }
    return profit[C][n];
}

8. Shortest Paths in a DAG

(Not from the lecture: the slides were not released. This is the standard method.)

  1. Sub-problem: dist(v)dist(v), the shortest distance from the source ss to vv.
  2. Recursion: the last edge into vv comes from some uu. By optimality, the path to uu is shortest. Try every incoming edge and take the minimum:

dist(s)=0,dist(v)=min(u,v)∈E(dist(u)+w(u,v)).dist(s) = 0, \qquad dist(v) = \min_{(u, v) \in E} \big(dist(u) + w(u, v)\big).

A vertex with no incoming edge (other than ss) has distance ∞\infty.

  1. Order: compute in topological order (Chapter 5), so every uu is done before vv.

Cost: each edge is used once, so O(|V|+|E|)O(|V| + |E|). Unlike Dijkstra (Chapter 6), this works with negative weights, since a DAG has no cycle. Replace min by max for the longest path.

  • A cell that reads a fixed number of cells (Fibonacci 2, LCS 3, knapsack 2) costs O(1)O(1).

10. Common Traps

  • Overlap. DP needs overlapping sub-problems. Without overlap, plain divide and conquer is enough.
  • Optimality. DP is correct only if the principle of optimality holds.
  • Memoization is top-down, tabulation is bottom-up. Same complexity.
  • Order. The subproblem graph must be a DAG. Fill dependencies first (reverse topological).
  • Two factors. Time ≈\approx (sub-problems) ×\times (work per sub-problem). Do not forget the second when a cell loops over many choices.
  • Fibonacci. Plain: O(2n)O(2^n) calls, between 2n/2+1−12^{n/2+1}-1 and 2n−12^n-1. Memoized: O(n)O(n) time. Two variables: O(1)O(1) space.
  • Define first. Write the sub-problem in words before step 2. A vague step 1 breaks the rest.
  • Subsequence vs substring. A subsequence keeps order but need not be contiguous. A substring must be contiguous.
  • LCS rules. Match: diagonal +1+1. Mismatch: larger of above and left, never the diagonal. Time and space O(nm)O(nm), traceback O(n+m)O(n+m). Tie: take above. An LCS may not be unique.
  • Memory saving loses the path. Two variables (or two rows) save memory, but you can no longer trace back.
  • Knapsack axes. Rows are capacities, columns are objects: profit[r][c].
  • Take reads the previous column (c−1c-1). Reading the same column lets an object be taken twice.
  • Too heavy. If wc>rw_c > r, “take” does not exist. Do not read a negative row.
  • Pseudo-polynomial. O(nC)O(nC) is not polynomial, because CC is a value, not a size.
  • Greedy fails. Profit per unit weight does not solve 0/1 knapsack.
