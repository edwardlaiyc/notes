11. String Matching

This chapter covers Lecture 11. Chapter 10 compared two whole sequences. This chapter asks a narrower question: where does one short string appear inside a long one? Three algorithms answer it, and each avoids repeating work:

  • Simple scan (brute force): try every position. It repeats work.
  • Rabin-Karp: turn each piece of text into a number, and compare numbers instead of characters.
  • Boyer-Moore: compare from the right end of the pattern, and skip ahead after a mismatch.

1. The Problem

Given a text TT of nn characters and a pattern PP of mm characters, return the position where the first occurrence of PP in TT starts, or −1-1 if there is none.

Name Meaning
TT, PP the text (length nn) and the pattern (length m≤nm \le n)
jj, kk the current position in TT and in PP
Σ\Sigma the alphabet: the set of possible characters
d=|Σ|d = |\Sigma| the number of characters in the alphabet

Cost is the number of character comparisons. The simple scan and Rabin-Karp count positions from 0. Boyer-Moore counts from 1, as the lecture does, so the same occurrence is one higher there.

2. The Simple Scan (Brute Force)

Put the pattern at position 0 and compare left to right. On a full match, return the position. On the first mismatch, shift the pattern one place right and restart from the pattern’s first character. Stop when fewer than mm characters remain.

int SimpleScan(char[] P, char[] T, int m) {
    int i, j, k;
    // i: the current guess of where P begins in T
    // j: the current character in T
    // k: the current character in P
    j = k = 0;
    i = 0;
    while (j < n) {
        if (T[j] == P[k]) {          // match: move both forward
            j++;
            k++;
            if (k == m) return i;    // all m characters matched
        }
        else {                       // mismatch: shift P one place right
            j = ++i;
            k = 0;
            if (j > n - m) break;    // not enough text left
        }
    }
    return -1;
}

On a mismatch, jj goes back to i+1i + 1, so matched text is read again. The other two algorithms avoid this.

Running example:

0 5 A, B, A, B match. C against A fails.
1 1 B against A fails at once.

Total: 11 comparisons.

Worst case. Near matches everywhere: the first m−1m - 1 characters match and the last fails. For PP = AAAAC and TT = AAAAAAAAAAAA (n=12n = 12): n−m+1=8n - m + 1 = 8 positions at 5 comparisons each.

m(n−m+1)=O(mn).m\,(n - m + 1) = O(mn).

Best cases. Found at once: mm comparisons. Not found, but the first character of PP never appears in TT: n−m+1n - m + 1 comparisons. Real text usually mismatches early, so the scan beats its worst case.

3. Rabin-Karp: Compare Numbers, Not Strings

Comparing two numbers costs one step. So turn the pattern into a number pp and each window (a block of mm text characters) into a number tt. If p=tp = t, the pattern is found. Otherwise slide the window one place right. This pays off only if:

  • pp and the first tt cost Θ(m)\Theta(m), once;
  • each next tt costs Θ(1)\Theta(1) from the previous one.

Strings as numbers: Horner’s rule

Read the string in base dd, each character as a digit 0…d−10 \dots d-1. For “36215” with d=10d = 10:

p=3⋅104+6⋅103+2⋅102+1⋅10+5=(((3⋅10+6)⋅10+2)⋅10+1)⋅10+5.p = 3 \cdot 10^4 + 6 \cdot 10^3 + 2 \cdot 10^2 + 1 \cdot 10 + 5 = \big(\big((3 \cdot 10 + 6) \cdot 10 + 2\big) \cdot 10 + 1\big) \cdot 10 + 5.

Horner’s rule (the right-hand form) multiplies by dd once per step: 3→36→362→3621→362153 \to 36 \to 362 \to 3621 \to 36215. It needs m−1m - 1 multiplications, not Θ(m2)\Theta(m^2) for separate powers.

p = P[0];
for j = 1 to m-1
    p = p * d + P[j];

For letters, pick digits: A = 0, B = 1, C = 2, d=3d = 3. Then ABABC is digits 0, 1, 0, 1, 2 and p=32p = 32. Check: 0⋅81+1⋅27+0⋅9+1⋅3+2=320\cdot81 + 1\cdot27 + 0\cdot9 + 1\cdot3 + 2 = 32.

Sliding the window in Θ(1)\Theta(1)

Moving the window right removes the leftmost digit (the most significant digit, MSD, with weight dm−1d^{m-1}) and adds a new digit on the right (the least significant digit, LSD, weight 1). For the text 3 6 4 1 5 2 with m=5m = 5: 36415→6415236415 \to 64152. Subtract 3⋅1043 \cdot 10^4, multiply by 10, add 2.

tnew=(told−MSD⋅dm−1)⋅d+LSD.t_{\text{new}} = \big(t_{\text{old}} - \text{MSD} \cdot d^{\,m-1}\big) \cdot d + \text{LSD}.

t = (t - T[i] * dM) * d + T[i+m];

dM is dm−1d^{\,m-1} (not dmd^{\,m}), computed once:

dM = 1;
for j = 1 to m-1
    dM = dM * d;

Hashing: keep the numbers small

A long pattern (m=100m = 100) gives a number too big for a machine word. Keep only the remainder mod a large prime qq. The value h=tmod⁡qh = t \bmod q is the hash. Hashing loses information:

  • hp≠hth_p \ne h_t: the window is definitely not the pattern.
  • hp=hth_p = h_t: it might be. Compare the characters to be sure.

A hash match that is not a real match is a spurious hit. It wastes up to mm comparisons.

Binary example with q=13q = 13 (hp=5h_p = 5):

At position 3, 18mod⁡13=5=hp18 \bmod 13 = 5 = h_p, but 10010 ≠\ne 00101. At position 9 the comparison succeeds.

The real algorithm never builds tt. It reduces mod qq at every step, using these rules:

(x+y)mod⁡q=[(xmod⁡q)+(ymod⁡q)]mod⁡q(xmod⁡q)mod⁡q=xmod⁡q(x⋅y)mod⁡q=[(xmod⁡q)⋅(ymod⁡q)]mod⁡q\begin{aligned} (x + y) \bmod q &= \big[(x \bmod q) + (y \bmod q)\big] \bmod q \\ (x \bmod q) \bmod q &= x \bmod q \\ (x \cdot y) \bmod q &= \big[(x \bmod q) \cdot (y \bmod q)\big] \bmod q \end{aligned}

Example, q=13q = 13: (3⋅10+6)mod⁡13=(4+6)mod⁡13=10(3 \cdot 10 + 6) \bmod 13 = (4 + 6) \bmod 13 = 10, and 36mod⁡13=1036 \bmod 13 = 10.

hash and rehash

hash is Horner’s rule with mod qq at each step. It runs in Θ(m)\Theta(m).

int hash(Txt, m, d) {
    int h = Txt[0] % q;
    for (int i = 1; i < m; i++)
        h = (h * d + Txt[i]) % q;
    return h;
}

Example: hash("36415", 5, 10) with q=7q = 7: 3→36mod⁡7=1→14mod⁡7=0→1→15mod⁡7=13 \to 36 \bmod 7 = 1 \to 14 \bmod 7 = 0 \to 1 \to 15 \bmod 7 = 1. Check: 36415=7×5202+136415 = 7 \times 5202 + 1.

rehash is the sliding formula with mod qq. It runs in Θ(1)\Theta(1).

int rehash(T, i, m, ht) {
    oldest = (T[i] * dM) % q;                 // dM is d^(m-1) mod q
    oldest_removed = ((ht + q) - oldest) % q;
    return (oldest_removed * d + T[i+m]) % q;
}
  • oldest is MSD⋅dm−1\text{MSD} \cdot d^{m-1} mod qq. oldest_removed subtracts it. The last line shifts left and adds the new digit.
  • Why + q: ht can be smaller than oldest, and % of a negative number may be negative. Adding qq keeps the value mod qq and makes it positive.
  • dM = (dM * d) % q inside the same loop as before.

Example: text 3 6 4 1 5 2, m=5m=5, d=10d=10, q=7q=7, first hash 1. Here dM=104mod⁡7=4dM = 10^4 \bmod 7 = 4. oldest =3⋅4mod⁡7=5= 3\cdot4 \bmod 7 = 5. oldest_removed =(1+7−5)mod⁡7=3= (1+7-5) \bmod 7 = 3. Result (3⋅10+2)mod⁡7=4(3\cdot10 + 2) \bmod 7 = 4. Check: 64152=7×9164+464152 = 7 \times 9164 + 4.

The full algorithm

int RKscan(P, T) {
    m = Length(P);
    n = Length(T);
    dM = 1;
    for j = 1 to m-1  dM = dM * d % q;       // d = |Sigma|
    hp = hash(P, m, d);                      // Theta(m)
    ht = hash(T, m, d);                      // Theta(m)
    for (j = 0; j <= n - m; j++) {           // at most n-m+1 windows
        if (hp == ht && equal_string(P, T, 0, j, m))
            return j;
        if (j < n - m) ht = rehash(T, j, m, ht);
    }
    return -1;                               // pattern not found
}

equal_string runs only when the hashes are equal.

Cost

  • Preprocessing: two hash calls, Θ(m)\Theta(m).
  • Scan: at most n−m+1n-m+1 windows, each Θ(1)\Theta(1) plus up to mm comparisons on a hash hit.
  • Worst case: every window is a hit: Θ((n−m+1)m)\Theta((n-m+1)\,m), no better than the simple scan.
  • Expected: O(n+m)O(n + m) plus the time for spurious hits.

(Not in the lecture; standard result.) If hashes spread evenly over qq values, a wrong window hits with chance about 1/q1/q. That gives about (n−m+1)/q(n-m+1)/q spurious hits at mm comparisons each:

O(n+m+(n−m+1)mq).O\!\left(n + m + \frac{(n - m + 1)\,m}{q}\right).

With q>mq > m this is O(n+m)O(n + m). So qq should be a large prime.

A good hash

  • Large prime qq. (Not in the lecture.) qq must share no factor with dd. With d=q=10d = q = 10, tmod⁡10t \bmod 10 is only the last digit.
  • Position matters. Horner’s rule multiplies each digit by a different power of dd. A hash that just adds characters gives every rearrangement the same value.
  • Always check the characters. Equal hashes never prove a match.

4. Boyer-Moore: Skip Ahead Using the Mismatch

At a mismatch the simple scan knows two things: which text character failed, and which part of the pattern matched just before. It shifts by one and forgets both. Boyer-Moore builds two tables from the pattern before the scan:

  • charJump uses the mismatched text character.
  • matchJump uses the part of the pattern that already matched.

Both shifts are safe (they cannot skip an occurrence), so the algorithm takes the larger.

Compare right to left. The scan moves along T[1..n]T[1..n] left to right, but compares P[1..m]P[1..m] from its last character backwards. If the text character under the pattern’s end is not in PP at all, the whole pattern can move past it. Many text characters are never compared, so long patterns help.

Shift and jump

Say the mismatch is at text position jj and pattern position kk. The pattern’s end is m−km - k places to the right of jj.

  • The shift ss is how far the pattern moves right.
  • The jump is how far jj moves right: catch up to the old end, then move with the pattern.

jump=(m−k)+s.\text{jump} = (m - k) + s.

The tables hold jumps, because the scan tracks jj.

int BMscan(char[] P, char[] T, int m, int[] charJump, int[] matchJump) {
    int j, k;
    j = m; k = m;                        // P[1] and T[1] are the first characters
    while (j <= n) {
        if (k < 1) return j + 1;         // match found
        if (T[j] == P[k]) { j--; k--; }  // match: move both left
        else {                           // mismatch: shift P right
            j += max(charJump[T[j]], matchJump[k]);
            k = m;
        }
    }
    return -1;                           // match not found
}

After a match, jj and kk go left. When kk reaches 0, the occurrence starts at j+1j + 1. After a mismatch, jj jumps right to the text position under the shifted pattern’s last character, and kk resets to mm.

charJump: the mismatched text character

Let the text character be “d”. After a shift, the pattern character under T[j]T[j] must be “d”, or no pattern character may sit under it.

  • “d” not in PP: slide PP to start just after T[j]T[j]. Shift s=ks = k, jump (m−k)+k=m(m-k) + k = m.
  • “d” in PP: slide until the rightmost “d” of PP, at position ii, is under T[j]T[j]. The rightmost one gives the smallest safe shift. Shift s=k−is = k - i, jump m−im - i.

charJump[d]={md is not in P,m−ithe rightmost d in P is at position i.\text{charJump}[d] = \begin{cases} m & d \text{ is not in } P, \\ m - i & \text{the rightmost } d \text{ in } P \text{ is at position } i. \end{cases}

It is the distance from the rightmost “d” to the end of PP, and does not depend on kk.

Lecture examples. For PP = crackers (m=8m = 8): a space is not in PP, so j=j+8j = j + 8. A “c” has its rightmost occurrence at position 4, so charJump[c]=8−4=4\text{charJump}[c] = 8 - 4 = 4.

void computeJumps(char[] P, int m, int alpha, int[] charJump) {
    char ch; int k;
    for (ch = 0; ch < alpha; ch++)      // alpha = |Sigma|
        charJump[ch] = m;               // default: not in P
    for (k = 1; k <= m; k++)
        charJump[P[k]] = m - k;         // distance from the end
}

The loop runs left to right, so a later position overwrites an earlier one and the table keeps the rightmost occurrence. Cost: O(|Σ|+m)O(|\Sigma| + m).

By hand: for each character of PP, find its rightmost position ii and write m−im - i. Every character not in PP gets mm. The last character of PP gets 0.

When charJump alone fails

If the rightmost copy of the text character lies to the right of the mismatch (i>ki > k), then s=k−is = k - i is negative: the pattern would move left. For PP = crackers, “ckers” matches, then P[3]P[3] = a fails against an e. The rightmost “e” is at position 6, to the right of k=3k = 3.

Simplified Boyer-Moore forces a shift of at least one: j += max(charJump[T[j]], m - k + 1). Here 8−3+1=68 - 3 + 1 = 6 instead of 2. The full algorithm uses matchJump in its place.

matchJump: the part that already matched

At a mismatch at P[k]P[k], the suffix P[k+1..m]P[k+1..m] (length m−km - k) has matched. We look for another copy of it in PP to slide into place.

matchJump[k]=(m−k)+Slide[k].\text{matchJump}[k] = (m - k) + \text{Slide}[k].

Slide[k]\text{Slide}[k] is the pattern’s own shift. Three cases, all with Slide[k]=m−q\text{Slide}[k] = m - q:

  1. The suffix appears earlier in PP, preceded by a character different from P[k]P[k]. Let qq be where that copy ends. The preceding character must differ, or it would meet the same text character and fail again. A copy at the very start of PP has nothing before it and counts.
  2. Only a prefix of PP matches the end of the suffix. Let qq be the length of the longest such prefix.
  3. Neither. q=0q = 0: slide the pattern fully past, Slide[k]=m\text{Slide}[k] = m.

Last position: at k=mk = m nothing has matched, so Slide[m]=1\text{Slide}[m] = 1 and matchJump[m]=1\text{matchJump}[m] = 1.

By hand, for each kk from mm down to 1: write the suffix P[k+1..m]P[k+1..m]. Try case 1 (take the rightmost valid copy), then case 2, then case 3. Then Slide[k]=m−q\text{Slide}[k] = m - q.

Tracing by hand: build both tables, set j=k=mj = k = m, and compare T[j]T[j] with P[k]P[k] (one comparison each). On a match, decrease both. On a mismatch, add the maximum jump to jj and set k=mk = m. Stop with “not found” when j>nj > n. After each shift, jj is under the pattern’s last character.

Cost

From the lecture: charJump takes O(|Σ|+m)O(|\Sigma| + m). Many text characters are never compared, so the scan is often sublinear, and longer patterns skip more.

Not in the lecture (standard results):

  • Best case: about n/mn/m comparisons, when no text character met is in PP.
  • matchJump can be built in O(m)O(m) with a cleverer algorithm than the by-hand method.
  • charJump only is Θ(mn)\Theta(mn) in the worst case. Take P=bam−1P = \text{b}\,\text{a}^{m-1} and T=anT = \text{a}^n. Each position matches m−1m-1 a’s, then b fails. charJump[a]=0\text{charJump}[a] = 0, so the pattern moves only one place.
  • Full Boyer-Moore fixes that example. At k=1k=1 the suffix am−1\text{a}^{m-1} is case 3, so matchJump[1]=(m−1)+m\text{matchJump}[1] = (m-1)+m.
  • First occurrence or none: at most about 3n3n comparisons (Cole, 1994), so O(n+m)O(n+m).
  • Every occurrence: O(mn)O(mn) again (for P=T=anP = T = \text{a}^n). The Galil rule restores O(n+m)O(n+m).

Experiments (lecture). Brute force did better than expected, because near matches are rare in real text. Rabin-Karp did much worse: function calls, slow mod divisions and character conversion cost time. Boyer-Moore is considered the most efficient for usual applications, such as a text editor. The lecture also tested KMP, which is not covered here.

Rules of thumb. Usual text and longer patterns: Boyer-Moore. Binary strings: KMP is recommended, since a two-letter alphabet gives tiny charJump values. Very short patterns: the brute-force scan, which has no preprocessing.

6. Common Traps

  • Simple scan. Worst case m(n−m+1)m(n-m+1). After a mismatch it shifts by one and restarts at the pattern’s first character.
  • Equal hashes prove nothing. Always compare characters. Different hashes do prove no match.
  • Rabin-Karp worst case is Θ((n−m+1)m)\Theta((n-m+1)m). Its advantage is only the expected case.
  • rehash. The + q stops a negative result. dM is dm−1d^{\,m-1}, not dmd^{\,m}.
  • Mod at every step. Never build the full number first.
  • Hash must use position. A hash that ignores it gives many spurious hits. Letters need digit values 0…d−10 \dots d-1 first.
  • Boyer-Moore directions. Compare the pattern right to left, move along the text left to right.
  • Numbering. Boyer-Moore counts from 1 (match at j+1j + 1 when k<1k < 1). The others count from 0.
  • Jumps, not shifts. The tables hold jumps: shift plus m−km - k.
  • charJump. Rightmost occurrence. The last character of PP gets 0. A character not in PP gets mm. Alone it can shift left; simplified Boyer-Moore uses max⁡(charJump,m−k+1)\max(\text{charJump}, m-k+1).
  • matchJump. (m−k)+Slide[k](m-k) + \text{Slide}[k], with matchJump[m]=1\text{matchJump}[m] = 1. In case 1 the earlier copy must be preceded by a character different from P[k]P[k].
  • Full shift is the maximum of charJump and matchJump.
  • charJump only can still be Θ(mn)\Theta(mn). matchJump protects the worst case.
