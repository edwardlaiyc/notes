Not all algorithmic problems admit polynomial-time solutions. When computational problems resist efficient algorithms, establishing that a problem is NP-complete provides a mathematical guarantee that no polynomial-time algorithm exists unless P=NPP = NP. Recognizing computational intractability prevents wasting engineering effort searching for non-existent optimal algorithms and directs focus toward approximation heuristics, special-case topologies, and parameterized algorithms.

This chapter covers decision vs. optimization problems, the formal definitions of complexity classes P, NP, and NP-Complete, polynomial-time reductions (A≤pBA \le_p B), Cook-Levin’s theorem, and formal NP-completeness proofs for canonical problems (SAT, 3-SAT, Clique, TSP, and Knapsack).

1. Decision Problems vs. Optimization Problems

Algorithms address two primary categories of computational problems:

  • Optimization Problem: Finds the optimal (minimum or maximum) feasible solution according to a cost objective (e.g. finding the absolute shortest path, or the minimum-cost travelling salesperson tour).
  • Decision Problem: Has a binary YES or NO answer (e.g. “Is there a simple path between ss and tt with total weight ≤k\le k?”).

Every optimization problem can be cast as an equivalent decision problem by introducing an explicit threshold bound kk:

Optimization Problem Equivalent Decision Formulation
Shortest Path: Find minimum distance from ss to tt. Is there a path from ss to tt of weight ≤k\le k?
0/1 Knapsack: Find maximum profit within capacity WW. Is there a subset of weight ≤W\le W with profit ≥P\ge P?
CLIQUE: Find maximum size complete subgraph in GG. Does GG contain a clique of size ≥k\ge k?
TSP: Find minimum weight tour visiting all cities. Does GG have a tour visiting every city with weight ≤k\le k?

[!NOTE] Equivalence of Difficulty: If an optimization problem can be solved in polynomial time, its decision counterpart is trivially solvable in polynomial time (compute the optimum and compare against kk). Conversely, binary searching over the threshold kk solves the optimization problem using O(log⁡(Range))O(\log(\text{Range})) calls to the decision procedure.

2. The Complexity Classes P and NP

Complexity theory classifies decision problems based on the computational resources required to solve them versus verify candidate solutions:

flowchart TD
    subgraph Classes ["Computational Complexity Classes"]
        P["Class P<br/>Solvable in polynomial time O(n^k)"]
        NP["Class NP<br/>Verifiable in polynomial time O(n^k)"]
        NPC["Class NP-Complete<br/>Hardest problems in NP"]
    end

Class P (Polynomial Time)

PP is the class of decision problems that can be solved by a deterministic algorithm in polynomial time O(nk)O(n^k) for some constant kk.

  • Examples: Shortest paths (Dijkstra O(|E|+|V|log⁡|V|)O(|E| + |V| \log |V|)), Minimum Spanning Tree (Prim/Kruskal O(|E|log⁡|V|)O(|E| \log |V|)), Connectivity (BFS/DFS O(|V|+|E|)O(|V| + |E|)), Sorting, Linear Programming.

Class NP (Nondeterministic Polynomial Time)

NPNP is the class of decision problems for which a proposed solution (“YES” instance certificate / witness) can be verified in polynomial time by a deterministic algorithm.

Alternatively, an NP problem is solvable in polynomial time by an idealized nondeterministic algorithm executing two phases:

  1. Guess Phase: A non-deterministic guessing machine magically generates an arbitrary string CC (the candidate certificate).
  2. Verify Phase: A standard deterministic algorithm inspects CC and instance xx, outputting YES in polynomial time if CC is a valid certificate.

The P⊆NPP \subseteq NP Relation and the P=?NPP \stackrel{?}{=} NP Question

  • Every problem in PP is also in NPNP (P⊆NPP \subseteq NP): If a problem can be solved from scratch in polynomial time, a certificate can simply be ignored and the problem solved directly in polynomial time.
  • The Millennium Open Question (P=?NPP \stackrel{?}{=} NP): Does the ability to verify a solution quickly imply the ability to find it quickly? Most computer scientists conjecture that P≠NPP \ne NP.
Tutorial 12 Q1: Classification of Decision Problem into P vs. NP

Question: Is the following problem in the class P or NP? Justify your answer: > Given a network of cities GG with non-negative edge weights and a positive integer kk. Are the shortest paths between all pairs of cities not longer than kk?

Solution:

  • Classification: The problem is in P (and consequently in NP).
  • Justification:
    1. Dijkstra’s algorithm computes the shortest paths from a single source vertex to all other vertices in O(|V|2)O(|V|^2) time (using an adjacency matrix) or O(|E|+|V|log⁡|V|)O(|E| + |V| \log |V|) time (using a min-heap).
    2. Running Dijkstra’s algorithm from every vertex u∈Vu \in V computes all-pairs shortest paths in |V|×O(|V|2)=O(|V|3)|V| \times O(|V|^2) = O(|V|^3) time. (Alternatively, the Floyd-Warshall dynamic programming algorithm solves all-pairs shortest paths directly in Θ(|V|3)\Theta(|V|^3) time).
    3. Once all-pairs shortest path distances dist[u][v]dist[u][v] are computed, checking whether every pairwise distance satisfies dist[u][v]≤kdist[u][v] \le k takes O(|V|2)O(|V|^2) comparisons.
    4. Total execution time is O(|V|3)O(|V|^3), which is strictly bounded by a polynomial in the input size.
    5. Because a deterministic algorithm can solve this decision problem in polynomial time, the problem belongs to Class P.
Tutorial 12 Q2: Proving the CLIQUE Problem is in NP

Question: Given a graph G=(V,E)G = (V, E) and positive integer k≤|V|k \le |V|. The CLIQUE problem asks whether GG contains a kk-clique (a subset V′⊆VV' \subseteq V of size |V′|≥k|V'| \ge k such that every pair of vertices in V′V' is connected by an edge in EE). Show that the CLIQUE problem is in NP.

Solution:

To prove CLIQUE ∈NP\in NP, we specify a polynomial-time verification algorithm:

  1. Certificate (Witness): The candidate subset of vertices V′⊆VV' \subseteq V.
  2. Verification Protocol:
    • Step 1: Verify that every vertex in V′V' belongs to VV. Time: O(|V′|)≤O(|V|)O(|V'|) \le O(|V|).
    • Step 2: Verify that |V′|≥k|V'| \ge k. Time: O(1)O(1) (or O(|V|)O(|V|)).
    • Step 3: For every distinct pair of vertices u,v∈V′u, v \in V', verify that edge (u,v)∈E(u, v) \in E.
      • Number of pairs checked: (|V′|2)=|V′|(|V′|−1)2=O(|V|2)\binom{|V'|}{2} = \frac{|V'|(|V'| - 1)}{2} = O(|V|^2).
      • Checking edge existence takes O(1)O(1) in an adjacency matrix, or O(|V|)O(|V|) in an adjacency list.
      • Total edge verification time: O(|V|2)O(|V|^2).
  3. Conclusion: The verification algorithm runs in deterministic O(|V|2)O(|V|^2) polynomial time. If GG contains a kk-clique, the verifier outputs YES given V′V'. Thus, CLIQUE ∈\in NP.
Tutorial 12 Q3: Proving 3-CNF-SAT is in NP

Question: In the 3-CNF-SAT problem, we are given a set of boolean variables U={u1,…,un}U = \{u_1, \dots, u_n\} and a collection of clauses C={c1,…,cm}C = \{c_1, \dots, c_m\} where each clause cjc_j is a disjunction (∨\lor) of exactly 3 literals. The problem asks if there exists a truth assignment satisfying all clauses simultaneously. Show that 3-CNF-SAT is in NP.

Solution:

  1. Certificate: An assignment of boolean truth values to the nn variables: A=(u1∈{T,F},u2∈{T,F},…,un∈{T,F})A = (u_1 \in \{T, F\}, u_2 \in \{T, F\}, \dots, u_n \in \{T, F\}).
  2. Verification Protocol:
    • For each of the mm clauses cj=(lj,1∨lj,2∨lj,3)c_j = (l_{j,1} \lor l_{j,2} \lor l_{j,3}):
      • Evaluate the truth value of the 3 literals under assignment AA.
      • The clause evaluates to True if at least one literal is True. This requires at most 3 lookups: O(1)O(1) time per clause.
    • Total verification time across all mm clauses: m×O(1)=𝑶(𝒎).m \times O(1) = \mathbf{O(m)}.
  3. Conclusion: The verifier validates the certificate in deterministic linear time O(m)=O(Input Size)O(m) = O(\text{Input Size}). Therefore, 3-CNF-SAT ∈\in NP.

3. Polynomial-Time Reductions (A≤pBA \le_p B)

To establish the relative hardness of problems, we use polynomial-time reductions:

A decision problem AA is polynomial-time reducible to decision problem BB (written A≤pBA \le_p B) if there exists a polynomial-time computable transformation function ff mapping instances of AA to instances of BB such that:

x is a YES-instance of A⇔f(x) is a YES-instance of Bx \text{ is a YES-instance of } A \iff f(x) \text{ is a YES-instance of } B

Core Implications of Reductions

  • Solvability: If A≤pBA \le_p B and B∈PB \in P, then A∈PA \in P. (If BB is easy, AA is easy).
  • Hardness: If A≤pBA \le_p B and A∉PA \notin P, then B∉PB \notin P. (BB is at least as hard as AA).
  • Transitivity: If A≤pBA \le_p B and B≤pCB \le_p C, then A≤pCA \le_p C.

4. NP-Completeness and the Cook-Levin Theorem

A decision problem XX is NP-Complete (NPC) if:

  1. X∈NPX \in NP (membership: verifiable in polynomial time).
  2. For every problem Y∈NPY \in NP, Y≤pXY \le_p X (XX is NP-hard).

[!IMPORTANT] The Cook-Levin Theorem (1971): Stephen Cook and Leonid Levin independently proved that the Boolean Satisfiability Problem (SAT) is NP-Complete. They proved directly from first principles that any polynomial-time verification computation of a nondeterministic Turing machine can be encoded as a polynomial-sized boolean formula in Conjunctive Normal Form.

Step-by-Step Method: Proving a Problem BB is NP-Complete

Once SAT was established as the initial NP-complete anchor, proving that any subsequent problem BB is NP-complete does not require reducing all problems in NPNP from scratch. By transitivity:

flowchart LR
    K["1. Select known NP-Complete problem A (e.g. SAT, 3-SAT, Clique)"] --> Red["2. Design polynomial reduction f mapping A -> B"]
    Red --> Equiv["3. Prove equivalence: x in A <=> f(x) in B"]
    Equiv --> Ver["4. Prove B in NP (polynomial verifier)"]
    Ver --> Done["Conclusion: B is NP-Complete"]
  1. Prove B∈NPB \in NP: Define a candidate certificate and verify it in deterministic polynomial time.
  2. Select a Known NP-Complete Problem AA: (e.g. SAT, 3-CNF-SAT, CLIQUE, VERTEX-COVER).
  3. Formulate Transformation ff: Define an algorithm that maps any instance xx of AA to an instance f(x)f(x) of BB in polynomial time (O(nc)O(n^c)).
  4. Prove Bidirectional Equivalence:
    • (⟹)(\implies) If xx is a YES-instance of AA, then f(x)f(x) is a YES-instance of BB.
    • (⟸)(\impliedby) If f(x)f(x) is a YES-instance of BB, then xx is a YES-instance of AA (or contrapositive: x∉A⟹f(x)∉Bx \notin A \implies f(x) \notin B).
Tutorial 12 Q4: Proving 3-CNF-SAT is NP-Complete via Reduction from SAT

Question: Given that SAT (satisfiability of arbitrary CNF formulas) is NP-complete, prove that 3-CNF-SAT is also NP-complete.

Solution:

  • 1. Membership in NP: From Tutorial 12 Q3, a truth assignment certificate can be verified across all mm clauses in O(m)O(m) linear time. Thus 3-CNF-SAT ∈\in NP.

  • 2. Reduction: SAT≤p3-CNF-SAT\text{SAT} \le_p \text{3-CNF-SAT}: We must transform an arbitrary CNF formula ϕ=C1∧C2∧…∧Cm\phi = C_1 \land C_2 \land \dots \land C_m where clauses have arbitrary length into a 3-CNF formula ϕ′\phi' where every clause has exactly 3 literals. Transform each clause C=(x1∨x2∨…∨xk)C = (x_1 \lor x_2 \lor \dots \lor x_k) independently:

    • Case 1 (k=1k = 1 literal, C=(x1)C = (x_1)): Introduce two new dummy variables y1,y2y_1, y_2 and expand into 4 clauses of 3 literals: C′=(x1∨y1∨y2)∧(x1∨¬y1∨y2)∧(x1∨y1∨¬y2)∧(x1∨¬y1∨¬y2)C' = (x_1 \lor y_1 \lor y_2) \land (x_1 \lor \neg y_1 \lor y_2) \land (x_1 \lor y_1 \lor \neg y_2) \land (x_1 \lor \neg y_1 \lor \neg y_2) (For all 4 clauses to be true simultaneously, x1x_1 must evaluate to True).
    • Case 2 (k=2k = 2 literals, C=(x1∨x2)C = (x_1 \lor x_2)): Introduce one dummy variable z1z_1 and expand into 2 clauses: C′=(x1∨x2∨z1)∧(x1∨x2∨¬z1)C' = (x_1 \lor x_2 \lor z_1) \land (x_1 \lor x_2 \lor \neg z_1) (Independent of whether z1z_1 is True or False, x1∨x2x_1 \lor x_2 must be True).
    • Case 3 (k=3k = 3 literals): Retain clause unmodified: C′=(x1∨x2∨x3)C' = (x_1 \lor x_2 \lor x_3).
    • Case 4 (k>3k > 3 literals, C=(x1∨x2∨…∨xk)C = (x_1 \lor x_2 \lor \dots \lor x_k)): Introduce k−3k - 3 auxiliary variables w1,w2,…,wk−3w_1, w_2, \dots, w_{k-3} and construct a chain of k−2k - 2 clauses: C′=(x1∨x2∨w1)∧(¬w1∨x3∨w2)∧(¬w2∨x4∨w3)∧…∧(¬wk−3∨xk−1∨xk)C' = (x_1 \lor x_2 \lor w_1) \land (\neg w_1 \lor x_3 \lor w_2) \land (\neg w_2 \lor x_4 \lor w_3) \land \dots \land (\neg w_{k-3} \lor x_{k-1} \lor x_k)

  • 3. Correctness & Equivalence Proof:

    • If original clause CC is satisfied: At least one literal xi=Truex_i = \text{True}.
      • If i∈{1,2}i \in \{1, 2\}, setting w1=w2=…=wk−3=Falsew_1 = w_2 = \dots = w_{k-3} = \text{False} satisfies all subsequent clauses.
      • If i∈{k−1,k}i \in \{k-1, k\}, setting all wj=Truew_j = \text{True} satisfies all preceding clauses.
      • If 2<i<k−12 < i < k-1, set w1…wi−2=Truew_1 \dots w_{i-2} = \text{True} and wi−1…wk−3=Falsew_{i-1} \dots w_{k-3} = \text{False}, satisfying every clause in the chain.
    • If all xi=Falsex_i = \text{False}: The chain collapses to: (w1)∧(¬w1∨w2)∧…∧(¬wk−3),(w_1) \land (\neg w_1 \lor w_2) \land \dots \land (\neg w_{k-3}), which requires w1⟹w2⟹…⟹wk−3⟹Falsew_1 \implies w_2 \implies \dots \implies w_{k-3} \implies \text{False}, making simultaneous satisfaction impossible.

  • 4. Complexity: A clause of kk literals yields at most k−2k - 2 new 3-literal clauses and k−3k - 3 variables. The reduction runs in O(|ϕ|)O(|\phi|) linear time. Therefore, SAT≤p3-CNF-SAT\text{SAT} \le_p \text{3-CNF-SAT}, establishing that 3-CNF-SAT is NP-Complete.

6. Coping with NP-Completeness in Practice

When a real-world problem is proven NP-complete, engineers deploy four practical alternatives:

  1. Small Input Sizes (N≤25N \le 25): Exact branch-and-bound or exhaustive search algorithms (e.g. O(2n)O(2^n) or O(n!)O(n!)) run within acceptable seconds on modern CPUs.
  2. Pseudo-Polynomial Algorithms: If parameters are bounded by small integers, dynamic programming provides fast practical runtimes (e.g. 0/1 Knapsack in O(nW)O(nW)).
  3. Special Topological Cases: Restricting problem domains often yields polynomial algorithms (e.g. 2-SAT in linear O(n+m)O(n + m) time; Maximum Independent Set on trees in linear time via DP).
  4. Approximation Algorithms & Greedy Heuristics: Accept a solution with a provable guarantee of being within a bounded factor of the optimum (e.g. 2-approximation for Vertex Cover; Christofides 1.5-approximation for Metric TSP).
