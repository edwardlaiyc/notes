The Divide and Conquer paradigm solves complex problems by breaking them recursively into smaller, independent subproblems of the identical type, solving each subproblem, and synthesizing their solutions.

This chapter analyzes the canonical divide-and-conquer sorting algorithm: Mergesort. It covers the mechanics of merging sorted sub-arrays, exact comparison counting across recursion levels, recurrence solving via unrolling and recursion trees, and algorithmic applications such as simultaneous minimum/maximum finding and duplicate detection.

1. The Divide-and-Conquer Paradigm

A divide-and-conquer algorithm operates in three distinct phases:

flowchart TD
    D["1. Divide: Partition input into disjoint subproblems"] --> C["2. Conquer: Recursively solve subproblems (base case if small)"]
    C --> M["3. Combine: Merge subproblem solutions into full solution"]
  1. Divide: Partition the problem of size nn into aa smaller subproblems of size n/bn/b.
  2. Conquer: Solve each subproblem recursively. When a subproblem is sufficiently small (base case), solve it directly.
  3. Combine: Merge the subproblem solutions into a solution for the original problem.

Subproblems in divide and conquer are strictly independent—solving the left partition provides no shared state for the right partition. When subproblems overlap, Dynamic Programming (Chapter 10) is used instead.

2. Merging Two Sorted Subarrays

The core work of Mergesort resides entirely in the combine step: merging two previously sorted lists L1L_1 and L2L_2 into a single sorted list.

Comparison Bounds in Merging

Given two sorted lists with total size m=|L1|+|L2|m = |L_1| + |L_2|:

  • Each comparison selects the smaller element and commits it to the output.
  • When one list is exhausted, all remaining elements of the non-empty list are appended without comparisons.
Scenario Condition Key Comparisons Example
Best Case Complete separation: all elements in L1L_1 are smaller than all elements in L2L_2 (or vice versa). min⁡(|L1|,|L2|)=m2\min(|L_1|, |L_2|) = \frac{m}{2} [1,2,3,4][1, 2, 3, 4] and [5,6,7,8][5, 6, 7, 8]
Worst Case Perfect interleaving: the largest and second-largest elements reside in opposite lists. m−1m - 1 [1,3,5,7][1, 3, 5, 7] and [2,4,6,8][2, 4, 6, 8]

In-Place vs. Buffer Merging

  • Auxiliary Buffer Merging (Standard): Merges elements into an auxiliary array of size mm, then copies them back. Requires Θ(n)\Theta(n) auxiliary space. Stable if ties pick from the left list.
  • In-Place Merging (Lecture Variant): Merges within the array by shifting elements upon encountering an out-of-order element (slot[a] > slot[b]).
    • While auxiliary memory is O(1)O(1) beyond stack frames, shifting can trigger up to O(n2)O(n^2) data movements.
    • Ties in the lecture variant move slot[b] next to slot[a], rendering it unstable.

3. Mergesort: Algorithm and Complexity

void mergesort(int n, int m) {      // Sort slot[n..m]
    int mid = (n + m) / 2;
    if (m - n <= 0)                 // Base case: 0 or 1 element
        return;
    else if (m - n > 1) {           // 3 or more elements: recurse
        mergesort(n, mid);
        mergesort(mid + 1, m);
    }
    merge(n, m);                    // 2 or more elements: combine
}

[!NOTE] Base-Case Optimization: When the subarray contains exactly 2 elements (m−n=1m - n = 1), the implementation bypasses recursive calls and directly calls merge(n, m), performing exactly 1 comparison.

Structural Invariants of the Call Graph

For an array of nn elements:

  1. merge() is invoked exactly n−1n - 1 times (each merge reduces the number of disjoint sorted segments by 1).
  2. The maximum recursion depth is ⌈lg⁡n⌉\lceil \lg n \rceil.

Step-by-Step Method: Exact Comparison Counting in Mergesort

  1. Construct the Partition Tree: Split nn down to leaves of size 1 (or 2).
  2. Count Merges Level-by-Level:
    • At level jj (where level 0 is the root), there are 2j2^j subproblems, each merging two subarrays of size n/2j+1n/2^{j+1}.
  3. Apply Merging Bounds:
    • Worst-Case Comparisons: Sum mi−1m_i - 1 across all merges: W(n)=2W(n/2)+(n−1)=nlg⁡n−n+1for n=2kW(n) = 2W(n/2) + (n - 1) = n \lg n - n + 1 \quad \text{for } n = 2^k
    • Best-Case Comparisons: Sum mi/2m_i / 2 across all merges: B(n)=2B(n/2)+n2=n2lg⁡nfor n=2kB(n) = 2B(n/2) + \frac{n}{2} = \frac{n}{2} \lg n \quad \text{for } n = 2^k
    • Average-Case: Squeezed between B(n)B(n) and W(n)W(n), hence Θ(nlog⁡n)\Theta(n \log n).

4. Divide-and-Conquer Applications

Simultaneous Maximum and Minimum

The naive approach compares each element against the current min and current max, requiring 2(n−1)2(n - 1) comparisons. Divide and conquer improves this by setting a 2-element base case.

void findMinMax(int ar[], int start, int end, int minMax[]) {
    if (start == end) {                      // Base case: 1 element
        minMax[0] = ar[start];               // min
        minMax[1] = ar[start];               // max
    } else if (end - start == 1) {           // Base case: 2 elements (1 comparison)
        if (ar[start] > ar[end]) {
            minMax[0] = ar[end]; minMax[1] = ar[start];
        } else {
            minMax[0] = ar[start]; minMax[1] = ar[end];
        }
    } else {
        int mid = (start + end) / 2;
        int left[2], right[2];
        findMinMax(ar, start, mid, left);
        findMinMax(ar, mid + 1, end, right);
        minMax[0] = (left[0] < right[0]) ? left[0] : right[0]; // 1 comparison
        minMax[1] = (left[1] > right[1]) ? left[1] : right[1]; // 1 comparison
    }
}
Tutorial 2 Q1: Complexity Analysis of MinMax Divide-and-Conquer

Question: Using divide-and-conquer, design an algorithm that finds both the largest and smallest elements in an array of n=2kn = 2^k integers. Prove that the algorithm performs at most ≈1.5n\approx 1.5n comparisons.

Solution:

  1. Recurrence Formulation:
    • Base case 1 element: W(1)=0W(1) = 0 comparisons.
    • Base case 2 elements: W(2)=1W(2) = 1 comparison.
    • General case (n>2n > 2): Two recursive calls on subproblems of size n/2n/2, plus 2 comparisons to combine (one between the subproblem minima, one between the subproblem maxima): W(n)=2W(n/2)+2W(n) = 2W(n/2) + 2
  2. Solving the Recurrence (n=2kn = 2^k): Unroll the recurrence down to base case W(2)W(2): W(n)=2W(n/2)+2=2(2W(n/4)+2)+2=22W(n/22)+22+2=23W(n/23)+23+22+2⋮=2k−1W(n/2k−1)+∑j=1k−12j\begin{aligned} W(n) &= 2W(n/2) + 2 \\ &= 2(2W(n/4) + 2) + 2 = 2^2 W(n/2^2) + 2^2 + 2 \\ &= 2^3 W(n/2^3) + 2^3 + 2^2 + 2 \\ &\;\;\vdots \\ &= 2^{k-1} W(n/2^{k-1}) + \sum_{j=1}^{k-1} 2^j \end{aligned} Since n=2kn = 2^k, n/2k−1=2n/2^{k-1} = 2, where W(2)=1W(2) = 1: W(n)=2k−1(1)+2∑j=0k−22j=2k−1+2(2k−1−1)=n2+2(n2−1)=n2+n−2=𝟑𝟐𝒏−𝟐\begin{aligned} W(n) &= 2^{k-1}(1) + 2 \sum_{j=0}^{k-2} 2^j \\ &= 2^{k-1} + 2(2^{k-1} - 1) \\ &= \frac{n}{2} + 2\left(\frac{n}{2} - 1\right) \\ &= \frac{n}{2} + n - 2 = \mathbf{\frac{3}{2}n - 2} \end{aligned} For nn elements, the algorithm performs exactly 𝟏.𝟓𝒏−𝟐\mathbf{1.5n - 2} key comparisons, representing a 25% reduction compared to the naive 2n−22n - 2 scan.

Duplicate Detection and Reductions

Detecting duplicate elements in an unsorted array illustrates the trade-off between comparison sorting and direct memory indexing:

Tutorial 2 Q3: Algorithmic Approaches to Duplicate Detection

Question: Given an unsorted array AA of nn elements:

  1. Outline an efficient comparison-based method to determine if AA contains duplicates.
  2. Derive its worst-case asymptotic running time.
  3. If keys are known to be integers in the range [1,2n][1, 2n], provide a specialized algorithm with lower asymptotic order.

Solution:

  • (a) Comparison-Based Method:

    1. Sort the array using Mergesort (or Heapsort) in Θ(nlog⁡n)\Theta(n \log n) time.

    2. Perform a single linear scan from index 11 to n−1n-1:

      bool HasDuplicates(int A[], int n) {
    mergesort(0, n - 1);
    for (int i = 1; i < n; i++) {
        if (A[i] == A[i-1]) return true;
    }
    return false;
}

  • (b) Worst-Case Running Time:

    • Mergesort guarantees worst-case time Θ(nlog⁡n)\Theta(n \log n).
    • The linear scan requires n−1n - 1 adjacent comparisons: Θ(n)\Theta(n).
    • Total worst-case time: Θ(nlog⁡n)+Θ(n)=𝚯(𝒏𝒍𝒐𝒈⁡𝒏)\Theta(n \log n) + \Theta(n) = \mathbf{\Theta(n \log n)}.

  • (c) Specialized Range [1,2n][1, 2n] Method (Direct Indexing): When keys are restricted to range [1,2n][1, 2n], allocate a boolean/counter array seen of size 2n+12n + 1 initialized to zero. 

    bool HasDuplicatesDirect(int A[], int n) {
    int seen[2*n + 1] = {0};
    for (int i = 0; i < n; i++) {
        if (seen[A[i]] > 0) return true;
        seen[A[i]]++;
    }
    return false;
}
    • Initializing seen takes Θ(n)\Theta(n) time.
    • The array is scanned once, performing O(1)O(1) lookup per item: Θ(n)\Theta(n) time.
    • Total running time: 𝚯(𝒏)\mathbf{\Theta(n)} with Θ(n)\Theta(n) auxiliary space, beating the comparison lower bound.
