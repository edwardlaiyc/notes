A binary heap is an array-backed complete binary tree that maintains a strict partial ordering between parents and children. Heaps provide optimal O(log⁡n)O(\log n) worst-case priority queue operations and enable Heapsort—an in-place, comparison-based sorting algorithm requiring Θ(nlog⁡n)\Theta(n \log n) time in all cases.

This chapter covers heap structural and ordering invariants, array index mechanics, the fixHeap (sift-down) routine, bottom-up linear-time heap construction, the full Heapsort lifecycle, and priority queue applications including kk-way merging.

1. Heap Structure and Array Representation

A binary max-heap satisfies two simultaneous properties:

Complete Binary Tree Topology

  • Height: A heap containing nn elements has height h=⌊lg⁡n⌋h = \lfloor \lg n \rfloor.
  • Implicit Array Layout: Because there are no missing nodes, heaps require zero pointer overhead. Nodes map directly to consecutive indices in an array.

Using 1-based indexing for node k∈{1,2,…,n}k \in \{1, 2, \dots, n\}:

Relationship Formula Condition
Parent ⌊k/2⌋\lfloor k / 2 \rfloor Valid for k>1k > 1 (root at index 1 has no parent)
Left Child 2k2k Exists if 2k≤n2k \le n
Right Child 2k+12k + 1 Exists if 2k+1≤n2k + 1 \le n
Internal Node 1≤k≤⌊n/2⌋1 \le k \le \lfloor n / 2 \rfloor Nodes with at least one child
Leaf Node ⌊n/2⌋+1≤k≤n\lfloor n / 2 \rfloor + 1 \le k \le n Nodes with no children (⌈n/2⌉\lceil n / 2 \rceil total leaves)

[!NOTE] Partial Order vs. Total Order: The heap property specifies relationships only along vertical ancestor-descendant paths (A[⌊k/2⌋]≥A[k]A[\lfloor k/2 \rfloor] \ge A[k]). It enforces no ordering between siblings or across subtrees. The left child may be larger or smaller than the right child.

2. Restoring the Heap: fixHeap (Sift-Down)

When the left and right subtrees of a node satisfy the heap property but the root key kk violates it, fixHeap restores the invariant by sinking kk down to its valid level.

void fixHeap(int H[], int n, int root, int k) {
    int j = root;
    int cj = 2 * j;                       // Left child index
    while (cj <= n) {
        if (cj < n && H[cj] < H[cj + 1])  // Comparison 1: Find larger child
            cj++;                         // cj is now right child
        if (k >= H[cj])                   // Comparison 2: Does k dominate children?
            break;                        // k is properly positioned
        H[j] = H[cj];                     // Promote larger child
        j = cj;                           // Vacant slot sinks down
        cj = 2 * j;
    }
    H[j] = k;                             // Deposit key into final resting slot
}

Complexity of fixHeap

  • At each level, fixHeap makes at most 2 comparisons:
    1. Compare left and right children to identify the larger child (H[cj]<H[cj+1]H[cj] < H[cj+1]).
    2. Compare key kk against the larger child (k<H[cj]k < H[cj]). (If the node has only one child, it performs only 1 comparison).
  • The maximum path length is the height of the tree, ⌊lg⁡n⌋\lfloor \lg n \rfloor.
  • Worst-Case Cost: ≤2⌊lg⁡n⌋=O(log⁡n)\le 2 \lfloor \lg n \rfloor = O(\log n) comparisons.
  • Best-Case Cost: 22 comparisons (or 1 if 1 child) when kk already exceeds both children: O(1)O(1).

3. Bottom-Up Heap Construction

To build a heap from an arbitrary unsorted array of size nn, we process internal nodes bottom-up, starting from the last internal node ⌊n/2⌋\lfloor n/2 \rfloor down to the root 1:

void constructHeap(int H[], int n) {
    for (int i = n / 2; i >= 1; i--) {
        fixHeap(H, n, i, H[i]);
    }
}

Step-by-Step Method: Proving Linear Time O(n)O(n) for constructHeap

  1. Count Nodes per Height: In an almost complete binary tree of nn elements, the number of nodes at height hh (where leaves have height 0) is at most ⌈n/2h+1⌉\lceil n / 2^{h+1} \rceil.
  2. Formulate Total Comparisons: Each node at height hh can sink at most hh levels, costing ≤2h\le 2h comparisons: T(n)=∑h=0⌊lg⁡n⌋⌈n2h+1⌉2h≤2n∑h=1∞h2h+1=n∑h=1∞h2hT(n) = \sum_{h=0}^{\lfloor \lg n \rfloor} \left\lceil \frac{n}{2^{h+1}} \right\rceil 2h \le 2n \sum_{h=1}^{\infty} \frac{h}{2^{h+1}} = n \sum_{h=1}^{\infty} \frac{h}{2^h}
  3. Evaluate the Infinite Arithmetic-Geometric Series: Let S=∑h=1∞h2h=12+24+38+416+…S = \sum_{h=1}^{\infty} \frac{h}{2^h} = \frac{1}{2} + \frac{2}{4} + \frac{3}{8} + \frac{4}{16} + \dots 12S=14+28+316+…\frac{1}{2}S = \frac{1}{4} + \frac{2}{8} + \frac{3}{16} + \dots Subtracting the two series: S−12S=12+14+18+116+…=1⟹12S=1⟹S=2S - \frac{1}{2}S = \frac{1}{2} + \frac{1}{4} + \frac{1}{8} + \frac{1}{16} + \dots = 1 \implies \frac{1}{2}S = 1 \implies S = 2
  4. Final Bound: T(n)≤n⋅S=2n⟹𝑻(𝒏)=𝚯(𝒏)T(n) \le n \cdot S = 2n \implies \mathbf{T(n) = \Theta(n)}

[!IMPORTANT] Bottom-Up Construction is O(n)O(n), Top-Down Insertion is O(nlog⁡n)O(n \log n): Building a heap by calling Insert nn times performs nn insertions from the leaves up, where most nodes sit at height ≈lg⁡n\approx \lg n, costing ∑i=1nlg⁡i=Θ(nlog⁡n)\sum_{i=1}^n \lg i = \Theta(n \log n). Bottom-up construction applies fixHeap downwards, where the vast majority of nodes reside near the bottom and sink at most 1 or 2 levels, achieving Θ(n)\Theta(n).

4. The Heapsort Algorithm

Heapsort converts a max-heap into an ascending sorted array in-place by repeatedly extracting the maximum:

void heapSort(int H[], int n) {
    constructHeap(H, n);                  // Phase 1: Build max-heap in O(n)
    for (int i = n; i >= 2; i--) {        // Phase 2: Successive extractions
        int maxVal = H[1];                // Root holds current maximum
        int lastKey = H[i];               // Evict last element of active heap
        H[i] = maxVal;                    // Place maximum into its final resting cell
        fixHeap(H, i - 1, 1, lastKey);    // Sift lastKey down into heap of size i - 1
    }
}
[ Active Max-Heap: H[1 .. i-1] ]  |  [ Sorted Prefix Ascending: H[i .. n] ]

Heapsort Complexity Profile

Property Value Rationale
Best-Case Time Θ(nlog⁡n)\Theta(n \log n) Sinking evicted leaf keys down shrinking heaps requires ≈nlg⁡n\approx n \lg n steps.
Worst-Case Time Θ(nlog⁡n)\Theta(n \log n) O(n)O(n) build + (n−1)×2lg⁡n(n-1) \times 2 \lg n extraction comparisons ≈2nlg⁡n\approx 2n \lg n.
Average-Case Time Θ(nlog⁡n)\Theta(n \log n) Squeezed between best and worst bounds.
Auxiliary Space O(1)O(1) Completely in-place; uses iterative fixHeap.
Stability Unstable Evicting keys across the tree permutes equal keys arbitrarily.
Tutorial 4 Q2: Heapsort Comparison Analysis on Decreasing Input

Question: An array of nn distinct keys in strictly decreasing order is sorted into ascending order using Heapsort.

  1. How many key comparisons are made to construct the initial heap?
  2. Describe the behavior and comparison cost during the extraction sorting phase.

Solution:

  • (a) Construction Phase Comparison Count:
    • When an array is strictly decreasing, every parent H[k]H[k] is already larger than both its children (H[2k]H[2k] and H[2k+1]H[2k+1]).
    • Consequently, every call to fixHeap(H, n, i, H[i]) terminates at the root of its subtree on the very first test.
    • For each internal node with 2 children: exactly 2 comparisons (one to find the larger child, one to compare with parent).
    • If nn is even, exactly one internal node (at index n/2n/2) has only 1 child: 1 comparison.
    • Number of internal nodes is ⌊n/2⌋\lfloor n/2 \rfloor.
      • If nn is odd: n−12\frac{n-1}{2} nodes with 2 children ⟹2×n−12=𝒏−𝟏\implies 2 \times \frac{n-1}{2} = \mathbf{n - 1} comparisons.
      • If nn is even: n2−1\frac{n}{2} - 1 nodes with 2 children, 1 node with 1 child ⟹2(n2−1)+1=𝒏−𝟏\implies 2(\frac{n}{2} - 1) + 1 = \mathbf{n - 1} comparisons.
    • Result: Constructing the heap from a strictly decreasing array is the absolute best case, requiring exactly 𝒏−𝟏\mathbf{n - 1} comparisons and zero data swaps.
  • (b) Extraction Phase Behavior:
    • In the extraction phase, the root (maximum element) is swapped with the last element of the active heap H[i]H[i].
    • Because the original input was decreasing, H[i]H[i] holds one of the smallest elements in the entire data set.
    • When this tiny key is inserted at root and sifted down via fixHeap, it must sink all the way to a leaf at the bottom of the active heap on almost every iteration.
    • Each sift-down across height lg⁡i\lg i takes 2lg⁡i2 \lg i comparisons.
    • Total comparisons in Phase 2: ∑i=2n2lg⁡i=2lg⁡(n!)≈2nlg⁡n−2.88n comparisons.\sum_{i=2}^n 2 \lg i = 2 \lg(n!) \approx 2n \lg n - 2.88n \text{ comparisons}.
    • Takeaway: A decreasing array yields an optimal O(n)O(n) heap build, but forces maximum 2nlg⁡n2n \lg n sinking during sorting.

5. Priority Queue Application: kk-Way Merging

A Priority Queue maintains a dynamic collection under Insert (O(log⁡n)O(\log n)), ExtractMax / ExtractMin (O(log⁡n)O(\log n)), and Peek (O(1)O(1)).

A major application is merging kk sorted lists containing nn elements in total into a single sorted list.

Step-by-Step Method: Merging kk Sorted Lists via Min-Heap

  1. Initialize Min-Heap: Insert the first element of each of the kk lists into a min-heap of size kk. Store list identifiers alongside keys: (key, list_index). Cost: O(k)O(k).
  2. Extract and Replenish:
    • Extract the minimum element (key, list_index) from the root and append it to the sorted output array.
    • Fetch the next element from list list_index.
    • If the list has remaining elements, sift the new element down into the heap using fixHeap (O(log⁡k)O(\log k)).
    • If the list is exhausted, replace the root with the last element of the heap and shrink heap size by 1 (O(log⁡k)O(\log k)).
  3. Repeat: Continue until all lists are empty and the heap is exhausted.
Tutorial 4 Q3: Algorithm and Complexity of kk-Way List Merging

Question: Given kk sorted lists containing a total of nn numbers (k≥2k \ge 2), each sorted in decreasing order:

  1. Design an efficient algorithm using a heap to merge all lists into one single sorted list.
  2. State and analyze the worst-case running time and auxiliary space.

Solution:

  • (a) Algorithm Design: Since the input lists are in decreasing order and we want a final list in decreasing order, use a Max-Heap of capacity kk.

    struct HeapNode {
    int val;
    int listIdx;
    int elemIdx;
};

void MergeKSortedLists(vector<vector<int>>& lists, int k, int n, vector<int>& output) {
    vector<HeapNode> H(k + 1);
    int heapSize = 0;

    // 1. Initialize heap with head of each non-empty list
    for (int i = 0; i < k; i++) {
        if (!lists[i].empty()) {
            heapSize++;
            H[heapSize] = {lists[i][0], i, 0};
        }
    }
    constructHeap(H, heapSize); // O(k)

    // 2. Extract maximum and replenish
    for (int step = 0; step < n; step++) {
        HeapNode maxNode = H[1];
        output.push_back(maxNode.val);

        int nextElemIdx = maxNode.elemIdx + 1;
        if (nextElemIdx < lists[maxNode.listIdx].size()) {
            // Replace root with next element from same list
            H[1] = {lists[maxNode.listIdx][nextElemIdx], maxNode.listIdx, nextElemIdx};
            fixHeap(H, heapSize, 1, H[1].val); // O(log k)
        } else {
            // List exhausted: move last heap element to root and reduce size
            H[1] = H[heapSize];
            heapSize--;
            if (heapSize > 0)
                fixHeap(H, heapSize, 1, H[1].val); // O(log k)
        }
    }
}

  • (b) Complexity Analysis:

    • Heap Initialization: Inserting kk elements takes O(k)O(k) time.
    • Processing Elements: Each of the nn elements is extracted from the heap exactly once. Each extraction triggers one fixHeap on a heap of size at most kk, taking O(log⁡k)O(\log k) time.
    • Total Worst-Case Time: O(k+nlog⁡k)=𝑶(𝒏𝒍𝒐𝒈⁡𝒌)O(k + n \log k) = \mathbf{O(n \log k)}. (This significantly outperforms pairwise merging, which takes O(n⋅k)O(n \cdot k) time).
    • Auxiliary Space: The heap stores at most 1 element per list: 𝑶(𝒌)\mathbf{O(k)} space (excluding the output array).
