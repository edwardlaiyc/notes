Comparison-based sorting algorithms determine relative order strictly by querying pairs of elements (A[i]≤A[j]A[i] \le A[j]). Information theory establishes that all comparison sorts require Ω(nlog⁡n)\Omega(n \log n) comparisons in the worst case. Non-comparison algorithms bypass this lower bound by exploiting the numerical structure of keys as direct memory addresses.

This chapter covers Quicksort and its partitioning schemes, the information-theoretic decision tree lower bound, and the linear-time non-comparison algorithms Counting Sort and Radix Sort.

1. Quicksort

Quicksort is a divide-and-conquer algorithm that executes its primary workload during the divide phase:

flowchart TD
    P["1. Partition: Select pivot, split into <= pivot and >= pivot"] --> L["2. Recurse Left Subarray"]
    P --> R["3. Recurse Right Subarray"]
    L & R --> Done["4. Combine: No-op (pivots already in final positions)"]

Unlike Mergesort, which splits arrays blind to content and expends effort merging, Quicksort partitions content around a pivot such that the pivot attains its permanent sorted position, eliminating any combine phase.

Lomuto/Lecture Partition Algorithm

int partition(int low, int high) {
    int mid = (low + high) / 2;
    swap(slot[low], slot[mid]);           // Move middle pivot to prefix
    int pivot = slot[low].key;
    int last_small = low;                 // Boundary of < pivot prefix

    for (int i = low + 1; i <= high; i++) {
        if (slot[i].key < pivot) {        // Key strictly smaller than pivot
            last_small++;
            swap(slot[last_small], slot[i]);
        }
    }
    swap(slot[low], slot[last_small]);    // Place pivot between partitions
    return last_small;
}

Invariant Regions During Partitioning

At iteration ii, the active range [low..high][low..high] is partitioned into four contiguous blocks:

  • slot[low]: The pivot element.
  • slot[low + 1 .. last_small]: Elements strictly smaller than the pivot.
  • slot[last_small + 1 .. i - 1]: Elements greater than or equal to the pivot.
  • slot[i .. high]: Unexamined elements.

Step-by-Step Method: Quicksort Cost Analysis

  1. Partition Cost: Partitioning kk elements compares each non-pivot element against the pivot exactly once, performing exactly k−1k - 1 key comparisons.
  2. Worst-Case Recurrence: When the pivot is the extreme minimum or maximum at every stage, one partition is empty (00 elements) and the other holds n−1n - 1 elements: T(n)=T(n−1)+(n−1)=∑i=1n−1i=n(n−1)2=𝚯(𝒏𝟐)T(n) = T(n - 1) + (n - 1) = \sum_{i=1}^{n-1} i = \frac{n(n-1)}{2} = \mathbf{\Theta(n^2)}
  3. Best-Case Recurrence: When the pivot splits the array into two equal halves of size ≈n/2\approx n/2: T(n)=2T(n/2)+Θ(n)=𝚯(𝒏𝒍𝒐𝒈⁡𝒏)T(n) = 2T(n/2) + \Theta(n) = \mathbf{\Theta(n \log n)}
  4. Average-Case Recurrence: Averaging over all nn equally likely pivot ranks yields: T(n)=(n−1)+2n∑i=0n−1T(i)≈1.39nlg⁡n=𝚯(𝒏𝒍𝒐𝒈⁡𝒏)T(n) = (n - 1) + \frac{2}{n}\sum_{i=0}^{n-1} T(i) \approx 1.39 n \lg n = \mathbf{\Theta(n \log n)}
Tutorial 3 Q3: Median-of-Three Pivot Selection and Adversarial Worst-Case

Question: Instead of using the middle element as pivot, Quicksort can select the median of the first, middle, and last elements.

  1. Why does this heuristic improve performance over choosing the first element?
  2. Does median-of-three eliminate the Θ(n2)\Theta(n^2) worst-case running time? Justify your answer.

Solution:

  • (a) Heuristic Advantage:
    • Choosing the first element produces worst-case Θ(n2)\Theta(n^2) splits on arrays that are already sorted or reverse-sorted.
    • Median-of-three samples three distributed keys (A[low],A[mid],A[high]A[low], A[mid], A[high]) and uses their median. On sorted inputs, the median is the true middle element, guaranteeing a balanced n/2n/2 split.
    • It prevents worst-case behavior whenever at least one extreme key resides at the boundaries.
  • (b) Persistence of Θ(n2)\Theta(n^2) Worst-Case:
    • No, median-of-three does not eliminate Θ(n2)\Theta(n^2) worst-case time.
    • An adversary can construct an input where the median of {A[low],A[mid],A[high]}\{A[low], A[mid], A[high]\} is consistently the second-smallest (or second-largest) element in the active range.
    • Under this input, each partition yields an asymmetric split of size 11 and n−2n - 2.
    • The recurrence becomes: T(n)=T(n−2)+Θ(n)=∑k=1n/22k≈n24=𝚯(𝒏𝟐).T(n) = T(n - 2) + \Theta(n) = \sum_{k=1}^{n/2} 2k \approx \frac{n^2}{4} = \mathbf{\Theta(n^2)}.
    • Conclusion: Only finding the true median in O(n)O(n) time (e.g. Median-of-Medians) guarantees a worst-case O(nlog⁡n)O(n \log n) Quicksort, though with high constant factor overhead.

2. Three-Way Partitioning: The Dutch National Flag

When arrays contain numerous duplicate keys, standard two-way partitioning degenerates toward quadratic time. Edsger Dijkstra’s Dutch National Flag algorithm partitions an array with three distinct keys (e.g., Red, White, Blue) into three contiguous blocks in a single pass.

void DutchNationalFlag(int A[], int n, int red, int white, int blue) {
    int r = 0;         // Upper boundary of Red region: A[0 .. r-1]
    int u = 0;         // Current unexamined element: A[r .. u-1] is White
    int b = n;         // Lower boundary of Blue region: A[b .. n-1]

    while (u < b) {
        if (A[u] == red) {
            swap(A[r], A[u]);
            r++;
            u++;
        } else if (A[u] == white) {
            u++;
        } else { // A[u] == blue
            b--;
            swap(A[u], A[b]);
            // Do NOT increment u: A[u] now holds unexamined element from A[b]
        }
    }
}
Tutorial 3 Q4: Dutch National Flag 3-Way Partitioning

Question: Each of nn elements in an array has one of the key values: red, white, or blue. Design an algorithm that rearranges the elements in-place so all reds precede all whites, which precede all blues. Your algorithm must inspect each key at most once and execute in O(n)O(n) time with O(1)O(1) extra space.

Solution:

  • Invariant Specification: Maintain three pointers r=0,u=0,b=nr = 0, u = 0, b = n partitioning the array into four regions:
    1. A[0..r−1]A[0 .. r - 1] contains exclusively red.
    2. A[r..u−1]A[r .. u - 1] contains exclusively white.
    3. A[u..b−1]A[u .. b - 1] contains unexamined elements.
    4. A[b..n−1]A[b .. n - 1] contains exclusively blue.
  • Execution Trace:
    • If A[u]==redA[u] == \text{red}: Swap A[r]A[r] with A[u]A[u]; advance both rr and uu.
    • If A[u]==whiteA[u] == \text{white}: Advance uu.
    • If A[u]==blueA[u] == \text{blue}: Decrement bb; swap A[u]A[u] with A[b]A[b]. Do not advance uu, because the swapped-in element at index uu is uninspected.
  • Complexity:
    • In every iteration, the unexamined range size (b−u)(b - u) decreases by exactly 1.
    • The loop runs at most nn times.
    • Time Complexity: 𝚯(𝒏)\mathbf{\Theta(n)} with at most nn key inspections and nn swaps.
    • Auxiliary Space: 𝑶(𝟏)\mathbf{O(1)} (in-place).

3. The Theoretical Limit of Comparison Sorts

A sort is comparison-based if the relative order of elements is determined solely by pairwise comparisons (ai≤aja_i \le a_j).

The Decision Tree Model

Any comparison sort operating on nn elements can be modeled as a full binary decision tree:

  • Internal Nodes: Pairwise key comparisons (i:ji : j).
  • Edges: Comparison outcomes (≤\le left, >> right).
  • Leaves: Permutations representing sorted outputs.
  • Execution Path: A single algorithm run corresponds to a path from the root to a leaf. Path length equals key comparisons made.

Step-by-Step Method: Lower Bound Derivation Ω(nlog⁡n)\Omega(n \log n)

  1. Count Required Leaves (LL): An algorithm sorting nn distinct elements must distinguish among all n!n! possible permutations. Thus: L≥n!L \ge n!
  2. Relate Leaves to Tree Height (hh): A binary tree of height hh contains at most 2h2^h leaves: 2h≥L≥n!⟹h≥⌈lg⁡(n!)⌉2^h \ge L \ge n! \implies h \ge \lceil \lg(n!) \rceil
  3. Apply Stirling’s Approximation: lg⁡(n!)=∑i=1nlg⁡i≥∑i=⌈n/2⌉nlg⁡i≥n2lg⁡(n2)=n2(lg⁡n−1)=Ω(nlog⁡n)\lg(n!) = \sum_{i=1}^n \lg i \ge \sum_{i=\lceil n/2 \rceil}^n \lg i \ge \frac{n}{2} \lg\left(\frac{n}{2}\right) = \frac{n}{2}(\lg n - 1) = \Omega(n \log n)
  4. Conclusion: The worst-case comparison count is the tree height hh. Hence, every comparison sort requires Ω(nlog⁡n)\Omega(n \log n) comparisons in the worst case. Mergesort and Heapsort achieve this bound and are asymptotically optimal comparison sorts.
Tutorial 3 Q1: Minimum Depth of a Leaf in a Comparison Sort Decision Tree

Question: Recall the Ω(nlog⁡n)\Omega(n \log n) worst-case lower bound proven via decision trees. What is the smallest possible depth of a leaf in a decision tree for a comparison sort?

Solution:

The smallest possible depth of a leaf is n−1n - 1.

  • Proof by Contradiction (Graph Connectivity):
    1. Suppose there exists a leaf at depth k<n−1k < n - 1.
    2. Construct an undirected comparison graph G=(V,E)G = (V, E) where the nn vertices represent array elements, and an edge (u,v)(u, v) is added whenever key uu is compared with key vv along the path to that leaf.
    3. A graph with nn vertices and k<n−1k < n - 1 edges cannot be connected; it must contain at least two disjoint connected components V1V_1 and V2V_2.
    4. Because no edge exists between V1V_1 and V2V_2, the algorithm performed zero comparisons between any element of V1V_1 and any element of V2V_2.
    5. The algorithm cannot determine whether the elements in V1V_1 are greater or smaller than those in V2V_2.
    6. Adding a sufficiently large constant to all keys in V1V_1 preserves all edge comparison outcomes (traversing the exact same path to the leaf), yet alters the true sorted permutation.
    7. Therefore, the leaf cannot output a permutation that is valid for all inputs.
  • Tightness: Insertion Sort on an already-sorted array performs exactly n−1n - 1 comparisons and terminates, proving n−1n - 1 is achievable.

4. Linear-Time Sorts: Counting Sort

Counting Sort breaks the Ω(nlog⁡n)\Omega(n \log n) barrier by avoiding key comparisons altogether. It assumes keys are integers drawn from a known bounded range [0..k][0..k].

The Algorithm

vector<int> CountingSort(const vector<int>& A, int n, int k) {
    vector<int> C(k + 1, 0);
    vector<int> B(n);

    // 1. Frequency count: C[v] = count of occurrences of key v
    for (int j = 0; j < n; j++)
        C[A[j]]++;

    // 2. Prefix sums: C[v] = number of keys <= v
    for (int i = 1; i <= k; i++)
        C[i] += C[i - 1];

    // 3. Right-to-left placement for STABILITY
    for (int j = n - 1; j >= 0; j--) {
        C[A[j]]--;
        B[C[A[j]]] = A[j];
    }
    return B;
}

Complexity Profile

  • Time Complexity: Θ(n+k)\Theta(n + k) across all cases. If k=O(n)k = O(n), running time is Θ(n)\Theta(n).
  • Auxiliary Space: Θ(n+k)\Theta(n + k) for frequency table CC and output array BB. Counting Sort is not in-place.
Tutorial 3 Q2: Loop Direction in Counting Sort and Algorithmic Stability

Question: In Counting Sort, the final placement loop runs backwards:

for j = n - 1 downto 0:
    C[A[j]] = C[A[j]] - 1
    B[C[A[j]]] = A[j]

What happens if the loop is rewritten to run forwards from j=0j = 0 to n−1n - 1?

  1. Is the resulting array still sorted?
  2. Is the algorithm still stable?

Solution:

  • (a) The Array Remains Sorted:
    • For any key vv, the prefix sum table defines an exclusive reservation block in output array BB spanning indices [C[v−1]…C[v]−1][C[v - 1] \dots C[v] - 1].
    • Running the loop forwards decrements C[A[j]]C[A[j]] upon each placement. Every element with key vv is still deposited inside this assigned index block.
    • Because elements are strictly placed within their designated key range, the final array BB is correctly sorted.
  • (b) Stability is Violated (Reversed):
    • When running backwards (j=n−1 downto 0j = n - 1 \text{ downto } 0), the rightmost occurrence of key vv in AA claims the rightmost slot in the output block, preserving relative input order (stable).
    • When running forwards (j=0 to n−1j = 0 \text{ to } n - 1), the first occurrence of key vv in AA is assigned the highest available index in vv’s block, and subsequent occurrences claim progressively lower indices to the left.
    • Consequently, the relative order of duplicate keys is completely inverted. The forward loop produces a correct sort, but is strictly unstable.

5. Radix Sort

Radix Sort decomposes multi-digit keys and sorts them digit-by-digit. To sort numbers with dd digits where each digit takes kk possible values:

for digit pos = 1 to d (from Least Significant Digit to Most Significant):
    Sort array A stably according to digit pos (e.g. using Counting Sort)

Why Stability is Mandatory

Radix Sort operates correctly if and only if the underlying digit-sorting algorithm is stable:

  • When pass ii sorts keys by digit ii, keys with distinct digit values are placed in correct relative order.
  • Keys with identical digits rely on earlier passes 1…i−11 \dots i-1 for correct ordering. A stable pass guarantees that this pre-existing lower-order arrangement is strictly maintained.

Radix Sort Complexity

  • Using Counting Sort per pass: 𝚯(𝒅(𝒏+𝒌))\mathbf{\Theta(d(n + k))} time and 𝚯(𝒏+𝒌)\mathbf{\Theta(n + k)} space.
  • When dd is constant and k=O(n)k = O(n), Radix Sort sorts nn elements in Θ(n)\Theta(n) linear time.
