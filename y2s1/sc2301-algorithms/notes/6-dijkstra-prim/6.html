The greedy strategy solves optimization problems by making the locally optimal choice at each decision step, never backtracking or reconsidering past selections. While greedy heuristics fail on arbitrary optimization landscapes, they yield provably optimal global solutions when the problem exhibits greedy-choice property and optimal substructure.

This chapter analyzes two classic greedy graph algorithms: Dijkstra’s Algorithm for single-source shortest paths on non-negative weighted graphs, and Prim’s Algorithm for constructing Minimum Spanning Trees (MSTs).

1. The Greedy Strategy and Optimal Substructure

In an optimization problem, an algorithm constructs a solution through a sequence of choices:

flowchart LR
    Opt["Global Optimum"] --- Sub["1. Optimal Substructure: Optimal solution contains optimal sub-solutions"]
    Opt --- GCP["2. Greedy Choice Property: Globally optimal solution reached via locally optimal choices"]
  • Optimal Substructure: A problem exhibits optimal substructure if an optimal solution to the problem contains within it optimal solutions to subproblems.
  • Greedy-Choice Property: A global optimum can be arrived at by making a series of locally optimal choices without solving subproblems first.

2. Single-Source Shortest Paths: Dijkstra’s Algorithm

Given a directed or undirected weighted graph G=(V,E,W)G = (V, E, W) and source s∈Vs \in V, find the shortest path from ss to every vertex v∈Vv \in V.

Sub-path Optimality

Lemma (Optimal Substructure of Shortest Paths): Any sub-path of a shortest path is itself a shortest path between its endpoints. Proof by Contradiction: If a sub-path between xx and yy could be replaced by a strictly shorter path, splicing that shorter path into the original route would yield a shorter overall path between source and destination, contradicting optimality.

Dijkstra’s Algorithm

Dijkstra maintains a set of finalized vertices SS and iteratively pulls the closest non-finalized vertex u∈V\Su \in V \setminus S into SS, relaxing all outgoing edges (u,v)(u, v).

void Dijkstra(const Graph& G, int source) {
    vector<int> dist(V, INF);
    vector<int> parent(V, -1);
    vector<bool> S(V, false);

    dist[source] = 0;
    priority_queue<pair<int, int>, vector<pair<int, int>>, greater<>> PQ;
    PQ.push({0, source});

    while (!PQ.empty()) {
        int u = PQ.top().second;
        PQ.pop();

        if (S[u]) continue;                // Already finalized
        S[u] = true;                       // u is finalized into S

        for (auto [v, weight] : G.adj[u]) {
            if (!S[v] && dist[u] + weight < dist[v]) { // Relaxation step
                dist[v] = dist[u] + weight;
                parent[v] = u;
                PQ.push({dist[v], v});
            }
        }
    }
}

Edge Relaxation Invariant

Relaxing edge (u,v)(u, v) tests whether traversing u→vu \to v improves the current shortest estimate to vv: If dist[u]+w(u,v)<dist[v]⟹dist[v]=dist[u]+w(u,v),parent[v]=u\text{If } dist[u] + w(u, v) < dist[v] \implies dist[v] = dist[u] + w(u, v), \quad parent[v] = u

[!WARNING] Strict Requirement: Non-Negative Weights Only: Dijkstra assumes that once a vertex uu enters SS, no path discovered later can reach uu with lower cost. If an edge has a negative weight, a longer path discovered later could offset previous costs, violating the greedy choice.

Adding a positive constant CC to all edges does NOT fix negative weights! Paths containing more edges accumulate more copies of CC, altering which path is shortest.

Tutorial 5 Q2: Shortest Path Uniqueness Under Distinct Edge Weights

Question: Let G=(V,E,W)G = (V, E, W) be a weighted graph with distinct vertices ss and zz. If all edge weights are distinct and positive, is the shortest path between ss and zz guaranteed to be unique? Justify with proof or counterexample.

Solution:

No, distinct edge weights do not guarantee a unique shortest path.

  • Counterexample: Consider a 3-vertex graph with vertices {s,a,z}\{s, a, z\}:
    • Edge (s,a)(s, a) with weight 22.
    • Edge (a,z)(a, z) with weight 33.
    • Edge (s,z)(s, z) with weight 55.
    • All edge weights {2,3,5}\{2, 3, 5\} are strictly positive and distinct.
    • Path 1: s→a→zs \to a \to z with total length 2+3=52 + 3 = 5.
    • Path 2: s→zs \to z with total length 55.
    • Both paths have identical total weight 5, demonstrating that shortest paths can tie even when all individual edge weights are unique.

3. Minimum Spanning Trees (MST)

For a connected, undirected weighted graph G=(V,E,W)G = (V, E, W), a spanning tree is an acyclic subgraph connecting all |V||V| vertices, containing exactly |V|−1|V| - 1 edges. A Minimum Spanning Tree (MST) minimizes total weight ∑e∈Tw(e)\sum_{e \in T} w(e).

Fundamental Cut and Cycle Properties

  • The Cut Property: For any partition (cut) of VV into (S,V\S)(S, V \setminus S), the minimum-weight edge crossing the cut belongs to an MST. If this crossing edge is uniquely minimal, it belongs to every MST.
  • The Cycle Property: For any cycle in GG, the strictly heaviest edge on the cycle cannot belong to any MST.
Tutorial 5 Q3: Proof of Unique MST When Edge Weights Are Distinct

Question: Show that every connected weighted graph whose edge weights are all distinct has a unique minimum spanning tree.

Solution:

  • Proof by Contradiction:
    1. Suppose GG contains distinct edge weights but possesses two distinct MSTs, T1T_1 and T2T_2 (T1≠T2T_1 \ne T_2).
    2. Consider the set of symmetric difference edges (T1\T2)∪(T2\T1)(T_1 \setminus T_2) \cup (T_2 \setminus T_1).
    3. Because edge weights are distinct, this set contains a unique edge e=(u,v)e = (u, v) of minimum weight. Without loss of generality, assume e∈T1\T2e \in T_1 \setminus T_2.
    4. Adding ee to T2T_2 forms a unique cycle CC in T2∪{e}T_2 \cup \{e\}.
    5. Since T1T_1 is an acyclic tree, cycle CC cannot be entirely contained in T1T_1. Therefore, there must exist at least one edge e′∈Ce' \in C such that e′∉T1e' \notin T_1 (meaning e′∈T2\T1e' \in T_2 \setminus T_1).
    6. By definition of ee as the strictly lightest edge in the symmetric difference, we have w(e)<w(e′)w(e) < w(e').
    7. Construct a new spanning tree T3=(T2\{e′})∪{e}T_3 = (T_2 \setminus \{e'\}) \cup \{e\}.
    8. The total weight of T3T_3 is: w(T3)=w(T2)−w(e′)+w(e)<w(T2)w(T_3) = w(T_2) - w(e') + w(e) < w(T_2)
    9. This strictly contradicts the assumption that T2T_2 is a Minimum Spanning Tree.
    10. Hence, the MST must be unique.

4. Prim’s Algorithm

Prim’s algorithm grows a single tree TT outward from an arbitrary start vertex ss. At each iteration, it absorbs the lightest edge connecting a vertex in the tree to a vertex outside the tree (the fringe).

void Prim(const Graph& G, int start) {
    vector<int> key(V, INF);              // Lightest single edge to tree
    vector<int> parent(V, -1);
    vector<bool> inMST(V, false);

    key[start] = 0;
    priority_queue<pair<int, int>, vector<pair<int, int>>, greater<>> PQ;
    PQ.push({0, start});

    while (!PQ.empty()) {
        int u = PQ.top().second;
        PQ.pop();

        if (inMST[u]) continue;
        inMST[u] = true;

        for (auto [v, weight] : G.adj[u]) {
            if (!inMST[v] && weight < key[v]) { // Prim's update rule
                key[v] = weight;
                parent[v] = u;
                PQ.push({key[v], v});
            }
        }
    }
}

Step-by-Step Method: Tracing Prim’s Algorithm

  1. Vertex Partitioning: Maintain sets TT (in tree), Fringe (key<∞key < \infty), and Unseen (key=∞key = \infty).
  2. Key Interpretation: Unlike Dijkstra (d[v]=d[u]+wd[v] = d[u] + w), Prim updates key[v]=w(u,v)key[v] = w(u, v) (cost of a single edge).
  3. Execution Protocol:
    • Pop minimum key from fringe.
    • Add edge (parent[u],u)(parent[u], u) to MST.
    • For each neighbor v∉Tv \notin T, update key[v]=min⁡(key[v],w(u,v))key[v] = \min(key[v], w(u, v)).
