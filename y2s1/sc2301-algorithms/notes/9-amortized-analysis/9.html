Worst-case analysis per operation can be excessively pessimistic when an expensive operation cannot occur in isolation, but only after a prolonged sequence of cheap operations. Amortized analysis determines the average performance of each operation over a worst-case sequence of nn operations, guaranteeing that the total cost of any sequence is strictly bounded.

This chapter covers the four standard amortization methodologies—Aggregate Analysis, the Accounting Method, the Charging Method, and the Potential Method—applied to dynamic array resizing, binary counters, heap operations, and thrashing prevention.

1. Principles of Amortized Analysis

Paradigm Evaluates Role of Probability
Worst-Case Cost Maximum possible cost of a single isolated operation None
Average-Case Cost Expected cost of an operation over random inputs High (assumes input distribution)
Amortized Cost Average cost per operation over the worst possible sequence None (deterministic bound)

[!IMPORTANT] No Probability Involved: Amortized bounds hold deterministically for any sequence of operations, regardless of input ordering. While individual operations within a sequence may spike to Θ(n)\Theta(n), the average cost per operation is guaranteed to remain O(1)O(1).

2. Dynamic Array Resizing (Table Doubling)

When inserting into an array of fixed capacity mm, an insertion into a non-full array costs 1. When the array is full (n=mn = m), capacity doubles to 2m2m, requiring allocation of a new buffer, copying all mm old elements, and inserting the new element (total cost m+1m + 1).

3. The Four Amortization Methods

Method 1: Aggregate Analysis

Compute the total worst-case cost T(n)T(n) across the entire sequence of nn operations, then divide uniformly:

ĉ=T(n)n\hat{c} = \frac{T(n)}{n}

For nn insertions with initial capacity 1:

  • Writing cost across nn insertions: ∑i=1n1=n\sum_{i=1}^n 1 = n.
  • Copying costs occur at capacities 1,2,4,…,2⌊lg⁡n⌋1, 2, 4, \dots, 2^{\lfloor \lg n \rfloor}: ∑j=0⌊lg⁡n⌋2j=2⌊lg⁡n⌋+1−1<2n\sum_{j=0}^{\lfloor \lg n \rfloor} 2^j = 2^{\lfloor \lg n \rfloor + 1} - 1 < 2n
  • Total cost T(n)<n+2n=3n⟹𝒄̂<𝟑=𝑶(𝟏)T(n) < n + 2n = 3n \implies \mathbf{\hat{c} < 3 = O(1)}.

Method 2: The Accounting Method (Credit / Banker’s Method)

Assign an artificial amortized charge ĉi\hat{c}_i to each operation. If ĉi>ci\hat{c}_i > c_i, deposit the surplus ĉi−ci\hat{c}_i - c_i as credit (coins) associated with specific data structures. When an expensive operation occurs (ci>ĉic_i > \hat{c}_i), withdraw stored credit.

Credit Balance Bankn=∑i=1nĉi−∑i=1nci≥0(∀n≥1)\text{Credit Balance } \text{Bank}_n = \sum_{i=1}^n \hat{c}_i - \sum_{i=1}^n c_i \ge 0 \quad (\forall n \ge 1)

[!CAUTION] Credit Invariant: The total accumulated credit balance in the bank must never drop below zero at any step in the sequence. If the bank ever falls negative, the amortized charges fail to upper-bound the actual workload.

  • Table Doubling Protocol (Charge ĉ=3\hat{c} = 3):
    1. 11 coin pays for writing the element into the array.
    2. 11 coin is deposited as credit to pay for moving this element during the next resize.
    3. 11 coin is deposited as credit to pay for moving an older element (which spent its credit in the prior resize). When table size doubles from mm to 2m2m, exactly m/2m/2 insertions occurred since the last resize, accumulating (m/2)×2=m(m/2) \times 2 = m credit coins—exactly paying for copying all mm elements.

Method 3: The Charging Method

Rather than banking credit in advance, an expensive operation bills its excess cost backwards to previous cheap operations that set up the resize:

ĉi=ci−(cost billed to past operations)+(cost billed by future operations)\hat{c}_i = c_i - (\text{cost billed to past operations}) + (\text{cost billed by future operations})

Method 4: The Potential Method (Physicist’s Method)

Instead of associating credit with individual elements, the potential method models credit as state energy Φ(D)\Phi(D) stored within the overall data structure DD:

ĉi=ci+Φ(Di)−Φ(Di−1)=ci+ΔΦi\hat{c}_i = c_i + \Phi(D_i) - \Phi(D_{i-1}) = c_i + \Delta\Phi_i

Summing across all nn operations yields a telescoping sum:

∑i=1nĉi=∑i=1n(ci+Φ(Di)−Φ(Di−1))=∑i=1nci+Φ(Dn)−Φ(D0)\sum_{i=1}^n \hat{c}_i = \sum_{i=1}^n (c_i + \Phi(D_i) - \Phi(D_{i-1})) = \sum_{i=1}^n c_i + \Phi(D_n) - \Phi(D_0)

∑i=1nci=∑i=1nĉi−(Φ(Dn)−Φ(D0))≤∑i=1nĉiprovided Φ(Dn)≥Φ(D0)\sum_{i=1}^n c_i = \sum_{i=1}^n \hat{c}_i - (\Phi(D_n) - \Phi(D_0)) \le \sum_{i=1}^n \hat{c}_i \quad \text{provided } \Phi(D_n) \ge \Phi(D_0)

Step-by-Step Method: Designing Potential Functions

  1. Set Baseline: Ensure Φ(D0)=0\Phi(D_0) = 0 and Φ(Di)≥0\Phi(D_i) \ge 0 for all valid states DiD_i.
  2. Align with Expense: Potential should reach a maximum immediately before an expensive operation, and drop to near-zero immediately after.
  3. Formulate for Table Doubling:
    • Before resize: n=mn = m, table needs mm work ⟹Φ=m\implies \Phi = m.
    • After resize: n=m/2n = m/2, table just doubled ⟹Φ=0\implies \Phi = 0.
    • Linear relation: 𝚽(𝑫)=𝟐𝒏−𝒎\mathbf{\Phi(D) = 2n - m}.
  4. Evaluate Cases:
    • No resize (n<mn < m): ci=1,ΔΦ=2(n+1−n)=2⟹ĉi=1+2=𝟑c_i = 1, \Delta\Phi = 2(n+1 - n) = 2 \implies \hat{c}_i = 1 + 2 = \mathbf{3}.
    • Resize (n=mn = m): ci=m+1,Φbefore=m,Φafter=2(m+1)−2m=2⟹ΔΦ=2−mc_i = m + 1, \Phi_{\text{before}} = m, \Phi_{\text{after}} = 2(m+1) - 2m = 2 \implies \Delta\Phi = 2 - m. ĉi=(m+1)+(2−m)=𝟑\hat{c}_i = (m + 1) + (2 - m) = \mathbf{3}
Tutorial 9 Q2: Multi-Method Amortized Analysis of Geometric Work Sequence

Question: Suppose a sequence of nn operations is performed on a data structure where the ii-th operation costs ii if ii is an exact power of 2, and 1 otherwise. Determine the amortized cost per operation using:

  1. Aggregate Analysis
  2. The Accounting Method
  3. The Potential Method

Solution:

  • (a) Aggregate Analysis: The actual cost of operation ii is ci=ic_i = i if i=2ki = 2^k, and ci=1c_i = 1 otherwise. Total cost T(n)T(n): T(n)=∑i=1nci=∑i=1n1+∑j=0⌊lg⁡n⌋(2j−1)≤n+∑j=0⌊lg⁡n⌋2j=n+(2⌊lg⁡n⌋+1−1)<n+2n=3nT(n) = \sum_{i=1}^n c_i = \sum_{i=1}^n 1 + \sum_{j=0}^{\lfloor \lg n \rfloor} (2^j - 1) \le n + \sum_{j=0}^{\lfloor \lg n \rfloor} 2^j = n + (2^{\lfloor \lg n \rfloor + 1} - 1) < n + 2n = 3n Amortized Cost ĉ=T(n)n<3nn=𝟑=𝑶(𝟏).\text{Amortized Cost } \hat{c} = \frac{T(n)}{n} < \frac{3n}{n} = \mathbf{3 = O(1)}.

  • (b) Accounting Method: Assign a uniform amortized charge of ĉi=3\hat{c}_i = 3 to every operation.

    • When ii is not a power of 2, actual cost ci=1c_i = 1. The surplus 3−1=23 - 1 = 2 coins are deposited into the credit bank.
    • Between power of two 2k−12^{k-1} and 2k2^k, there are exactly 2k−2k−1−1=2k−1−12^k - 2^{k-1} - 1 = 2^{k-1} - 1 cheap operations, accumulating 2(2k−1−1)=2k−22(2^{k-1} - 1) = 2^k - 2 coins.
    • When operation i=2ki = 2^k arrives, its actual cost is 2k2^k. We pay ĉ=3\hat{c} = 3 from the operation charge and withdraw the saved 2k−32^k - 3 coins from credit.
    • The bank balance never drops below zero. Hence, amortized cost is 𝟑=𝑶(𝟏)\mathbf{3 = O(1)}.

  • (c) Potential Method: Define potential function: Φ(Di)=2i−2⌈lg⁡i⌉+1+2≥0,Φ(D0)=0\Phi(D_i) = 2i - 2^{\lceil \lg i \rceil + 1} + 2 \ge 0, \quad \Phi(D_0) = 0

    • Case 1: ii is not a power of 2 (2k−1<i<2k2^{k-1} < i < 2^k): Actual cost ci=1c_i = 1. ⌈lg⁡i⌉\lceil \lg i \rceil is constant. ΔΦ=2(i−(i−1))=2\Delta\Phi = 2(i - (i - 1)) = 2. ĉi=ci+ΔΦ=1+2=𝟑.\hat{c}_i = c_i + \Delta\Phi = 1 + 2 = \mathbf{3}.
    • Case 2: ii is a power of 2 (i=2ki = 2^k): Actual cost ci=2kc_i = 2^k. Φ(Di−1)=2(2k−1)−2k+1+2=2k+1−2−2k+1+2=0\Phi(D_{i-1}) = 2(2^k - 1) - 2^{k+1} + 2 = 2^{k+1} - 2 - 2^{k+1} + 2 = 0. Φ(Di)=2(2k)−2k+1+2=2\Phi(D_i) = 2(2^k) - 2^{k+1} + 2 = 2. ΔΦ=2−0=2−2k\Delta\Phi = 2 - 0 = 2 - 2^k. ĉi=ci+ΔΦ=2k+(2−2k)=𝟐≤3.\hat{c}_i = c_i + \Delta\Phi = 2^k + (2 - 2^k) = \mathbf{2} \le 3.
    • Both cases yield 𝑶(𝟏)\mathbf{O(1)} amortized cost.

4. Pathological Sequences and Thrashing

An amortized bound is valid strictly for the specific set of operations evaluated. Introducing a new operation can destroy amortization if it resets the structure into an expensive boundary state.

The kk-Bit Counter with DECREMENT

A standard kk-bit counter supporting only INCREMENT achieves O(1)O(1) amortized cost (Tutorial 8). Adding DECREMENT destroys this bound:

Tutorial 9 Q1: Amortization Breakdown in kk-Bit Counter with DECREMENT

Question: Show that if a DECREMENT operation is included alongside INCREMENT on an initially zero kk-bit counter, a sequence of nn operations can cost as much as Θ(n⋅k)\Theta(n \cdot k).

Solution:

  • Adversarial Thrashing Sequence:
    1. Perform 2k−12^{k-1} initial increments to reach state: A=01111…1(value 2k−1−1)A = 01111\dots1 \quad (\text{value } 2^{k-1} - 1)
    2. Now alternate between INCREMENT and DECREMENT:
      • INCREMENT: flips all kk bits to transition 01111…1→10000…001111\dots1 \to 10000\dots0. Actual cost = kk.
      • DECREMENT: flips all kk bits to transition 10000…0→01111…110000\dots0 \to 01111\dots1. Actual cost = kk.
    3. Repeating this alternation m=n/2m = n/2 times forces every single operation to flip all kk bits.
    4. Total cost of the sequence: ∑i=1nci=Θ(n⋅k)\sum_{i=1}^n c_i = \Theta(n \cdot k)
    5. The amortized cost per operation degrades from O(1)O(1) to Θ(k)\Theta(k), matching worst-case single operation cost.

Dynamic Table Contraction: Preventing Thrashing

When elements are deleted, shrinking the array when it becomes half-full (n=m/2n = m/2) causes thrashing: alternating INSERT and DELETE at the boundary forces a resize on every step.

Half-Full Resizing Flaw:
[ Full: n = m ] -> Insert -> [ Double: m' = 2m, n = m + 1 ]
                <- Delete <- [ Halve: m' = m, n = m ] (Copies m elements on every step!)

To preserve O(1)O(1) amortized cost, the contraction threshold must be decoupled from the doubling expansion:

Tutorial 9 Q4: Dynamic Table Contraction at One-Third Load Factor

Question: Suppose that instead of contracting an array by halving when load factor drops below 1/41/4, we contract by halving when load factor drops below 1/31/3 (contracting from mm to m/2m/2, so the new load factor is 2/32/3). Show that this rule still achieves O(1)O(1) amortized time for INSERT and DELETE.

Solution:

  • Load Factor Invariant:
    • When n=m/3n = m/3, we halve capacity from m→m/2m \to m/2.
    • The new load factor immediately following resize is: αnew=nm/2=m/3m/2=23.\alpha_{\text{new}} = \frac{n}{m/2} = \frac{m/3}{m/2} = \frac{2}{3}.
    • The table is now at 2/32/3 capacity, which is strictly separated from both triggers:
      1. To trigger a doubling (at α=1\alpha = 1), the table must absorb: m/2−n=m/2−m/3=m6 insertions.m/2 - n = m/2 - m/3 = \frac{m}{6} \text{ insertions}.
      2. To trigger another halving (at α=1/3\alpha = 1/3), the table must absorb: n−m/23=m3−m6=m6 deletions.n - \frac{m/2}{3} = \frac{m}{3} - \frac{m}{6} = \frac{m}{6} \text{ deletions}.
  • Amortization Accounting:
    • In either direction, at least m/6=Ω(m)m/6 = \Omega(m) non-resizing operations must occur before the next resize can possibly trigger.
    • The actual cost of contracting is copying n=m/3=Θ(m)n = m/3 = \Theta(m) elements.
    • Spreading the O(m)O(m) resize cost across the Ω(m)\Omega(m) preceding operations charges at most: m/3m/6=2 coins per operation.\frac{m/3}{m/6} = 2 \text{ coins per operation}.
    • Hence, both INSERT and DELETE execute in O(1)O(1) amortized time.
Tutorial 9 Q3: Amortized Analysis of Binary Min-Heap Operations

Question: Consider an ordinary binary min-heap supporting INSERT and EXTRACT-MIN. Can we achieve O(1)O(1) amortized cost for INSERT while keeping EXTRACT-MIN at O(log⁡n)O(\log n)? Explain.

Solution:

  • Standard Binary Heap:
    • In an ordinary binary min-heap, INSERT places an element at the next available leaf and bubbles up, costing O(log⁡n)O(\log n) in the worst case.
    • However, over a sequence of insertions into an initially empty heap, the average height of a newly inserted node is small: half of all nodes reside in leaves (height 0), one quarter at height 1, etc.
    • By aggregate analysis, nn insertions into an empty heap cost ∑i=1nO(depth(i))=O(n)\sum_{i=1}^n O(\text{depth}(i)) = O(n) total work. Thus, INSERT takes O(1)O(1) amortized time when no deletions occur.
  • Interleaved Sequence Bound:
    • If arbitrary sequences of INSERT and EXTRACT-MIN are allowed, comparison lower bounds dictate that sorting nn elements by performing nn insertions followed by nn extractions requires Ω(nlog⁡n)\Omega(n \log n) comparisons.
    • If INSERT were O(1)O(1) amortized and EXTRACT-MIN were o(log⁡n)o(\log n), sorting would violate the Ω(nlog⁡n)\Omega(n \log n) decision tree lower bound.
    • In a binary min-heap, EXTRACT-MIN remains Θ(log⁡n)\Theta(\log n), while INSERT achieves O(1)O(1) amortized and O(log⁡n)O(\log n) worst-case.
