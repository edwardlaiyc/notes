Loop Invariant Proof Protocol

A loop invariant is a statement about the variables that is true at the start of every iteration.

  1. Initialization: show it holds before the first iteration.
  2. Maintenance: assume it holds before iteration kk; show it still holds before iteration k+1k+1.
  3. Termination: at loop exit, the invariant plus the exit condition (i=ni = n) implies the algorithm’s goal.

Insertion Sort & Inversions

  • Mechanism: for j=2..nj = 2..n, insert A[j]A[j] into the sorted prefix A[1..j−1]A[1..j-1] by shifting larger elements right. Invariant: A[1..j−1]A[1..j-1] holds the original first j−1j-1 elements in sorted order.
  • Inversion: a pair of indices i<ji < j with A[i]>A[j]A[i] > A[j]. A sorted array has 0; a reverse-sorted array has the maximum (n2)=n(n−1)2\binom{n}{2} = \frac{n(n-1)}{2}.
  • Inversion theorem: each adjacent swap removes exactly one inversion, so Total Swaps=Total Inversions\text{Total Swaps} = \text{Total Inversions}, and Swaps≤Comparisons\text{Swaps} \le \text{Comparisons}.
  • Best case (sorted): n−1n - 1 comparisons, 0 swaps, Θ(n)\Theta(n).
  • Worst case (reverse sorted): n(n−1)2\frac{n(n-1)}{2} comparisons and swaps, Θ(n2)\Theta(n^2).
  • Average case (random permutation): half the pairs are inversions, n(n−1)4\frac{n(n-1)}{4} swaps, Θ(n2)\Theta(n^2).

Decision Tree Lower Bound

A comparison sort on nn distinct keys is a binary tree: each internal node is one comparison, each leaf is one output permutation. A correct sort needs ≥n!\ge n! leaves; a binary tree of height hh has ≤2h\le 2^h leaves. 2h≥n!⟹h≥⌈lg⁡(n!)⌉=Ω(nlog⁡n)2^h \ge n! \implies h \ge \lceil \lg(n!) \rceil = \Omega(n \log n)

  • Consequence: no comparison sort beats Ω(nlog⁡n)\Omega(n \log n) worst-case comparisons, so Mergesort and Heapsort are asymptotically optimal.
  • The shallowest leaf has depth ≥n−1\ge n - 1 (the comparisons must connect all nn elements), which is why the best case is Ω(n)\Omega(n).

Heaps & Heapsort

  • Max-heap: a complete binary tree stored in an array where every node is ≥\ge its children, i.e. A[⌊k/2⌋]≥A[k]A[\lfloor k/2 \rfloor] \ge A[k]. The root A[1]A[1] is the maximum. Complete = all levels full except possibly the last, which fills left to right. Height =⌊lg⁡n⌋= \lfloor \lg n \rfloor.
  • Index arithmetic (1-indexed): Parent =⌊k/2⌋= \lfloor k/2 \rfloor, Left =2k= 2k, Right =2k+1= 2k + 1. Leaves are ⌊n/2⌋+1…n\lfloor n/2 \rfloor + 1 \dots n; the last internal node is ⌊n/2⌋\lfloor n/2 \rfloor.
  • fixHeap (sift-down): swap a node with its larger child until it is ≥\ge both children. Each level costs 2 comparisons (child vs child, larger child vs node), so ≤2⌊lg⁡n⌋\le 2\lfloor \lg n \rfloor comparisons.
  • constructHeap (bottom-up): call fixHeap for i=⌊n/2⌋i = \lfloor n/2 \rfloor down to 1. At most ⌈n/2h+1⌉\lceil n/2^{h+1} \rceil nodes have height hh, each costing O(h)O(h): ∑h=0⌊lg⁡n⌋n2h+1⋅O(h)=O(n∑h≥0h2h)=O(n)\sum_{h=0}^{\lfloor \lg n \rfloor} \frac{n}{2^{h+1}} \cdot O(h) = O\Big(n \sum_{h \ge 0} \frac{h}{2^h}\Big) = O(n) using ∑h=1∞h2h=2\text{using } \sum_{h=1}^\infty \frac{h}{2^h} = 2 So construction is Θ(n)\Theta(n). A decreasing array is already a max-heap, the best case, costing exactly n−1n - 1 comparisons.
  • Heapsort: constructHeap, then n−1n - 1 times: swap root with last element, shrink heap by 1, fixHeap(1). Total Θ(n)+(n−1)⋅2lg⁡n=Θ(nlog⁡n)\Theta(n) + (n-1) \cdot 2\lg n = \Theta(n \log n).
  • Priority queue: insert (sift-up) and extractMax (swap last into root, sift-down) each cost O(log⁡n)O(\log n); peek costs O(1)O(1).

Quicksort

Algorithm. Partition first, then recurse on both sides. There is no combine step: after partition the pivot is already in its final sorted position. (The work happens on the way down, in pre-order; Mergesort does its work on the way up.)

void quicksort(int low, int high) {
    if (low >= high) return;          // 0 or 1 element
    int p = partition(low, high);     // pivot lands at index p
    quicksort(low, p - 1);
    quicksort(p + 1, high);
}

Partition as taught in the lecture (pivot = middle element; keys equal to the pivot stay on the right):

int partition(int low, int high) {
    int mid = (low + high) / 2;
    swap(slot[low], slot[mid]);           // move pivot to the front
    int pivot = slot[low].key;
    int last_small = low;                 // end of the "< pivot" block
    for (int i = low + 1; i <= high; i++) {
        if (slot[i].key < pivot) {
            last_small++;
            swap(slot[last_small], slot[i]);
        }
    }
    swap(slot[low], slot[last_small]);    // pivot goes between the blocks
    return last_small;
}

  • Result: everything left of index last_smalllast\_small is << pivot, everything right is ≥\ge pivot, and the pivot sits at last_smalllast\_small.

Applications & Problem Patterns

  • Simultaneous min & max: compare elements in pairs (n/2n/2 comparisons), compare the winners to find the max (n/2−1n/2 - 1), compare the losers to find the min (n/2−1n/2 - 1): n2+2(n2−1)=𝟑𝟐𝒏−𝟐(even n; ⌈3n/2⌉−2 in general)\tfrac{n}{2} + 2\left(\tfrac{n}{2} - 1\right) = \mathbf{\tfrac{3}{2}n - 2}\ \text{(even } n\text{; } \lceil 3n/2 \rceil - 2 \text{ in general)} versus the naive 2n−22n - 2.
  • Duplicate detection: sorting then scanning neighbours costs Θ(nlog⁡n)\Theta(n \log n). If keys lie in a range of size O(n)O(n), a frequency array gives Θ(n)\Theta(n).
  • kk-way list merging: keep a min-heap of size kk holding the front element of each list. Repeat nn times: extractMin, output it, insert that list’s next element. Each step is O(log⁡k)O(\log k), so total 𝑶(𝒏𝒍𝒐𝒈⁡𝒌)\mathbf{O(n \log k)} time, O(k)O(k) auxiliary space.

3. Linear-Time Non-Comparison Sorts

These escape the Ω(nlog⁡n)\Omega(n \log n) bound because they read key values directly instead of comparing pairs, so the decision-tree argument does not apply.

Counting Sort

Keys are integers in [0..k][0..k]. Arrays: input A[0..n−1]A[0..n-1], count C[0..k]C[0..k], output B[0..n−1]B[0..n-1].

C[0..k] = 0
for j = 0..n-1:       C[A[j]]++            // C[v] = number of keys equal to v
for v = 1..k:         C[v] += C[v-1]       // C[v] = number of keys <= v (= last slot of v + 1)
for j = n-1 downto 0: C[A[j]]--; B[C[A[j]]] = A[j]
  • Time Θ(n+k)\Theta(n + k) (linear if k=O(n)k = O(n)). Space Θ(n+k)\Theta(n + k), not in-place.
  • Stability: the placement loop must run backwards. Running forwards still sorts correctly but reverses the order of equal keys.

Radix Sort

Keys have dd digits in radix (base) kk. Sort by Least Significant Digit first, then the next digit, up to the most significant, using a stable sort (usually counting sort, kk buckets) on each pass.

  • Time: Θ(d(n+k))\Theta(d(n + k)).
  • Choosing the radix: for bb-bit keys split into rr-bit digits, d=b/rd = b/r and k=2rk = 2^r, giving Θ(br(n+2r))\Theta\big(\frac{b}{r}(n + 2^r)\big), minimised near r≈lg⁡nr \approx \lg n at Θ(bn/lg⁡n)\Theta(bn / \lg n).
  • Critical rule: the digit sort must be stable, otherwise a later pass destroys the order set by earlier passes. (Sorting MSD-first with this scheme is wrong.)

4. Graph Traversals: BFS, DFS & Topological Sort

Definitions

  • Graph G=(V,E)G = (V, E); |V||V| vertices, |E||E| edges. Adjacency list: Θ(|V|+|E|)\Theta(|V| + |E|) space. Adjacency matrix: Θ(|V|2)\Theta(|V|^2) space.
  • Vertex colours: White = undiscovered, Gray = discovered but not finished (still on the stack/queue), Black = finished (all neighbours discovered).
  • Timestamps (DFS): d[v]d[v] = discovery time, f[v]f[v] = finish time, d[v]<f[v]d[v] < f[v].
  • BFS: explores in layers using a FIFO queue; d[v]d[v] = fewest edges from the source ss.
  • DFS: follows one path as deep as possible, then backtracks; restarts from any white vertex so every vertex is visited (DFS forest).
  • DAG: directed acyclic graph. Topological order: a linear order of VV in which every edge u→vu \to v has uu before vv; exists ⇔\iff the graph is a DAG.

Traversal Invariants & Theorems

  • Black-White invariant: in both BFS and DFS, a black vertex never has a white neighbour.
  • Parenthesis theorem: for any two vertices, the intervals [d,f][d, f] are either disjoint or one nests inside the other; never partially overlapping.
  • White-path theorem: vv becomes a descendant of uu in DFS ⇔\iff at time d[u]d[u] there is a path u⤳vu \leadsto v of all-white vertices.
  • DFS edge classification for edge (u,v)(u, v), examined when uu is Gray:
    • vv is White ⟹\implies Tree edge (d[u]<d[v]<f[v]<f[u]d[u] < d[v] < f[v] < f[u]).
    • vv is Gray ⟹\implies Back edge to an ancestor (d[v]≤d[u]<f[u]≤f[v]d[v] \le d[u] < f[u] \le f[v]) ⟹\implies cycle.
    • vv is Black, d[u]<d[v]d[u] < d[v] ⟹\implies Forward edge (to a descendant already finished).
    • vv is Black, d[v]<d[u]d[v] < d[u] ⟹\implies Cross edge (between subtrees or branches).
  • Cycle test (directed): the graph has a cycle ⇔\iff DFS finds a back edge.
  • Undirected graphs: only Tree and Back edges exist in DFS; forward and cross edges cannot occur.
  • Topological sort via DFS (as taught in the lecture). Start with an empty list LL.
    1. Pick any unvisited vertex vv and run DFS from it, marking vertices visited as you go.
    2. When a vertex finishes (all its neighbours are done, it turns black), insert it at the head of LL.
    3. Repeat from step 1 until every vertex is visited.
    4. LL is the topological order. It lists vertices by decreasing f[v]f[v].
    • Why it works: for every edge u→vu \to v, vv finishes before uu, so vv is inserted first and uu ends up ahead of it. If uu is visited first, it cannot finish until vv does. If vv is visited first, uu is unreachable from vv (otherwise there is a cycle), so vv finishes first anyway.
    • Time: Θ(|V|+|E|)\Theta(|V| + |E|), since it is just DFS.
  • Topological sort via Kahn’s algorithm (not in the lecture; the slides use the in-degree-0 idea only to prove an order exists). In-degree of vv = number of edges entering vv. A vertex with in-degree 0 has no prerequisites left, so it can go next.
    1. Compute the in-degree of every vertex.
    2. Put every vertex with in-degree 0 into a queue QQ.
    3. While QQ is not empty: dequeue uu and append it to the output order. For each edge u→vu \to v, decrease in-degree(v)(v) by 1 (edge deleted); if it reaches 0, enqueue vv.
    4. Cycle check: if the output has fewer than |V||V| vertices, the remaining vertices all have in-degree ≥1\ge 1, which means they lie on or behind a cycle, so no topological order exists.
    • Time: Θ(|V|+|E|)\Theta(|V| + |E|): computing in-degrees scans every edge once, each vertex is enqueued once, and each edge is deleted once.

5. Greedy Graph Algorithms: Dijkstra, Prim, Kruskal

Definitions

  • Weighted graph: each edge (u,v)(u, v) has weight w(u,v)w(u, v). Path weight = sum of its edge weights; shortest-path distance δ(s,v)\delta(s, v) = minimum path weight from ss to vv.
  • Spanning tree: a connected acyclic subgraph containing all |V||V| vertices (|V|−1|V| - 1 edges). MST: the spanning tree of minimum total weight.
  • Cut (S,V\S)(S, V \setminus S): a partition of the vertices. An edge crosses the cut if its endpoints lie on opposite sides.
  • Relaxation of edge (u,v)(u, v): if d[u]+w(u,v)<d[v]:d[v]←d[u]+w(u,v),parent[v]←u\text{if } d[u] + w(u, v) < d[v]:\quad d[v] \leftarrow d[u] + w(u, v),\ \ \text{parent}[v] \leftarrow u

Algorithms

  • Dijkstra (single-source shortest paths). Arrays S[v]S[v] (1 once finalised), d[v]d[v], π[v]\pi[v].
    • Init: SS all 0; d[s]=0d[s] = 0, every other d=∞d = \infty; all π\pi null.
    • Each iteration:
      1. Pick the vertex uu with S[u]=0S[u] = 0 and smallest d[u]d[u].
      2. Set S[u]=1S[u] = 1.
      3. For each edge (u,v)(u, v) with S[v]=0S[v] = 0: if d[u]+w(u,v)<d[v]d[u] + w(u,v) < d[v], set d[v]=d[u]+w(u,v)d[v] = d[u] + w(u,v) and π[v]=u\pi[v] = u.
    • Tutorials ask for S,d,πS, d, \pi after every iteration (|V||V| iterations).
    • Correctness: when uu is extracted, d[u]=δ(s,u)d[u] = \delta(s, u). This needs all w≥0w \ge 0.
  • Prim (MST). Same arrays S,d,πS, d, \pi, but d[v]d[v] is the key: one edge weight, not a path length.
    • Init: d[start]=0d[\text{start}] = 0 and S[start]=1S[\text{start}] = 1 (as in the tutorial); every other d=∞d = \infty.
    • Iteration 1 only relaxes the start vertex’s neighbours.
    • Each later iteration:
      1. Pick the vertex uu with S[u]=0S[u] = 0 and smallest d[u]d[u].
      2. Set S[u]=1S[u] = 1; edge (π[u],u)(\pi[u], u) joins the MST.
      3. For each neighbour vv with S[v]=0S[v] = 0: if w(u,v)<d[v]w(u,v) < d[v], set d[v]=w(u,v)d[v] = w(u,v) and π[v]=u\pi[v] = u. Never add d[u]d[u].

  • Kruskal (MST). Arrays id[], sz[] (Weighted QuickUnion).
    • Init: id[x] = x, sz[x] = 1. Sort the edges ascending.
    • For each edge (p,q)(p, q): find both roots.

      • Different roots: accept. Attach the smaller tree’s root under the larger’s (id[small root] = big root) and add its size to sz[big root]. On a size tie, qq’s root goes under pp’s.

Core Theorems & Properties

  • MST Cut Property: the minimum-weight edge crossing any cut (S,V\S)(S, V \setminus S) belongs to some MST. If it is the unique minimum, it belongs to every MST. (Justifies Prim and Kruskal.)
  • MST Cycle Property: the strictly heaviest edge on any cycle cannot belong to any MST.
  • Distinct edge weights: if all weights in a connected graph are distinct, the MST is unique.
  • Shortest path vs. MST: the shortest path between two vertices is not guaranteed to use MST edges; the MST minimises total weight, not individual distances.
  • Dijkstra negative-weight trap: adding a positive constant CC to every edge does not fix negative weights, because a path with kk edges gains kCkC, so paths with more edges are penalised and the shortest path can change.

2. Characteristic Equations (Linear Homogeneous Recurrences)

8. Amortized Analysis Playbook

Definitions

Amortized cost is the average cost per operation over a worst-case sequence of nn operations, with no probability involved. Let cic_i = actual cost of operation ii, ĉi\hat{c}_i = amortized cost. Validity requires ∑ĉi≥∑ci\sum \hat{c}_i \ge \sum c_i for every sequence, so total actual cost ≤n⋅max⁡ĉi\le n \cdot \max \hat{c}_i.

Method Summary

  1. Aggregate analysis: bound the total cost of nn operations directly: ĉ=∑cin\hat{c} = \frac{\sum c_i}{n}. Every operation gets the same amortized cost.
  2. Accounting method: assign each operation type a charge ĉi\hat{c}_i. If ĉi>ci\hat{c}_i > c_i the surplus is stored as credit on elements; later expensive operations spend it. Rule: Bankk=∑i≤k(ĉi−ci)≥0\text{Bank}_k = \sum_{i \le k}(\hat{c}_i - c_i) \ge 0 at every step.
  3. Potential method: choose a potential function Φ(Di)≥0\Phi(D_i) \ge 0 on the data structure’s state: ĉi=ci+Φ(Di)−Φ(Di−1)\hat{c}_i = c_i + \Phi(D_i) - \Phi(D_{i-1}) Summing telescopes: ∑ĉi=∑ci+Φ(Dn)−Φ(D0)≥∑ci\sum \hat{c}_i = \sum c_i + \Phi(D_n) - \Phi(D_0) \ge \sum c_i whenever Φ(Dn)≥Φ(D0)=0\Phi(D_n) \ge \Phi(D_0) = 0.

9. Dynamic Programming Playbook

Definitions

Dynamic programming solves a problem by combining solutions to overlapping subproblems, each solved once and stored in a table. It requires optimal substructure: an optimal solution contains optimal solutions to its subproblems. Top-down = recursion + memoization; bottom-up = fill the table in dependency order. Table size ×\times work per cell = running time.

Canonical DP Problem Formulations

1. Longest Common Subsequence (LCS)

  • Base: c[i,0]=c[0,j]=0c[i, 0] = c[0, j] = 0.
  • Recurrence: c[i,j]={c[i−1,j−1]+1if xi=yjmax⁡(c[i−1,j],c[i,j−1])if xi≠yjc[i, j] = \begin{cases} c[i - 1, j - 1] + 1 & \text{if } x_i = y_j \\ \max(c[i - 1, j], c[i, j - 1]) & \text{if } x_i \ne y_j \end{cases}

2. 0/1 Knapsack Problem

11. Complexity Classes & NP-Completeness

Concept Definitions

  • Decision problem: a problem whose answer is YES or NO (e.g. “does GG have a clique of size kk?”). Complexity classes are defined on decision problems; an optimization problem is converted by adding a threshold.
  • Class P: decision problems solvable by a deterministic algorithm in polynomial time O(nk)O(n^k) for some constant kk.
  • Certificate / verifier: a certificate is a proposed solution (e.g. the kk vertices of the clique); a verifier checks it.
  • Class NP: decision problems whose YES instances have a certificate verifiable in deterministic polynomial time. (NP = “nondeterministic polynomial”, not “non-polynomial”.)
  • P⊆NPP \subseteq NP: a polynomial-time solver can ignore the certificate and just solve the instance. Whether P=NPP = NP is open.
  • Polynomial reduction (A≤pBA \le_p B): a polynomial-time computable function ff with x∈A⇔f(x)∈Bx \in A \iff f(x) \in B (YES maps to YES, NO to NO). Meaning “BB is at least as hard as AA”:
    • B∈P⟹A∈PB \in P \implies A \in P.
    • A∉P⟹B∉PA \notin P \implies B \notin P.
    • Transitive: A≤pB∧B≤pC⟹A≤pCA \le_p B \land B \le_p C \implies A \le_p C.
  • NP-hard: XX such that every Y∈NPY \in NP satisfies Y≤pXY \le_p X (XX itself need not be in NP).
  • NP-Complete (NPC): X∈NPX \in NP and XX is NP-hard, i.e. X∈NPX \in NP and for all Y∈NPY \in NP, Y≤pXY \le_p X. If any NPC problem is in P then P=NPP = NP.
  • Cook-Levin theorem: SAT is NP-complete (the first NPC problem, used as the root for all reductions).

Standard NPC Problems

Problem Question
SAT Is there a truth assignment making a Boolean formula true?
3-CNF-SAT Same, for a conjunction of clauses each an OR of exactly 3 literals
CLIQUE Does GG have kk vertices that are all pairwise adjacent?
VERTEX-COVER Is there a set of ≤k\le k vertices touching every edge?

Common reductions: 3-CNF-SAT ≤p\le_p CLIQUE; CLIQUE ≤p\le_p VERTEX-COVER (take the complement graph, use |V|−k|V| - k).

Proving Problem BB is NP-Complete (Protocol)

  1. Show B∈NPB \in NP (specify the polynomial-time certificate and verifier).
  2. Choose a known NP-complete problem AA (e.g. SAT, 3-CNF-SAT, CLIQUE, VERTEX-COVER).
  3. Construct a polynomial-time reduction ff mapping instances of AA to instances of BB.
  4. Prove equivalence: xx is YES for A⇔f(x)A \iff f(x) is YES for BB.

Trap: reduce from the known-hard problem to the new one (A≤pBA \le_p B). Reducing the other way proves nothing.

Coping Strategies for NP-Complete Problems

  1. Small NN (N≤25N \le 25): exact branch-and-bound / backtracking (O(2n)O(2^n)).
  2. Pseudo-polynomial DP: when numeric values are small (e.g. Knapsack O(nW)O(nW)).
  3. Special cases: restricted inputs (e.g. 2-SAT in O(n+m)O(n + m) time; many graph problems on trees in O(n)O(n) time).
  4. Approximation algorithms: polynomial heuristics with provable approximation ratios.
