Interfaces, Conflict Resolution & Scanner I/O

1. Definitions Reference

  • Interface: An abstract reference type declaring a contractual specification of method signatures and constants that implementing classes must fulfill.
  • Default Method: An interface instance method declared with the default modifier providing a fallback implementation body inherited by implementing classes.
  • Static Interface Method: A concrete method declared with static inside an interface that belongs strictly to the interface namespace and is not inherited by implementers.
  • Diamond Problem: Ambiguity occurring when a class inherits conflicting default method implementations with identical signatures from two or more interfaces.
  • Scanner: A utility class from java.util that parses primitive types and strings using regular expression patterns across an underlying character stream.

2. Interface Mechanics & Multiple Extension

  • Interface Fields: Every variable declared in an interface is implicitly public static final (constants only). They cannot be marked protected, private, or re-assigned.
  • Interface Methods: By default, non-default interface methods are implicitly public abstract.
  • Extending Multiple Interfaces: While a class cannot extend multiple classes, an interface can extend multiple parent interfaces simultaneously using the syntax interface C extends A, B.
  • Implementing Multiple Interfaces: A class can implement any number of interfaces: class Item implements A, B, C.
  • Transitive Implementation: If class Child extends Parent, and Parent implements Actionable, Child is-a Actionable transitively.
  • UML Notation: Interfaces are denoted with the stereotype <<interface>> (or <<Interface>>) and connected via a dashed arrow with an open triangle for implementation/realization.

3. Interface Default & Static Method Rules

  • Default Methods: Declared with the default keyword to enable non-breaking API evolution. Implementing classes inherit them automatically and may optionally override them.
  • Diamond Problem Collision: If a class implements two interfaces that provide the identical method signature with default bodies, the Java compiler refuses to guess and triggers a compile-time ambiguity error.
  • Collision Resolution Syntax: The implementing class must explicitly override the conflicting method. Inside the override, it can invoke a specific parent interface version using InterfaceName.super.methodName().
  • Static Interface Method Invocation: Static interface methods are never inherited by implementing classes or sub-interfaces. Calling SubClass.staticMethod() or instanceRef.staticMethod() causes a compile-time error. It must be called via InterfaceName.staticMethod().

4. Scanner Parsing Mechanics & The Token/Delimiter Formula

Core Scanner Methods Behavior

  • scanner.next(): Consumes leading whitespace, reads and returns the token up to the next whitespace delimiter.
  • scanner.nextLine(): Reads everything from the current cursor position up to the next newline character (\n), returns that character sequence, and consumes/discards the \n.
  • scanner.nextInt() / scanner.nextDouble(): Consumes leading whitespace, scans the numeric token, but leaves the trailing delimiter/newline (\n) sitting in the buffer.
  • scanner.next().toUpperCase().charAt(0): Extracts a single uppercase command character (useful for menu command parsing: Y/N, Q/T/F/N).

The Orphaned Newline Formula (Diagnostic & Fix)

  1. Trigger Condition: Calling scanner.nextLine() immediately following any token-based read (nextInt(), nextDouble(), next()).
  2. Failure Symptom: The subsequent nextLine() instantly reads the residual \n left behind in the buffer and returns an empty string "" without waiting for user typing.
  3. Resolution Rule: Insert an explicit blank buffer flush scanner.nextLine(); immediately after the numeric read before executing the real nextLine() input.
import java.util.Scanner;

// Interface with constants, default, and static methods
interface Storable {
    int MAX_CAPACITY = 500; // implicitly public static final

    void store(); // implicitly public abstract

    default void audit() {
        System.out.println("Storable audit log");
    }

    static void printSchema() {
        System.out.println("Schema version: 1.0");
    }
}

interface Auditable {
    default void audit() {
        System.out.println("Auditable audit log");
    }
}

// Interface extending multiple interfaces
interface SecureStorable extends Storable, Auditable {
    // Sub-interface must resolve default method collision if neither is overridden
    @Override
    default void audit() {
        Storable.super.audit();
    }
}

// Concrete class resolving Diamond Problem collision
class ArchiveManager implements Storable, Auditable {
    @Override
    public void store() {
        System.out.println("Archived up to capacity: " + MAX_CAPACITY);
    }

    // Explicit resolution required by compiler
    @Override
    public void audit() {
        Auditable.super.audit(); // Disambiguates to Auditable's default implementation
        System.out.println("Additional ArchiveManager audit checks complete");
    }
}
// Traps: Interface Static Resolution & Scanner Delimiter Parsing
class TrapDemo {
    public static void testInterfaceCalls() {
        // Valid static call:
        Storable.printSchema();

        // Compile-time error: Static methods on interfaces are not inherited
        // ArchiveManager.printSchema();
    }

    public static void processInput(Scanner sc) {
        System.out.print("Enter item count: ");
        int count = sc.nextInt();

        // MANDATORY: Flush leftover newline from buffer
        sc.nextLine();

        System.out.print("Enter item description: ");
        String description = sc.nextLine(); // Successfully waits and reads full string

        System.out.print("Enter coin input code (Q/T/F/N): ");
        char coinCode = sc.next().toUpperCase().charAt(0); // Safely grabs first uppercase char
    }
}
