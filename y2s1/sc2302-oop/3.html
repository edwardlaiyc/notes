Interfaces and Scanner Input

This chapter covers the end of Lecture 3 (multiple inheritance and interfaces), the interface parts of Lecture 10 (default and static methods), and console input with Scanner.

1. Multiple Inheritance

Multiple inheritance means one class has more than one parent class. A PartTimeStudent is a Student and an Employee. A Professor is a Researcher and a Teacher.

The problem: if two parents have a method or field with the same name, which one does the child get? Languages solve it in different ways (a priority order, renaming, or keeping both if the signatures differ).

Java does not allow multiple inheritance of classes. A class extends at most one class. Java gives the same benefit in a safer way: a class can implement many interfaces.

2. Interfaces

An interface is a list of methods that a class promises to provide. It says what a class can do, not how.

public interface IntFigure {
    double PI = 3.14159;           // a constant: public static final
    double findArea();             // public abstract
    double findPerimeter();
}

public class Circle implements IntFigure {
    private double radius;
    public Circle(double r) { radius = r; }
    public double findArea()      { return PI * radius * radius; }
    public double findPerimeter() { return 2 * PI * radius; }
}

Rules for what goes inside an interface

  • Every field is a constant. Java treats it as public static final, even if you do not write these words. You cannot change it: K = 2; is a compile error.
  • A method with no body is public abstract, even if you do not write these words.
  • From Java 8, an interface can also have default methods and static methods with bodies (Section 4).
  • An interface has no constructor and no instance fields.
  • You cannot create an object of an interface: new IntFigure() is a compile error. You can declare a variable of the interface type: IntFigure f = new Circle(2);

Rules for a class that implements an interface

  • Write class Circle implements IntFigure.
  • The class must give a body for every abstract method of the interface. If it does not, the class must be declared abstract.
  • The implementing method must be public. Because the interface method is public, a package-private version reduces the access and does not compile.
  • A class can implement many interfaces: class C extends SuperClass implements I1, I2, I3. Write extends before implements.
  • If Parent implements I and Child extends Parent, then Child is also an I. A Child object can go in an I variable.

Interfaces that extend interfaces

  • An interface extends another interface (it does not “implement” it): interface IShowablyOrdered extends IOrdered.
  • An interface can extend many interfaces: interface C extends A, B.
  • A concrete class that implements the derived interface must give bodies for the methods of both the derived and the base interface.
Pair Keyword How many
class → class extends one
class → interface implements many
interface → interface extends many
interface → class not allowed —

Why use interfaces

  • They give common behaviour to classes that are not related. Ship, Building, Person and Pet can all implement INameable with name(), but they share no useful parent class.
  • Code that uses the interface type works with any class that implements it, now or later. This gives loose coupling (Chapter 8).
  • In UML, an interface has the stereotype <<interface>>. A class that implements it connects with a dashed line and a hollow triangle (realisation).

3. Abstract Class vs Interface

Abstract class Interface
Is it a real parent class? Yes No, it is a contract
Fields Any fields, final or not, any access Only constants (public static final)
Methods Abstract and concrete; any access (protected, static, …) Abstract (public), plus default and static methods with bodies
Constructor Yes No
A class can extend / implement Only one Many
Create with new? No No
Use it when Subclasses share state and code Unrelated classes share a capability

A concrete class has a body for every method. It is the only kind of class you can create with new.

4. Default and Static Methods in Interfaces (Java 8)

Default methods

A default method has a body and the keyword default.

interface Printer {
    void print();
    default void scan() { System.out.println("Scanning document..."); }
}

Why Java added them. Before Java 8, adding a new abstract method to an interface broke every class that implemented it, because each class then missed a body. A default method gives a body, so old classes still compile and get the new method for free. A class can still override it.

The diamond problem with default methods

If a class implements two interfaces, and both have a default method with the same signature, the compiler does not know which body to use. This is a compile error, until the class overrides the method itself. Inside the override, the class can pick one parent version with InterfaceName.super.method().

interface A { default void show() { System.out.println("A"); } }
interface B { default void show() { System.out.println("B"); } }

class C implements A, B {
    @Override
    public void show() {     // REQUIRED: without it, class C does not compile
        A.super.show();      // pick A's version (optional)
    }
}

Static methods

A static method in an interface is a helper that belongs to the interface.

interface Utility {
    static void displayMessage() { System.out.println("static in interface"); }
}
Utility.displayMessage();      // OK

Static interface methods are not inherited. You must call them with the interface name. ImplClass.displayMessage() or obj.displayMessage() is a compile error. (A static method in a class can be called through a subclass name; an interface is different.)

Interface member Has a body? Inherited by implementing classes? Can be overridden?
abstract method No Yes Must be implemented
default method Yes Yes Yes
static method Yes No No
constant — Yes Cannot change

5. Console Input with Scanner

Scanner (in java.util) reads input. Make one with Scanner sc = new Scanner(System.in);.

A token is a piece of text between spaces or line breaks (the delimiters).

Method What it reads What it leaves behind
next() The next token The delimiter after it
nextInt(), nextDouble() The next token, as a number The line break (\n) after it
nextLine() Everything up to the end of the line Nothing; it also removes the \n
hasNext(), hasNextInt() Nothing; tests if a token (of that type) is next —

If the token is not a number, nextInt() throws an InputMismatchException.

The leftover line-break problem. After nextInt(), the \n that the user typed stays in the input. A nextLine() call straight after it reads that empty rest of the line and returns "" at once, without waiting for the user. The fix: call sc.nextLine(); once to remove the leftover \n, then call nextLine() again for the real input.

int count = sc.nextInt();
sc.nextLine();                    // remove the leftover \n
String name = sc.nextLine();      // now waits for the user
char cmd = sc.next().toUpperCase().charAt(0);   // first letter of a command, e.g. Q/T/F/N

6. Quiz Traps

  • class C extends A, B: compile error. class C implements A, B: fine. interface C extends A, B: fine.
  • Interface fields are constants. Assigning to one is a compile error.
  • Interface methods are public. Implementing one without public is a compile error.
  • A class that skips one interface method must be abstract.
  • Two interfaces with the same default method: the class does not compile until it overrides that method. Use A.super.show() to pick one.
  • Static interface methods are called only as Interface.method().
  • An interface cannot be created with new, and neither can an abstract class.
  • nextLine() straight after nextInt() returns an empty string.
