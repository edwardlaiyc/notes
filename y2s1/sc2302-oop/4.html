Polymorphism, Typecasting Matrix & Identity

1. Definitions Reference

  • Polymorphism: The capability of a superclass or interface reference type to refer to instances of different concrete subtypes, transparently invoking overridden behaviours at runtime.
  • Liskov Substitution Principle (LSP): Subtypes must be substitutable for their base types without altering program correctness (e.g., a subclass method must not strengthen preconditions or throw unexpected exceptions for inputs accepted by the base class).
  • Static Binding: Method call resolution performed by the compiler at compile time using declared reference and argument types (used for static, private, final, and overloaded methods).
  • Dynamic Binding: Method call resolution performed by the JVM at runtime using the actual object type on the heap via virtual table (vtable) dispatch.
  • Upcasting: Casting a subclass reference up to a superclass or interface reference type (implicit, automatic, and always type-safe).
  • Downcasting: Casting a superclass reference down to a concrete subclass reference type (requires explicit syntax (Subclass) ref and carries runtime validation risks).

2. Dispatch Mechanics: The 2-Step Resolution Formula

For any method call ref.method(arg):

  1. Step 1 (Compile-Time Check & Overload Resolution):
    • The compiler inspects only the declared static type of ref.
    • Access Gate Rule: If method is not declared in ref’s declared type or its ancestors, compilation fails immediately—even if the actual heap object contains the method.
    • Static Parameter Overload Matching: Overloaded signatures are matched based on the declared static reference type of arg. A subclass method accepting a subtype parameter (print(Cat)) does not override a superclass method accepting a supertype parameter (print(Animal)); it is purely an overload resolved at compile time.
  2. Step 2 (Runtime Dispatch Execution):
    • If the method is static, private, or final, execute the static implementation determined at compile time (Static Binding).
    • Otherwise, the JVM inspects the actual heap instance that ref points to (Dynamic Binding).
    • Method lookup begins at the actual object’s class and traverses up the ancestor hierarchy until the overriding version is found.

Static Overload Resolution vs Dynamic Override Dispatch

  • Overloading: Static binding. The compiler chooses which overloaded method signature to invoke based on the declared reference type of the argument.
  • Overriding: Dynamic binding. The JVM invokes the implementation belonging to the actual heap object type of the receiver instance.
  • Static Method Hiding: Static methods do not participate in dynamic dispatch; re-declaring them in a child class hides them. Calls execute strictly according to the reference type.

3. The 2-Step Typecasting Validity Formula & Issues with Usage

For an explicit downcasting expression TargetType target = (TargetType) originalVar;:

Step 1: Compile-Time Legality Check (Static Verification)

  • Inspect the declared static type of originalVar (Tdecl) and TargetType.
  • The expression compiles if and only if:
    1. Tdecl and TargetType belong to the same class inheritance lineage (TargetType is an ancestor or descendant of Tdecl), OR
    2. At least one is an interface (unless the other is marked final and does not implement the interface).
  • If neither condition is met -> Compile-Time Error (incompatible types).

Step 2: Runtime Safety Check (Heap Object Verification)

  • The JVM inspects the actual heap object (Tactual) referenced by originalVar.
  • The cast succeeds if and only if: Tactual is an instance of TargetType.
  • If Tactual does not satisfy instanceof TargetType -> Throws ClassCastException.

Issues with Usage (Exam Rubric Theory)

  1. Issues with Upcasting (Subclass View Restriction / Slicing): Upcasting is always safe and implicit, but it restricts the caller’s view to only the members declared in the superclass. Any methods or attributes specific to the subclass become inaccessible through the upcast reference, triggering compile-time errors unless an explicit downcast is performed.
  2. Issues with Downcasting (Runtime Instability & ClassCastException): Downcasting bypasses compile-time type safety. If the actual heap object is not an instance of the target subtype, the program crashes with a runtime ClassCastException. It must always be guarded using an instanceof check beforehand.

  • instanceof Guard Rule: Always evaluate if (ref instanceof TargetType) prior to an explicit downcast to avoid runtime ClassCastException. Evaluating null instanceof AnyType returns false safely.

4. Design Protocol: Extensibility via Dynamic Binding & Equality

Extensibility via Dynamic Binding (OCP Pattern)

  • Overloaded Static Dispatch Anti-pattern: Writing separate overloaded methods for each subtype (start(Car c), start(Boat b)). Adding a new vehicle requires modifying the caller class.
  • Polymorphic Dynamic Dispatch Pattern: Declaring a single method accepting the base type (start(Vehicle v)). The method dynamically dispatches to v.drive().
  • Abstract Method Forcing: Marking base methods abstract (public abstract void drive();) forces all concrete subclasses to implement their specific logic.

Object Equality Protocols: instanceof vs getClass()

  • instanceof Equality: Treats subclass instances as equal if their inherited fields match. Adheres to Liskov Substitution Principle (LSP), but requires caution if subclasses introduce distinct state variables.
  • getClass() Equality: Rejects any subclass instances outright, strictly enforcing that both operands share the identical concrete class.
// Base Abstract Class enforcing dynamic calculation
abstract class Polygon {
    protected String name;
    protected float width;
    protected float height;

    public Polygon(String name, float width, float height) {
        this.name = name;
        this.width = width;
        this.height = height;
    }

    // Abstract method: forces subclasses to override
    public abstract float calArea();
}

class RectanglePoly extends Polygon {
    public RectanglePoly(float width, float height) {
        super("Rectangle", width, height);
    }

    @Override
    public float calArea() {
        return width * height;
    }
}

class TrianglePoly extends Polygon {
    public TrianglePoly(float width, float height) {
        super("Triangle", width, height);
    }

    @Override
    public float calArea() {
        return 0.5f * width * height;
    }
}
// Identity Protocols: Member with instanceof vs getClass() equality
public class Member {
    private final String id;
    private final int level;

    public Member(String id, int level) {
        this.id = id;
        this.level = level;
    }

    public void displayRole() {
        System.out.println("Standard Member: " + id);
    }

    // Pattern A: instanceof-based equality (subclasses can satisfy equality contract)
    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;               // 1. Identity check
        if (!(obj instanceof Member)) return false; // 2. Handles null & unrelated types
        Member other = (Member) obj;                // 3. Guaranteed safe downcast
        return this.level == other.level &&
               (this.id != null && this.id.equals(other.id)); // 4. Field comparison
    }

    // Pattern B: strict getClass() equality (rejects subclass instances)
    public boolean strictEquals(Object obj) {
        if (this == obj) return true;
        if (obj == null || this.getClass() != obj.getClass()) return false; // Rejects subclasses
        Member other = (Member) obj;
        return this.level == other.level &&
               (this.id != null && this.id.equals(other.id));
    }
}

class VIPMember extends Member {
    public VIPMember(String id, int level) {
        super(id, level);
    }

    @Override
    public void displayRole() {
        System.out.println("VIP Member dynamic override");
    }

    // Subclass-only method for Access Gate testing
    public void exclusivePrivilege() {
        System.out.println("VIP Lounge Access Granted");
    }
}
// Traps: Access Gate, Argument Overload Resolution & Dynamic Dispatch
class AnimalTarget {
    public void print(AnimalTarget a) {
        System.out.println("Animal");
    }
}

class CatTarget extends AnimalTarget {
    // TRAP: Parameter is CatTarget, NOT AnimalTarget. This OVERLOADS print, it does NOT override it!
    public void print(CatTarget c) {
        System.out.println("Cat");
    }
}

class PolymorphismTrap {
    // Extensible Dynamic Binding demonstration
    static void processPolygon(Polygon p) {
        System.out.println("Area calculated dynamically: " + p.calArea());
    }

    public static void main(String[] args) {
        // --- TRAP 1: Subtype Argument Overload Trap (AY22/23 S2 Q1c) ---
        AnimalTarget a1 = new CatTarget();
        CatTarget a2 = new CatTarget();
        // a1 has declared type AnimalTarget -> compiler matches print(AnimalTarget)
        // Inherited AnimalTarget.print(AnimalTarget) is called -> prints "Animal"
        a2.print(a1); 

        // --- TRAP 2: Compile-Time Access Gate Trap ---
        Member ref = new VIPMember("M100", 5);
        // ref.exclusivePrivilege(); // COMPILE ERROR: exclusivePrivilege() not declared in Member
        ((VIPMember) ref).exclusivePrivilege(); // Valid downcast -> prints "VIP Lounge Access Granted"

        // --- Dynamic Polymorphic Dispatch ---
        ref.displayRole(); // Dynamic dispatch -> prints "VIP Member dynamic override"
        processPolygon(new RectanglePoly(10.0f, 5.0f)); // Prints: 50.0
        processPolygon(new TrianglePoly(10.0f, 5.0f));  // Prints: 25.0

        // --- Equality Comparison Protocols ---
        Member normal = new Member("M100", 5);
        System.out.println(normal.equals(ref));       // true (instanceof allows subtype)
        System.out.println(normal.strictEquals(ref)); // false (getClass() rejects subtype)
    }
}
