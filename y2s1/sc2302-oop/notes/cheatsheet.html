Part I: Concept Quiz Playbook (MCQs)

1. Java Execution, Memory & Types

Value Semantics vs. Reference Semantics

  • Primitives (byte, short, int, long, float, double, boolean, char): Stored directly in the variable’s memory cell. Assignment (b = a) copies the raw bits.
  • Object References: The variable stores a pointer (heap memory address) to the object instance. Assignment (ref2 = ref1) copies the address, creating two handles to the identical heap object (aliasing).
  • Java is Strictly Pass-By-Value: Method invocations always copy parameter values. Passing an object reference copies the address into the method’s local parameter frame. Mutating the object’s fields through that parameter mutates the original heap object; reassigning the parameter pointer itself does not affect the caller’s variable.

Identity vs. Equivalence Matrix

Operator / Method What It Evaluates Behavior on Primitives Behavior on Objects
== Literal bit comparison Checks if values are equal (5 == 5) Checks reference identity (do both point to the identical heap memory address?)
.equals() Logical equivalence Cannot be called on primitives Defined in Object as ==. Overridden by value classes (String, Integer, Date) to compare encapsulated state values.

Strings and the String Constant Pool

  • String is immutable. Any operation (toUpperCase(), concat(), replace()) returns a brand-new heap object; the original string is never modified.
  • String literals ("Java") are pooled in Metaspace/Heap. new String("Java") forces the allocation of a distinct, unpooled object.
    • "Java" == "Java" ⟹\implies true
    • "Java" == new String("Java") ⟹\implies false
    • "Java".equals(new String("Java")) ⟹\implies true
  • Left-to-right evaluation order: "A" + 1 + 2 ⟹\implies "A12", but 1 + 2 + "A" ⟹\implies "3A".

2. Access and Visibility Modifiers

Modifier Enclosing Class Same Package Subclass (Outside Package) Everywhere (World)
public Yes Yes Yes Yes
protected Yes Yes Yes (via inheritance only) No
(default / package-private) Yes Yes No No
private Yes No No No

“Watch Out” Access Traps

  • protected Subclass Rule: A subclass in another package can access an inherited protected member only through a reference of its own subclass type (or its children), never via an arbitrary superclass reference variable.
  • Package-Private: Omitting an access modifier does not mean protected. It grants access strictly to classes in the identical package.
  • Class Declarations: Top-level classes can only be declared public or package-private (never private or protected).

5. Exception Taxonomy and Invariants

                               java.lang.Throwable
                                        │
                 ┌──────────────────────┴──────────────────────┐
                 ▼                                             ▼
          java.lang.Error                            java.lang.Exception
       (Fatal; Unchecked)                                      │
                                        ┌──────────────────────┴──────────────────────┐
                                        ▼                                             ▼
                             java.lang.RuntimeException                     [Checked Exceptions]
                             (Programming bugs; Unchecked)                  (Mandatory handle/declare)
  • Checked Exceptions: All subclasses of Exception except RuntimeException. Compiler forces you to catch via try-catch or declare via throws.
  • Unchecked Exceptions: RuntimeException, Error, and their subclasses. Catch/declare is optional.
  • Catch Block Ordering: Handlers are evaluated top-to-bottom. Specific subclass catches must precede broader superclass catches; otherwise, a compile error occurs.
  • The finally Block: Executes unconditionally—even after return statements in try or catch. Bypassed only by System.exit().
  • Overriding Rule: An overriding method cannot declare broader checked exceptions than the superclass method.

6. UML Class Relationships Decision Matrix

Relationship Symbol & Arrow Head Line Style Conceptual Keyword Code Implementation Pattern
Dependency Client ..> Supplier Dashed “Uses-a” (transient) Method parameter, local variable, or return type
Association A ──> B (Directed) Solid “Knows-a” (structural) Instance field holding reference to B
Aggregation Whole ◇── Part Solid (Hollow diamond) “Has-a” (weak ownership) Collection field; Part outlives Whole (e.g. Team ◇── Player)
Composition Whole ◆── Part Solid (Filled diamond) “Contains-a” (strong ownership) Part instantiated/destroyed with Whole (e.g. Car ◆── Engine)
Generalization Sub ──▷ Super Solid (Hollow triangle) “Is-a” (inheritance) class Sub extends Super
Realization Impl ..▷ Inter Dashed (Hollow triangle) “Implements” (contract) class Impl implements Inter

7. Sequence Diagrams and BCE Invariants

Arrow Head Conventions

  • Synchronous Call: Solid line with filled triangle arrow ──► (caller blocks until return).
  • Asynchronous Call: Solid line with open arrow ──> (caller continues without blocking).
  • Reply / Return Message: Dashed line with open arrow <-- - - (returns value to caller).
  • Object Creation: Message points directly to the head of the new object’s box (<<create>>).
  • Object Destruction: Dashed lifeline terminates with a bold X.

BCE Communication Invariants

  • Boundary: Interacts with external actors and translates requests to Controllers.
  • Controller: Orchestrates business logic, validates transactions, coordinates Entities.
  • Entity: Stores persistent domain data and core entity rules.
  • Strict Rule: Boundary ↔\leftrightarrow Entity direct communication is FORBIDDEN. All interactions must be mediated through a Controller.

8. SOLID Principles Recognition Matrix

Principle Core Directive Primary Code Smell Indicating Violation
SRP One class, one single reason to change Class mixes business logic with SQL queries, XML serialization, or GUI code.
OCP Open for extension, closed for modification Adding a new payment or vehicle type requires editing an existing switch/if-else statement.
LSP Subtypes must be substitutable for base types Subclass throws UnsupportedOperationException, overrides method with empty body, or violates base postconditions (Square extends Rectangle).
ISP No client forced to depend on unused methods Monolithic interface with 15 methods forcing simple implementers to provide empty dummy methods.
DIP Depend on abstractions, not concretions High-level business class directly instantiates concrete hardware driver (private HPPrinter p = new HPPrinter();).

9. Modern Java: Collections, Streams, and Lambdas

Collections Framework Selection

  • Need fast random indexed lookups? ⟹\implies ArrayList (O(1)O(1) read).
  • Need constant-time insertions/deletions at ends? ⟹\implies LinkedList (O(1)O(1) head/tail).
  • Need unique elements with maximum search performance? ⟹\implies HashSet (O(1)O(1)).
  • Need unique elements sorted by natural ordering? ⟹\implies TreeSet (O(log⁡n)O(\log n)).
  • Need key-value pairs with fast lookup? ⟹\implies HashMap (O(1)O(1)).

Functional Interfaces (SAM)

  • Predicate<T>: T -> boolean (test())
  • Function<T, R>: T -> R (apply())
  • Consumer<T>: T -> void (accept())
  • Supplier<T>: () -> T (get())

Streams API: Intermediate vs. Terminal Operations

  • Intermediate (Lazy - returns Stream<T>): filter, map, distinct, sorted, limit, skip. None execute until a terminal operation is called!
  • Terminal (Eager - triggers execution): forEach, collect, reduce, count, anyMatch, findFirst.

Part II: Code Tracing Playbook (10 Tracing Recipes)

Recipe 1: Tracing Object Reference Aliasing

Algorithm:

  1. Draw a box for each new ClassName() allocated on the heap.
  2. Label reference variables on the stack pointing to their respective heap boxes.
  3. When refB = refA; executes, redirect refB’s arrow to point to refA’s heap box.
  4. Mutating a field through refB.setVal(x) updates the single underlying box; checking refA.getVal() reveals the updated value.

Recipe 2: Tracing Constructor Chaining & Initialization

Algorithm:

  1. Ascent Phase: Follow explicit this(...) or super(...) calls upward to java.lang.Object. If omitted, insert implicit super();.
  2. Descent Phase: From topmost parent down to child:
    • Step A: Run that class’s field declarations and instance initializers in textual order.
    • Step B: Run the rest of that class’s constructor body statements.

Recipe 3: Method Resolution & Dynamic Binding

The 2-Step Exam Protocol:

  • Step 1 (Compile-Time Check on Declared Type):
    • Look strictly at the declared reference type.
    • Does this type declare the method signature? If NO ⟹\implies COMPILE ERROR.
    • If field access (obj.field), evaluate the field value defined in the declared type immediately (HALT TRACE; fields do not dynamically dispatch).
  • Step 2 (Runtime Dispatch on Actual Instance):
    • Look at the concrete runtime heap object.
    • Has the concrete subclass overridden this method?
    • If YES ⟹\implies Execute the subclass implementation.
    • If NO ⟹\implies Walk up the inheritance tree to the nearest parent implementation.

Recipe 4: Overridden Methods Called in Parent Constructors

Execution Trap Protocol:

  1. Parent constructor invokes an instance method foo().
  2. Because the runtime object is Child, the JVM dispatches to Child.foo().
  3. However, Child’s field initializers have not run yet.
  4. The method executes against uninitialized default field values (0, 0.0, null, false).

Recipe 5: Downcasting, instanceof, and ClassCastException

Validation Protocol:

  1. Compile-Time Validation: Does an inheritance relationship exist between the reference type and target cast type?
    • If completely unrelated trees ⟹\implies Compilation Error.
  2. Runtime Validation: Inspect the actual heap object.
    • Is actualObject instanceof TargetType true?
    • If YES ⟹\implies Cast succeeds.
    • If NO ⟹\implies Throws ClassCastException.

Recipe 6: Exception Control Flow and finally

Execution Flow Protocol:

1. Run try block sequentially.
2. Exception thrown at Line L?
   ├── YES ──► Abort rest of try. Match first compatible catch block top-to-bottom.
   │           Execute catch body.
   └── NO  ──► Skip all catch blocks.
3. Run finally block UNCONDITIONALLY.
4. Continue with statement following the try-catch block (unless exception was uncaught or a return fired).

Recipe 7: Scanner Newline Buffer Leftover Trap

Tracing Rule:

  • sc.nextInt(), sc.nextDouble(), and sc.next() consume only the token bits, leaving trailing \n in the input stream.
  • A subsequent sc.nextLine() immediately reads that unconsumed \n and returns empty string "" without waiting.
  • Fix: Insert sc.nextLine(); to flush the buffer before capturing textual input.

Recipe 8: Code-to-UML Relationship Classification

Flowchart Protocol:

  1. extends Class ⟹\implies Generalization (Solid line + hollow triangle).
  2. implements Interface ⟹\implies Realization (Dashed line + hollow triangle).
  3. Instance field holding object reference ⟹\implies Association (Solid line).
    • Part destroyed with Whole? ⟹\implies Composition (Filled diamond at Whole).
    • Part exists independently? ⟹\implies Aggregation (Hollow diamond at Whole).
  4. Object only in method parameter/local variable ⟹\implies Dependency (Dashed line + open arrow).

Recipe 9: Stream Pipeline Evaluation

Evaluation Protocol:

  1. Write the source list: [e1, e2, e3, ...].
  2. Apply filter(p): Strike out elements that return false.
  3. Apply map(f): Transform each surviving element.
  4. Apply Terminal Operation: Combine, print, or collect the results.

Recipe 10: Generic Wildcards and the PECS Principle

Decision Protocol:

  • Reading/pulling elements out? ⟹\implies ? extends T (Producer Extends). Safe to read as T; compiler forbids add().
  • Writing/putting elements in? ⟹\implies ? super T (Consumer Super). Safe to add T; reading returns raw Object.
