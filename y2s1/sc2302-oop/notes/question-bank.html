1. Classes, Objects, References and Strings

Q1 · Basic · Reassigning one of two aliases

class Box { int v; Box(int v) { this.v = v; } }

Box a = new Box(1);
Box b = a;
b.v = 5;
a = new Box(9);
System.out.print(a.v + " " + b.v);

What is printed?

  • A 5 5
  • B 1 5
  • C 9 5
  • D 9 9
Q1 answer

C. b = a copies the reference, so both names point at the box holding 1. b.v = 5 changes that shared box. a = new Box(9) points a at a new box. b still points at the old box, which now holds 5.

Q2 · Basic · A constructor parameter with the field’s name

class Acc {
    int bal;
    Acc(int bal) { bal = bal; }
}
System.out.print(new Acc(50).bal);

What is printed?

  • A 50
  • B 0
  • C Compilation error: bal is assigned to itself
  • D NullPointerException
Q2 answer

B. Inside the constructor, the parameter bal shadows the field. bal = bal copies the parameter into itself and never touches the field, which keeps its default 0. Self-assignment is legal, so this compiles. The fix is this.bal = bal;.

Q3 · Intermediate · Pass-by-value with an object argument

static void change(Box x) {
    x.v = 2;
    x = new Box(3);
    x.v = 4;
}

Box b = new Box(1);
change(b);
System.out.print(b.v);

Box is the class from Q1. What is printed?

  • A 1
  • B 2
  • C 3
  • D 4
Q3 answer

B. Java passes a copy of the reference. So x and b start out pointing at the same box.

  1. x.v = 2 changes the shared box, so b.v is now 2.
  2. x = new Box(3) re-points only the local copy x. b is not affected.
  3. x.v = 4 changes the new box, which is thrown away when the method returns.

Q4 · Basic · Static versus instance counters

class Counter {
    static int total = 0;
    int mine = 0;
    Counter() { total++; mine++; }
}

Counter c1 = new Counter();
Counter c2 = new Counter();
Counter c3 = c2;
System.out.print(Counter.total + " " + c1.mine + " " + c3.mine);

What is printed?

  • A 2 1 1
  • B 3 1 1
  • C 2 2 2
  • D 2 1 2
Q4 answer

A. new runs twice, so the constructor runs twice. c3 = c2 copies a reference and creates no object. All objects share the one static total, so it ends at 2. Each object has its own mine, and each was incremented once. c3.mine is c2.mine, which is 1.

Q5 · Intermediate · Using an instance field in a static method

class Shop {
    private int stock = 5;
    static int fee = 2;
    static int total() { return stock + fee; }
    int net() { return stock - fee; }
}

What happens when Shop is compiled?

  • A It compiles. total() returns 7.
  • B Compilation error in total(): it is static, so there is no this object whose stock it could read.
  • C Compilation error in net(): an instance method cannot read the static fee.
  • D It compiles, but total() throws NullPointerException at run time.
Q5 answer

B. javac reports “non-static variable stock cannot be referenced from a static context”. A static method belongs to the class, so it runs with no object and has no stock to read. The reverse direction is fine: an instance method can read static members, so net() compiles.

Q6 · Hard · Strings built at compile time versus run time

String s1 = "OOP";
String s2 = "OO" + "P";
String s3 = new String("OOP");
String p  = "OO";
String s4 = p + "P";
System.out.print((s1 == s2) + " " + (s1 == s3) + " " + (s1 == s4) + " " + s1.equals(s4));

What is printed?

  • A true false true true
  • B false false false true
  • C true true false true
  • D true false false true
Q6 answer

D.

  1. "OO" + "P" joins two literals. The compiler folds it into the literal "OOP", which is the same pooled object as s1. So s1 == s2 is true.
  2. new String(...) always makes a new heap object, so s1 == s3 is false.
  3. p is a variable, so p + "P" is computed at run time and makes a new object. So s1 == s4 is false.
  4. equals compares characters, so it gives true.

Twist: if p were declared final String p = "OO";, then p + "P" would also be a compile-time constant, and s1 == s4 would be true.

Q7 · Hard · final does not protect a list’s contents

class Team {
    private final List<String> members;
    Team(List<String> m) { members = m; }
    List<String> getMembers() { return members; }
}

List<String> src = new ArrayList<>(List.of("Ann"));
Team t = new Team(src);
src.add("Bob");
t.getMembers().add("Cat");
System.out.print(t.getMembers().size());

What is printed?

  • A 1
  • B 2
  • C 3
  • D Compilation error: members is final
Q7 answer

C. final freezes the reference members, not the list it points to. The constructor stores the caller’s list itself, so src.add("Bob") changes the team. The getter returns that same list, so add("Cat") changes it as well. That gives Ann, Bob and Cat. This is an encapsulation leak. The fix is a defensive copy on the way in (members = new ArrayList<>(m)) and a read-only view on the way out (return List.copyOf(members) or Collections.unmodifiableList(members)).

Q8 · Hard · A HashSet of a class without equals

class P { int id; P(int id) { this.id = id; } }

Set<P> s = new HashSet<>();
s.add(new P(1));
s.add(new P(1));
P x = new P(2);
s.add(x);
s.add(x);
System.out.print(s.size());

What is printed?

  • A 1
  • B 2
  • C 3
  • D 4
Q8 answer

C. P does not override equals/hashCode, so it keeps Object’s versions, which compare identity. The two new P(1) objects are different objects, so both are kept. x is added twice, but it is the same object, so the second add is rejected. That leaves 2 + 1 = 3. If P overrode both methods to compare id, the answer would be 2.

2. Inheritance, Access and Constructors

Q9 · Basic · Which inherited fields are visible in another package?

// file a/Base.java
package a;
public class Base {
    private   int p;
              int d;     // no modifier
    protected int q;
    public    int r;
}

// file b/Sub.java
package b;
import a.Base;
public class Sub extends Base {
    void f() { /* which fields can f() use by their simple name? */ }
}
  • A r only
  • B q and r
  • C d, q and r
  • D All four
Q9 answer

B. Sub is in a different package from Base. private is visible only inside Base. No modifier (package-private) is visible only inside package a. protected is visible to subclasses in any package, through inheritance. public is visible everywhere.

Q10 · Basic · The parent has no no-argument constructor

class Parent { Parent(int x) { System.out.print("P" + x); } }
class Child extends Parent { Child() { System.out.print("C"); } }
new Child();

What happens?

  • A Prints P0C
  • B Prints C
  • C Compilation error
  • D Prints CP0
Q10 answer

C. Child() has no explicit super(...), so the compiler inserts super();. Parent declares a constructor, so Java gives it no default constructor, and Parent() does not exist. javac reports “constructor Parent in class Parent cannot be applied to given types”. The fix is to write super(0); as the first line of Child().

Q11 · Intermediate · Chaining this(...) and super(...)

class A {
    A()      { System.out.print("A"); }
    A(int x) { this(); System.out.print("a" + x); }
}
class B extends A {
    B()      { this(5); System.out.print("B"); }
    B(int y) { super(y); System.out.print("b"); }
}
new B();

What is printed?

  • A BbAa5
  • B Aa5bB
  • C a5AbB
  • D AbBa5
Q11 answer

B. First climb the chain, then print on the way back down.

  1. B() calls this(5), so B(5) runs.
  2. B(5) calls super(5), so A(5) runs.
  3. A(5) calls this(), so A() runs and prints A.
  4. Back in A(5), it prints a5. Back in B(5), it prints b. Back in B(), it prints B.

Q12 · Intermediate · Access and return type when overriding

class Shape { protected double area() { return 0; } }
class Sq extends Shape { /* ??? */ }

Which declaration of area() in Sq compiles?

  • A public double area() { return 4; }
  • B private double area() { return 4; }
  • C double area() { return 4; }
  • D protected int area() { return 4; }
Q12 answer

A. An override may keep or widen access (protected → public), but never narrow it. C (package-private) and B (private) are narrower. D fails because a primitive return type must match exactly. Covariant returns apply only to reference types, and int is not a subtype of double.

Q13 · Intermediate · Four uses of final

final class Token { }
class Vault { final void lock() { } }

class Safe extends Vault { void lock() { } }      // L1
class Coin extends Token { }                      // L2
final int[] arr = {1, 2};  arr[0] = 9;            // L3
final int k = 1;  k++;                            // L4

Which lines fail to compile?

  • A L1 and L2 only
  • B L2, L3 and L4
  • C L1, L2 and L4
  • D All four
Q13 answer

C. L1: a final method cannot be overridden. L2: a final class cannot be extended. L4: a final local cannot be reassigned. L3 compiles, because final fixes the reference arr, and the array’s elements can still change.

Q14 · Hard · super.m() followed by a dynamically dispatched call

class A { void m() { System.out.print("A"); n(); }
          void n() { System.out.print("a"); } }
class B extends A { void m() { System.out.print("B"); super.m(); }
                    void n() { System.out.print("b"); } }
class C extends B { void n() { System.out.print("c"); super.n(); } }

A x = new C();
x.m();

What is printed?

  • A BAcb
  • B BAb
  • C BAcba
  • D BAa
Q14 answer

A.

  1. C has no m(), so the nearest one is B.m(). It prints B.
  2. super.m() is bound statically to A.m(). It prints A.
  3. Inside A.m(), the call n() means this.n(), and this is a C object. So C.n() runs and prints c.
  4. super.n() in C is B.n(). It prints b. A.n() never runs.

Q15 · Hard · An overridden method called from the parent constructor

class Base {
    Base() { System.out.print("B"); show(); }
    void show() { System.out.print("x"); }
}
class Derived extends Base {
    int n = 7;
    String s = "hi";
    Derived() { System.out.print("D" + n); }
    @Override void show() { System.out.print(n + s); }
}
new Derived();

What is printed?

  • A BxD7
  • B B7hiD7
  • C B0nullD7
  • D BD7
Q15 answer

C.

  1. Derived() first calls super(). Derived’s field initialisers have not run yet, so n = 0 and s = null.
  2. Base() prints B and then calls show(). The object is a Derived, so Derived.show() runs and prints 0null.
  3. Control returns to Derived(). The initialisers now run (n = 7, s = "hi"), then the body prints D7.

3. Interfaces, Abstract Classes and Scanner

Q16 · Basic · What you can do with an abstract type

abstract class Shape { abstract double area(); }
class Circle extends Shape { double area() { return 3; } }

Shape s1 = new Circle();       // L1
Shape s2 = new Shape();        // L2
Shape[] arr = new Shape[2];    // L3

Which lines fail to compile?

  • A L2 only
  • B L2 and L3
  • C L1 and L2
  • D None
Q16 answer

A. An abstract class cannot be instantiated, so L2 fails. It can still be a variable type (L1). L3 creates an array of two Shape references, both null. That creates no Shape object, so it compiles.

Q17 · Basic · nextInt() followed by nextLine()

The user types 25, Enter, Alice Tan, Enter.

Scanner sc = new Scanner(System.in);
int age = sc.nextInt();
String name = sc.nextLine();
System.out.print("[" + age + "][" + name + "]");

What is printed?

  • A [25][Alice Tan]
  • B [25][Alice]
  • C [25][]
  • D InputMismatchException
Q17 answer

C. nextInt() reads 25 and leaves the newline in the buffer. nextLine() reads up to that newline and returns the empty string at once, so the user never gets to enter the name. The fix is an extra sc.nextLine(); after nextInt().

Q18 · Intermediate · Mixing next() and nextLine()

The user types 25 Alice Tan on one line and presses Enter.

Scanner sc = new Scanner(System.in);
int age = sc.nextInt();
String first = sc.next();
String rest = sc.nextLine();
System.out.print("[" + age + "][" + first + "][" + rest + "]");

What is printed?

  • A [25][Alice][Tan]
  • B [25][Alice Tan][]
  • C [25][][Alice Tan]
  • D [25][Alice][ Tan]
Q18 answer

D. nextInt() and next() each skip leading spaces and read one token. They stop just after 25 and just after Alice. nextLine() returns everything left on the line, including the leading space: " Tan".

Q19 · Intermediate · Implementing an interface method without public

interface Flyer { void fly(); }
class Bird implements Flyer {
    void fly() { System.out.print("F"); }
}

What happens?

  • A It compiles. new Bird().fly() prints F.
  • B Compilation error: Bird.fly() has package access, but interface methods are implicitly public.
  • C Compilation error: Bird must be declared abstract.
  • D It compiles, because Flyer.fly() is package-private too.
Q19 answer

B. An interface method with no modifier is public abstract. Implementing it is overriding, and an override cannot narrow access. javac reports “attempting to assign weaker access privileges; was public”. The same rule makes an interface field implicitly public static final, so MAX++ on an interface constant is also a compile error.

Q20 · Intermediate · A constructor in an abstract class

abstract class Animal {
    String name;
    Animal(String n) { name = n; System.out.print("A"); }
    abstract String sound();
    String describe() { return name + ":" + sound(); }
}
class Cat extends Animal {
    Cat() { super("Tom"); System.out.print("C"); }
    String sound() { return "meow"; }
}
Animal a = new Cat();
System.out.print(" " + a.describe());

What is printed?

  • A C Tom:meow
  • B CA Tom:meow
  • C Compilation error: an abstract class cannot have a constructor
  • D AC Tom:meow
Q20 answer

D. An abstract class cannot be instantiated directly, but it can have constructors. Subclasses run them through super(...). Animal(String) prints A first, then Cat() prints C. describe() is a concrete method in Animal. It calls the abstract sound(), which dispatches to Cat.sound(). This is the template-method pattern.

Q21 · Hard · Default methods inherited along two paths

interface A { default String hi() { return "A"; } }
interface B extends A { default String hi() { return "B"; } }
interface C extends A { }
class D implements B, C { }

System.out.print(new D().hi());

What happens?

  • A Prints A
  • B Prints B
  • C Compilation error: D inherits conflicting defaults from B and C
  • D Compilation error: D must override hi()
Q21 answer

B. C does not declare its own hi(). It only passes on A.hi(). B.hi() overrides A.hi(), so it is the more specific default, and Java uses it. There is no conflict. A conflict exists only if C also declared its own default String hi(). Then D would have to override hi(), and it could pick one with B.super.hi().

Q22 · Hard · The superclass method and the interface default have the same signature

interface Greeter { default String greet() { return "I"; } }
class Base { public String greet() { return "C"; } }
class Kid extends Base implements Greeter { }

System.out.print(new Kid().greet());

What happens?

  • A Prints I
  • B Compilation error: Base.greet() and Greeter.greet() conflict
  • C Prints C
  • D Compilation error: Kid must override greet()
Q22 answer

C. The class wins. A method inherited from a superclass always beats an interface default with the same signature, so Base.greet() runs. The defaults rule from Q21 applies only when the competing methods are all interface defaults.

4. Polymorphism, Overloading and Casting

Q23 · Intermediate · Field hiding through an inherited getter

class A { String name = "A"; String getName() { return name; } }
class B extends A { String name = "B"; }

A x = new B();
B y = new B();
System.out.print(x.name + y.name + y.getName());

What is printed?

  • A ABA
  • B ABB
  • C BBB
  • D AAA
Q23 answer

A. Fields are bound to the declared type. x.name reads A.name (A), and y.name reads B.name (B). getName() is not overridden, so the code in A runs, and the name written inside A means A.name. It prints A. A field is not overridden, even when a method reads it.

Q24 · Intermediate · Widening, boxing or varargs?

static void f(long x)    { System.out.print("L"); }
static void f(Integer x) { System.out.print("I"); }
static void f(int... x)  { System.out.print("V"); }

f(5);
f(Integer.valueOf(5));
f('a');

What is printed?

  • A IIL
  • B LIV
  • C VIL
  • D LIL
Q24 answer

D. The compiler tries three phases in order: ① exact match or widening, ② boxing, ③ varargs.

  1. f(5): int → long is widening, so phase 1 finds f(long). Boxing to Integer is never tried. Prints L.
  2. f(Integer.valueOf(5)): the argument is already an Integer, so it is an exact match. Prints I.
  3. f('a'): char widens to long in phase 1. Prints L.

Q25 · Intermediate · Two casts, one of which is impossible

class Animal { }
class Dog extends Animal { }
class Cat extends Animal { }

Animal a = new Cat();
Dog d = (Dog) a;          // L1
String s = (String) a;    // L2

What happens?

  • A It compiles. L1 throws ClassCastException at run time.
  • B Compilation error at L1 only.
  • C It compiles and runs with no error.
  • D Compilation error at L2. If L2 is removed, L1 compiles but throws ClassCastException at run time.
Q25 answer

D. The compiler allows a cast only when it could succeed for some object. L1 is plausible, because an Animal variable might hold a Dog, so it compiles. At run time the object is a Cat, so L1 throws. L2 can never succeed: String is a final class outside Animal’s tree. javac rejects it with “Animal cannot be converted to String”.

Q26 · Hard · Casting to an interface

interface Swimmer { }
class Animal { }
final class Rock { }

Animal a = new Animal();
Swimmer s1 = (Swimmer) a;            // L1
Swimmer s2 = (Swimmer) new Rock();   // L2

What happens?

  • A Both lines compile. Both throw ClassCastException at run time.
  • B L1 is a compilation error. L2 compiles.
  • C L1 compiles and throws ClassCastException at run time. L2 is a compilation error.
  • D Both are compilation errors.
Q26 answer

C. Animal is not final, so some subclass of Animal might implement Swimmer. The compiler must therefore allow L1. At run time this object is a plain Animal, so the cast throws. Rock is final and does not implement Swimmer, so no Rock can ever be a Swimmer. The compiler rejects L2.

Q27 · Hard · A static method called from an inherited instance method

class P { static String id() { return "P"; }
          String who() { return id(); } }
class C extends P { static String id() { return "C"; } }

P p = new C();
C c = new C();
System.out.print(p.id() + c.id() + c.who());

What is printed?

  • A PCP
  • B PCC
  • C CCC
  • D CCP
Q27 answer

A. Static methods hide; they do not override. A static call binds to a type at compile time.

  1. p.id(): the declared type is P, so it prints P.
  2. c.id(): the declared type is C, so it prints C.
  3. c.who() runs the code in P. The call id() written there binds to P.id(), so it prints P. Compare Slido Q8: if id() were an instance method, it would dispatch to C.

Q28 · Hard · The overload is fixed at compile time, the override at run time

class Shape {
    String meet(Shape s)  { return "SS"; }
    String meet(Circle c) { return "SC"; }
}
class Circle extends Shape {
    String meet(Shape s)  { return "CS"; }
    String meet(Circle c) { return "CC"; }
}

Shape a = new Circle();
Shape b = new Circle();
Circle c = new Circle();
System.out.print(a.meet(b) + " " + a.meet(c) + " " + c.meet(a));

What is printed?

  • A CC CC CC
  • B CS CC CS
  • C SS SC CS
  • D CS CC CC
Q28 answer

B. Make two separate choices for each call.

Call Compiler picks the overload (declared argument type) JVM picks the override (receiver object) Result
a.meet(b) b is declared Shape → meet(Shape) Circle CS
a.meet(c) c is declared Circle → meet(Circle) Circle CC
c.meet(a) a is declared Shape → meet(Shape) Circle CS

The argument’s runtime type never affects the choice. Java dispatches only on the receiver.

Q29 · Hard · An equals that overloads instead of overriding

class Pt {
    int x;
    Pt(int x) { this.x = x; }
    public boolean equals(Pt o) { return o.x == x; }
}

Object a = new Pt(1);
Pt b = new Pt(1);
System.out.print(a.equals(b) + " " + b.equals(b) + " " + b.equals(a));

What is printed?

  • A false true false
  • B true true false
  • C false false false
  • D true true true
Q29 answer

A. equals(Pt) has a different parameter type from Object.equals(Object), so it is an overload, not an override.

  1. a.equals(b): a is declared Object, which sees only equals(Object). Pt never overrode it, so it compares identity and gives false.
  2. b.equals(b): the declared type Pt sees both. For a Pt argument, equals(Pt) is the more specific match, so it gives true.
  3. b.equals(a): the argument is declared Object, so only equals(Object) fits. It compares identity and gives false.

The fix is @Override public boolean equals(Object o). With @Override, the compiler would have flagged the mistake.

Q58 answer

A. Each .get…() in the chain adds one more class that InvoicePrinter must know about. Getters hide fields, but this code still exposes the structure between the objects. Low coupling means each class talks only to its direct collaborators. (The rule is often called the Law of Demeter; that name is not in the lecture.)

Q59 · Hard · What the “inversion” in DIP means

  high-level layer      OrderService ───────► «interface» OrderRepository
                                              (declared in the high-level layer)
                                                         △
                                                         ┆ realises
                                                         ┆
  low-level layer                                   SqlRepository

What exactly is inverted, compared with OrderService calling SqlRepository directly?

  • A Control flow: calls now go from SqlRepository to OrderService.
  • B The source-code dependency. SqlRepository now depends on an interface that the high-level layer owns. At run time, calls still go from the service down to SQL.
  • C OrderService now inherits from SqlRepository.
  • D The database now calls the service through callbacks.
Q59 answer

B. Before, the high-level policy depended on a low-level detail. Now both depend on the abstraction, and the low-level class points up at it. Control still flows down: submit() calls save(), and save() runs SQL. Only the compile-time dependency arrow is reversed. That is why the interface belongs with the high-level code.

Q60 · Basic · Records

record Point(int x, int y) {}

Point p = new Point(1, 2);
Point q = new Point(1, 2);
System.out.print((p == q) + " " + p.equals(q) + " " + p.x() + " " + p);

What is printed?

  • A false true 1 Point[x=1, y=2]
  • B true true 1 Point[x=1, y=2]
  • C false false 1 Point@1b6d3586
  • D Compilation error: the accessor is getX()
Q60 answer

A. A record generates a constructor, private final fields, accessors named after the components (x(), not getX()), and equals, hashCode and toString based on the components. == still compares references, and there are two separate objects.

Q61 · Basic · remove(int) versus remove(Object)

List<Integer> xs = new ArrayList<>(List.of(5, 1, 3, 1));
xs.remove(1);
xs.remove(Integer.valueOf(1));
System.out.print(xs);

What is printed?

  • A [3, 1]
  • B [5, 3]
  • C [5, 3, 1]
  • D [5]
Q61 answer

B. remove(1) is an exact match for remove(int index), so it removes the element at index 1, which is the first 1. That leaves [5, 3, 1]. remove(Integer.valueOf(1)) calls remove(Object), which removes the first element equal to 1. That leaves [5, 3].

Q62 · Intermediate · Counting words with a Map

Map<String, Integer> m = new HashMap<>();
for (String w : "to be or not to be".split(" "))
    m.put(w, m.getOrDefault(w, 0) + 1);
System.out.print(m.get("to") + m.get("be") + " " + m.get("xyz"));

What is printed?

  • A 22 null
  • B 4 0
  • C NullPointerException
  • D 4 null
Q62 answer

D. “to” and “be” each appear twice. + works left to right: Integer + Integer unboxes and adds to give 4, and only then joins with " ". get on a missing key returns null, which string concatenation prints as null. No unboxing of null happens, so there is no exception.

Q63 · Intermediate · Changing a local variable inside a lambda

int count = 0;
List.of(1, 2, 3).forEach(x -> count++);
System.out.print(count);

What happens?

  • A Compilation error
  • B Prints 0
  • C ConcurrentModificationException
  • D Prints 3
Q63 answer

A. A lambda may use a local variable of the enclosing method only if that variable is effectively final (never reassigned). count++ reassigns it, so javac reports “local variables referenced from a lambda expression must be final or effectively final”. A field, or int[] count = {0} with count[0]++, would compile.

Q64 · Intermediate · Removing from a list inside a for-each loop

List<String> names = new ArrayList<>(List.of("a", "b", "c"));
for (String n : names) {
    if (n.equals("a")) names.remove(n);
}
System.out.print(names);

What happens?

  • A Prints [b, c]
  • B Prints [a, b, c]
  • C Compilation error
  • D ConcurrentModificationException
Q64 answer

D. A for-each loop uses a hidden Iterator. names.remove(n) changes the list behind the iterator’s back, so the iterator’s next next() call detects the change and throws. Safe alternatives are it.remove() with an explicit iterator (Slido Q35) or names.removeIf(n -> n.equals("a")).

Edge case: removing "b" (the second-last element) happens not to throw, because hasNext() then returns false before next() can check. Do not rely on this.

Q65 · Hard · Adding to and reading from wildcard lists

List<? extends Number> a = new ArrayList<Integer>();
a.add(1);                       // L1
Number n = a.get(0);            // L2
List<? super Integer> b = new ArrayList<Number>();
b.add(1);                       // L3
Integer i = b.get(0);           // L4

Ignore run-time errors. Which lines fail to compile?

  • A L1 and L3
  • B L1 and L4
  • C L2 and L4
  • D L1 only
Q65 answer

B. Remember PECS: Producer Extends, Consumer Super.

  • ? extends Number could be a list of Double, so adding an Integer is unsafe (L1 fails). Every element is some kind of Number, so reading as Number is safe (L2).
  • ? super Integer could be a list of Number or Object, so adding an Integer is always safe (L3). A read can only be guaranteed to return an Object, so assigning it to Integer fails (L4).

Q66 · Hard · The order of prints in a stream pipeline

Stream.of("a", "bb", "ccc")
      .filter(s -> { System.out.print("F" + s); return s.length() > 1; })
      .map(s -> { System.out.print("M" + s); return s.toUpperCase(); })
      .forEach(s -> System.out.print("E" + s));

What is printed?

  • A FaFbbFcccMbbMcccEBBECCC
  • B FbbMbbEBBFcccMcccECCC
  • C FaFbbMbbEBBFcccMcccECCC
  • D Nothing, because streams are lazy
Q66 answer

C. forEach is a terminal operation, so the pipeline runs. Elements move through it one at a time. "a" fails the filter and stops there (Fa). "bb" passes through every stage (Fbb Mbb EBB) before "ccc" starts (Fccc Mccc ECCC). Option A is the stage-by-stage order, which streams do not use. D would be right only if there were no terminal operation (Slido Q38).

Q67 · Hard · A TreeSet ordered by a Comparator

Set<String> s = new TreeSet<>(Comparator.comparing(String::length));
s.addAll(List.of("kiwi", "fig", "pear", "apple", "bean"));
System.out.print(s);

What is printed?

  • A [fig, kiwi, apple]
  • B [apple, bean, fig, kiwi, pear]
  • C [fig, bean, apple]
  • D [fig, kiwi, pear, apple, bean]
Q67 answer

A. A TreeSet treats two elements as the same when the comparator returns 0. It never calls equals. Comparing by length makes "pear" and "bean" equal to "kiwi" (all 4 letters). kiwi was added first, so the other two are rejected. The result is sorted by length: 3, 4, 5. B would be the result with natural (alphabetical) ordering.

Q68 · Hard · A switch expression without default

int code = 3;
String s = switch (code) {
    case 1 -> "one";
    case 2 -> "two";
};
System.out.print(s);

What happens?

  • A Prints null
  • B Prints two
  • C Compilation error
  • D Throws an exception at run time, because no case matches 3
Q68 answer

C. A switch expression must produce a value for every possible input. Over an int, that requires a default. javac reports “the switch expression does not cover all possible input values”. The old switch statement has no such rule. Without a matching case it simply does nothing, and without break it falls through.
